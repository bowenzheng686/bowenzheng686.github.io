文件操作 —— ls / cp / mv / rm / find / ln / tar

核心
命令常用选项说明
ls -lah-l长格式 -a含隐藏 -h人类可读 -t按时间 -S按大小 -r倒序列出目录内容。最常用：ls -lah
ls -l --time=atime显示访问时间而非修改时间排查文件读取问题
cp -a src dst-a归档模式(保留权限/时间) -r递归 -v显示过程 -u仅更新 -n不覆盖复制文件或目录
cp -p保留权限、时间戳、所有者备份时保持元数据一致
mv -i src dst-i覆盖前确认 -n不覆盖 -v显示过程 -b备份目标移动或重命名（同文件系统内是改 inode 指针，几乎瞬间完成）
rm -rf dir-r递归 -f强制 -i确认 -v显示过程 -d删空目录危险！生产环境切勿 rm -rf / 或 rm -rf *
find /path -name "*.log" -mtime +7 -delete-name按名称 -type f/d/l按类型 -mtime n修改时间 -size +100M按大小 -user按所有者 -perm按权限 -exec cmd {} \;执行命令 -delete删除搜索文件（Linux 最强文件查找工具）
find . -type f -empty查找空文件清理无用的空文件
find . -type f -perm 0777查找权限为 777 的文件安全检查
ln -s target linkname-s符号链接 -f强制覆盖 -n不跟随已有链接创建软链接（类似 Windows 快捷方式）
ln target hardlink不加 -s 即硬链接硬链接：同一 inode 的多个目录入口，删除原文件不影响硬链接
tar -czvf archive.tar.gz dir/-c创建 -x解压 -t查看 -zgzip -jbzip2 -Jxz -v详细 -f指定文件 -C指定目录 --exclude排除打包/压缩（tape archive 的历史命名）
tar -xzvf archive.tar.gz -C /dest/解压到指定目录-C 必须在目标路径前加上
stat filename查看 inode 详细信息显示文件大小、权限、时间戳、inode 号、链接数
file filename检测文件类型不依赖扩展名——检测文件头魔数
du -sh dir/-s汇总 -h人类可读 --max-depth=N深度查看目录占用磁盘空间
du -h --max-depth=1 / | sort -hr | head -10找出根目录下最大的 10 个目录磁盘清理第一步
head -n 20 file / tail -n 20 file-n行数 -f跟踪（tail 专用）查看文件头/尾部
less file分页查看，/搜索 n/N跳转 g/G首尾大文件查看利器，比 more 强大
硬链接 vs 软链接
硬链接（同一 inode）：删原文件不影响它，不能跨文件系统，不能链接目录。
软链接（符号链接，独立 inode 指向路径）：删原文件就断链（悬空链接），能跨文件系统和链接目录。

用户与权限 —— useradd / passwd / chmod / chown / umask

核心
命令常用选项说明
useradd -m -s /bin/bash username-m创建家目录 -s指定 shell -G附加组 -u指定 UID -d指定家目录 -e过期日期添加用户
useradd -M -s /usr/sbin/nologin appuser创建无家目录、不能登录的系统用户为服务创建专用账户
userdel -r username-r同时删除家目录和邮件删除用户
usermod -aG docker username-aG追加到附加组（不用 -a 会覆盖已有组！）修改用户属性
passwd username-l锁定 -u解锁 -e强制下次改密 -S状态设置/修改密码（root 可改他人密码，普通用户只能改自己）
groupadd groupname-g指定 GID添加组
chmod 755 file数字模式：4读+2写+1执行。三位=所有者/组/其他。或 u/g/o/a +/- r/w/x修改文件权限
chmod u+x script.sh给所有者加执行权限使脚本可执行
chmod -R 755 dir/递归修改目录及其下所有文件批量授权
chmod 1777 /tmp黏滞位（t）：只有文件所有者能删除共享目录的安全设置
chmod u+s /usr/bin/passwdSETUID（s）：执行时以文件所有者权限运行普通用户改密码时临时获得 root 权限
chmod g+s dir/SETGID（s）：目录下新文件继承目录的组共享工作目录
chown user:group file-R递归修改文件所有者和组
chown -R user:group dir/递归修改整个目录树批量改所有者
umask 022默认值 022 → 新文件权限 644，新目录 755控制新文件的默认权限掩码
getfacl file / setfacl -m u:user:rwx fileACL 扩展权限：突破"所有者-组-其他"三级限制给特定用户额外权限
su - username-/-l/--login 完整登录环境切换用户
sudo -u username cmd-u指定用户 -i模拟初始登录以其他用户身份执行命令
visudo安全编辑 /etc/sudoers（带语法校验）配置 sudo 权限
id username查看 UID、GID、所有组验证用户身份
chmod 777 是大忌
任何需要 chmod 777 才能跑的程序都是在掩盖错误。权限问题应该通过正确设置所有者和组来解决，不是给全世界开放。

[Unit]
Description=My Application
After=network.target

[Service]
Type=simple
User=appuser
Group=appgroup
WorkingDirectory=/opt/myapp
ExecStart=/opt/myapp/bin/myapp --config /etc/myapp/config.yml
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5
LimitNOFILE=65536
EnvironmentFile=-/etc/myapp/env
# 安全加固
PrivateTmp=yes
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/var/log/myapp /var/lib/myapp
ProtectHome=yes

[Install]
WantedBy=multi-user.target

# 启用服务:
# systemctl daemon-reload    # 重读单元
# systemctl enable --now myapp   # 开机启动 + 立即运行

终端与 Shell 快捷键 —— 让你的手不离开键盘

核心
快捷键作用使用场景
Ctrl + C发送 SIGINT(2) 中断信号终止正在运行的命令（最常用的快捷键）
Ctrl + D发送 EOF（文件结束符）退出当前 shell / 退出交互式程序（如 python repl）
Ctrl + Z发送 SIGTSTP(20) 暂停信号暂停前台进程（用 fg 恢复，bg 放后台继续）
Ctrl + L清屏等同于 clear 命令，但保留滚动缓冲区（终端上为 Ctrl+Shift+L）
Ctrl + R反向搜索历史命令输入关键词查找以前执行过的命令，再按 Ctrl+R 继续往前搜
Ctrl + R（再次）继续向前（更早的历史）搜索多次按键循环查找

4进程信号速查表

清

Linux 信号 —— 与进程通信的唯一方式

必备

信号是 Linux 内核与进程、进程与进程之间通信的"通知机制"。每个信号有一个编号和一个名称。进程可以注册信号处理器（handler），也可以选择忽略（SIGKILL 和 SIGSTOP 除外——这两者不可被捕获或忽略）。

编号信号名默认行为触发方式典型用途
1SIGHUP终止终端挂断 / kill -1 PID重新加载配置（Nginx、systemd 等服务用此信号触发 reload）
2SIGINT终止键盘 Ctrl+C中断前台进程（用户主动停止）
3SIGQUIT终止 + core dump键盘 Ctrl+\退出并生成 core dump（调试用）
9SIGKILL终止kill -9 PID内核强制杀死——进程无任何机会反抗或清理
10SIGUSR1终止kill -10 PID用户自定义信号 1（如 Nginx 用 USR1 重新打开日志文件）
11SIGSEGV终止 + core dump无效内存访问（段错误）程序 bug：访问 NULL 指针、栈溢出、缓冲区溢出
12SIGUSR2终止kill -12 PID用户自定义信号 2（如 Nginx 用 USR2 平滑升级）
15SIGTERM终止kill PID（默认）优雅终止——给进程清理资源的机会（关闭连接、写回数据）
17SIGCHLD忽略子进程状态改变父进程被告知子进程退出了（避免僵尸进程）
18SIGCONT继续运行kill -18 PID恢复被 SIGSTOP/SIGTSTP 暂停的进程
19SIGSTOP暂停kill -19 PID暂停进程（不可被捕获/忽略，只能等 SIGCONT）
20SIGTSTP暂停键盘 Ctrl+Z终端暂停信号（可被捕获，vim 就捕获了它）

信号的使用场景

# 优雅停止（让进程自己清理）
kill 1234                    # 等同于 kill -15 1234
# 等价于:
kill -TERM 1234

# 强制杀死（最后手段）
kill -9 1234                 # SIGKILL —— 内核直接销毁进程

# 重新加载配置（很多守护进程支持）
kill -HUP $(pgrep nginx)      # SIGHUP(1)
# 等价于:
systemctl reload nginx
nginx -s reload

# 暂停/恢复进程
kill -STOP 1234              # 暂停
kill -CONT 1234              # 恢复

# Nginx 平滑升级（USR2 启动新 master，WINCH 优雅关闭旧 worker）
kill -USR2 $(cat /var/run/nginx.pid)   # 启动新版本的 master
kill -WINCH $(cat /var/run/nginx.pid.oldbin)  # 关闭旧 worker
SIGKILL(9) vs SIGTERM(15)
kill -9 是暴力手段——内核直接回收进程的内存、关闭文件描述符、释放锁，进程完全不知情。数据库可能在写入一半时被杀，导致数据损坏。
kill -15 (SIGTERM) 是礼貌做法——通知进程"请你自己退出"，进程可以在信号处理器中关闭连接、刷写缓存、删除临时文件。永远先用 kill -15，等几秒无效后再用 kill -9。
core dump 进程崩溃时内核将其内存镜像写入磁盘文件，用于 gdb 事后分析。 不可捕获 SIGKILL(9) 和 SIGSTOP(19) 由内核直接处理，进程无法安装 handler。

网络排障六步法（自底向上，逐层排查）

第一步：链路层 —— 网线/网卡是否正常

命令：ip link show ethtool eth0 dmesg | grep eth

查：LINK 状态是否为 UP？速度/双工是否正确？是否有 CRC 错误？

ethtool eth0 | grep "Link detected" → 应为 yes

第二步：IP 层 —— 地址和路由是否正确

命令：ip addr show ip route show

查：IP 地址是否配置？子网掩码是否对？默认网关是否有？

ip route | grep default → 必须有默认路由

第三步：连通性 —— 能不能到达目标

命令：ping -c 4 target mtr target

查：丢包率？延迟是否正常？哪一跳开始不通？

先 ping 网关，再 ping 外网——逐步缩小范围

第四步：端口 —— 目标服务是否在监听

命令：telnet host port nc -zv host port nmap -p port host

查：端口是否可达？防火墙/安全组是否拦截？

ss -tlnp | grep port 先在目标机器上确认服务在监听

第五步：DNS —— 域名能否解析

命令：nslookup domain dig domain host domain

查：A 记录是否正确？DNS 服务器是否可达？缓存是否过期？

dig +short domain @8.8.8.8 绕过本地 DNS 测试

第六步：应用层 —— HTTP 返回是否符合预期

命令：curl -v https://host curl -I host wget --debug host

查：HTTP 状态码？响应头？响应体内容？SSL 证书是否有效？

curl -w "\nhttp_code:%{http_code}\ntime_total:%{time_total}s\n" host

网络排障的黄金命令组合

# 一次性检查所有网络层面（复制粘贴到终端）
echo "=== 网卡状态 ===" && ip link show && echo
echo "=== IP 地址 ===" && ip addr show | grep -E "inet " && echo
echo "=== 路由表 ===" && ip route show && echo
echo "=== DNS 配置 ===" && cat /etc/resolv.conf && echo
echo "=== 监听端口 ===" && ss -tlnp && echo
echo "=== 防火墙规则 ===" && iptables -L -n -v --line-numbers 2>/dev/null || echo "需要 root"
echo "=== 网关 Ping ===" && GATEWAY=$(ip route | grep default | awk '{print $3}')
ping -c 3 -W 1 "$GATEWAY" 2>/dev/null && echo "网关可达" || echo "网关不可达!"
echo "=== 外网 Ping ===" && ping -c 3 -W 1 8.8.8.8 2>/dev/null && echo "外网可达" || echo "外网不可达!"
echo "=== DNS 解析测试 ===" && nslookup google.com 2>/dev/null || echo "DNS 解析失败"
网络排障的心法：逐层排除，不跳跃
遇事不决先 ping 网关（确认内部网络正常），再 ping 8.8.8.8（确认能出外网），然后 nslookup（确认 DNS 解析正常），最后 curl 目标 URL（确认应用层通讯正常）。绝不要跳过步骤——90% 的误判都是因为跳过了某一层。
