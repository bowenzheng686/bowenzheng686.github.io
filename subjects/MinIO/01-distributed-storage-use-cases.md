# 01 分布式存储系统应用场景

选择存储方式，先看应用需要的是**块设备、共享文件**还是**按对象键访问的内容**。三者并非线性的“新技术替换旧技术”，各自适合不同的读写方式。

![MinIO 对象存储第 2 页插图](assets/img-b8176eb32f75a924.webp)

### 常见的传统存储方案

![MinIO 对象存储第 3 页插图](assets/img-7a31bfd6fcd7c91d.webp)

**DAS（直连存储）**直接连接一台主机，如服务器内部磁盘。主机通常把它作为块设备使用，延迟较低、结构简单；但其他主机不能直接共享同一块磁盘。若服务只依赖这一台主机，主机故障就会影响访问。DAS 不只适合“小数据量”，许多分布式存储系统本身也以多台机器上的直连磁盘为底层介质。

**NAS（网络附加存储）**经网络提供文件访问，常见协议包括 NFS 和 SMB。应用看到的是文件与目录，便于多台主机共享，但性能取决于网络、服务端和工作负载；不能笼统说 NAS “性能不好”。FTP 属于文件传输协议，不宜与 NFS／SMB 的共享文件系统能力混为一谈。

**SAN（存储区域网络）**通常向主机提供远程块设备或逻辑卷，可通过光纤通道或 iSCSI 等方式连接。主机仍需在块设备上创建文件系统；多台主机共同访问同一卷时，还要解决文件系统并发与一致性问题。SAN 便于集中管理和扩容，但成本、性能与复杂度取决于具体架构。

### 对象存储是什么

对象存储按“桶、对象键、对象内容及元数据”组织数据，应用通常通过 HTTP API 读写整个对象。图片、视频、备份、日志与安装包都可作为对象，并不限于“大文件”。每个对象主要包含：

1. 数据：需要存储的内容（例如一张图片或一个视频）。

2. 元数据：关于这个数据的描述性信息，比如创建时间、文件类型等。

3. **对象键**：在桶内标识对象；相同键的更新行为还受版本控制配置影响。

### 适合哪些应用

电商商品图、音视频内容、用户上传、日志归档与备份都适合按对象键访问。对象存储通常更容易把容量扩展和访问接口从单台文件服务器中解耦，但不是说 NAS 或 SAN 在这些场景“完全无能为力”：若应用需要频繁随机改写文件内部、POSIX 文件锁或块设备语义，对象存储未必合适。

### 对象存储服务 OSS (Object Storage Service ) 特点

对象存储的常见特点是 API 访问、按桶与键组织对象、适合水平扩容，并可结合分片上传处理大对象。对象键中的斜杠通常只是命名约定，界面可把它显示成目录，但底层不必有传统文件系统目录树。持久性依赖具体产品的副本／纠删码、故障域与备份设计；对象也不应默认暴露在公网。部分系统提供挂载工具，但挂载层不等于完整的 POSIX 文件系统语义。

### OSS 分类

公有云服务包括阿里云 OSS、腾讯云 COS、Amazon S3 和 Azure Blob Storage 等，基础设施由服务商运营；自建方案如 MinIO、Ceph RGW 则需要自行规划磁盘、网络、升级与故障恢复。下一篇先用公有云 OSS 说明能力，再转向 MinIO 的实现。
