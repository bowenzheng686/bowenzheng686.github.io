<p class="noindent-c">前两章介绍了如何在路由器接口上配置 IP 地址和掩码，使路由器能够路由进出该地址／掩码组合所表示子网的数据包。虽然这些内容正确且实用，但迄今所有示例都忽略了 LAN 交换机以及 VLAN 的可能存在。实际上，前面的示例都是最简单的情况：连接的交换机是二层交换机，只使用一个 VLAN，路由器在物理接口上配置一条 <strong>ip address</strong> 命令。本章详细探讨如何配置路由器，使其能够路由进出每个 VLAN 上子网的数据包。</p>

<p class="noindent">由于二层交换机不会在 VLAN 之间转发二层帧，网络必须使用能够执行 IP 路由的设备，在子网之间路由 IP 数据包。该设备可以是路由器，也可以是兼具路由功能的交换机。</p>

<p class="noindent">回顾一下，以太网定义了 VLAN 的概念，而 IP 定义了 IP 子网的概念，因此 VLAN 并不等同于子网。不过，一个 VLAN 中的设备通常使用同一子网内的 IP 地址。同理，位于两个不同 VLAN 中的设备通常也属于两个不同的子网。为了让不同 VLAN 中的两台设备相互通信，路由器必须连接到各 VLAN 上的子网，然后在这些子网中的设备之间转发 IP 数据包。</p>

<p class="noindent">本章讨论多种 VLAN 间路由方法，它们在不同场景下都可能有用：</p>

<ul class="sq">

<li><p class="bull"><strong>通过路由器 802.1Q 中继进行 VLAN 路由：</strong>第一节讨论配置路由器，在连接二层交换机的链路上使用 VLAN 中继。路由器负责路由，交换机负责创建 VLAN。路由器与交换机之间的链路使用 VLAN 中继，使路由器拥有连接每个 <span id="page_455" data-epub-type="pagebreak"></span>VLAN／子网的接口。这项功能称为通过 VLAN 中继进行路由，也称为<a id="key_208" href="#ref-gloss_351"><span class="blue">单臂路由（router-on-a-stick，ROAS）</span></a>。</p></li>

<li><p class="bull"><strong>通过三层交换机 SVI 进行 VLAN 路由：</strong>第二节讨论使用同时支持二层交换和三层路由的 LAN 交换机（称为<a id="key_205" href="#ref-gloss_227"><span class="blue">三层交换机</span></a>或<a id="key_206" href="#ref-gloss_261"><span class="blue">多层交换机</span></a>）。为执行路由，三层交换机配置使用称为交换虚拟接口（SVI）的接口，也称为 VLAN 接口。</p></li>

<li><p class="bull"><strong>通过三层交换机路由端口进行 VLAN 路由：</strong>本章第三个主要部分讨论 SVI 的替代方案，即<a id="key_207" href="#ref-gloss_346"><span class="blue">路由端口</span></a>，它使物理交换机端口像路由器接口一样工作。这一节还介绍将 EtherChannel 用作路由端口的概念，这项功能称为<a id="key_204" href="#ref-gloss_225"><span class="blue">三层 EtherChannel（L3 EtherChannel）</span></a><em>。</em></p></li>

<li><p class="bull"><strong>在路由器的 LAN 交换端口上进行 VLAN 路由：</strong>最后一个主要部分讨论集成 LAN 交换端口的 Cisco 路由器。例如，在分支机构中，可以部署带有少量集成交换端口的路由器，来代替一台小型路由器加一台独立小型交换机。本节展示如何配置路由器的交换端口及内部逻辑，使路由器为这些交换端口上的子网路由数据包。</p></li>

</ul>

<h3 class="h3" id="ch18lev1sec3">通过路由器 802.1Q 中继进行 VLAN 路由</h3>

<p class="noindent">几乎所有企业网络都使用 VLAN。为了路由进出这些 VLAN 的 IP 数据包，某些设备（路由器或三层交换机）需要在每个子网中拥有一个 IP 地址，并且拥有到达每个子网的直连路由。这样，这些路由器或三层交换机上的 IP 地址就可以充当各子网的默认网关。</p>

<p class="noindent">本章将 LAN 路由选项分为五类：</p>

<ul class="sq">

<li><p class="bull">使用路由器，为每个 VLAN 各用一个路由器 LAN 接口和一条线缆连接交换机（通常不采用）</p></li>

<li><p class="bull">使用路由器，通过 VLAN 中继连接 LAN 交换机（称为单臂路由或 ROAS）</p></li>

<li><p class="bull">使用带有交换虚拟接口（SVI）的三层交换机</p></li>

<li><p class="bull">使用带有路由接口的三层交换机（这些接口可以是三层 EtherChannel，也可以不是）</p></li>

<li><p class="bull">使用集成交换端口的路由器，配置方式与使用 SVI 的三层交换机很相似</p></li>

</ul>

<p class="noindent">在这些选项中，第一个可行，但所需接口太多，难以实际采用。此处提及它只是为了使列表完整。</p>

<p class="noindent">至于其他选项，本章会逐一讨论。实际网络会使用这些功能，选择哪一种取决于特定网络部分的设计和需求。<a href="#ch18fig01">图 18-1</a> 展示了可以使用这些选项的场景。</p>

<h4 class="h4" id="ch18lev2sec1">配置 ROAS</h4>

<p class="noindent">接下来讨论路由器如何将数据包路由到与路由器 802.1Q 中继所连接 VLAN 关联的子网。每次讨论此功能时都重复这么长的描述会有些麻烦，因此，随着时间推移，网络领域为它确定了一个更简短、更有趣的名称：单臂路由（ROAS）。</p>

<p class="noindent">ROAS 使用路由器 VLAN 中继配置，为路由器提供连接每个 VLAN 的逻辑接口。由于路由器随后拥有连接每个 VLAN 的接口，也就能为其配置各 VLAN 所在子网中的 IP 地址。</p>

<p class="noindent">路由器需要为中继上的每个 VLAN 关联一个 IP 地址／掩码。然而，路由器在连接中继的链路上只有一个物理接口。Cisco 通过创建多个虚拟路由器接口来解决这个问题，为该中继上每个受支持的 VLAN 创建一个接口。Cisco 将这些虚拟接口称为<a id="key_209" href="#ref-gloss_381"><span class="blue">子接口</span></a>，路由器配置中为每个子接口包含一条 <strong>ip address</strong> 命令。</p>

<p class="noindent"><a href="#ch18fig02">图 18-2</a> 通过<a href="#ch18fig01">图 18-1</a> 中的一台分支路由器 B1 展示这一概念。由于该路由器只需要在两个 VLAN 之间进行路由，图中也展示了两个<span id="page_459" data-epub-type="pagebreak"></span>子接口，名称分别为 G0/0/0.10 和 G0/0/0.20，它们在配置中创建了新的位置，可用于设置各 VLAN 的配置参数。路由器将带 VLAN 10 标记的帧视为从 G0/0/0.10 进出，将带 VLAN 20 标记的帧视为从 G0/0/0.20 进出。</p>

<ul class="sq">

<li><p class="bull">在物理接口上配置 <strong>ip address</strong> 命令，但不配置 <strong>encapsulation</strong> 命令；路由器会认为该物理接口使用本征 VLAN。</p></li>

<li><p class="bull">在子接口上配置 <strong>ip address</strong> 命令，并使用 <strong>encapsulation dot1q</strong> <em>vlan-id</em> <strong>native</strong> 子命令，向路由器同时说明 VLAN ID 以及它是本征 VLAN 这一事实。</p></li>

</ul>

<h4 class="h4" id="ch18lev2sec3">ROAS 故障排查</h4>

<p class="noindent">排查 ROAS 时最大的挑战在于：如果仅路由器或仅交换机配置错误，中继另一端的设备无法知道对端存在配置错误。也就是说，路由器配置可能正确，但路由仍可能因相连交换机上的问题而失败。因此，ROAS 故障排查通常从检查路由器和交换机两端的配置开始，因为任何一端的状态输出都无法告诉你问题可能出在哪里。</p>

<p class="noindent">首先，要检查路由器上的 ROAS，需要从预期配置出发，针对配置提出以下问题：</p>

<ol class="number">

<li><p class="number">是否为每个非本征 VLAN 在路由器子接口上配置了 <strong>encapsulation dot1q</strong> <em>vlan-id</em> 命令？</p></li>

<li><p class="number">相邻交换机的中继上是否存在相同的 VLAN（<strong>show interfaces trunk</strong>），而且它们是否位于允许列表中、未被 VTP 修剪且未被 STP 阻塞？</p></li>

<li><p class="number">每个路由器 ROAS 子接口是否都按规划配置了 IP 地址／掩码？</p></li>

<li><p class="number">如果使用本征 VLAN，是否已在路由器上正确配置：要么在子接口上使用 <strong>encapsulation dot1q</strong> <em>vlan-id</em> <strong>native</strong> 命令，要么隐含地配置在物理接口上？</p></li>

<li><p class="number">相邻交换机中继上配置的本征 VLAN 是否与路由器上配置的相同？</p></li>

<li><p class="number">路由器物理接口或 ROAS 子接口是否配置了 <strong>shutdown</strong> 命令？</p></li>

</ol>

<p class="noindent">对于其中某些步骤，需要准备检查 LAN 交换机可能存在的 VLAN 中继问题。许多 Cisco 路由器接口不会协商中继。因此，ROAS 依赖路由器和交换机两端的静态中继配置。如果交换机一侧的 VLAN 或 VLAN 中继配置存在问题，路由器无法察觉。</p>

<p class="noindent">例如，假设你像<a href="#exa18_1">例 18-1</a> 或<a href="#exa18_2">例 18-2</a> 那样在路由器上配置了 ROAS，但链路另一端的交换机却没有相应配置。比如，交换机可能根本没有定义 VLAN 10 和 20，或者连接路由器的端口没有配置中继。即使交换机上存在明显的<span id="page_464" data-epub-type="pagebreak"></span>配置错误或缺失，路由器仍会显示 up/up 的 ROAS 接口和子接口，<strong>show ip route</strong> 的输出中仍有 IP 路由，<strong>show vlans</strong> 命令的输出中仍有有意义的配置信息。路由器会向交换机转发数据包（封装在帧中），但交换机的配置不足以支持正确转发该帧。</p>

<h3 class="h3" id="ch18lev1sec4">通过三层交换机 SVI 进行 VLAN 路由</h3>

<p class="noindent">在某些情况下，特别是小型远程站点，使用 ROAS 路由器路由数据包很合理。在 LAN 较大的站点，网络设计人员会选择三层交换机来执行大部分 VLAN 间路由。</p>

<p class="noindent">三层交换机（也称多层交换机）是一台设备，但执行两个层次的逻辑：二层 LAN 交换和三层 IP 路由。二层交换功能在每个 VLAN 内转发帧，但不会在 VLAN 之间转发帧。三层转发（路由）逻辑则对这些 VLAN 中设备发出的 IP 数据包应用 IP 路由逻辑，在 VLAN 之间转发 IP 数据包。</p>

<p class="noindent">三层交换机通常支持两种配置选项，用于在交换机内部启用 IPv4 路由，具体来说，是在交换机接口上启用 IPv4。本节介绍使用交换虚拟接口（SVI）的选项。本章下一个主要部分将讨论在三层交换机上配置 IPv4 地址的另一个选项：路由接口。</p>

<section>

<h4 class="h4" id="ch18lev2sec4">使用交换机 SVI 配置路由</h4>

<p class="noindent">三层交换机的配置大部分与本书<a href="v1-04.html#part02">第二部分</a>和<a href="v1-08.html#part03">第三部分</a>介绍的二层交换配置相似，只需为三层功能增加少量配置。三层交换功能需要在交换机内部为每个 VLAN 连接一个虚拟接口。这些 <a id="key_212" href="#ref-gloss_434"><span class="blue">VLAN 接口</span></a>像路由器接口一样工作，具有 IP 地址和掩码。三层交换机具有 IP 路由表，其中包含经由各 VLAN 接口的直连路由。Cisco 将这些虚拟接口称为<a id="key_211" href="#ref-gloss_400"><span class="blue">交换虚拟接口（SVI）</span></a>。</p>

<ol class="step-lower-alpha">

</ol>

<h4 class="h4" id="ch18lev2sec6"><span id="page_467" data-epub-type="pagebreak"></span>使用 SVI 的路由故障排查</h4>

<p class="noindent">在物理路由器上使用物理接口时，路由器可以根据物理因素为接口确定状态，例如是否接入线缆，或是否通过线缆收到电信号或光信号。然而，SVI 是三层交换机路由功能的虚拟接口，交换机必须使用其他逻辑来决定是否将 SVI 置于工作状态（up/up）。</p>

<p class="noindent">三层交换机通过两种接口配置设置之一，指定确定接口状态的逻辑：<strong>autostate</strong> 或 <strong>no autostate</strong>。VLAN 接口的默认设置 <strong>autostate</strong> 会检查底层 VLAN 的多个因素，以确定 VLAN 接口状态。配置 VLAN 接口子命令 <strong>no autostate</strong> 后，交换机会改用更简单、检查项更少的逻辑。下面几页将解释这两种方式。</p>

<section>

<h5 class="h5" id="ch18lev3sec1">启用 autostate 时的 SVI 接口状态</h5>

<p class="noindent">VLAN 接口充当交换机路由功能与 VLAN 之间的接口。要使该 VLAN 接口正常工作，VLAN 本身必须正常。具体而言，使用 autostate 设置时，VLAN 接口要处于 up/up 状态，需满足以下条件：</p>

<p class="step"><span class="stepb">步骤 1。</span>本地交换机上必须定义该 VLAN（显式配置或通过 VTP 学习）。</p>

<p class="step"><span class="stepb">步骤 2。</span>交换机必须至少有一个使用该 VLAN 的 up/up 接口，包括：</p>

<ol class="step-lower-alpha">

<li><p class="alpha">分配给该 VLAN 的 up/up 接入接口</p></li>

<li><p class="alpha">该 VLAN 位于允许列表中、处于 STP 转发状态且未被 VTP 修剪的中继接口</p></li>

</ol>

<p class="step"><span class="stepb">步骤 3。</span>VLAN 必须在管理上启用（即没有 <strong>shutdown</strong>）。</p>

<p class="step"><span class="stepb">步骤 4。</span>VLAN 接口必须在管理上启用（即没有 <strong>shutdown</strong>）。</p>

<p class="noindent">不要忽略这一点：VLAN 和 VLAN 接口是相关但不同的概念，分别在 CLI 中配置。全局命令 <strong>interface vlan</strong> <em>vlan-id</em> 配置 VLAN 接口，创建交换机上连接该 VLAN 的三层接口。全局命令 <strong>vlan</strong> <em>vlan-id</em> 则创建 VLAN。如果要使用 SVI 为 VLAN 11、12 和 13 上的子网路由数据包，就必须配置相同 VLAN ID 11、12 和 13 的 VLAN 接口。这些相同 VLAN ID 的 VLAN 也必须存在。</p>

<p class="noindent">IOS 支持通过 <strong>shutdown</strong> 和 <strong>no shutdown</strong> 命令禁用和启用 VLAN 及 VLAN 接口（如前面列表中的步骤 3 和 4 所述）。作为配置核对任务的一部分，应检查状态，确保配置启用了所有相关 VLAN 和 VLAN 接口。</p>

<p class="noindent"><a href="#exa18_8">例 18-8</a> 展示三个场景，每个场景都会使前一个配置示例（<a href="#ch18fig04">图 18-4</a>、<a href="#exa18_6">例 18-6</a>）中的一个 VLAN 接口失效。示例开始时，三个 VLAN 接口均为 up/up。此时，VLAN 10、20 和 30 <span id="page_468" data-epub-type="pagebreak"></span>各至少有一个接入接口处于启用且正常工作的状态。示例依次演示三个场景：</p>

<h3 class="h3" id="ch18lev1sec5">通过三层交换机路由端口进行 VLAN 路由</h3>

<p class="noindent">当三层交换机使用 SVI 时，交换机的物理接口仍像以往一样作为二层接口工作。也就是说，物理接口接收以太网帧，交换机学习帧的源 MAC 地址，并根据目的 MAC 地址转发帧。这一逻辑独立于任何已配置的路由逻辑。</p>

<p class="noindent">使用三层交换机时，交换机充当终端主机的默认路由器。与通常情况一样，主机向默认路由器发送数据包时，先使用 ARP 学习其 MAC 地址，再将数据包封装到目的地址为默认路由器 MAC 地址的帧中。因此，在使用 SVI 的三层交换机中，主机会将帧发送到 SVI 的 MAC 地址。这些帧到达物理交换端口后，端口根据目的 MAC 地址将帧转发到内部目的地 VLAN 接口。这一过程会触发内部路由操作，例如剥离数据链路首部、作出路由决策等。</p>

<p class="noindent">另一种方式是通过三层交换机配置，让物理端口作为路由器接口而不是交换机接口工作。为此，需要将该端口配置为<span id="page_470" data-epub-type="pagebreak"></span>路由端口。在<em>路由端口</em>上，交换机不会对帧执行二层交换逻辑。相反，到达路由端口的帧会触发三层路由逻辑，包括：</p>

<ol class="number">

<li><p class="number">剥离入站帧的以太网数据链路首部／尾部</p></li>

<li><p class="number">将目的 IP 地址与 IP 路由表比较，作出三层转发决策</p></li>

<li><p class="number">为数据包添加新的以太网数据链路首部／尾部</p></li>

<li><p class="number">转发封装在新帧中的数据包</p></li>

</ol>

<p class="noindent">本章第三个主要部分研究 Cisco 三层交换机上路由接口的配置，但还有一个特定目标：讨论三层 EtherChannel。三层 EtherChannel 使用路由端口，因此学习它之前必须先理解路由端口。</p>

<h4 class="h4" id="ch18lev2sec8">实现三层 EtherChannel</h4>

<p class="noindent">到目前为止，本节指出，两台三层交换机之间，或者三层交换机与路由器之间，可以在单条点到点链路上使用路由接口。然而，在大多数设计中，网络工程师会在每对分布层和核心交换机之间使用至少两条链路，如<a href="#ch18fig07">图 18-7</a> 所示。</p>

<figure class="image-c" id="ch18fig07">

<img src="assets/volume1/part5-chapter18/images/vol1_18fig07.jpg" aria-describedby="a18fig07" alt="展示核心交换机与分布层交换机之间双重连接的示意图。">

<figcaption>

<p class="title-f"><strong>图 18-7</strong> <em>每对分布层和核心交换机之间的两条链路</em></p>

<aside class="hidden" id="a18fig07">

<p>在这一设计中，核心交换机 Core1、Core2 和汇聚交换机 D11、D12、D21、D22，利用路由接口和点对点接入执行三层交换。每台汇聚交换机与核心交换机之间的两条链路十分显眼。标为 A11、A12、A13、A14、A21、A22、A23、A24 的接入交换机仅使用 SVI 执行二层交换。（译注：原书这段隐藏的无障碍说明与本图不符；本图实际展示 Archie 和 Bob 同时向 Hub 1 发送信号，集线器将两路信号转发给 Larry，导致冲突。）</p>

</aside>

</figcaption>

</figure>

<p class="noindent">虽然分布层和核心层中的每个端口都可以作为单独的路由端口，但将每对并行链路组合成三层 EtherChannel 更好。即使不使用 EtherChannel，仍可以将图中央每台交换机的各端口设为路由端口，这也能工作。然而，一旦启用路由协议却不使用 EtherChannel，每台三层交换机就会学到两条以同一相邻交换机为下一跳的 IP 路由：一条经过一根链路，另一条经过另一根链路。</p>

<p class="noindent">两台交换机之间存在多条并行链路时，使用三层 EtherChannel 更合理。这样，每对链路就作为一条三层链路工作。因此，每对交换机与邻居只有一个路由协议邻居关系，而不是两个。对于每个目的地，每台交换机经由这对链路学到一条路由，而不是两条。随后 IOS 会分担流量，其均衡效果通常优于使用多条通往同一子网的 IP 路由时的效果。总体而言，三层 EtherChannel 的方式，比让每条链路保持独立路由端口并使用三层负载均衡的方式更好。</p>

<p class="noindent"><span id="page_474" data-epub-type="pagebreak"></span>与已经学过的内容相比，配置三层 EtherChannel 只需要多做一点工作。<a href="v1-10.html#ch10">第 10 章</a>“<a href="v1-10.html#ch10">RSTP 和 EtherChannel 配置</a>”已介绍如何配置 EtherChannel，本章也已介绍如何将端口设为三层路由端口。接下来，需要将两者结合，同时配置 EtherChannel 和路由端口。以下清单展示操作步骤，假设采用静态方式定义 EtherChannel。</p>

<figure class="figure1">

<img src="assets/volume1/part5-chapter18/images/vol1_config_checklist.jpg" alt="配置检查表按钮图标。">

</figure>

<p class="step"><span class="stepb">步骤 1。</span>在接口配置模式下，按如下方式配置物理接口：</p>

<ol class="step-lower-alpha">

<li><p class="alpha">添加 <strong>no switchport</strong> 命令，将每个物理端口设为路由端口。</p></li>

<li><p class="alpha">添加 <strong>channel-group</strong> <em>number</em> <strong>mode on</strong> 命令，将其加入通道。同一交换机上的所有物理接口使用相同编号，但两台相邻交换机使用的编号（channel-group 编号）可以不同。</p></li>

</ol>

<p class="step"><span class="stepb">步骤 2。</span>配置 PortChannel 接口：</p>

<ol class="step-lower-alpha">

<li><p class="alpha">使用 <strong>interface port-channel</strong> <em>number</em> 命令进入 PortChannel 配置模式，通道编号应与物理接口上配置的相同。</p></li>

<li><p class="alpha">添加 <strong>no switchport</strong> 命令，确保 PortChannel 接口作为路由端口工作。（IOS 可能已经添加了该命令。）</p></li>

<li><p class="alpha">使用 <strong>ip address</strong> <em>address mask</em> 命令配置地址和掩码。</p></li>

</ol>

<div class="note">

<h4 class="h4" id="ch18lev2sec9">三层 EtherChannel 故障排查</h4>

<p class="noindent">排查三层 EtherChannel 时，主要考虑两个方面。首先，需要查看 <strong>channel-group</strong> 命令的配置，该命令将接口启用为 EtherChannel 成员。其次，应检查一组必须在接口间匹配的设置，以确保三层 EtherChannel 正常工作。</p>

<p class="noindent"><strong>channel-group</strong> 接口子命令可以静态或动态地启用 EtherChannel。如果采用动态方式，该命令的关键字将指定端口聚合协议（PAgP）或链路聚合控制协议（LACP），由相邻交换机通过该协议协商是否将链路加入 EtherChannel。</p>

<p class="noindent">如果这些听起来有点熟悉，那是因为它与前面<a href="v1-10.html#ch10">第 10 章</a>“<a href="v1-10.html#ch10lev2sec12">配置动态 EtherChannel</a>”一节介绍的配置完全相同。无论配置二层还是三层 EtherChannel，<strong>channel-group</strong> 子命令的配置及要求都完全一致。因此，现在可能正适合复习<a href="v1-10.html#ch10">第 10 章</a> 的这些 <span id="page_477" data-epub-type="pagebreak"></span>EtherChannel 配置细节。无论何时复习并掌握这些命令，都请记住：无论二层还是三层，EtherChannel 的配置（使用 <strong>channel-group</strong> 子命令）都相同。</p>

<p class="noindent">此外，要将所有物理端口绑定进 EtherChannel，仅正确配置 <strong>channel-group</strong> 命令还不够。二层 EtherChannel 的要求列表更长，但三层 EtherChannel 在加入端口之前，也需要执行一些端口间一致性检查。以下是三层 EtherChannel 的要求：</p>

<p class="ul-noindent"><strong>no switchport：</strong>PortChannel 接口及物理接口都必须配置 <strong>no switchport</strong> 命令。如果物理接口没有配置 <strong>no switchport</strong> 命令，它就无法在 EtherChannel 中投入运行。</p>

<p class="ul-noindent"><strong>速率：</strong>通道中的物理端口必须使用相同速率。</p>

<p class="ul-noindent"><strong>双工：</strong>通道中的物理端口必须使用相同双工模式。</p>

</section>

<h3 class="h3" id="ch18lev1sec6">在路由器的 LAN 交换端口上进行 VLAN 路由</h3>

<p class="noindent">本章前面的主要部分展示的设计，都是将主机连接到交换机。可能由交换机执行路由，也可能由连接交换机的路由器执行路由，但主机都是通过线缆连接交换机。</p>

<p class="noindent">最后一个主要部分讨论仅使用一台路由器的设计，具体来说，是硬件包含一组 LAN 交换端口的路由器。实际上，路由器硬件内嵌了一台 LAN 交换机。因此，路由器需要同时实现路由和交换。</p>

<p class="noindent">包含小型分支机构的设计可以充分利用带内嵌交换端口的路由器。这类站点需要能够通过 WAN 进行路由的路由器，但可能只需要少量 LAN 端口。许多厂商（包括 Cisco）都提供带有少量 LAN 交换端口的路由器产品，以满足此类需求。许多消费级路由器，例如你家用于互联网接入的路由器，也内嵌了少量交换端口。</p>

<p class="noindent">作为硬件示例，<a href="#ch18fig09">图 18-9</a> 展示 ISR1K 路由器和 Catalyst 8200L 边缘路由器的照片。Cisco 将某些 ISR1K 定位为适合较小站点的企业级路由器，它们包含几个路由端口以及一组<a id="key_210" href="#ref-gloss_399"><span class="blue">交换端口</span></a>。路由端口像本书迄今讨论的路由器端口一样工作，收发 IP 数据包，并需要配置 IP 地址和掩码。交换端口像 LAN 交换机上的端口一样工作，收发以太网帧，由路由器的交换逻辑学习 MAC 地址表项。</p>

<h4 class="h4" id="ch18lev2sec12">识别路由器中的交换端口</h4>

<p class="noindent">当查看路由器或使用其 CLI 时，如何知道哪些以太网端口是路由端口，哪些是交换端口？答案可能不容易找到。最后这个简短小节将说明方法。</p>

<p class="noindent">首先，路由器端口作为路由端口还是交换端口的角色，并不是由你配置的。Cisco 创建的路由器接口固定作为两者之一工作。你可以在 <a href="http://www.cisco.com">www.cisco.com</a> 上研究路由器型号和系列，了解各型号自带的固定端口。相关文档还会说明 NIM 等插卡的模块化选项。</p>

<p class="noindent">也可以通过 CLI 发现路由器的交换端口，但其规律并不明显。大多数 <strong>show</strong> 命令没有帮助，只有少数有用。需要注意：</p>

<p class="ul-noindent"><strong>show running-config、show startup-config：</strong>这些命令不会区分路由端口和交换端口。</p>

<p class="ul-noindent"><span id="page_482" data-epub-type="pagebreak"></span><strong>show interfaces、show interfaces description、show ip interface brief、show protocols：</strong>这些命令都会列出全部接口，包括路由接口和交换接口，但不会标注各自属于哪一种。</p>

<p class="ul-noindent"><strong>show interfaces status：</strong>该命令仅列出交换端口。</p>

<p class="noindent">使用 <strong>show interfaces status</strong> 识别交换端口最为合适。</p>

<p class="noindent">此外，还可以尝试配置仅受某一种端口支持的命令，来确认哪些是路由端口、哪些是交换端口。例如，路由端口接受 <strong>ip address</strong> <em>address mask</em> 子命令，但拒绝 <strong>switchport access vlan</strong> <em>vlan-id</em> 子命令。交换端口则相反。</p>

<p class="noindent"><a href="#exa18_18">例 18-18</a> 使用前面示例中的路由器 B1，展示几种识别路由端口和交换端口的情况。首先，<strong>show interfaces status</strong> 命令输出仅显示交换端口 G0/1/0–G0/1/7。请注意，输出遵循 LAN 交换机的格式，标明分配给每个接口的接入 VLAN。随后，输出展示交换端口拒绝 <strong>ip address</strong> 接口子命令的情况。</p>

<h3 class="h3" id="ref-appclev1sec18">第 18 章</h3>

<p class="quiz"><strong><a id="ref-ques18_1" href="#quess18_1">1</a>．</strong> A 和 F。所有列出的命令中，只有这两个正确答案是语法正确的路由器配置命令。启用 802.1Q 中继的命令是 <strong>encapsulation dot1q</strong> <em>vlan_id</em>。</p>

<p class="quiz"><strong><a id="ref-ques18_2" href="#quess18_2">2</a>．</strong> B 和 C。由于在子接口 G0/1.1 上执行了 <strong>shutdown</strong> 命令，它必须处于 administratively down 状态。对于子接口 G0/1.2，由于执行了 <strong>no shutdown</strong> 命令，其<span id="ref-page_795" data-epub-type="pagebreak"></span>状态不可能是 administratively down。G0/1.2 的状态随后会跟随底层物理接口。由于物理接口处于 down/down 状态，本例中的子接口 G0/1.2 也将处于 down/down 状态。</p>

<p class="quiz"><strong><a id="ref-ques18_3" href="#quess18_3">3</a>．</strong> C。三层交换机路由功能的配置使用 VLAN 接口。VLAN 接口编号必须与关联的 VLAN ID 一致，因此使用 VLAN 1、2 和 3 时，交换机会配置 <strong>interface vlan 1</strong>、<strong>interface vlan 2</strong>（正确答案）和 <strong>interface vlan 3</strong>。对应直连路由与所有直连 IP 路由一样，将列出 VLAN 接口。</p>

<p class="quiz-para">对于错误答案，直连路由列表不会列出任何下一跳 IP 地址。每条路由都会列出出接口；由于题目说明配置使用 SVI，所以出接口不会是物理接口，而是 VLAN 接口。最后，所有列出的子网都采用 /25 掩码，即 255.255.255.128，因此没有任何路由会列出 255.255.255.0 掩码。</p>

<p class="quiz"><strong><a id="ref-ques18_4" href="#quess18_4">4</a>．</strong> C 和 D。首先解释正确答案：除非 VLAN 接口处于 up/up 状态，否则三层交换机不会在其上路由数据包。使用 autostate 时，只有当匹配的 VLAN（相同 VLAN 编号）存在于交换机上、未被关闭，而且至少有一个端口在该 VLAN 中处于启用和活动状态，VLAN 接口才会为 up/up。一个正确答案是，如果执行 <strong>no vlan 2</strong> 命令删除 VLAN 2，交换机会将 VLAN 2 接口置于 up/down 状态，使其无法继续路由数据包。另一个正确答案是，在 VLAN 配置模式下使用 <strong>shutdown</strong> 命令禁用 VLAN 2，也会产生相同结果。</p>

<p class="quiz-para">对于错误答案，使用 autostate 时，三层交换机只需要一个为 VLAN 转发的接入端口或中继端口，就能为该 VLAN 启用路由。因此，VLAN 2 的十个接入端口中即使有九个故障，只剩一个正常端口，交换机仍会继续为 VLAN 2 路由。</p>

<p class="quiz-para">对 VLAN 4 执行 <strong>shutdown</strong> 不会影响 VLAN 接口 2 和 3 的路由。如果该答案列出的是 VLAN 2 或 3，就会构成使该 VLAN 接口路由失败的原因。</p>

<p class="quiz"><strong><a id="ref-ques18_5" href="#quess18_5">5</a>．</strong> A 和 C。对于三层 EtherChannel，物理端口和 PortChannel 接口必须通过配置 <strong>no switchport</strong> 接口子命令，禁用交换端口行为，从而作为路由端口工作。（<strong>routedport</strong> 不是 IOS 命令。）创建之后，物理接口不应配置 IP 地址，应在代表 EtherChannel 的 PortChannel 接口上配置 IP 地址。</p>

<p class="quiz"><strong><a id="ref-ques18_6" href="#quess18_6">6</a>．</strong> B 和 C。对于三层 EtherChannel，所有物理端口上必须有两项配置相同，即通过 <strong>speed</strong> 和 <strong>duplex</strong> 命令设置的速率及双工。此外，物理端口和 PortChannel 端口都必须配置 <strong>no switchport</strong> 命令，使各自作为路由端口工作。因此，不同的速率设置，或配置了 <strong>switchport</strong> 而非 <strong>no switchport</strong>，都会阻止 IOS 将 G0/2 接口加入三层 EtherChannel。</p>

<p class="quiz-para">对于错误答案，两者都会在将端口加入二层 EtherChannel 时导致问题，但不会对三层 EtherChannel 造成问题。通过 <strong>no switchport</strong> 命令禁用二层操作后，这些<span id="ref-page_796" data-epub-type="pagebreak"></span>设置就不会再影响三层 EtherChannel。因此，接入 VLAN、中继允许列表和 STP 等二层设置，虽然在接口加入二层 EtherChannel 前必须匹配，但对三层 EtherChannel 并不重要。</p>

<p class="quiz"><strong><a id="ref-ques18_7" href="#quess18_7">7</a>．</strong> A。在同时拥有路由端口和交换端口的路由器上，IOS 仅在交换端口上支持 LAN 交换子命令。因此，在某个路由器交换接口的接口配置模式下，IOS 接受 <strong>switchport access</strong> 命令，但不接受 <strong>ip address</strong> 命令。路由器在交换端口和路由端口上都支持 <strong>description</strong> 子命令，因此该答案不正确。最后，一个答案列出全局命令 <strong>hostname</strong>，而题目询问接口子命令，因此也不正确。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_225"><strong>三层 EtherChannel（L3 EtherChannel）</strong> 作为路由端口（而非交换端口）工作的 EtherChannel，由交换机的三层转发逻辑使用。因此，三层交换机会在 IP 路由表的各种路由中列出三层 EtherChannel，并在其中各端口之间分担流量。</p>

<p class="gloss" id="ref-gloss_227"><strong>三层交换机（Layer 3 switch）</strong> <em>参见</em><a href="#ref-gloss_261">多层交换机</a>。</p>

<p class="gloss" id="ref-gloss_261"><strong>多层交换机（multilayer switch）</strong> 同时能够执行三层路由功能的 LAN 交换机。这个名称源于该设备会根据多个 OSI 层（二层和三层）的逻辑作出转发决策。</p>

<p class="gloss" id="ref-gloss_346"><strong>路由端口（routed port）</strong> 指路由器接口上的默认逻辑，例如从入站二层帧中解封装三层数据包，并将数据包交给设备的三层转发逻辑。</p>

<p class="gloss" id="ref-gloss_351"><strong>单臂路由（Router-on-a-Stick，ROAS）</strong> 指 Cisco 路由器在以太网接口上使用 VLAN 中继的功能的术语。这使路由器能够路由从该中继进入、又从同一中继离开但属于不同 VLAN 的数据包。</p>

<p class="gloss" id="ref-gloss_381"><strong>子接口（subinterface）</strong> 单个物理接口上的虚拟接口之一。</p>

<p class="gloss" id="ref-gloss_399"><strong>交换端口（switched port）</strong> 指二层交换端口上的默认逻辑，例如学习收到帧的源 MAC 地址，并将入站帧交给设备的二层转发逻辑。</p>

<p class="gloss" id="ref-gloss_400"><strong>交换虚拟接口（switched virtual interface，SVI）</strong> Cisco 交换机上任何 VLAN 接口的另一个名称。<em>另请参阅</em> <a href="#ref-gloss_434">VLAN 接口</a>。</p>

<p class="gloss" id="ref-gloss_434"><strong>VLAN 接口（VLAN interface）</strong> Cisco 交换机内部的一种配置概念，作为交换机上运行的 IOS 与交换机内部支持的某个 VLAN 之间的接口，使交换机可以分配 IP 地址，并向该 VLAN 发送 IP 分组。</p>
