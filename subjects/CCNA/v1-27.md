<h2 class="h2a">在路由器上实现 IPv6 编址</h2>

<p class="objset">本章涵盖以下考试主题：</p>

<p class="obj">1.0 网络基础</p>

<p class="obj1">1.8 配置并验证 IPv6 编址和前缀</p>

<p class="obj2">1.9.b 任播</p>

<p class="obj2">1.9.c 组播</p>

<p class="obj2">1.9.d 修改后的 EUI-64</p>

<p class="noindent-c">在 IPv4 编址中，服务器和路由器等设备通常使用预先定义的静态 IPv4 地址。终端用户设备并不在意地址偶尔变化，通常通过 DHCP 动态学习 IPv4 地址。IPv6 采用相同方法：由 IT 团队管理的服务器、路由器和其他设备往往使用预定义 IPv6 地址，终端用户设备则使用动态学习的 IPv6 地址。</p>

<p class="noindent">本章重点介绍路由器上的 IPv6 地址配置，下一章关注终端用户设备。本章先介绍较直观、与 IPv4 功能相对应的 IPv6 编址配置，展示如何为接口配置 IPv6 地址，并通过 <strong>show</strong> 命令查看配置。后半章介绍相对于 IPv4 新增的 IPv6 编址概念，展示路由器执行不同任务时使用的其他 IPv6 地址。</p>

<h3 class="h3" id="ch27lev1sec3">在路由器上实现单播 IPv6 地址</h3>

<p class="noindent">每家企业都以一种或多种协议模型或协议栈构建企业网络。网络发展的早期，企业使用来自不同厂商的一种或多种协议栈，如 <a href="#ch27fig01">图 27-1</a> 左侧所示。随着时间推移，企业加入了基于 IPv4 的 TCP/IP，最终完全迁移到 TCP/IP，仅使用这一种协议栈。</p>

<p class="noindent">IPv6 可能有一天会完全替代 IPv4；不过，在漫长的迁移阶段，大多数企业会在主机和路由器上同时运行 IPv4 和 IPv6，实际上像过去一样使用多个协议栈。随着时间推移，主机会越来越多地使用 IPv6，直到某一天可能关闭 IPv4，仅运行 IPv6，如 <a href="#ch27fig02">图 27-2</a> 所示。</p>

<p class="noindent">使用<a id="key_284" href="#ref-gloss_114"><span class="blue">双栈（dual stacks）</span></a>，即同时运行 IPv4 和 IPv6，对今天的企业网络很合理。为此，在路由器接口上配置 IPv6 地址，使其路由 IPv6 数据包，并通过路由协议通告 IPv6 路由，同时继续使用 IPv4 地址和路由协议完成同样的工作。主机和服务器上也同时实施 IPv4 和 IPv6。主机采用新的方法决定何时使用哪种版本，并优先选择 IPv6。</p>

<p class="noindent">双栈策略运行良好，而 IPv6 的配置模型与 IPv4 非常相似。为此，本章第一大节介绍如何在路由器上配置和验证单播 IPv6 地址。</p>

<section>

<h4 class="h4" id="ch27lev2sec1">静态单播地址配置</h4>

<p class="noindent">Cisco 路由器提供两种静态配置 IPv6 地址的方式。一种是配置完整的 128 位地址和标准 /64 前缀长度；另一种是配置 64 位前缀，让路由器推导地址的后半部分，即接口 ID（IID）。接下来的几页展示这两种方式。</p>

<section>

<h5 class="h5" id="ch27lev3sec1">配置完整的 128 位地址</h5>

<section>

<h5 class="h5" id="ch27lev3sec2">启用 IPv6 路由</h5>

<p class="noindent">有趣的是，Cisco 路由器默认启用 IPv4 路由，却不启用 IPv6 路由。全局命令 <strong>ip routing</strong>（默认设置）启用 IPv4 数据包路由。要路由 IPv6 数据包，还必须配置 <strong>ipv6 unicast-routing</strong> 全局命令。</p>

<p class="noindent">如果忘记配置 <strong>ipv6 unicast-routing</strong> 全局命令，路由器仍会接受 <strong>ipv6 address</strong> 接口子命令。此时，路由器充当 IPv6 <span id="page_673" data-epub-type="pagebreak"></span>主机，可以发送自己生成的 IPv6 数据包。但是，只有配置了 <strong>ipv6 unicast-routing</strong> 全局命令后，它才会路由 IPv6 数据包，也就是转发从接口收到的 IPv6 数据包。</p>

</section>

<section>

<h5 class="h5" id="ch27lev3sec3">验证 IPv6 地址配置</h5>

<p class="noindent">IPv6 使用许多在语法上模仿 IPv4 <strong>show</strong> 命令的 <strong>show</strong> 命令。例如：</p>

<ul class="sq">

<li><p class="bull"><strong>show ipv6 interface brief</strong> 提供接口 IPv6 地址信息，但不提供前缀长度信息，类似于 IPv4 的 <strong>show ip interface brief</strong> 命令。</p></li>

<li><p class="bull"><strong>show ipv6 interface</strong> 提供 IPv6 接口设置的详细信息，很像 IPv4 的 <strong>show ip interface</strong> 命令。</p></li>

</ul>

<h5 class="h5" id="ch27lev3sec4">使用修改后的 EUI-64 生成唯一接口 ID</h5>

<p class="noindent">IOS 支持两种配置永久、稳定的路由器 IPv6 接口地址的方法。<a href="#exa27_1">例 27-1</a> 和 <a href="#exa27_2">例 27-2</a> 展示第一种方法，即配置完整的 128 位地址。第二种使用相同的 <strong>ipv6 address</strong> 命令，但只为接口配置 64 位 IPv6 前缀，让路由器自动生成唯一 IID。</p>

<p class="noindent">第二种方法使用称为<em>修改后的 EUI-64</em>（扩展唯一标识符），或简称 <a id="key_285" href="#ref-gloss_139"><span class="blue">EUI-64</span></a> 的规则来生成地址后半部分。使用时，在命令末尾添加 <strong>eui-64</strong> <span id="page_675" data-epub-type="pagebreak"></span>关键字，路由器随后按以下 EUI-64 规则创建地址的 IID 部分：</p>

<ol class="number">

<li><p class="number">将 6 字节（12 个十六进制数字）的 MAC 地址分成两半，每半六个十六进制数字。</p>

</li>

<li><p class="number">在两半之间插入 FFFE，使接口 ID 达到 16 个十六进制数字（64 位）。</p></li>

<li><p class="number">将 IID 的第七位取反。</p></li>

</ol>

<h5 class="h5" id="ch27lev3sec5">IPv6 地址属性</h5>

<p class="noindent">IOS 为某些 IPv6 地址定义一组属性，在 <strong>show ipv6 interface</strong> 等命令输出中用简短的大写代码显示，但不出现在 <strong>show ipv6 interface brief</strong> 输出中。最常见的属性包括：</p>

<p class="ul-noindent"><strong>EUI：</strong> 路由器使用修改后的 EUI-64 生成了该地址。</p>

<p class="ul-noindent"><strong>TEN：</strong> 暂定（Tentative）。路由器执行重复地址检测（DAD）期间出现的临时属性。</p>

<p class="ul-noindent"><strong>CAL：</strong> 具有时限（Calendared）。地址具有规定的生存期，包括有效生存期和首选生存期，通常在使用 DHCP 和 SLAAC 时列出。</p>

<p class="ul-noindent"><strong>PRE：</strong> 首选（Preferred）。接口使用基于时间、具有时限的地址时，优先使用的地址，通常在使用 DHCP 和 SLAAC 时列出。</p>

<h3 class="h3" id="ch27lev1sec4">路由器使用的特殊地址</h3>

<p class="noindent">路由器上的 IPv6 配置从本章前半部分介绍的简单步骤开始。配置 <strong>ipv6 unicast-routing</strong> 全局命令启用 IPv6 路由功能后，为接口添加单播 IPv6 地址会使路由器：</p>

<ul class="sq">

<li><p class="bull">为接口赋予单播 IPv6 地址。</p>

</li>

<li><p class="bull">启用该接口进出方向的 IPv6 数据包路由。</p></li>

<li><p class="bull">定义该接口所连接的 IPv6 前缀（子网）。</p></li>

<li><p class="bull">在接口处于 up/up 状态时，将该前缀的 IPv6 直连路由加入 IPv6 路由表。</p></li>

</ul>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">实际上，再看一次这个列表就会发现，在路由器接口上配置 IPv4 地址时，也会发生相同的事情。</p>

</div>

<p class="noindent">虽然列表中的 IPv6 功能与 IPv4 对应功能很相似，但 IPv6 还有一些 IPv4 中没有的额外功能。这些功能常常使用其他 IPv6 地址，其中许多是组播地址。本章第二大节介绍路由器上出现的额外 IPv6 地址，并简述其用途。</p>

<section>

<h4 class="h4" id="ch27lev2sec3">链路本地地址</h4>

<p class="noindent">IPv6 使用<a id="key_288" href="#ref-gloss_232"><span class="blue">链路本地地址（link-local addresses，LLA）</span></a>作为一种特殊的单播 IPv6 地址。每个支持 IPv6 的接口都必须有 LLA。少数重要的 IPv6 协议使用 LLA 收发数据包，协助完成邻居发现和地址发现等辅助功能，有时甚至在设备拥有 GUA 或 ULA 之前就使用。下一个主题先介绍 IPv6 如何使用 LLA，再介绍路由器如何创建它们。</p>

<section>

<h5 class="h5" id="ch27lev3sec6">链路本地地址概念</h5>

<p class="noindent">LLA 让每个支持 IPv6 的设备，在动态学到或被配置可路由的 GUA 或 ULA 之前，就能在本地链路上收发单播数据包。虽然主机可以通过 LLA 在单个子网上收发应用数据，但 LLA 的目的并非支持普通应用数据，而是支持某些需要一个可用地址的 IPv6 辅助协议。</p>

<p class="noindent">对于那些在主机获得正常单播地址分配前就需要发送数据包的协议，IPv6 设计者希望提供比 IPv4 更好的选择。例如，IPv4 主机通过 DHCP 租用地址前，需要在 IP 数据包内发送 DHCP 消息。为此，IPv4 定义了特殊地址 0.0.0.0 和 255.255.255.255。IPv6 设计者寻求更好的方法，LLA 在一些情况下提供了解决方案。</p>

<p class="noindent"><span id="page_681" data-epub-type="pagebreak"></span>主机会自行生成 LLA，随后用它在本地链路上收发 IPv6 数据包。所有使用 IPv6 的接口都必须有 LLA，设备可在没有外部帮助的情况下动态创建。创建后，主机通过重复地址检测（DAD）确认没有其他主机使用相同 LLA。如果唯一，就继续使用；如果 DAD 发现其他主机已使用，新主机就选择不同的 LLA。一些 IPv6 协议依赖主机 LLA 作为协议消息的源地址，包括替代 IPv4 ARP 的邻居发现协议（NDP）和动态主机配置协议（DHCP）。</p>

<p class="noindent">LLA 还会出现在一个令人意外的位置：IPv6 路由中的下一跳 IPv6 地址，如 <a href="#ch27fig08">图 27-8</a> 所示。对于路由协议学到的路由，<strong>show ipv6 route</strong> 命令列出邻居路由器的 LLA，而不是 GUA 或 ULA。主机的默认路由器设置也引用路由器的 LLA。</p>

<figure class="image-c" id="ch27fig08">

<img src="assets/volume1/part7-chapter27/images/vol1_27fig08.jpg" aria-describedby="a27fig08" alt="演示 IPv6 在网络中使用链路本地地址作为下一跳地址的过程的示意图。">

<figcaption>

<aside class="hidden" id="a27fig08">

<p>网络包含主机 PC1、PC2 和路由器 R1、R2。PC1 连接 R1，箭头标为“1”，上方标签为“网关 = R1 的链路本地地址”。R1 通过 WAN 线路连接 R2，标为“2”，上方标签为“前缀：子网 2”和“下一跳：R2 的链路本地地址”。最后，R2 连接 PC2，标注“子网 2：2001:DB8:1111:2::/64”，表示 IPv6 地址。</p>

</aside>

</figcaption>

<p class="noindent">下面总结链路本地地址的一些关键事实：</p>

<p class="ul-noindent"><strong>单播（不是组播）：</strong> LLA 代表单台主机，发往链路本地地址的数据包应仅由这一台 IPv6 主机处理。</p>

<p class="ul-noindent"><strong>转发范围仅限本地链路：</strong> 发往链路本地地址的数据包不会离开本地数据链路，因为路由器不转发目的地址为链路本地地址的数据包。</p>

<p class="ul-noindent"><strong>自动生成：</strong> 每个 IPv6 主机接口和路由器接口都能自动创建自己的链路本地地址，解决主机在动态学到全球单播地址前的一些初始化问题。</p>

<p class="ul-noindent"><strong>常见用途：</strong> 链路本地地址用于某些局限于一个子网的辅助协议，也用作 IPv6 路由的下一跳地址。</p>

</section>

<section>

<h5 class="h5" id="ch27lev3sec7">在路由器上创建链路本地地址</h5>

<p class="noindent">默认情况下，路由器会为每个启用了 IPv6 的接口自行分配 LLA。为此，它将地址前半部分设为 FE80:0000:0000:0000，如 <a href="#ch27fig09">图 27-9</a> 左侧所示，再按修改后的 EUI-64 规则创建 IID（可回顾前面的“<a href="#ch27lev3sec4">使用修改后的 EUI-64 生成唯一接口 ID</a>”一节）。因此，路由器的完整 LLA 应当唯一，因为输入 EUI-64 过程的 MAC 地址应当唯一。</p>

<span id="page_682" data-epub-type="pagebreak"></span>

<figure class="image-c" id="ch27fig09">

<img src="assets/volume1/part7-chapter27/images/vol1_27fig09.jpg" aria-describedby="a27fig09" alt="展示 128 位 IPv6 链路本地地址结构的横条图。">

<figcaption>

<p class="title-f"><strong>图 27-9</strong> <em>链路本地地址格式</em></p>

<aside class="hidden" id="a27fig09">

<p>地址分为两个主要部分，每部分 64 位。左侧显示固定前缀“FE80”和三组零，右侧标为“接口 ID：EUI-64”。两部分共同构成完整的 IPv6 链路本地地址。</p>

</aside>

</figcaption>

</figure>

</div>

<ul class="sq">

<li><p class="bull"><strong>ipv6 address</strong> <em>address</em> <strong>link-local</strong> 接口子命令配置 LLA；此时，路由器不会按 EUI-64 规则创建 LLA。</p></li>

<li><p class="bull">如果未配置，IOS 按 EUI-64 规则计算 LLA。</p></li>

</ul>

<section>

<h5 class="h5" id="ch27lev3sec8">在接口仅有链路本地地址时路由 IPv6</h5>

<p class="noindent">到目前为止，本章展示了 <strong>ipv6 address</strong> 命令的四种变体，用于配置可路由地址（GUA 和 ULA）。回顾如下：</p>

<p class="ul-noindent"><strong>ipv6 address</strong> <em>address/prefix-length</em>：静态配置完整的可路由地址和前缀长度。</p>

<p class="ul-noindent"><strong>ipv6 address</strong> <em>prefix/prefix-length</em> <strong>eui-64</strong>：静态配置前缀及长度，由路由器按 EUI-64 规则计算 IID。</p>

<p class="ul-noindent"><strong>ipv6 address dhcp</strong>：使用 DHCP 动态学习地址和前缀长度。</p>

<p class="ul-noindent"><strong>ipv6 address autoconfig</strong>：动态学习前缀及长度，由路由器按 EUI-64 规则计算 IID（SLAAC）。</p>

<p class="noindent">为补全列表，现在介绍 <strong>ipv6 enable</strong> 接口子命令。它启用接口的 IPv6 处理，并使路由器自行分配 LLA，但不为接口提供可路由的 GUA 或 ULA 地址。</p>

<p class="noindent">只有理解某些链路，尤其是 WAN 链路，并不需要 GUA 或 ULA，才能理解 <strong>ipv6 enable</strong> 的用途。以 <a href="#ch27fig10">图 27-10</a> 为背景，考虑 PC1 和 PC2 等主机发送数据包的目的地。PC1 向 PC2 发送 IPv6 数据包时，数据包包含 PC1 与 PC2 的 IPv6 地址，从不包含 WAN 链路的 IPv6 地址。主机不需要知道路由器的 WAN 接口地址。（相同逻辑也适用于 IPv4。）</p>

<figure class="image-c" id="ch27fig10">

<img src="assets/volume1/part7-chapter27/images/vol1_27fig10.jpg" aria-describedby="a27fig10" alt="演示网络中 ipv6 enable 命令典型用途的示意图。">

<figcaption>

<p class="title-f"><strong>图 27-10</strong> <em><span class="font"><strong>ipv6 enable</strong></span> 命令的典型用途</em></p>

<aside class="hidden" id="a27fig10">

<p>网络包含主机 PC1、PC2 和路由器 R1、R2。PC1 连接 R1，全球单播前缀为 2001:DB8:1111:1::/64；PC2 连接 R2，前缀为 2001:DB8:1111:2::/64。两台路由器均启用 IPv6，地址分别为 FE80::1 和 FE80::2，并通过以太网 WAN 互连。</p>

</aside>

</figcaption>

</figure>

<p class="noindent">此外，要让路由正常工作，路由器在 WAN 链路上不需要 GUA 或 ULA，只需要 LLA。例如，IPv6 路由协议动态构建路由时使用 LLA 作为下一跳地址。另外，如 <a href="v1-29.html#ch29">第 29 章</a>“<a href="v1-29.html#ch29">实现 IPv6 路由</a>”所述，静态路由也可使用 LLA 作为下一跳地址。</p>

<p class="noindent">因此，IPv6 路由可在仅使用 LLA、没有 GUA 或 ULA 的 WAN 链路上工作，甚至不必为每条 WAN 链路分配 IPv6 子网前缀。配置 WAN 接口时，使用 <strong>ipv6 enable</strong> 启用 IPv6，并为每个接口生成链路本地 IPv6 地址。</p>

<p class="noindent"><span id="page_684" data-epub-type="pagebreak"></span>使用时，只需在 WAN 链路两端接口上都配置 <strong>ipv6 enable</strong> 命令。</p>

</section>

<section>

<h4 class="h4" id="ch27lev2sec4">IPv6 组播地址</h4>

<p class="noindent">IPv6 为多种目的使用组播地址。与 IPv4 一样，它包含可供组播应用使用的一段地址范围，并采用许多与 IPv4 组播相同的基本概念。例如，IANA 将 FF30::/12（所有以 FF3 开头的 IPv6 地址）定义为组播应用使用的地址范围。</p>

<p class="noindent">此外，不同 IPv6 RFC 还为特定用途保留组播地址。例如，OSPFv3 分别使用 FF02::5 和 FF02::6 作为所有 OSPF 路由器和所有 DR 路由器的组播地址，类似于 OSPFv2 使用 IPv4 地址 224.0.0.5 和 224.0.0.6。IANA 和各 RFC 使用<em>知名组播地址（well-known multicast address）</em>一词指这些保留的预定义组播地址，并为其保留 FF00::/12（所有以 FF0 开头的 IPv6 地址）范围。</p>

<p class="noindent">下一节关注知名的永久 IPv6 组播地址。第一类是<a id="key_289" href="#ref-gloss_233"><span class="blue">链路本地组播地址（link-local multicast addresses）</span></a>，作用域将其限制在单条链路内。另一类是为每台主机计算的特殊辅助组播地址，称为<a id="key_293" href="#ref-gloss_368"><span class="blue">被请求节点组播地址（solicited-node multicast address）</span></a>。</p>

<section>

<h5 class="h5" id="ch27lev3sec9">知名组播地址</h5>

<p class="noindent">停下来回想本书迄今讨论的一些控制平面协议。部分 IPv4 控制平面协议使用 IPv4 广播，数据包目的地址为 255.255.255.255（本地子网所有主机的地址）或子网广播地址（该特定子网所有主机的地址）。发送方将数据包封装在以太网广播帧内，发往以太网广播地址 FFFF.FFFF.FFFF。</p>

<p class="noindent">虽然这种方式有用，但 IPv4 广播加 LAN 广播要求 VLAN 中的每台主机都处理广播帧，即使只有另一个设备需要关注该消息。LAN 交换机将广播转发到同一 VLAN 中的每个端口，因此每次广播的副本都会到达子网中的每台主机。每台主机必须先处理帧、再处理数据包、读取消息类型等，然后才能决定忽略。例如，IPv4 ARP 请求同时是 IPv4 和 LAN 广播，主机必须处理消息的以太网及 ARP 细节，才能决定是否回复。</p>

<p class="noindent">IPv6 使用第 3 层组播地址来代替第 3 层和第 2 层广播，进而使以太网帧使用以太网组播地址。LAN 交换机可利用早已成熟的组播优化功能，仅向愿意接收副本的主机转发组播帧，不向不感兴趣的主机转发。因此，IPv6 协议更高效，也减少了对主机不必要的打扰。</p>

<p class="noindent">例如，OSPFv3 使用 IPv6 组播地址 FF02::5 和 FF02::6。子网上的 OSPFv3 路由器在接口初始化 OSPF 时，会发送消息，登记自己希望接收发往这两个地址的数据包。但主机不会登记<span id="page_685" data-epub-type="pagebreak"></span>接收这些数据包的意愿。LAN 交换机观察组播注册消息，记住哪些端口连接的主机希望接收发往各组播地址的数据包。收到发往这些组播地址的帧时，交换机仅将其转发给已预先注册的 OSPFv3 路由器，不转发给其他主机或路由器。</p>

<h5 class="h5" id="ch27lev3sec10">组播地址作用域</h5>

<p class="noindent">IPv6 RFC 4291 定义单播和组播编址的细节，包括 <a id="key_287" href="#ref-gloss_215"><span class="blue">IPv6 地址作用域（IPv6 address scope）</span></a>概念。每种作用域定义不同的规则，决定路由器是否应转发数据包，以及应将其转发多远。</p>

<h4 class="h4" id="ch27lev2sec5"><span id="page_689" data-epub-type="pagebreak"></span>未指定地址和环回地址</h4>

<p class="noindent">所有 IPv6 主机都可使用另外两个特殊地址：</p>

<ul class="sq">

<li><p class="bull">未指定 IPv6 地址 ::，即全 0。</p>

</li>

<li><p class="bull">环回 IPv6 地址 ::1，即 127 个二进制 0 后接一个 1。</p></li>

</ul>

<p class="noindent">未指定地址很少使用，主机尚未学到可用单播地址时可以使用它。它只能作为源地址，并且只在主机还没有 LLA 或其他单播地址可用时使用。</p>

<p class="noindent">IPv6 环回地址为每台 IPv6 主机提供测试协议栈的方法。与 IPv4 环回地址 127.0.0.1 一样，发往 ::1 的数据包不会离开主机，而是沿协议栈向下交给 IPv6，再向上交回本地主机的应用程序。</p>

</section>

<h4 class="h4" id="ch27lev2sec6">任播地址</h4>

<p class="noindent">假设路由器需要共同实现某项服务。这项服务由多台路由器提供时效果最好，而不是只由一台提供。但使用服务的主机只需联系最近的服务实例，网络希望对主机隐藏这些细节。主机只要向一个 IPv6 地址发送数据包，路由器就会将其转发给支持该服务、也就是支持该目的 IPv6 地址的最近路由器。</p>

<p class="noindent">IPv6 <a id="key_283" href="#ref-gloss_022"><span class="blue">任播地址（anycast addresses）</span></a>正好提供这一功能。名称中的 <em>any（任意）</em>表示可以使用该服务的任意实例。<a href="#ch27fig13">图 27-13</a> 通过两个主要步骤展示这一总体概念：</p>

<p class="step"><span class="stepb">步骤 1．</span> 两台路由器配置完全相同的 IPv6 地址，并指定为任播地址，以支持某项服务。</p>

<p class="step"><span class="stepb">步骤 2．</span> 此后，任何路由器收到发往该任播地址的数据包时，其他路由器只需将其路由到支持该地址的最近路由器。</p>

<p class="quiz"><strong><a id="ref-ques27_1" href="#quess27_1">1</a>．</strong> A。正确答案列出与题目完全相同的 IPv6 地址，前缀长度为 /64，语法中没有空格。另一个错误答案除了在地址与前缀长度之间留了空格外完全相同，但空格使语法错误。两个包含 <strong>eui-64</strong> 参数的答案列出地址而不是前缀；正确用法应列出前缀。不过，即使这两个错误答案使用所示地址的前缀 2001:1:1:1::，EUI-64 过程也不会产生题目给出的 IPv6 地址。</p>

<p class="quiz"><strong><a id="ref-ques27_2" href="#quess27_2">2</a>．</strong> B。使用 <strong>eui-64</strong> 参数时，路由器根据 MAC 地址计算 IPv6 地址的接口 ID。从 5055.4444.3333 开始，在中间插入 FF FE，得到 5055.44FF.FE44.3333，然后将第一个字节的第七位取反。具体来说，十六进制 50 转为二进制 0101 0000，改变第七位后为 0101 0010，再转回十六进制 52。最终接口 ID 为 5255:44FF:FE44:3333。错误答案只是列出了不同值。</p>

<p class="quiz"><strong><a id="ref-ques27_3" href="#quess27_3">3</a>．</strong> A 和 C。四个答案中，两个正确答案给出 Cisco 路由器支持 IPv6 所需的最小配置：启用 IPv6 路由（<strong>ipv6 unicast-routing</strong>），并在各接口上启用 IPv6，通常是为每个接口添加单播地址（<strong>ipv6 address…</strong>）。两个错误答案列出的命令不存在。</p>

<p class="quiz"><strong><a id="ref-ques27_4" href="#quess27_4">4</a>．</strong> B 和 D。<strong>show ipv6 route connected</strong> 列出所有已知直连路由，每条都包含路由的前缀／长度。<strong>show ipv6 interface g0/0/0</strong> 列出接口地址，以及根据配置的地址／长度计算出的前缀／长度。</p>

<p class="quiz-para">对于错误答案，<strong>show ipv6 interface brief</strong> 列出接口地址，但不列出直连子网的前缀／长度。<strong>show ipv6 address</strong> 命令不存在，尝试输入会被作为无效命令拒绝。</p>

<p class="quiz"><strong><a id="ref-ques27_5" href="#quess27_5">5</a>．</strong> A。配置了全球单播地址的 <strong>ipv6 address</strong> 命令，但没有通过 <strong>ipv6 address</strong> 配置链路本地地址时，路由器会根据接口 MAC 地址和 EUI-64 规则计算 LLA，不使用全球单播 IPv6 地址进行计算。</p>

<p class="quiz-para"><span id="ref-page_803" data-epub-type="pagebreak"></span>链路本地地址的前半部分为 FE80:0000:0000:0000。路由器用 MAC 地址 0200.0001.000A，在中间插入 FF FE 得到 0200.00FF.FE01.000A，再翻转第七位得到 0000.00FF.FE01.000A，从而计算后半部分。</p>

<p class="quiz"><strong><a id="ref-ques27_6" href="#quess27_6">6</a>．</strong> B。FF02::1 供链路上所有 IPv6 主机使用，FF02::5 供所有 OSPFv3 路由器使用，FF02::A 供所有 EIGRPv6 路由器使用。FF02::2 用于向链路上所有 IPv6 路由器发送数据包。</p>

<p class="quiz"><strong><a id="ref-ques27_7" href="#quess27_7">7</a>．</strong> A。路由器根据单播地址 2001:db8:1:1::1234:5678，将 NDP NS 消息发送到对应的被请求节点组播地址。创建该地址时，取最后六个十六进制数字（本例为 34:5678），在前面加 FF02::1:FF，正确答案为 FF02::1:FF34:5678。其他答案是相似值，但不符合正确的被请求节点地址规则。</p>

<p class="quiz"><strong><a id="ref-ques27_8" href="#quess27_8">8</a>．</strong> B 和 C。首先，对于 G0/0/1，<strong>ipv6 enable</strong> 命令启用 IPv6，并按 EUI-64 规则生成接口 ID，创建 LLA。这说明了一个正确答案和一个错误答案。</p>

<p class="quiz-para">接着，对于 G0/0/2 和 <strong>ipv6 autoconfig</strong> 命令，命令通过 SLAAC 启用 IPv6。因此，它按 EUI-64 规则生成 LLA，并通过 SLAAC 生成可路由的单播地址，接口 ID 同样使用 EUI-64 规则。因此，G0/0/2 的 LLA 和全球单播地址具有相同的接口 ID。</p>

<p class="quiz-para">最后，对于 G0/0/3 和 <strong>ipv6 address</strong> 子命令，每个支持 IPv6 的接口都必须具有 LLA。路由器会再次使用 EUI-64，自行分配该接口 LLA 的接口 ID 部分。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_019"><strong>所有节点组播地址（all-nodes multicast address）</strong> 特定的 IPv6 组播地址 FF02::1，具有链路本地作用域，用于向链路上所有支持 IPv6 的设备发送数据包。</p>

<p class="gloss" id="ref-gloss_020"><strong>所有路由器组播地址（all-routers multicast address）</strong> 特定的 IPv6 组播地址 FF02::2，具有链路本地作用域，用于向本地链路上所有充当 IPv6 路由器的设备发送数据包。</p>

<p class="gloss" id="ref-gloss_022"><strong>任播地址（anycast address）</strong> 由网络不同位置的两台或多台主机共享的地址。按设计，路由器将数据包转发给最近的服务器，让客户端与最近的服务实例通信，而无须关心具体是哪台服务器。</p>

<p class="gloss" id="ref-gloss_114"><strong>双栈（dual stack）</strong> 主机或路由器同时运行 IPv4 与 IPv6 的工作模式。</p>

<p class="gloss" id="ref-gloss_139"><strong>EUI-64</strong> 字面含义是长 64 位的扩展唯一标识符标准。具体到 IPv6，它是一组生成 64 位标识符的规则，用作 IPv6 地址的接口 ID：从 48 位 MAC 地址开始，在中间插入十六进制 FFFE，并将第七位取反。</p>

<p class="gloss" id="ref-gloss_195"><strong>接口本地作用域（interface-local scope）</strong> IPv6 中的一种概念，发送到此作用域地址的数据包不应实际离开接口，而应留在发送主机内部。</p>

<p class="gloss" id="ref-gloss_215"><strong>IPv6 地址作用域（IPv6 address scope）</strong> IPv6 网络中主机和路由器应将 IPv6 数据包转发多远的概念，包括接口本地、链路本地、站点本地和组织本地作用域。</p>

<p class="gloss" id="ref-gloss_232"><strong>链路本地地址（link-local address，LLA）</strong> 以 FE80 开头的单播 IPv6 地址，用于每个启用了 IPv6 的接口，通过应用链路本地作用域在所连链路内发送数据包。</p>

<p class="gloss" id="ref-gloss_233"><strong>链路本地组播地址（link-local multicast address）</strong> 以 FF02 开头的组播 IPv6 地址，第四个数字 2 将作用域标识为链路本地，设备对其应用链路本地作用域。</p>

<p class="gloss" id="ref-gloss_234"><strong>链路本地作用域（link-local scope）</strong> 在 IPv6 组播中，指组播数据包可流经的网络部分（作用范围）；链路本地表示数据包留在其起源子网中。</p>

<p class="gloss" id="ref-gloss_286"><strong>组织本地作用域（Organization-local scope）</strong> IPv6 中的一种概念，发送到此作用域地址的数据包应由组织内部路由器转发，但不应跨越连接其他组织或互联网的链路。</p>

<p class="gloss" id="ref-gloss_366"><strong>站点本地作用域（site-local scope）</strong> IPv6 中的一种概念，发送到此作用域地址的数据包应由路由器转发，但不应通过 WAN 链路转发到其他站点。</p>

<p class="gloss" id="ref-gloss_368"><strong>被请求节点组播地址（solicited-node multicast address）</strong> 一种具有链路本地作用域的 IPv6 组播地址，用于向子网中单播 IPv6 地址最后六个十六进制数字相同的所有主机发送数据包，以 FF02::1:FF00:0/104 开头。</p>

<p class="gloss" id="ref-gloss_392"><strong>子网路由器任播地址（subnet router anycast address）</strong> 每个 IPv6 子网中的特殊任播地址，保留给路由器使用，以便将数据包发送给子网上的任意一台路由器。其数值与该子网的子网 ID 相同。</p>
