<p class="objset">本章涵盖以下考试主题：</p>

<p class="obj">1.0 网络基础</p>

<p class="obj1">1.6 配置与验证 IPv4 编址和子网划分</p>

<p class="noindent-c">网络工作通常从找出某台主机使用的 IP 地址和掩码开始。随后，为了理解互连网络如何将数据包路由到该主机，你必须确定有关该子网的关键信息，具体包括：</p>

<ul class="sq">

<li><p class="bull">子网 ID</p></li>

<li><p class="bull">子网广播地址</p></li>

<li><p class="bull">子网中可用单播 IP 地址的范围</p></li>

</ul>

<p class="noindent">本章讨论如何从已知 IP 地址和掩码出发，利用相关概念和计算，求出上面列出的数值，从而完整描述一个子网。这些具体任务很可能是本书所有 IP 编址和子网划分内容中最重要的 IP 技能，因为它们可能也是实际网络运维和故障排查中最常用的任务。还应注意，和其他章节一样，本章示例针对 A 类、B 类或 C 类网络划分子网，而不是 CIDR 地址块。</p>

<h3 class="h3" id="ch14lev1sec3">定义子网</h3>

<p class="noindent">IP 子网是有类网络的一个子集，由网络工程师通过选择来创建。不过，工程师不能任意挑选地址子集，而必须遵循一些规则，例如：</p>

<ul class="sq">

<li><p class="bull">子网包含一组连续的数值。</p></li>

<li><p class="bull">子网包含 2<sup><em>H</em></sup> 个数值，其中 H 为子网掩码定义的主机位数。</p></li>

<li><p class="bull">范围内有两个特殊数值不能用作 IP 地址：</p>

<ul class="sq-i">

<li><p class="bull">第一个（最小）数值用作子网的标识符（子网 ID）。</p></li>

<li><p class="bull">最后一个（最大）数值用作<em>子网广播地址</em>。</p></li>

</ul></li>

<li><p class="bull">其余地址的数值位于子网 ID 和子网广播地址之间，用作<em>单播 IP 地址</em>。</p></li>

</ul>

<p class="noindent">本节回顾并进一步介绍子网 ID、子网广播地址以及子网地址范围的基本概念。</p>

<section>

<h4 class="h4" id="ch14lev2sec1">网络 172.16.0.0 划分为四个子网的示例</h4>

<p class="noindent">假设你在客户支持中心工作，负责接听计算机出现问题的用户打来的初次求助电话。你指导用户找到她的 IP 地址和掩码：172.16.150.41、255.255.192.0。根据这些信息，最先执行且最常见的任务之一，就是求出该地址所属子网的子网 ID。（事实上，该子网 ID 有时称为<a id="key_179" href="#ref-gloss_331"><span class="blue">所属子网</span></a>，因为这个 IP 地址存在于该子网中。）</p>

<p class="noindent">在开始计算之前，先看一下掩码（255.255.192.0）和有类网络（172.16.0.0）。根据<a href="v1-13.html#ch13">第 13 章</a>“<a href="v1-13.html#ch13">分析子网掩码</a>”所学内容，你可以通过掩码确定子网中地址的结构，包括主机位数和子网位数。分析结果表明有两个子网位，意味着应该有四个（2<sup><em>2</em></sup>）子网。<a href="#ch14fig01">图 14-1</a> 展示了这一概念。</p>

<h4 class="h4" id="ch14lev2sec2"><span id="page_360" data-epub-type="pagebreak"></span>子网 ID 的概念</h4>

<p class="noindent">子网 ID 只是一个用于简洁表示子网的数字。将子网 ID 与匹配的子网掩码一同列出，就能标识该子网，并据此推导出子网广播地址和子网地址范围。你不必写出有关子网的全部细节，只需写下子网 ID 和掩码，就拥有足够的信息来完整描述这个子网。</p>

<p class="noindent">子网 ID 会出现在许多地方，其中最常见的是 IP 路由表。例如，工程师为路由器配置 IP 地址和掩码后，路由器会计算子网 ID，并在路由表中加入一条该子网的路由。随后，路由器通常会通过某种 IP 路由协议，向相邻路由器通告子网 ID／掩码组合。最终，企业中的所有路由器都会通过子网 ID 和子网掩码这一组合得知该子网，并将其显示在路由表中。（可以使用 <strong>show ip route</strong> 命令显示路由器 IP 路由表的内容。）</p>

<p class="noindent">遗憾的是，与子网相关的术语有时会造成困扰。首先，<a id="key_182" href="#ref-gloss_385"><span class="blue">子网 ID</span></a>、<a id="key_183" href="#ref-gloss_389"><span class="blue">子网号</span></a>和<a id="key_180" href="#ref-gloss_383"><span class="blue">子网地址</span></a>是同义词。此外，人们有时会直接用<em>子网</em>，同时指代子网这一概念以及作为子网 ID 的数值。在讨论路由时，人们有时用<em>前缀</em>代替<em>子网</em>。<em>前缀</em>与<em>子网</em>指的是同一个概念，只是采用了无类编址方式中描述 IP 地址的术语，详见<a href="v1-13.html#ch13">第 13 章</a>的“<a href="v1-13.html#ch13lev2sec8">无类编址与有类编址</a>”一节。</p>

<p class="noindent">最大的术语混淆发生在<em>网络</em>和<em>子网</em>之间。在现实中，人们经常把这两个词作为同义词使用，在某些情况下完全合理。但在其他情况下，这些术语的具体含义及其差别，会影响所讨论的内容。</p>

<p class="noindent">例如，人们常会问“网络 ID 是什么？”，实际上想知道的是子网 ID。但在另一种情况下，他们可能想知道的是 A 类、B 类或 C 类网络 ID。因此，当一位工程师问“172.16.150.41/18 的 net ID 是什么？”这类问题时，要结合上下文判断，他想要的是严格意义上的有类网络 ID（本例为 172.16.0.0），还是严格意义上的子网 ID（本例为 172.16.128.0）。</p>

<p class="noindent">在考试中，要留意何时使用了<em>子网</em>和<em>网络</em>这些词，并利用上下文确定它们在具体情形下的含义。</p>

<h4 class="h4" id="ch14lev2sec3"><span id="page_361" data-epub-type="pagebreak"></span>子网广播地址</h4>

<p class="noindent">子网广播地址有两个主要作用：用作目的 IP 地址，向子网中的所有主机发送数据包；以及用于确定子网地址范围的高端边界。</p>

<p class="noindent">子网广播地址最初的目的是为主机提供一种高效方式，只发送一个数据包就能送达某个子网中的所有主机。例如，子网 A 中的主机可以发送一个数据包，将目的地址设为子网 B 的子网广播地址。路由器会像转发发送给子网 B 中某台主机的单播 IP 数据包一样，转发这个数据包。数据包到达连接子网 B 的路由器后，最后这台路由器会将其转发给子网 B 中的所有主机，通常会把数据包封装进数据链路层广播帧。因此，主机 B 所在子网中的所有主机都会收到该数据包的副本。</p>

<p class="noindent">子网广播地址也能帮助你确定子网中的地址范围，因为它是子网地址范围中的最后一个（最大）数值。要确定范围的低端，计算子网 ID；要确定范围的高端，计算子网广播地址。</p>

<h4 class="h4" id="ch14lev2sec4">可用地址范围</h4>

<p class="noindent">负责实施 IP 互连网络的工程师需要了解每个子网中的单播 IP 地址范围。在规划哪些地址用作静态分配的 IP 地址、哪些地址配置为由 DHCP 服务器出租，以及哪些地址预留待用之前，必须先知道可用地址范围。</p>

<p class="noindent">要确定子网中的可用 IP 地址范围，先求出子网 ID 和子网广播地址。然后，将子网 ID 的第四个八位组加 1，就得到第一个（最小的）可用地址；将子网广播地址的第四个八位组减 1，就得到子网中的最后一个（最大的）可用地址。</p>

<p class="noindent">例如，<a href="#ch14fig03">图 14-3</a> 给出的子网 ID 是 172.16.128.0，掩码为 /18。第一个可用地址只比子网 ID 大 1，本例为 172.16.128.1。同一张图给出的子网广播地址为 172.16.191.255，因此最后一个可用地址比它小 1，即 172.16.191.254。</p>

<p class="noindent">本节已经说明了共同定义一个子网的各项数值背后的概念，接下来本章其余内容将重点介绍求出这些值所需的计算。</p>

<h3 class="h3" id="ch14lev1sec4"><span id="page_362" data-epub-type="pagebreak"></span>分析现有子网：二进制方法</h3>

<p class="noindent">“分析子网”是什么意思？在本书中，它意味着能够从 IP 地址和掩码入手，确定该地址所属子网的关键信息。具体来说，就是求出子网 ID、子网广播地址和地址范围。分析还可以包括<a href="v1-13.html#ch13">第 13 章</a>讨论的子网地址数量计算，但本章不再回顾那些概念。</p>

<p class="noindent">根据地址／掩码计算子网详细信息的方法有很多。本节先介绍一些使用二进制运算的方法，下一节再介绍仅使用十进制运算的替代方法。虽然很多人为了在考试中提高速度，更喜欢十进制方法，但二进制计算最终能让你更深入地理解 IPv4 编址。尤其是，如果你打算继续获得高于 CCNA 的 Cisco 认证，即使考试时采用十进制方法，也应花时间理解本节讨论的二进制方法。</p>

<section>

<h4 class="h4" id="ch14lev2sec5">求子网 ID：二进制方法</h4>

<p class="noindent">以下两句话概括了任意子网 ID 的二进制值背后的规律：</p>

<p class="ul-noindent">子网中的所有数值（子网 ID、子网广播地址和全部可用 IP 地址），其前缀部分都相同。</p>

<p class="ul-noindent">子网 ID 是子网中的最小数值，因此其主机部分的二进制形式全部为 0。</p>

<p class="noindent">要以二进制求子网 ID，先取得 IP 地址的二进制形式，再将所有主机位改为二进制 0。因此，需要将 IP 地址转换为二进制，还需要识别前缀位和主机位；根据需要将掩码转换为前缀格式，就能轻松识别它们。<a href="#ch14fig04">图 14-4</a> 使用与本章前面示例相同的地址／掩码说明这一思路：172.16.150.41，掩码 /18。</p>

<figure class="image-c" id="ch14fig04">

<img src="assets/volume1/part4-chapter14/images/vol1_14fig04.jpg" aria-describedby="a14fig04" alt="示意图说明了将 IP 地址转换为子网 ID 的二进制概念。">

<figcaption>

<p class="title-f"><strong>图 14-4</strong> <em>二进制概念：将 IP 地址转换为子网 ID</em></p>

<aside class="hidden" id="a14fig04">

<p>该过程包括四个步骤。步骤 1 将子网掩码 /18 表示为二进制格式 PPPPPPPP PPPPPPPP PP HHHHHH HHHHHHHH，其中 P 表示网络部分，H 表示主机部分。步骤 2 将 IP 地址 172.16.150.41 转换为二进制形式，得到 10101100 00010000 00101001。步骤 3 将前缀复制到子网 IDF，得到 10101100 00010000。步骤 4 将主机部分设为 0，把 010110 00101001 改为 000000 00000000。</p>

</aside>

</figcaption>

</figure>

<p class="noindent">从<a href="#ch14fig04">图 14-4</a> 的顶部开始看，掩码用 18 个前缀位（P）和 14 个主机位（H）表示 IP 地址格式（步骤 1）。第二行（步骤 2）展示了 IP 地址的二进制形式，由点分十进制表示法（DDN）的值 172.16.150.41 转换而来。</p>

<p class="noindent"><span id="page_363" data-epub-type="pagebreak"></span>接下来的两个步骤展示了复制 IP 地址前缀位（步骤 3），以及将主机位赋值为二进制 0（步骤 4）的操作。结果就是二进制形式的子网 ID。</p>

<p class="noindent">最后一步没有显示在<a href="#ch14fig04">图 14-4</a> 中，即将子网 ID 从二进制转换为十进制。本书在<a href="#ch14fig05">图 14-5</a> 中单独展示这一步，主要是因为很多人会在此处出错。将 32 位数字（例如 IP 地址或 IP 子网 ID）转换回 IPv4 DDN 时，必须遵循以下规则：</p>

<p class="ul-noindent">每次将 8 位从二进制转换为十进制，无需考虑该数字中前缀部分与主机部分之间的分界。</p>

<figure class="image-c" id="ch14fig05">

<img src="assets/volume1/part4-chapter14/images/vol1_14fig05.jpg" aria-describedby="a14fig05" alt="示意图展示了将 IP 地址转换为子网 ID 的二进制概念。">

<figcaption>

<p class="title-f"><strong>图 14-5</strong> <em>将子网 ID 从二进制转换为 DDN</em></p>

<aside class="hidden" id="a14fig05">

<p>该过程包括五个步骤。步骤 1 将子网掩码 /18 表示为二进制格式 PPPPPPPP PPPPPPPP PP HHHHHH HHHHHHHH，其中 P 表示网络部分，H 表示主机部分。步骤 2 将 IP 地址 172.16.150.41 转换为二进制：10101100 00010000 00101001。步骤 3 将前缀复制到子网 ID，得到 10101100 00010000。步骤 4 将主机部分设为 0，把 010110 00101001 改为 000000 00000000。步骤 5 将子网 ID 从二进制转换为点分十进制表示法（DDN），得到 172.16.128.0。</p>

</aside>

</figcaption>

</figure>

<p class="noindent"><a href="#ch14fig05">图 14-5</a> 展示了最后这一步。请注意，第三个八位组（第三组 8 位）有 2 位属于前缀，6 位属于主机部分，但转换是针对整个 8 位进行的。</p>

<h4 class="h4" id="ch14lev2sec6">求子网广播地址：二进制方法</h4>

<p class="noindent">求子网广播地址采用类似过程。使用求子网 ID 时的相同二进制方法，但不将所有主机位设为最小值（全部为二进制 0），而是将主机部分设为最大值（全部为二进制 1）。<a href="#ch14fig06">图 14-6</a> 展示了这一概念。</p>

<p class="noindent"><a href="#ch14fig06">图 14-6</a> 展示的前三个步骤与<a href="#ch14fig04">图 14-4</a> 相同。具体而言，包括识别前缀位和主机位（步骤 1），将 IP 地址 172.16.150.41 转换为二进制（步骤 2），以及在步骤 3 复制前缀位（本例为前 18 位）。区别出现在步骤 4 的右侧主机位：将所有主机位（本例为最后 14 位）改为可能的最大值，即全部为二进制 1。步骤 5 再将 32 位子网广播地址转换为 DDN 格式。此外，请记住，无论从 DDN 转为二进制，还是反向转换，始终每次转换 8 位。特别是在本例中，第三个八位组的完整二进制值 10111111 转换为十进制 191。</p>

<h4 class="h4" id="ch14lev2sec8">二进制过程的快捷方法</h4>

<p class="noindent">到目前为止，本节介绍的二进制方法需要将全部四个八位组转换为二进制，然后再转回十进制。不过，根据 DDN 掩码，你可以轻松预测四个八位组中至少三个的结果。这样，除一个八位组之外，其余八位组都可以避免二进制运算，从而减少所需的二进制转换次数。</p>

<p class="noindent">首先，仅考虑一个 DDN 掩码值为 255 的八位组。掩码值 255 转换为二进制 11111111，表示这 8 位都是前缀位。逐步思考这一过程：在步骤 2，将地址转换成某个数值；在步骤 3，复制这个数值；在步骤 4，将同一个 8 位数字转换回十进制。对这个八位组而言，你在这三步中所做的全部事情，只是从十进制转换为二进制，再将同一个数字转换回原来的十进制值！</p>

<p class="noindent"><span id="page_366" data-epub-type="pagebreak"></span>简而言之，对于值为 255 的任意掩码八位组，子网 ID 和子网广播地址中对应八位组的值，都等于 IP 地址中该八位组的值。</p>

<p class="noindent">例如，172.16.150.41、掩码 255.255.192.0 所属的子网 ID 为 172.16.128.0。掩码的前两个八位组为 255。因此，无需考虑二进制运算，直接先复制地址中这两个八位组的值：172.16。</p>

<p class="noindent">对于 DDN 掩码值为十进制 0（即二进制 00000000）的八位组，也存在一个快捷方法。当十进制掩码值为 0 时，无论 IP 地址中该八位组的初始值是什么，子网 ID 中的计算结果始终为十进制 0。具体来说，只需看此时的步骤 4 和 5：步骤 4 写出 8 个二进制 0，步骤 5 将 00000000 转回十进制 0。</p>

<p class="noindent">下面修订后的步骤考虑了这两个快捷方法。但是，当掩码既不是 0 也不是 255 时，仍需进行相同的转换。最多只需要对一个八位组进行转换。要求子网 ID，对四个八位组分别应用以下规则：</p>

<p class="step"><span class="stepb">步骤 1。</span>如果掩码 = 255，复制 IP 地址中该八位组的十进制值。</p>

<p class="step"><span class="stepb">步骤 2。</span>如果掩码 = 0，将该八位组写为十进制 0。</p>

<p class="step"><span class="stepb">步骤 3。</span>如果该八位组的掩码既不是 0 也不是 255，使用本章前面“<a href="#ch14lev2sec5">求子网 ID：二进制方法</a>”一节中的相同二进制方法。</p>

<p class="noindent"><a href="#ch14fig07">图 14-7</a> 再次使用 172.16.150.41、255.255.192.0，展示了这一过程的示例。</p>

<h4 class="h4" id="ch14lev2sec9"><span id="page_367" data-epub-type="pagebreak"></span>布尔运算简介</h4>

<p class="noindent">到目前为止，本章介绍了人们如何使用二进制运算求子网 ID 和子网广播地址。不过，计算机通常使用一种完全不同的二进制过程来求相同的值，它采用名为<em>布尔代数</em>的数学分支。计算机已经以二进制形式存储 IP 地址和掩码，因此不必在十进制与二进制之间转换。随后，某些布尔运算让计算机仅用几条 CPU 指令就能计算出子网 ID 和子网广播地址。</p>

<p class="noindent">你无需掌握布尔运算，也能很好地理解 IP 子网划分。不过，如果你感兴趣，计算机分别使用以下布尔逻辑求子网 ID 和子网广播地址：</p>

<p class="ul-noindent">对 IP 地址和掩码执行<em>布尔与运算</em>。此过程会将所有主机位转换为二进制 0。</p>

<p class="ul-noindent">先将掩码取反，再对 IP 地址和取反后的子网掩码执行<em>布尔或运算</em>。此过程会将所有主机位转换为二进制 1。</p>

</section>

<section>

<h4 class="h4" id="ch14lev2sec10">求地址范围</h4>

<p class="noindent">知道子网 ID 和子网广播地址后，只需简单的加减运算，就能确定子网中的可用地址范围。求子网中第一个（最小的）可用 IP 地址时，只需将子网 ID 的第四个八位组加 1。求最后一个（最大的）可用 IP 地址时，只需将子网广播地址的第四个八位组减 1。</p>

</section>

</section>

<h3 class="h3" id="ch14lev1sec5">分析现有子网：十进制方法</h3>

<p class="noindent">使用二进制方法分析现有子网效果很好。不过，其中一些运算对大多数人来说比较耗时，尤其是十进制与二进制之间的转换。而 Cisco CCNA 考试要求你快速完成计算。对于考试，你确实应该能够根据 IP 地址和掩码，在大约 15 秒内算出子网 ID 和可用地址范围。采用二进制方法时，大多数人需要大量练习才能求出这些答案，即使使用简化的二进制过程也是如此。</p>

<p class="noindent">本节讨论如何仅使用十进制运算求子网 ID 和子网广播地址。与二进制方法相比，大多数人使用此过程能更快得出答案，至少稍加练习后是这样。不过，十进制过程不会解释计算背后的含义。因此，如果你还没有阅读前面的“<a href="#ch14lev1sec4">分析现有子网：二进制方法</a>”一节，为了理解子网划分，值得回头读一读。本节重点是采用一种经过练习后应该更快的方法，得到正确答案。</p>

<h4 class="h4" id="ch14lev2sec11">使用简单掩码进行分析</h4>

<p class="noindent">对于三个特定的简单子网掩码，求子网 ID 和子网广播地址只需简单推理，实际上完全不用计算。这三个简单掩码是：</p>

<p class="ul-noindent">255.0.0.0</p>

<p class="ul-noindent">255.255.0.0</p>

<p class="ul-noindent">255.255.255.0</p>

<p class="noindent">这些简单掩码的十进制形式仅包含 255 和 0。相比之下，复杂掩码中有一个八位组既不是 255 也不是 0，使得推导更具挑战性。</p>

<p class="step"><span class="stepb">步骤 1。</span>如果掩码八位组 = 255，复制 IP 地址的十进制值。</p>

<h4 class="h4" id="ch14lev2sec12">关键八位组中的可预测规律</h4>

<p class="noindent">虽然有三个掩码比较容易处理（255.0.0.0、255.255.0.0 和 255.255.255.0），但其余所有子网掩码都会使十进制运算稍微复杂一些，因此我们称之为<em>复杂掩码</em>。复杂掩码中有一个八位组的值既不是 0，也不是 255。为了突出这个值最难处理的八位组，本书将其称为<em>关键八位组</em>（interesting octet）。</p>

<p class="noindent">如果花时间思考不同题目，并把注意力放在关键八位组上，就会开始发现其中的规律。本节将带你进行这种观察，让你学会以十进制预测规律并求出子网 ID。</p>

<p class="noindent">首先，子网 ID 的十进制值具有可预测性，是因为我们假设单个有类网络的所有子网使用相同的子网掩码。本书这一部分的各章都假设，对于给定有类网络，设计工程师选择让所有子网使用一个子网掩码。（更多细节见<a href="v1-11.html#ch11">第 11 章</a>“<a href="v1-11.html#ch11">IPv4 子网划分概览</a>”中的“<a href="v1-11.html#ch11lev2sec6">一种子网大小适合所有情况吗</a>”一节。）</p>

<p class="noindent"><span id="page_369" data-epub-type="pagebreak"></span>要观察这种可预测性，可以查看一位网络工程师记录的规划信息，如<a href="#ch14fig08">图 14-8</a> 所示。图中给出了工程师考虑在 IPv4 网络中使用的四种不同掩码，以及 B 类网络 172.16.0.0。图中从上到下，依次展示了使用掩码 255.255.128.0、255.255.192.0、255.255.224.0 和 255.255.240.0 时，所创建子网 ID 的第三个八位组取值。</p>

<section>

<h4 class="h4" id="ch14lev2sec13">求子网 ID：复杂掩码</h4>

<p class="noindent">下面以文字列出仅使用十进制运算求子网 ID 的全部步骤。这一过程在前面简单掩码方法的基础上增加了内容。对每个八位组：</p>

<p class="step"><span class="stepb">步骤 1。</span>如果掩码八位组 = 255，复制 IP 地址的十进制值。</p>

<p class="step"><span class="stepb">步骤 2。</span>如果掩码八位组 = 0，写入十进制 0。</p>

<p class="step"><span class="stepb">步骤 3。</span>如果掩码不属于以上两种情况，将此八位组称为<em>关键八位组</em>：</p>

<ol class="step-lower-alpha">

<li><p class="alpha">计算<em>魔数</em>：256 − 掩码。</p></li>

<li><p class="alpha">将子网 ID 的值设为最接近 IP 地址但不超过它的那个魔数倍数。</p></li>

</ol>

<p class="noindent"><span id="page_370" data-epub-type="pagebreak"></span>这一过程使用了本书定义的两个新术语：<em>魔数</em>和<em>关键八位组</em>。<em>关键八位组</em>指步骤 3 中识别出的八位组，也就是掩码既不是 255 也不是 0 的八位组。步骤 3A 使用了<em>魔数</em>一词，它由 DDN 掩码推导得出。从概念上说，魔数就是在一个子网 ID 上相加后，能够得到按顺序排列的下一个子网 ID 的数值，如<a href="#ch14fig08">图 14-8</a> 所示。从数值上说，如步骤 3A 所述，用 256 减去 DDN 掩码在关键八位组中的值，就能求出魔数。</p>

<p class="noindent">学习这一过程的最好方法，是观看实际演示。事实上，如果条件允许，现在可以暂停阅读，打开本书配套网站，观看使用复杂掩码求子网 ID 的视频。这些视频会演示这一过程。你也可以使用接下来几页展示的纸上计算示例，然后按照本章后面“<a href="#ch14lev1sec6">现有子网分析练习</a>”一节提供的安排进行练习。</p>

</figure>

<p class="noindent">首先，检查三个非关键八位组（本例为第 1、2 和 4 个）。这一过程以掩码为依据：前两个八位组的掩码值为 255，因此只需把 IP 地址的值复制到准备填写子网 ID 的位置。第四个八位组的掩码值为 0，因此将子网 ID 的第四个八位组写为 0。</p>

<p class="noindent">最有挑战性的推导发生在关键八位组中。本例是第三个八位组，因为该八位组的掩码值为 240。对于这个八位组，步骤 3A 要求按 256 − 掩码计算魔数，也就是用 256 减去掩码在关键八位组中的值（本例为 240）：256 − 240 = 16。因此，本例中子网 ID 在该八位组中的值必须是十进制 16 的倍数。</p>

<p class="noindent">步骤 3B 随后要求求出魔数（本例为 16）的倍数，并选择最接近 IP 地址但不超过它的那个。具体而言，你应当<span id="page_371" data-epub-type="pagebreak"></span>从 0 开始心算魔数的倍数。（不要忘记从 0 开始！）依次计算：0、16、32、48、64、80、96、112，依此类推。然后，找到最接近 IP 地址在该八位组中的值（本例为 102）、但不超过 102 的倍数。因此，如<a href="#ch14fig09">图 14-9</a> 所示，将第三个八位组的值设为 96，得到完整子网 ID 130.4.96.0。</p>

</section>

<h4 class="h4" id="ch14lev2sec14"><span id="page_372" data-epub-type="pagebreak"></span>求子网广播地址：复杂掩码</h4>

<p class="noindent">要求子网的广播地址，可以使用类似过程。为简化起见，此过程从子网 ID 开始，而不是从 IP 地址开始。如果你拿到的是 IP 地址，先使用本章的方法求出子网 ID，再使用以下过程求同一子网的子网广播地址。对每个八位组：</p>

<p class="step"><span class="stepb">步骤 1。</span>如果掩码八位组 = 255，复制子网 ID 的值。</p>

<p class="step"><span class="stepb">步骤 2。</span>如果掩码八位组 = 0，写入 255。</p>

<p class="step"><span class="stepb">步骤 3。</span>如果掩码不属于以上两种情况，将此八位组确定为<em>关键八位组</em>：</p>

<ol class="step-lower-alpha">

<li><p class="alpha">计算<em>魔数</em>：256 − 掩码。</p></li>

<li><p class="alpha">取子网 ID 的值，加上魔数，再减去 1（ID + 魔数 − 1）。</p></li>

</ol>

<h2 class="h2a">“这些知识我已经掌握了吗？”自测题答案</h2>

<section>

<h3 class="h3" id="ref-appclev1sec14"><span id="ref-page_791" data-epub-type="pagebreak"></span>第 14 章</h3>

<p class="quiz"><strong><a id="ref-ques14_1" href="#quess14_1">1</a>.</strong> D。采用<a href="v1-13.html#ch13">第 13 章</a>“<a href="v1-13.html#ch13">分析子网掩码</a>”所述的有类 IP 编址概念时，地址包含网络、子网和主机三个部分。对于单个有类网络中的地址，要属于同一网络，其网络部分必须相同。对于同一子网中的地址，网络部分和子网部分都必须具有相同的值。比较同一子网中的不同地址时，主机部分则不同。</p>

<p class="quiz"><strong><a id="ref-ques14_2" href="#quess14_2">2</a>.</strong> B 和 D。在任意子网中，子网 ID 是范围中的最小数值，子网广播地址是最大数值，可用 IP 地址位于两者之间。子网中所有数值的前缀部分（无类视角）以及网络 + 子网部分（有类视角）的二进制值都相同。要成为最小数值，子网 ID 的主机部分必须具有可能的最小二进制值，即全部为 0。要成为最大数值，广播地址的主机部分必须具有可能的最大二进制值，即全部为二进制 1。可用地址不包括子网 ID 和子网广播地址，因此可用 IP 地址范围中的地址，其主机部分绝不会全部为 0 或全部为 1。</p>

<p class="quiz"><strong><a id="ref-ques14_3" href="#quess14_3">3</a>.</strong> C。掩码转换为 255.255.255.0。要求子网 ID，对于值为 255 的每个掩码八位组，可以复制 IP 地址中对应的值。对于十进制值为 0 的掩码八位组，可以将子网 ID 中对应八位组写为 0。因此，复制 10.7.99，并将第四个八位组写为 0，得到子网 ID 10.7.99.0。</p>

<p class="quiz"><strong><a id="ref-ques14_4" href="#quess14_4">4</a>.</strong> C。首先，所属子网（即地址所在子网的子网 ID）在数值上必须小于该 IP 地址，这就排除了一个选项。掩码转换为 255.255.255.252。因此，由于掩码前三个八位组为 255，可以复制 IP 地址的前三个八位组。对于第四个八位组，子网 ID 的值必须是 4 的倍数，因为 256 − 252（掩码）= 4。这些倍数包括 96 和 100，正确选择是最接近 IP 地址在该八位组中的值（97）、但不超过它的倍数。因此，正确的子网 ID 为 192.168.44.96。</p>

<p class="quiz"><strong><a id="ref-ques14_5" href="#quess14_5">5</a>.</strong> C。本例中，所属子网 ID 为 172.31.77.192。根据子网 ID 和掩码，可以使用多种方法求子网广播地址。按照本书的十进制过程，掩码转换为 255.255.255.224，因此第四个八位组为关键八位组，魔数为 256 − 224 = 32。对于掩码 = 255 的三个八位组，复制子网 ID（172.31.77）。对于关键八位组，取子网 ID 的值（192），加上魔数（32），再减去 1，得到 223。因此，子网广播地址为 172.31.77.223。</p>

<p class="quiz"><strong><a id="ref-ques14_6" href="#quess14_6">6</a>.</strong> C。要回答此题，需要确定子网中的地址范围，通常意味着需要计算子网 ID 和子网广播地址。对于子网 ID／掩码 10.1.4.0/23，掩码转换为 255.255.254.0。按照本章介绍的十进制过程求子网广播地址时，由于掩码的前两个八位组都为 255，可以复制子网 ID 的前两个八位组。由于掩码第四个八位组为 0，将第四个八位组写为 255。对于第三个八位组，即关键八位组，将魔数（2）加到子网 ID 的值（4）上，再减去 1，得到 2 + 4 − 1 = 5。（本例中魔数的计算为 256 − 254 = 2。）因此，广播地址为 10.1.5.255。最后一个可用地址比它小 1：10.1.5.254。包含最后 100 个地址的范围为 10.1.5.155—10.1.5.254。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_331"><strong>所属子网</strong> 每个 IP 子网包含若干单播 IP 地址；对于其中的每个地址，该子网就是其所属子网，即这些地址所在的子网。</p>

<p class="gloss" id="ref-gloss_383"><strong>子网地址</strong> <em>参见</em><a href="#ref-gloss_389">子网号</a>。</p>

<p class="gloss" id="ref-gloss_384"><strong>子网广播地址（subnet broadcast address）</strong> 每个 IPv4 子网中的一个特殊地址，具体是该子网中数值最大的地址。发往这个地址的分组，应被交付给该子网中的所有主机。</p>

<p class="gloss" id="ref-gloss_385"><strong>子网 ID（IPv4）</strong> <em>参见</em><a href="#ref-gloss_389">子网号</a>。</p>

<p class="gloss" id="ref-gloss_389"><strong>子网号</strong> 在 IPv4 中，代表某个子网全部地址的点分十进制数。从数值上说，它是子网数值范围中的最小值，已被保留，不能由主机用作单播 IP 地址。</p>
