<h3 class="h3" id="ch10lev1sec3">通过配置理解 RSTP</h3>


<p class="noindent">如今，Cisco IOS 交换机通常默认使用 RSTP 而不是 STP，并提供无需配置即可运行 RSTP 的默认设置。你可以购买几台 Cisco 交换机，用以太网线缆连接成冗余拓扑，RSTP 就会确保帧不发生循环。即使部分交换机使用 RSTP、其他交换机使用 STP，它们也能互操作，建立正常工作的生成树，甚至完全不必考虑修改任何设置！</p>


<p class="noindent">虽然 RSTP 无需配置即可运行，但大多数中大型园区 LAN 都能从适当的 RSTP 配置中获益。例如，<a href="#ch10fig01">图 10-1</a> 展示了典型 LAN 设计模型，其中包含两台汇聚层交换机 D1 和 D2。设计中可能有数十台连接终端用户的接入层交换机，图中只显示三台：A1、A2 和 A3。出于多种原因，大多数网络工程师会让汇聚层交换机成为根。</p>


<figure class="image-c" id="ch10fig01">


<img src="assets/volume1/part3-chapter10/images/vol1_10fig01.jpg" aria-describedby="a10fig01" alt="示意图展示一种网络配置。">


<figcaption>

<p>汇聚交换机 D1 和 D2 连接接入交换机 A1、A2 和 A3。汇聚交换机承担生成树协议（STP）的根。接入交换机 A1 通过 10/100/1000 Mbps 以太网连接三台 PC，A2 和 A3 也一样。D1 和 D2 是作为根交换机的最佳选择。</p>

<h4 class="h4" id="ch10lev2sec1"><span id="page_260" data-epub-type="pagebreak"></span>多棵生成树的必要性</h4>


<p class="noindent">IEEE 最初将 STP 标准化为 IEEE 802.1D，首次发布于 1990 年。为帮助理解这个时间点，当时 Cisco 还没有 LAN 交换机产品线，虚拟局域网也尚未出现。物理以太网 LAN 中没有多个 VLAN，而是整个物理 LAN 构成一个广播域，运行一个 STP 实例。</p>


<p class="noindent">到 20 世纪 90 年代中期，VLAN 与 LAN 交换机一起出现。VLAN 的出现给当时唯一可用的 STP 带来了挑战，因为 STP 为整个 LAN 定义的是一棵公共生成树（CST）拓扑。IEEE 需要一种创建多棵生成树的选项，使流量能够在可用链路上均衡分布，如<a href="#ch10fig02">图 10-2</a> 所示。使用两个不同的 STP 实例，SW3 就可以在各 VLAN 中阻塞不同接口，如图所示。</p>


<figure class="image-c" id="ch10fig02">


<img src="assets/volume1/part3-chapter10/images/vol1_10fig02.jpg" aria-describedby="a10fig02" alt="示意图展示 VLAN 1 与 VLAN 2 的两种生成树协议（STP）拓扑，旨在实现负载均衡。">


<figcaption>


<p class="title-f"><strong>图 10-2</strong> <em>为 VLAN 1 和 VLAN 2 各使用一棵树实现负载均衡</em></p>


<aside class="hidden" id="a10fig02">


<p>对于 VLAN 1，拓扑以 SW1 为根，Gi0/1 连接 SW2，SW2 的 Gi0/1 连接 SW3 的 Gi0/2，SW3 的 Gi0/1 再连接回 SW1 的 Gi0/1。SW2 与 SW3 之间的连接被阻塞，以防止环路。VLAN 2 的拓扑类似，SW1 仍为根，连接 SW2 的 Gi0/1，后者再连接 SW3 的 Gi0/2。SW3 的 Gi0/1 连接回 SW1 的 Gi0/1。这一次，SW1 与 SW3 之间的连接被阻塞，以保持网络稳定。</p>


</aside>


</figcaption>


</figure>

<section>


<h4 class="h4" id="ch10lev2sec2">STP 模式与标准</h4>


<p class="noindent">由于 STP 协议家族历史上的发展顺序，Cisco 等厂商需要创建自己的专有功能，来实现<a href="#ch10fig02">图 10-2</a> 所示每 VLAN 生成树的概念。这个发展过程产生了以下结果：</p>


<ul class="sq">


<li><p class="bull">在 20 世纪 90 年代，802.1D 中的 STP 是唯一的 STP 标准，Cisco 创建了基于 STP 的每 VLAN 生成树增强版协议（<a id="key_147" href="#ref-gloss_322"><span class="blue">PVST+</span></a>），为每个 VLAN 创建一个生成树实例。</p></li>


<li><p class="bull">IEEE 在 2001 年通过 802.1D 的 802.1w 修订案引入 RSTP 时，仍将它定义为创建单棵生成树的方法。</p></li>


<li><p class="bull">Cisco 为交换机添加 RSTP 支持时，创建了 <a id="key_148" href="#ref-gloss_325"><span class="blue">Rapid PVST+</span></a>（RPVST+）协议。RPVST+ 提供了比标准 RSTP 更多的功能，包括每 VLAN 一棵树。</p></li>


<li><p class="bull">为了创建多棵生成树，IEEE 没有采用 Cisco 的 PVST+ 或 RPVST+，而是创建了另一种方法：多生成树协议（MSTP），最初定义于 802.1Q 的 802.1s 修订案中。</p></li>


</ul>


<p class="noindent"><span id="page_261" data-epub-type="pagebreak"></span><a href="#ch10fig03">图 10-3</a> 以时间线展示这些功能，帮助理解其发展。</p>


<figure class="image-c" id="ch10fig03">


<img src="assets/volume1/part3-chapter10/images/vol1_10fig03.jpg" aria-describedby="a10fig03" alt="示意图展示 1990 年到 2010 年的时间线，标出多项生成树协议（STP）功能的起源年份。">


<figcaption>


<p class="title-f"><strong>图 10-3</strong> <em>每 VLAN 生成树与多生成树功能的时间线</em></p>


<aside class="hidden" id="a10fig03">


<p>1990 年，引入每 VLAN 生成树增强版（PVST+）功能。大约 2000 年，快速生成树协议（RSTP）出现。到 2010 年，引入了多生成树协议（MST）和快速每 VLAN 生成树增强版（RPVST+）。</p>


</aside>


</figcaption>

<h4 class="h4" id="ch10lev2sec3">桥 ID 与系统 ID 扩展</h4>


<p class="noindent">为了支持多棵生成树，无论是每 VLAN 一棵，还是使用 MSTP 创建的多棵树，协议都必须考虑 VLAN 和 VLAN 中继。（这也是 RSTP 和 MSTP 如今成为定义 VLAN 与 VLAN 中继的 802.1Q 标准一部分的原因之一。）为此，IEEE 重新定义了原始 BID 值的格式，帮助实现每 VLAN 的 STP/RSTP 实例。</p>


<p class="noindent">最初，交换机 BID 由 2 字节交换机优先级和 6 字节 MAC 地址组合而成。后来，IEEE 如<span id="page_262" data-epub-type="pagebreak"></span><a href="#ch10fig04">图 10-4</a> 所示，将 2 字节优先级字段修订为 4 位优先级字段和一个 12 位子字段，后者称为<a id="key_149" href="#ref-gloss_401"><span class="blue">系统 ID 扩展</span></a>，用于表示 VLAN ID。</p>


<figure class="image-c" id="ch10fig04">


<img src="assets/volume1/part3-chapter10/images/vol1_10fig04.jpg" aria-describedby="a10fig04" alt="示意图展示生成树协议（STP）系统 ID 扩展的格式。">


<figcaption>


<p class="title-f"><strong>图 10-4</strong> <em>STP 系统 ID 扩展</em></p>


<aside class="hidden" id="a10fig04">


<p>原始格式中，桥 ID 包括范围为 0 到 65,535 的优先级字段（2 字节），以及由 MAC 地址构成的系统 ID（6 字节）。优先级字段扩展后，优先级变为 4096 的倍数（4 位），通常承载 VLAN ID 的系统 ID 扩展占 12 位。系统 ID 仍包含 MAC 地址（6 字节）。</p>


</aside>


</figcaption>


</figure>


<p class="noindent">Cisco 交换机只允许配置 BID 的优先级部分。交换机使用自身的全局通用固化 MAC 地址填入系统 ID，并将某个 VLAN 的 VLAN ID 填入 12 位系统 ID 扩展字段；这两种行为都无法修改。</p>


<p class="noindent">不过，优先级字段可能是 Cisco 路由器或交换机上最奇特的配置项之一。看<a href="#ch10fig04">图 10-4</a> 上方，优先级字段最初是一个 16 位数字，表示 0 到 65,535 的十进制数。由于这一历史原因，配置命令（<strong>spanning-tree vlan</strong> <em>vlan-id</em> <strong>priority</strong> <em>x</em>）要求输入 0 到 65,535 之间的十进制数。但由于如今该字段的最后 12 位保留给 VLAN ID，IOS 将该命令的取值限制为 4096 的倍数。<a href="#ch10tab03">表 10-3</a> 说明了原因：允许的十进制值转换为 16 位二进制后，最后 12 位全部为零。</p>

<h4 class="h4" id="ch10lev2sec4"><span id="page_263" data-epub-type="pagebreak"></span>识别交换机优先级和根交换机</h4>


<p class="noindent">Cisco Catalyst 交换机使用表示 16 位值的数字配置优先级；但系统 ID 扩展又占据同一数字的低 12 位。接下来将说明这些概念如何关联。</p>


<p class="noindent">交换机构建某个 VLAN 中 RSTP 使用的 BID 时，必须将已配置优先级与该 VLAN 的 VLAN ID 组合。有趣的是，配置优先级产生的 16 位值总是以 12 个二进制 0 结尾。这让交换机组合数值来创建 BID 的过程稍微简单一些；理解之后，网络工程师也可能觉得更容易了。</p>


<p class="noindent">首先，考虑<a href="#ch10fig05">图 10-5</a> 的过程。顶部以 16 位二进制显示已配置优先级值（十进制 32768），系统 ID 扩展为 12 个零。向下看，会看到 VLAN ID（十进制 9）的二进制形式。最后一步，交换机用与 VLAN ID 对应的值替换系统 ID 扩展的最后 12 位，并将结果用作 BID 的前 16 位。</p>


<figure class="image-c" id="ch10fig05">

<figcaption>

<aside class="hidden" id="a10fig05">


<p>第一种情况下，已配置优先级中的 Priority 为 1000，系统 ID 扩展为 0000 0000 0000。第二种情况下，分配 VLAN ID 9，系统 ID 扩展变为 0000 0000 1001。最后显示的 16 位优先级中，Priority 为 1000，系统 ID 扩展为 0000 0000 1001。</p>

<h5 class="h5" id="ch10lev3sec2">使用 Root Primary 和 Secondary 设置交换机优先级</h5>


<p class="noindent"><a href="#exa10_3">示例 10-3</a> 和 <a href="#exa10_4">10-4</a> 直接为 SW1 配置最佳优先级 24,576，为 SW2 配置次佳优先级 28,672。不过，Cisco 知道大多数 STP 设计都会指定最适合和次适合担任根的交换机，因此提供了两条<span id="page_266" data-epub-type="pagebreak"></span>与这一思路对应的命令。要将两台交换机配置为最有可能成为根的两台，只需配置：</p>


<p class="ul-noindent"><strong>spanning-tree vlan</strong> <em>x</em> <strong>root primary</strong>（在应作为主要根的交换机上）</p>


<p class="ul-noindent"><strong>spanning-tree vlan</strong> <em>x</em> <strong>root secondary</strong>（在应作为次要根的交换机上）</p>


<p class="noindent">与大多数配置命令相比，这两条命令采用不同的 IOS 逻辑。将命令加入配置时，它们会让 IOS 选择一个优先级值。随后，IOS 不保存上述命令，而是以 <strong>spanning-tree vlan</strong> <em>x</em> <strong>priority</strong> <em>value</em> 命令保存优先级设置。配置中不会出现包含 <strong>root primary</strong> 或 <strong>root secondary</strong> 的命令。</p>


<p class="noindent">配置 <strong>root primary</strong> 时，交换机会查看当前根交换机的优先级，并选择以下值之一：（a）24,576；（b）比当前根的优先级低 4096 的值，如果当前根的优先级为 24,576 或更低。<strong>root secondary</strong> 选项始终让交换机使用优先级 28,672；该值比使用默认值 32,768 的其他交换机更低（更好），但比任何配置为 <strong>root primary</strong> 的交换机更高（更差）。</p>

<section>


<h4 class="h4" id="ch10lev2sec5">RSTP（一棵树）与 RPVST+（每 VLAN 一棵树）</h4>


<p class="noindent">为补充桥 ID 的概念讨论，下面关注标准 RSTP 与 Cisco 专有的近亲 RPVST+。两者都使用<a href="v1-09.html#ch09">第 9 章</a>“<a href="v1-09.html#ch09">生成树协议概念</a>”介绍的 RSTP 机制，但 RPVST+ 为每个 VLAN 使用这些机制，而标准 RSTP 不会。它们的方法有哪些区别？</p>


<ul class="sq">


<li><p class="bull">RSTP 创建一棵树，即公共生成树（CST）；RPVST+ 为每一个 VLAN 各创建一棵树。</p></li>


<li><p class="bull">RSTP 在网络中发送一套 RSTP 消息（BPDU），RPVST+ 则为每个 VLAN 发送一套消息。</p></li>


<li><p class="bull">RSTP 按 IEEE 标准将消息发送到多播地址 0180.C200.0000，而 RPVST+ 使用 Cisco 选择的多播地址 0100.0CCC.CCCD。</p></li>


<li><p class="bull">在 VLAN 中继上，RSTP 将所有 BPDU 放在本征 VLAN 中发送，不带 VLAN 首部／标签。RPVST+ 则分别发送各 VLAN 的 BPDU。例如，描述 VLAN 9 的 BPDU 带有列出 VLAN 9 的 802.1Q 首部。</p></li>


<li><p class="bull">RSTP 将 BID 的 VLAN 字段（扩展系统 ID）设为 0000.0000.0000，表示“无 VLAN”；RPVST+ 则使用 VLAN ID。</p></li>


</ul>


<p class="noindent">换句话说，标准 RSTP 的行为就像 VLAN 不存在一样，而 Cisco RPVST+ 将 VLAN 信息整合到整个过程中。</p>


<div class="note">


<p class="note-title">注意</p>


<p class="note-para">某些文档将通过中继发送、且 VLAN 标签与所描述 VLAN 相同的 BPDU 这一功能称为 <em>BPDU 隧道</em>。</p>


</div>


</section>

<h3 class="h3" id="ch10lev1sec4"><span id="page_269" data-epub-type="pagebreak"></span>识别可选 STP 功能</h3>

<section>


<h4 class="h4" id="ch10lev2sec7">PortFast 与 BPDU Guard</h4>


<p class="noindent">如<a href="v1-09.html#ch09">第 9 章</a>所述，PortFast 既提供实用功能，也带来明显风险。接口一旦达到 connected 状态，PortFast 逻辑就立即将端口置于 STP 指定端口（DP）角色和转发状态。但如果该端口连接的不是终端，而是一台还连接网络其他部分的交换机，这种行为就可能造成转发环路。将 PortFast 与 BPDU Guard 结合使用，可以在端口收到任何 BPDU 时禁用它，从而防止环路。因此，将这两项功能一起考察很合理。</p>

<h5 class="h5" id="ch10lev3sec5"><span id="page_273" data-epub-type="pagebreak"></span>PortFast 与 BPDU Guard 的全局配置</h5>


<p class="noindent">目前的配置示例使用接口子命令，它们会覆盖任何全局设置。IOS 的默认全局设置让每个端口都禁用这两项功能，但你可以全局启用各项功能。对于没有相关子命令的接口，IOS 会在接口上启用该功能。随后，应找出不应启用功能的接口，并根据需要使用另一条接口子命令逐接口禁用。</p>


<p class="noindent">例如，考虑一台接入层交换机，具有 48 个连接终端的接入端口，以及两个连接其他交换机的中继端口。你可能希望在全部 48 个接入端口上启用 PortFast 和 BPDU Guard。无需在这 48 个端口逐一配置接口子命令，可以全局启用两项功能，再在上行端口禁用。</p>


<p class="noindent">先看 PortFast。配置 <strong>spanning-tree portfast default</strong> 全局命令后，IOS 会根据以下条件在部分端口上应用 PortFast：</p>


<ul class="sq">


<li><p class="bull">只在作为接入端口运行的端口上启用 PortFast。</p></li>


<li><p class="bull">忽略使用 <strong>spanning-tree portfast disable</strong> 接口子命令配置为禁用 PortFast 的端口。</p></li>


</ul>


<p class="noindent">要观察这一逻辑，考察<a href="#ch10fig09">图 10-9</a> 中的示例。交换机使用全局命令 <strong>spanning-tree portfast default</strong>。G1/0/11 没有 <strong>spanning-tree portfast</strong> 子命令，并被配置为接入端口，因此 IOS 对其应用 PortFast。但 G1/0/12 有 <strong>spanning-tree portfast disable</strong> 子命令，因此 IOS 不应用 PortFast。G1/0/13 因使用中继而不满足必要条件。</p>

<ul class="sq">


<li><p class="bull">在当前使用 PortFast 的端口上启用 BPDU Guard。</p></li>

<h4 class="h4" id="ch10lev2sec8">BPDU Filter</h4>


<p class="noindent">在<a href="v1-09.html#ch09">第 9 章</a>同样名为“<a href="v1-09.html#ch09lev2sec16">BPDU Filter</a>”的一节中，你已了解该功能的两种不同逻辑分支。回顾如下：</p>


<ol class="number">


<li><p class="number">通过全局配置命令启用 BPDU Filter 后，IOS 只在 PortFast 端口上应用它。应用期间，它监视收到的 BPDU。出现 BPDU 时，BPDU Filter 会禁用 PortFast 逻辑，使该端口恢复正常 STP 逻辑。</p></li>


<li><p class="number">通过接口子命令在端口上启用 BPDU Filter。它会丢弃端口发送和接收的全部 BPDU，实际上禁用了该端口上的 STP。</p></li>


</ol>


<p class="noindent">本节按顺序考察这两种逻辑分支。</p>


<section>


<h5 class="h5" id="ch10lev3sec6"><span id="page_275" data-epub-type="pagebreak"></span>通过全局配置实现有条件的 BPDU 过滤</h5>


<p class="noindent">要启用 BPDU Filter 的条件逻辑，必须将默认全局设置 <strong>no spanning-tree portfast bpdufilter enable</strong> 改为不带 <strong>no</strong> 选项的同一命令，即 <strong>spanning-tree portfast bpdufilter enable</strong> 全局命令。</p>


<p class="noindent">与 <strong>spanning-tree portfast bpduguard enable</strong> 全局命令的效果相似，<strong>spanning-tree portfast bpdufilter enable</strong> 全局命令要求 IOS 根据以下条件启用 BPDU Filter：</p>


<ul class="sq">


<li><p class="bull">在当前使用 PortFast 的端口上启用 BPDU Filter。</p></li>


<li><p class="bull">忽略使用 <strong>spanning-tree bpdufilter disable</strong> 接口子命令配置为禁用 BPDU Filter 的端口。</p></li>


</ul>


<p class="noindent"><a href="#exa10_12">示例 10-12</a> 展示了 SW1 G1/0/23 端口上的一个简单场景。这是 VLAN 9 中的典型接入端口，通过接口子命令启用 PortFast，同时全局启用有条件的 BPDU Filter。</p>

<h4 class="h4" id="ch10lev2sec9">Root Guard</h4>


<p class="noindent">使用 Root Guard 最具挑战的部分，是分析 STP 设计，决定哪些端口适合使用它。<a href="v1-09.html#ch09">第 9 章</a>同名的“<a href="v1-09.html#ch09lev2sec17">Root Guard</a>”一节讨论了相关逻辑。概括而言，只考虑连接其他交换机的端口，然后根据预期 STP 设计找出一些特殊端口：它们绝不应收到来自新根交换机的更优 Hello。Root Guard 会监视收到的更优 Hello，并在出现时禁用端口。某些网络可能没有任何端口需要 Root Guard，但正如<a href="v1-09.html#ch09">第 9 章</a>所述，端口选择首先要从 STP 设计出发。</p>


<p class="noindent">如果端口需要 Root Guard，实现和验证只需几个简短步骤。配置只有一个选项：<strong>spanning-tree guard root</strong> 接口子命令。没有全局命令可以更改默认值，默认情况下接口不使用 Root Guard。</p>


<p class="noindent">关于 Root Guard 采取的操作，<a href="v1-09.html#ch09">第 9 章</a>介绍了主要概念，下面的列表提供更多细节，你将在接下来的 CLI 示例中看到它们。</p>


<ul class="sq">


<li><p class="bull"><strong>触发条件：</strong>Root Guard 在端口收到更优 BPDU 后采取行动。</p></li>


<li><p class="bull"><strong>操作：</strong>一旦触发，Root Guard 会执行以下操作：</p>


<ul class="sq-i">


<li><p class="bull">操作根据更优 Hello 所属的 VLAN，按 VLAN 执行。</p></li>


<li><p class="bull">STP 将该 VLAN 中的端口置于 broken（BRK）状态，丢弃所有流量，与丢弃和阻塞状态类似。</p></li>


<li><p class="bull">在 show 命令的端口类型信息中，STP 将该端口描述为根不一致（root inconsistent）状态。</p></li>


</ul></li>


<li><p class="bull"><strong>恢复：</strong>当一段时间内不再收到更优 BPDU 后，STP 自动恢复先前状态，无需操作人员干预。</p></li>


</ul>

<h3 class="h3" id="ch10lev1sec5"><span id="page_281" data-epub-type="pagebreak"></span>配置二层 EtherChannel</h3>


<p class="noindent">如<a href="v1-09.html#ch09">第 9 章</a>“<a href="v1-09.html#ch09">生成树协议概念</a>”所介绍，两台相邻交换机可以将彼此之间多条并行链路视为一条称作 <em>EtherChannel</em> 的逻辑链路。不使用 EtherChannel 时，交换机将每个物理端口视为独立端口，按物理端口应用 MAC 学习、转发和 STP 逻辑。使用 EtherChannel 后，交换机将同样的过程应用于作为单一实体的一组物理端口，即 EtherChannel。两台交换机之间有并行链路时，如果不使用 EtherChannel，STP/RSTP 会阻塞除一条之外的所有链路；使用 EtherChannel 后，交换机可利用所有链路，在它们之间均衡流量。</p>


<div class="note">


<p class="note-title">注意</p>


<p class="note-para">本章提及的 EtherChannel 全部指二层 EtherChannel，不包括<a data-original-href="vol1_ch18.xhtml#ch18" data-unavailable="true" title="此内容不在当前提取范围内；请参阅原始 EPUB：vol1_ch18.xhtml#ch18">第 18 章</a>“<a data-original-href="vol1_ch18.xhtml#ch18" data-unavailable="true" title="此内容不在当前提取范围内；请参阅原始 EPUB：vol1_ch18.xhtml#ch18">LAN 中的 IP 路由</a>”讨论的三层 EtherChannel。CCNA 200-301 考试主题同时包括二层和三层 EtherChannel。</p>


</div>


<p class="noindent">EtherChannel 可能是最难配置成功的交换机功能之一。首先，配置有多个选项，必须记住哪些选项可以配合工作。其次，交换机还要求通道中所有链路的多种其他接口设置相匹配，因此也必须掌握这些设置。</p>


<p class="noindent">本节介绍如何配置二层 EtherChannel，先使用手动（静态）配置，再让动态协议创建通道。Cisco 建议使用动态方式，但静态方式最初可能更容易学习，因此先从静态或手动选项开始。本节最后介绍二层 EtherChannel 的一些常见配置问题。</p>

<h4 class="h4" id="ch10lev2sec11">手动配置二层 EtherChannel</h4>


<p class="noindent">要将二层 EtherChannel 配置为所有端口始终尝试加入通道，只需在每台交换机的每个物理接口上添加正确的 <strong>channel-group</strong> 配置命令，全部使用 <strong>on</strong> 关键字和相同编号。<strong>on</strong> 关键字告诉交换机将物理接口加入 EtherChannel，而编号指定该接口应归属的 PortChannel 接口编号。</p>


<p class="noindent">不过，在介绍配置和验证之前，需要开始将三个术语视为同义词：<a id="key_142" href="#ref-gloss_224"><span class="blue">EtherChannel</span></a>、<a id="key_146" href="#ref-gloss_308"><span class="blue">PortChannel</span></a> 和 <a id="key_141" href="#ref-gloss_057"><span class="blue">Channel-group</span></a>。奇怪的是，IOS 使用 <strong>channel-group</strong> 配置命令，但显示状态时却使用 <strong>show etherchannel</strong> 命令。而该 <strong>show</strong> 命令的输出既不称“<a href="v1-09.html#ch09lev2sec13">EtherChannel</a>”，也不称“Channel-group”，而是使用“PortChannel”。因此，请特别留意示例中的这三个术语。</p>

<p class="step"><span class="stepb">步骤 1.</span> 在每个应属于通道的物理接口的接口配置模式下，添加 <strong>channel-group</strong> <em>number</em> <strong>mode on</strong> 命令，将其加入通道。</p>

<section>


<h4 class="h4" id="ch10lev2sec12">配置动态 EtherChannel</h4>


<p class="noindent">Cisco 交换机还支持两种不同的配置选项，使用动态协议协商某条链路是否加入 EtherChannel。基本上，配置会为某个 channel-group 编号启用协议。此后，交换机利用协议与邻居交换机收发消息，检查双方配置是否通过全部检查。如果某条物理链路通过检查，就加入 EtherChannel 并投入使用；否则置于 down 状态，不予使用，直到解决配置不一致的问题。</p>


<p class="noindent">大多数 Cisco Catalyst 交换机支持 Cisco 专有的端口聚合协议（<a id="key_145" href="#ref-gloss_297"><span class="blue">PAgP</span></a>），以及 IEEE 标准链路聚合控制协议（<a id="key_144" href="#ref-gloss_223"><span class="blue">LACP</span></a>）。虽然两者存在差异，但就这里讨论的深度而言，它们完成相同任务：通过协商确保只有通过配置检查的链路才实际用于 EtherChannel。（注意，IEEE 最初在 802.3ad 修订案中定义 LACP，如今则在 IEEE 802.1AX 标准中定义。）</p>


<p class="noindent">一个值得注意的区别是，LACP 支持一个通道包含更多链路，最多 16 条，而 PAgP 最多 8 条。使用 LACP 时，同时只有 8 条链路可以活动，其余链路等待在其他链路失效时接替使用。</p>


<p class="noindent"><span id="page_285" data-epub-type="pagebreak"></span>配置任一种协议时，都在每台交换机上使用 <strong>channel-group</strong> 配置命令，但关键字分别表示“使用此协议并开始协商”或“使用此协议并等待另一台交换机开始协商”。如<a href="#ch10fig11">图 10-11</a> 所示，<strong>desirable</strong> 和 <strong>auto</strong> 启用 PAgP，<strong>active</strong> 和 <strong>passive</strong> 启用 LACP。使用这些选项时，至少一端必须主动发起协商。换句话说，使用 PAgP 时，至少一端必须使用 <strong>desirable</strong>；使用 LACP 时，至少一端必须使用 <strong>active</strong>。</p>

<p class="noindent">在结束 EtherChannel 核心配置与验证主题之前，将 EtherChannel 和生成树结合起来思考。STP/RSTP 根据链路开销选择更好的链路。EtherChannel 可能有多条正常工作的链路，活动链路数量会随链路故障和恢复而改变。因此，IOS 默认根据活动链路数量计算 EtherChannel 的默认 STP 开销。</p>


<p class="noindent"><span id="page_287" data-epub-type="pagebreak"></span>例如，STP/RSTP 的默认开销优先选择 10 Gbps 链路，而不是由 1 Gbps 链路组成的 EtherChannel；同时优先选择包含多条 1 Gbps 链路的 EtherChannel，而不是单条 1 Gbps 链路。对应默认端口开销如下：</p>


<ul class="sq">


<li><p class="bull"><strong>默认开销 4：</strong>只有一条活动 1 Gbps 链路的 EtherChannel，以及任何未使用 EtherChannel 的单条 1 Gbps 链路</p></li>


<li><p class="bull"><strong>默认开销 3：</strong>包含 2 到 8 条活动 1 Gbps 链路的 EtherChannel</p></li>


<li><p class="bull"><strong>默认开销 2：</strong>单条 10 Gbps 链路</p></li>

<h4 class="h4" id="ch10lev2sec13">EtherChannel 的接口配置一致性</h4>


<p class="noindent">即使所有 <strong>channel-group</strong> 命令都配置正确，其他配置设置也可能使交换机无法在 EtherChannel 中使用某个物理端口，即使该端口是手动配置为通道成员也一样。接下来考察这些原因。</p>


<p class="noindent">首先，在动态 EtherChannel 中使用物理端口之前，交换机会将新物理端口的配置与通道中现有端口比较。新接口的设置必须与现有端口相同，否则交换机不会将新链路加入通道中获准且正常工作的接口列表。也就是说，物理接口在配置上仍是 PortChannel 的一部分，但实际上不参与通道，往往会被置于某种非正常工作状态。</p>


<p class="noindent">交换机检查的项目包括：</p>


<ul class="sq">


<li><p class="bull">速率</p></li>


<li><p class="bull">双工模式</p></li>


<li><p class="bull">实际运行的接入或中继状态：必须全部为接入，或全部为中继</p></li>


<li><p class="bull">若为接入端口，则检查接入 VLAN</p></li>


<li><p class="bull">若为中继端口，则检查允许的 VLAN 列表（由 <strong>switchport trunk allowed</strong> 命令设置）</p></li>


<li><p class="bull">若为中继端口，则检查本征 VLAN</p></li>


</ul>

<p class="noindent">要理解为什么可能需要不同方法，就必须考虑交换机选择所产生的结果。（这里关注结果，而不是具体逻辑，因为逻辑属于交换机内部实现，Cisco 并未记录每种型号或 IOS 版本的内部工作方式。）不过，各种负载分配算法确实具有一些共同目标：</p>


<ul class="sq">


<li><p class="bull">让单个应用流中的所有消息使用通道中的同一条链路，而不是分散到不同链路。这样可以避免交换机无意中改变应用流消息的顺序，例如先把一条消息发到有排队消息的繁忙链路，却立即将下一条消息发到空闲链路。</p></li>


<li><p class="bull">将负载分配算法整合到硬件转发 ASIC 中，使负载分配与转发其他帧一样快速。</p></li>


<li><p class="bull">使用 EtherChannel 中的所有活动链路，并随活动链路的加入和移除而调整。</p></li>


<li><p class="bull">在满足其他目标的约束下，在这些活动链路之间均衡流量。</p></li>


</ul>


<p class="noindent">简而言之，算法首先旨在避免消息乱序、利用交换机转发 ASIC，并使用所有活动链路。不过，算法不会尝试让各链路随时间传送完全相同的比特数。它确实会尝试均衡流量，但始终受其他目标约束。</p>


<p class="noindent">无论选择哪种负载分配方法，该方法都会指定消息首部中的字段。同一应用流中的所有消息，在负载分配算法使用的字段中具有相同值，因此总会通过同一链路转发。例如，用户连接网站时，Web 服务器可能向客户端返回数千个分组。这数千个分组应当沿 EtherChannel 中的同一链路传输。</p>


<p class="noindent">例如，使用 <strong>src-mac</strong>（源 MAC 地址）负载分配方法时，源 MAC 地址相同的所有帧都会沿同一链路传输。<a href="#ch10fig13">图 10-13</a> 用假设的通用 MAC 地址展示这一思路：负载分配将源 MAC 1 的帧发到链路 1，源 MAC 2 的帧发到链路 2，源 MAC 3 的帧发到链路 3。</p>

<h3 class="h3" id="ref-appclev1sec10">第 10 章</h3>

<p class="quiz"><strong><a id="ref-ques10_1" href="#quess10_1">1</a>.</strong> A。四个答案中，只有 <strong>pvst</strong> 和 <strong>rapid-pvst</strong> 是该命令的有效选项。其中，<strong>rapid-pvst</strong> 启用使用 RSTP 的快速每 VLAN 生成树（RPVST+）。<strong>pvst</strong> 启用使用 STP 而不是 RSTP 的每 VLAN 生成树（PVST）。另外两个选项并不存在，如果尝试使用，命令会被拒绝。</p>

<p class="quiz"><strong><a id="ref-ques10_2" href="#quess10_2">2</a>.</strong> A 和 C。桥 ID 中的系统 ID 扩展（也称扩展系统 ID）部分包含 12 位，位于 4 位优先级字段之后、48 位系统 ID 之前。交换机使用 STP 或 RSTP 为每个 VLAN 构建生成树时，用这个字段保存 VLAN ID。因此，两个提及系统 ID 扩展的答案中，列出 VLAN ID（本例为 5）的选项正确。</p>

<p class="quiz-para">输出还列出优先级 32773。但这实际上是 16 位优先级值对应的十进制数，等于已配置十进制优先级与 VLAN ID 的和：32768 + 5 = 32773。因此，本例根的已配置优先级为 32,768。</p>

<p class="quiz"><strong><a id="ref-ques10_3" href="#quess10_3">3</a>.</strong> A、B 和 D。Cisco 快速每 VLAN 生成树（RPVST+）为每个 VLAN 创建一个生成树实例，因此会按 VLAN 发送 BPDU。每台交换机在每个 VLAN 中使用唯一桥 ID（BID）标识自身，通过把 VLAN ID 加入 BID 的 12 位系统 ID 扩展字段，使其按 VLAN 唯一。RPVST 还会在 BPDU 本身中添加一个新的类型－长度－值（TLV），其中包含记录 VLAN ID 的位置。最后，通过 VLAN 中继传输 BPDU 时，交换机会使用列出 VLAN ID 的中继首部，这种做法在 802.1Q 中有时称为隧道传送。接收交换机可以检查列出 VLAN ID 的三个位置，确保它们对 BPDU 描述哪个 VLAN 的认定一致。四个答案中的三个正确答案，描述的正是 RPVST+ 实际记录 VLAN ID 的三个位置。</p>

<p class="quiz"><strong><a id="ref-ques10_4" href="#quess10_4">4</a>.</strong> B 和 C。BPDU Guard 通过将端口置于错误禁用（err-disabled）接口状态来禁用端口。只要接口启用了 BPDU Guard，就会执行这一操作，无论是否同时启用 PortFast。两个正确答案都说明 BPDU Guard 已启用，两个错误答案则将其列为禁用。</p>

<p class="quiz"><strong><a id="ref-ques10_5" href="#quess10_5">5</a>.</strong> A 和 E。Root Guard 收到更优 BPDU 后会禁用端口。它保持接口状态为 connected，而是操控 STP 端口状态，将其改为称作 broken 的特殊状态。命令用字母 BRK 显示 broken 状态。因此，<strong>show interfaces status</strong> 命令列出 connected 接口状态，而 <strong>show spanning-tree</strong> 命令列出 BRK，即 broken 端口状态，停止接口上的所有流量。</p>

<p class="quiz"><span id="ref-page_788" data-epub-type="pagebreak"></span><strong><a id="ref-ques10_6" href="#quess10_6">6</a>.</strong> D。IOS 使用 <strong>channel-group</strong> 配置命令创建 EtherChannel。随后，<em>etherchannel</em> 这一术语用于显示通道状态的 <strong>show etherchannel</strong> 命令。该 <strong>show</strong> 命令的输出又将通道称为 <em>PortChannel</em>。答案中唯一没有在 IOS 某处用于描述这种多链路通道的术语是 <em>Ethernet-Channel</em>。</p>

<p class="quiz"><strong><a id="ref-ques10_7" href="#quess10_7">7</a>.</strong> B 和 D。<strong>channel-group</strong> 命令分别使用 <strong>active</strong> 和 <strong>passive</strong> 关键字时，会让交换机使用 LACP 动态协商将链路加入 EtherChannel。<strong>desirable</strong> 和 <strong>passive</strong> 关键字则让交换机使用 PAgP，而不是 LACP。四个答案中，两个正确答案都使用两个 LACP 值，而两个错误答案至少使用一个会让交换机采用 PAgP 的值，因此不正确。</p>

<p class="quiz-para">两个正确答案的组合都会让交换机使用 LACP 作为协商协议，尝试将链路加入 EtherChannel。如果两台交换机都使用 <strong>passive</strong>，就会都等待另一台交换机开始发送 LACP 消息，因此永远不会尝试将链路加入通道。</p>

<p class="quiz"><strong><a id="ref-ques10_8" href="#quess10_8">8</a>.</strong> C。Cisco Catalyst 交换机上的 EtherChannel 负载分配（负载均衡）使用算法。算法检查各种首部中的某些字段，使这些字段值相同的消息始终沿特定 EtherChannel 中的同一链路传输。注意，它不会将帧拆成较小片段，不会采用忽略首部值的轮询方式，也不会在选择时检查链路利用率。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_057"><strong>Channel-group</strong> Cisco 交换机用于表示一组捆绑链路的术语之一，这组链路在某些方面被视为单条链路。其他类似术语包括 <em>EtherChannel</em> 和 <em>PortChannel</em>。</p>

<p class="gloss" id="ref-gloss_130"><strong>EtherChannel 负载分配（EtherChannel Load Distribution）</strong> 交换机通过 EtherChannel 转发消息时，用于选择具体物理出链路来转发帧的逻辑。</p>

<p class="gloss" id="ref-gloss_223"><strong>LACP</strong> 链路聚合控制协议是 IEEE 802.3ad 标准定义的消息协议，使两台相邻设备发现彼此之间存在多条并行链路，并决定哪些链路能够组合成 EtherChannel。</p>

<p class="gloss" id="ref-gloss_224"><span id="ref-page_824" data-epub-type="pagebreak"></span><strong>二层 EtherChannel（L2 EtherChannel）</strong> 作为交换端口而非路由端口运行的 EtherChannel，因此由交换机的二层转发逻辑使用。二层交换机会在 MAC 地址表中列出二层 EtherChannel；根据这些 MAC 表条目转发帧时，交换机在二层 EtherChannel 的各端口之间均衡流量。</p>

<p class="gloss" id="ref-gloss_297"><strong>PAgP</strong> 端口聚合协议（PAgP）是 Cisco 定义的消息协议，使两台相邻设备发现彼此之间存在多条并行链路，并决定哪些链路能够组合成 EtherChannel。</p>

<p class="gloss" id="ref-gloss_308"><strong>PortChannel</strong> Cisco 交换机用于表示一组捆绑链路的术语之一，这组链路在某些方面被视为单条链路。其他类似术语包括 <em>EtherChannel</em> 和 <em>Channel-group</em>。</p>

<p class="gloss" id="ref-gloss_322"><strong>PVST+</strong> Cisco 交换机中的一种 STP 选项，为每个 VLAN 创建一个 STP 实例，是 Cisco 专有协议。</p>

<p class="gloss" id="ref-gloss_325"><strong>RAM</strong> 随机存取存储器。一种可由微处理器读写的易失性存储器。</p>

<p class="gloss" id="ref-gloss_401"><strong>系统 ID 扩展（system ID extension）</strong> 指对原始 16 位 STP 优先级字段采用的格式调整，将其分为 4 位优先级字段和 12 位 VLAN ID 字段。</p>
