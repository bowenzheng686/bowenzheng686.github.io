<h3 class="h3" id="ch04lev1sec3">连接 Cisco AP</h3>

<p class="noindent">Cisco 无线网络由 AP 以及与其配合的一台或多台无线 LAN 控制器组成。AP 最基本的功能是将无线设备连接到有线网络。因此，你应了解如何连接 AP 的有线侧，使其能够在相应的 WLAN 和 VLAN 之间传递流量。</p>

<p class="noindent">回顾一下，自治 AP 是一台独立设备；它无需其他设备，就能将以太网帧从有线 VLAN 转发到无线 LAN，反向也一样。实际上，AP 将每个 VLAN 映射到一个 WLAN 和 BSS。自治 AP 只有一个有线以太网接口，如<a href="#ch04fig01">图 4-1</a> 左侧所示，这意味着必须通过中继链路将多个 VLAN 传送到 AP。</p>

<div class="note">

<p class="note-title">提示</p>

<p class="note-para">为 AP 提供有线连接的交换机端口必须配置为支持接入模式或中继模式。在中继模式下，802.1Q 封装根据每个帧所属的 VLAN 编号为其打上标签。AP 的无线侧则通过在 802.11 帧中标记其所属 WLAN 的 BSSID，自然实现多 WLAN 帧的中继传送。</p>

</div>

<p class="noindent">Cisco AP 同样只有一个有线以太网接口，但它必须与 WLC 配合才能完整发挥功能。终止于 WLC 的有线 VLAN 可以映射到 AP 上提供的 WLAN。虽然多个 VLAN 从 <span id="page_59" data-epub-type="pagebreak"></span>WLC 延伸到了 AP，但它们都通过二者之间的 CAPWAP 隧道传送。这意味着 AP 只需要一条接入链路，即可连接网络基础设施并终止隧道的本端，如<a href="#ch04fig01">图 4-1</a> 右侧所示。</p>

<figure class="image-c" id="ch04fig01">

<img src="assets/volume2/part1-chapter4/images/vol2_04fig01.jpg" aria-describedby="a04fig01" alt="示意图比较网络中自治接入点（AP）与 Cisco AP 的连接方式。">

<figcaption>

<aside class="hidden" id="a04fig01">

<p>图分为两部分。左侧：自治 AP 连接。交换式 LAN：连接到局域网（LAN）中的网络交换机。中继链路：交换机与自治 AP 之间的连接标为中继链路。自治 AP：独立运行的接入点。客户端：使用设备连接自治 AP 的用户，位于锥形覆盖区域内。右侧：Cisco AP 连接。WLC（无线 LAN 控制器）：集中管理多台 Cisco AP 的控制器。交换式 LAN：连接到局域网（LAN）中的网络交换机。接入链路：交换机与 Cisco AP 之间的连接标为接入链路。CAPWAP 隧道：表示用于管理 Cisco AP 的无线接入点控制和配置协议，以标有 CAPWAP 的竖直虚线表示。Cisco AP：由无线 LAN 控制器管理的接入点。客户端：使用设备连接 Cisco AP 的用户，位于锥形覆盖区域内。此图突出展示了自治 AP 和 Cisco AP 使用的不同网络配置和连接类型。自治 AP 独立运行，通过中继链路连接交换式 LAN；Cisco AP 则由无线 LAN 控制器通过 CAPWAP 隧道管理，并通过接入链路连接交换式 LAN。</p>

</aside>

<p class="title-f"><strong>图 4-1</strong> <em>比较自治 AP 与 Cisco AP 的连接</em></p>

</figcaption>

</figure>

<p class="noindent">通常，通过浏览器会话访问 WLC 来管理 Cisco AP 最为高效。不过，也可以使用串行控制台电缆，将 PC 直接连接到 AP 的控制台端口，以监视其启动过程，或在需要时进行一些基本配置更改。AP 正常运行并拥有 IP 地址后，还可以使用 Telnet 或 SSH 通过有线网络连接到其 CLI。</p>

<h3 class="h3" id="ch04lev1sec4">访问 Cisco WLC</h3>

<p class="noindent">要连接并配置 WLC，需要打开 Web 浏览器，通过 HTTP 或 HTTPS 访问 WLC 的管理地址。只有在 WLC 已具备初始配置、管理接口已分配管理 IP 地址，并已生成供 HTTPS 使用的有效 SSL 证书之后，才能这样操作。基于 Web 的 GUI 为监视、配置和排查无线网络故障提供了有效方式。也可以通过 SSH 会话连接 WLC，使用其 CLI 监视、配置和调试运行活动。</p>

<p class="noindent">基于 Web 的 GUI 和 CLI 都要求管理用户登录。用户身份可以通过内部的本地用户名列表进行验证，也可以通过 TACACS+ 或 RADIUS 等身份验证、授权和记账（AAA）服务器进行验证。</p>

<p class="noindent"><span id="page_60" data-epub-type="pagebreak"></span>首次在 Web 浏览器中打开管理地址时，将看到初始登录界面。单击<strong>登录（Login）</strong>按钮，如<a href="#ch04fig02">图 4-2</a>（IOS-XE 控制器）和<a href="#ch04fig03">图 4-3</a>（AireOS 控制器）所示，然后根据提示输入用户凭据。</p>

<h3 class="h3" id="ch04lev1sec5">连接 Cisco WLC</h3>

<p class="noindent">Cisco 无线 LAN 控制器（WLC）提供多种不同类型的端口和连接。以下各节将详细解释这些连接类型。本章后面针对 IOS-XE 和 AireOS 的“<a href="#ch04lev1sec6">配置 WLAN</a>”部分将进一步介绍 WLC 端口的配置。</p>

<section>

<h4 class="h4" id="ch04lev2sec1">WLC 物理端口</h4>

<p class="noindent">WLC 有多种可以连接到网络的物理端口，如<a href="#ch04fig08">图 4-8</a> 所示。例如，可以连接串行<em>控制台端口</em>，执行初始启动功能和系统恢复。以太网<em>服务端口</em>用于通过 SSH 或 Web 浏览器进行带外管理，有时也称为<em>设备管理接口</em>。<em>冗余端口</em>用于连接对等控制器，以实现高可用性（HA）运行。</p>

<figure class="image-c" id="ch04fig08">

<img src="assets/volume2/part1-chapter4/images/vol2_04fig08.jpg" aria-describedby="a04fig08" alt="示意图展示网络基础设施中无线 LAN 控制器（WLC）的物理端口和连接。">

<figcaption>

<aside class="hidden" id="a04fig08">

<p>过程从连接到交换式基础设施的接入点（AP）开始，基础设施以网络交换机图标表示。流量经由此基础设施，通过链路聚合组（LAG）传送到 WLC 的多个以太网端口。图中还展示无线接入点控制和配置（CAPWAP）协议，它通过隧道在 AP 与 WLC 之间传送流量。WLC 配备多个端口：串行控制台端口用于初始启动功能和系统恢复；以太网服务端口用于通过安全外壳（SSH）或 Web 浏览器进行带外管理，也称设备管理接口；冗余端口用于连接对等控制器，以确保高可用性（HA）运行。</p>

</aside>

<p class="title-f"><strong>图 4-8</strong> <em>无线 LAN 控制器的物理端口</em></p>

</figcaption>

</figure>

<p class="noindent">控制器还具有多个必须连接到网络的以太网端口。这些端口承载进出控制器的大部分数据。例如，延伸到控制器各台 AP 的 CAPWAP 控制隧道和数据隧道都会经过这些端口。此外，使用 Web 浏览器、SSH、简单网络管理协议（SNMP）、简单文件传输协议（TFTP）等产生的管理流量，通常也通过这些端口以带内方式到达控制器。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para"><span id="page_64" data-epub-type="pagebreak"></span>AireOS 控制器上的以太网端口称为<em>分布系统端口</em>。你也许会觉得，外观看似普通的数据端口却采用了一个奇怪的名称。回顾<a href="v2-01.html#ch01">第 1 章</a>“<a href="v2-01.html#ch01">无线网络基础</a>”中的“<a href="v2-01.html#ch01lev1sec4">无线 LAN 拓扑</a>”一节，将 AP 连接在一起的有线网络称为分布系统（DS）。在分离 MAC 架构中，AP 与 DS 的连接点被移到了上游的 WLC 上。</p>

</div>

<p class="noindent">由于以太网端口必须承载属于许多不同 VLAN 的数据，VLAN 标签和编号就十分重要。本章稍后将介绍控制器如何将 VLAN 映射到无线 LAN。IOS-XE 控制器的以太网端口应始终配置为在 802.1Q 中继模式下工作。AireOS 控制器端口只能以中继模式工作，不能配置为其他模式。将控制器端口连接到交换机时，也应将相应交换机端口配置为无条件的 802.1Q 中继模式，以保持匹配。</p>

<p class="noindent">控制器的以太网端口可以独立工作，每个端口将多个 VLAN 的数据传送到一组特定的控制器内部接口。为提高故障恢复能力，可以将端口配置为链路聚合组（LAG），把它们捆绑成一条更大的链路，其方式类似于交换机上的 EtherChannel 或端口通道。事实上，与控制器端口相连的交换机端口也必须配置为端口通道。采用 LAG 配置后，流量可以在组成 LAG 的各个端口之间实现负载均衡。此外，LAG 还提供故障恢复能力；如果一个或多个端口发生故障，流量将被重定向到其余正常工作的端口。</p>

<p class="noindent">Cisco 无线控制器必须在无线 LAN 与有线 VLAN 之间提供必要的连接。控制器可以通过物理以太网端口接入 VLAN，而 WLAN 则经由 CAPWAP 隧道承载并在控制器内部终止。因此，控制器必须使用内部动态接口在 VLAN 与 WLAN 之间建立映射，如<a href="#ch04fig09">图 4-9</a> 所示。</p>

<figure class="image-c" id="ch04fig09">

<figcaption>

<p class="noindent"><span id="page_65" data-epub-type="pagebreak"></span>IOS-XE 控制器的动态接口工作在第二层，因此控制器不需要在每个 VLAN 上配置第三层 IP 地址。相比之下，AireOS 控制器必须为每个连接 VLAN 的动态接口配置 IP 地址、子网掩码、默认网关以及动态主机配置协议（DHCP）服务器。</p>

<p class="noindent">IOS-XE 和 AireOS 两种控制器平台都需要无线管理接口（WMI），用于所有带内管理流量。该接口用于常规管理流量，例如 RADIUS 用户身份验证、WLC 间通信、基于 Web 和 SSH 的会话、SNMP、网络时间协议（NTP）、syslog 等。管理接口还用于终止控制器与其 AP 之间的 CAPWAP 隧道。</p>

<p class="noindent">WMI 使用 IP 地址、子网掩码和默认网关，使控制器能够在网络上通信。WMI 通常连接到上游交换机的管理 VLAN。在 IOS-XE 控制器上，WMI 实际上是一个交换虚拟接口（SVI），拥有整台控制器唯一配置的 IP 地址。</p>

<p class="noindent">虚拟接口仅用于某些面向客户端的操作。例如，无线客户端发出获取 IP 地址的请求时，控制器可以将请求中继到能够提供适当 IP 地址的实际 DHCP 服务器。从客户端的角度看，DHCP 服务器似乎就是控制器的虚拟接口地址。客户端可能会看到虚拟接口地址，但控制器与交换网络上的其他设备通信时绝不会使用该地址。应为虚拟接口配置一个唯一且不可路由的地址，例如 RFC 1918 所定义的私有地址空间内的 10.1.1.1。</p>

<p class="noindent">虚拟接口地址也用于支持客户端移动。因此，同一移动组中的每台控制器都应配置相同的虚拟地址。使用一个共同的虚拟地址后，当客户端在控制器之间漫游时，所有控制器看起来就像一个集群一样工作。</p>

<h3 class="h3" id="ch04lev1sec6">配置 WLAN</h3>

<p class="noindent">无线 LAN 控制器与接入点协同工作，为无线客户端提供网络连接。从无线侧看，AP 通告一个服务集标识符（SSID），供无线客户端加入。从有线侧看，控制器通过某个动态接口连接到虚拟 LAN（VLAN）。要完成 SSID 与 VLAN 之间的路径，如<a href="#ch04fig10">图 4-10</a> 所示，必须先在控制器上定义一个 WLAN。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">CCNA 的两个考试目标涉及仅通过控制器 GUI 配置 WLAN，使用 WPA2 和 PSK 提供客户端连接。本节提供一个基于<a href="#ch04fig10">图 4-10</a> 拓扑的完整 WLAN 示例，采用 WPA2-Personal（PSK）安全模型。</p>

</div>

<span id="page_66" data-epub-type="pagebreak"></span>

<figure class="image-c" id="ch04fig10">

<img src="assets/volume2/part1-chapter4/images/vol2_04fig10.jpg" aria-describedby="a04fig10" alt="图展示使用无线局域网（WLAN）连接有线和无线网络。">

</aside>

</figcaption>

</figure>

<p class="noindent">控制器将 WLAN 绑定到某个动态接口，然后默认把 WLAN 配置推送到其所有 AP。从此，无线客户端就能通过接收信标获知新 WLAN，并能够探测和加入新的 BSS。</p>

<p class="noindent">与 VLAN 一样，可以使用 WLAN 将无线用户及其流量划分到不同的逻辑网络中。关联到一个 WLAN 的用户无法进入另一个 WLAN，除非其流量通过有线网络基础设施，在 VLAN 之间进行桥接或路由。</p>

<p class="noindent">创建新 WLAN 之前，通常最好先规划无线网络。在大型企业中，可能需要支持多种无线设备、用户群体和安全策略等。你或许会想针对每种情况创建一个新 WLAN，以隔离不同用户群体或支持不同类型的设备。虽然这种策略很有吸引力，但应注意两个限制：</p>

<ul class="sq">

<li><p class="bull">Cisco 控制器最多支持 512 个 WLAN，但一台 AP 上只能配置并启用其中的 16 个。</p></li>

<li><p class="bull">向潜在无线客户端通告每个 WLAN 都会消耗宝贵的空口时间。</p></li>

</ul>

<p class="noindent">每台 AP 都必须定期广播信标管理帧，以通告 BSS 的存在。由于每个 WLAN 都绑定到一个 BSS，因此每个 WLAN 都必须使用自己的信标进行通告。信标通常以最低的强制数据速率每秒发送 10 次，即每 100 ms 发送一次。创建的 WLAN 越多，通告它们所需的信标也就越多。</p>

<p class="noindent">而且，强制数据速率越低，传输每个信标所需的时间就越长。最终结果是：如果创建过多 WLAN，信道的可用空口时间可能耗尽。由于信道忙于传输来自 AP 的信标，客户端将难以传输自己的数据。按照经验，应始终将 WLAN 数量限制在五个以内；最好不超过三个。</p>

<p class="noindent">默认情况下，控制器只有有限的初始配置，因此尚未定义任何 WLAN。创建新 WLAN 之前，请考虑它需要哪些参数：</p>

<ul class="sq">

<li><p class="bull">SSID 字符串</p></li>

<li><p class="bull">控制器接口和 VLAN 编号</p></li>

<li><p class="bull">所需的无线安全类型</p></li>

</ul>

<p class="noindent"><span id="page_67" data-epub-type="pagebreak"></span>以下各节先演示如何在 IOS-XE 控制器上创建 WLAN，然后演示 AireOS 控制器上的操作。每个配置步骤都通过连接到 WLC 管理 IP 地址的 Web 浏览器会话执行。</p>

<section>

<h4 class="h4" id="ch04lev2sec2">在 IOS-XE WLC 上配置 WLAN</h4>

<p class="noindent">IOS-XE 无线控制器平台功能丰富而强大，可以精细控制无线网络配置的每个部分。可以采用全局方式，让网络中的所有 AP 使用相同配置，也可以根据 AP 的位置或其他共同要求定制配置。例如，企业可能有多栋建筑。你可能希望某栋建筑内的 AP 仅在一个频段上提供 WLAN，或者希望某组 AP 仅提供完整 WLAN 列表中的一部分。在其他建筑中，则可能需要支持另一组限制条件。</p>

<p class="noindent">使用 IOS-XE 控制器，可以配置并应用三大类用于定义 AP 运行方式的参数：</p>

<ul class="sq">

<li><p class="bull"><strong>策略（Policy）：</strong>定义各无线 LAN 及其安全策略的设置。</p></li>

<li><p class="bull"><strong>站点（Site）：</strong>按站点影响 AP 与控制器及 CAPWAP 关系，以及 FlexConnect 行为的设置。</p></li>

<li><p class="bull"><strong>射频（RF）：</strong>定义各无线频段射频运行方式的设置。</p></li>

</ul>

<p class="noindent">这三类设置通过配置<em>文件（profile）</em>和<em>标签（tag）</em>应用到网络中的每台 AP。可以定义包含所需自定义设置的策略、站点和 RF 配置文件，然后为每台 AP 打上标签，标识其应使用哪些策略、站点和 RF 配置文件。<a href="#ch04fig11">图 4-11</a> 展示这一概念，并列出每类配置文件中可自定义的相关参数。</p>

<figure class="image-c" id="ch04fig11">

<img src="assets/volume2/part1-chapter4/images/vol2_04fig11.jpg" aria-describedby="a04fig11" alt="示意图展示在 IOS-XE 控制器环境中，通过配置文件和标签配置接入点（AP）。">

<p class="noindent">选择 WLAN Profile 右侧的 <strong>+</strong> 图标。从 Add WLAN &gt; General 选项卡开始，如<a href="#ch04fig13">图 4-13</a> 所示，系统会提示输入 WLAN 配置文件名称和 SSID 的文本字符串（1–32 个字符）。默认情况下，WLAN 配置文件名称会复制到 SSID 字段中，但可以按需编辑。WLAN ID 只是一个用于索引控制器上各个已配置 WLAN 的数字。</p>

<p class="noindent">可以将 WLAN Status 改为 Enabled，使其投入使用。还应启用 Broadcast SSID，允许 AP 向潜在无线客户端通告该 SSID。</p>

<p class="noindent">General 选项卡还允许选择 WLAN 使用哪些频段。默认情况下，所有受支持频段都已启用，让无线客户端根据自身内部算法选择频段。</p>

<p class="noindent"><span id="page_70" data-epub-type="pagebreak"></span>由于 2.4 GHz 频段经常被附近无关网络挤占，可以在自己的 AP 上禁用该频段，改用更高的频段。5 GHz 和 6 GHz 频段（<a href="#ch04fig13">图 4-13</a> 未显示 6 GHz 频段）中相互竞争的 AP 少得多，而且性能好得多，这些特性很适合语音和视频等无线应用。在 2.4 GHz 频段上，还可以选择要使用的 802.11 策略。默认支持 802.11b 和 802.11g 两项修订。可以选择 <strong>802.11g-only</strong>，彻底禁用 802.11b 设备使用的较慢旧式数据速率。</p>

<h4 class="h4" id="ch04lev2sec3">在 AireOS WLC 上配置 WLAN</h4>

<p class="noindent">旧式 AireOS 控制器不使用 IOS-XE 控制器的配置文件和标签概念，而是允许直接在 GUI 中配置 WLAN，对 AP 配置的控制粒度要粗得多。</p>

<p class="noindent">创建新 WLAN 包括以下三个步骤：</p>

<p class="step"><span class="step">步骤 1。</span>创建动态接口，然后分配接口名称和 VLAN ID。</p>

<p class="step"><span class="step">步骤 2。</span>创建 WLAN，然后分配 WLAN 配置文件名称、SSID 以及唯一的 WLAN ID。</p>

<p class="step"><span class="step">步骤 3。</span>配置 WLAN 参数，启用 WLAN，并允许其广播 SSID。</p>

<p class="noindent-c">以下各节将更详细地讨论这些步骤。</p>

<section>

<h5 class="h5" id="ch04lev3sec5">步骤 1：创建动态接口</h5>

<p class="noindent">在 AireOS 控制器上，动态接口用于将控制器连接到有线网络中的 VLAN。创建 WLAN 时，需要将动态接口（及 VLAN）绑定到无线网络。</p>

<p class="noindent">要创建新的动态接口，请进入 <strong>Controller &gt; Interfaces</strong>。这里应显示当前已配置的所有控制器接口列表。在<a href="#ch04fig26">图 4-26</a> 中，已存在名为 management 和 virtual 的两个接口。单击 <strong>New（新建）</strong>按钮，定义一个新接口。输入接口名称及其要绑定的 VLAN 编号。在<a href="#ch04fig27">图 4-27</a> 中，名为 Engineering 的接口映射到有线 VLAN 100。单击 <strong>Apply（应用）</strong>按钮。</p>

<section>

<h5 class="h5" id="ch04lev3sec10">配置 WLAN 高级设置</h5>

<p class="noindent">最后，可以选择 <strong>Advanced（高级）</strong>选项卡，配置各种 WLAN 高级设置。在<a href="#ch04fig35">图 4-35</a> 所示的页面上，可以配置许多功能；其中大多数超出 CCNA 目标范围，因此未在图中展示。不过，你应了解一些可能影响无线客户端的参数及默认值。</p>

<p class="noindent">可以配置 Session Timeout，设置客户端会话在被强制重新进行身份验证前允许持续的时间。默认情况下，会话在 1800 秒（30 分钟）后超时。如果 WLAN 使用 802.1x，可以将会话超时值设在 300–86,400 秒范围内；否则，范围为 0–86,400 秒，其中 0 表示不超时。</p>

<p class="noindent">如果启用 Client Exclusion（客户端排除），控制器将使用其无线入侵防御系统（IPS），根据特征数据库评估客户端活动。如果检测到可疑活动，控制器会将该客户端加入排除列表，并将其与无线网络隔离，默认持续 180 秒。</p>

<span id="page_86" data-epub-type="pagebreak"></span>

<figure class="image-c" id="ch04fig35">

<img src="assets/volume2/part1-chapter4/images/vol2_04fig35.jpg" aria-describedby="a04fig35" alt="截图展示 Cisco 网络管理系统中 WLANs &gt; Edit 页面的 Advanced 选项卡，用于配置无线局域网（WLAN）的高级设置。">

<figcaption>

<aside class="hidden" id="a04fig35">

<p>界面包含 Enable Session Timeout（启用会话超时）选项，已勾选并设为 1800 秒；Client Exclusion（客户端排除）已启用，超时为 180 秒，最大失败次数为 3。Maximum Allowed Clients（允许的最大客户端数）设为 200，Maximum Allowed Clients Per AP Radio（每个 AP 无线电允许的最大客户端数）也设为 200。此外，Load Balancing and Band Select（负载均衡和频段选择）部分突出显示客户端负载均衡和客户端频段选择选项。其他设置包括 DHCP 配置，其中 DHCP Required 已启用，并提供 DHCP 服务器覆盖选项。Management Frame Protection（管理帧保护，MFP）部分提供保护管理帧的设置，还有与网络准入控制（NAC）、代理 ARP 和客户端负载均衡相关的配置。界面也包含 MAC 过滤选项及具体的范围设置。右上角有 Back（返回）和 Apply（应用）按钮，用于导航和应用更改。</p>

</aside>

<p class="title-f"><strong>图 4-35</strong> <em>配置 WLAN 高级设置</em></p>

</figcaption>

</figure>

<p class="noindent">可以通过 Maximum Allowed Clients 限制并发客户端数量。默认情况下，控制器允许每个 WLAN 的客户端数量不受限制（以零表示）。也可以限制 WLAN 中每个 AP 无线电允许连接的客户端数量，其默认值为 200。</p>

<p class="noindent">你可能还希望让控制器决定如何允许无线客户端接入 AP 无线电。例如，可以使用 Client Load Balancing 选项，让控制器在客户端探测和关联时，将它们分配到相邻 AP。Client Band Select 选项允许控制器主动影响客户端的选择：如果客户端尝试在较低且效率较差的频段上关联，就引导它们加入效率更高的频段。例如，如果附近也有可用的 5 GHz 信道，Client Band Select 就可以尝试阻止客户端加入 2.4 GHz 信道。</p>

<div class="note">

<p class="note-title">提示</p>

<p class="note-para">180 秒真的足以阻止无线客户端发起的攻击吗？对于从可能密码字典中逐一猜测密码的暴力攻击，180 秒足以打断并延缓攻击者的进度。在没有排除策略时，找到匹配密码可能只需 3 分钟；启用排除策略后，则可能需要 15 年。</p>

</div>

<p class="quiz"><strong><a id="ref-ques4_8" href="#quess4_8">8</a>.</strong> A 和 C。列表中只有 WLAN 配置文件和策略配置文件是必需的。信道编号不是必需项，因为它由系统自动提供，或通过更高级的 AP 配置指定。BSSID 也不是必需项，因为它是标识 AP 所提供 BSS 的地址。IP 子网用于绑定的 VLAN 和 WLAN，但不用于 WLAN 配置。</p>
