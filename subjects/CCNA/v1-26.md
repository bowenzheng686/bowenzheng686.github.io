<p class="objset">本章涵盖以下考试主题：</p>

<p class="obj">1.0 网络基础</p>

<p class="obj1">1.8 配置并验证 IPv6 编址和前缀</p>

<p class="obj1">1.9 描述 IPv6 地址类型</p>

<p class="obj2">1.9.a 单播（全球、唯一本地和链路本地）</p>

<p class="noindent-c">互联网号码分配机构（IANA）分配公有 IPv6 地址的过程，与 IPv4 使用 CIDR 地址块的方式很相似。IANA 先将部分 IPv6 地址空间定义为单播，其他部分定义为组播。大多数单播地址空间用作公有地址，少量空间保留用于特定目的。IANA 与 RIR 使用任意有效前缀长度定义并分配公有地址块，常见大小为 /32 到 /48。</p>

<p class="noindent">本章有两个主要部分。第一部分介绍用作公有 IPv6 地址的<a id="key_274" href="#ref-gloss_161"><span class="blue">全球单播地址（global unicast addresses）</span></a>，也讨论比 IPv4 简单得多的 IPv6 子网划分。第二部分介绍用作私有 IPv6 地址的<a id="key_280" href="#ref-gloss_423"><span class="blue">唯一本地地址（unique local addresses）</span></a>。</p>

<section>

<h3 class="h3" id="ch26lev1sec3">全球单播编址概念</h3>

<p class="noindent">本章第一大节关注一种单播 IPv6 地址：全球单播地址。实际上，这类地址背后的许多总体概念和过程遵循公有 IPv4 地址的最初设计意图。因此，本节先回顾一些 IPv4 概念，再详细说明企业如何使用全球单播地址。</p>

<p class="noindent"><span id="page_656" data-epub-type="pagebreak"></span>第一节还讨论 IPv6 子网划分，以及获取一块全球单播地址并为企业创建子网的完整过程。这个过程从全球唯一的全球路由前缀开始，创建 IPv6 子网，再从各子网内分配 IPv6 地址，与 IPv4 非常相似。</p>

<section>

<h4 class="h4" id="ch26lev2sec1">公有和私有 IPv6 地址</h4>

<p class="noindent">全球 IPv4 地址的最初规划，要求为每个连接互联网的组织分配一个唯一的公有 IPv4 网络。各组织随后划分该网络并从中分配地址，使每个组织的每台主机都使用全世界唯一的 IPv4 地址。遗憾的是，当所有公司、组织和家庭都希望连接互联网时，IPv4 地址空间不足以实现这一计划，因此负责 IPv4 编址的人修改了规划。</p>

<p class="noindent">作为修订规划的一部分，20 世纪 90 年代，企业开始使用 RFC 1918 定义的私有 IPv4 地址范围，并配合网络地址转换（NAT）。采用 NAT 和私有 IPv4 地址，使一个组织的所有主机访问互联网时，可以共享少量全球唯一的公有 IPv4 地址。</p>

<p class="noindent">IPv6 也提供公有和私有单播编址两种类似选择，首先是作为公有 IPv6 地址空间的<em>全球单播</em>地址。与公有 IPv4 地址类似，IPv6 全球单播地址依赖管理分配过程，为每家企业分配唯一的 IPv6 地址块。企业随后划分该地址块，仅使用块内地址，因此每家企业使用的地址也在全球范围内唯一。</p>

<p class="noindent">第二种选择是 IPv6 <em>唯一本地</em>地址，其作用类似于 IPv4 私有地址。不计划连接互联网的企业，以及计划使用 IPv6 NAT 的企业，都可使用唯一本地地址。在 IPv4 中，组织只需从 RFC 1918 的私有网络中选取数字。在 IPv6 中，则参考 RFC 4193，它建议使用随机过程选择唯一本地前缀。与 IPv4 私有网络一样，采用 IPv6 唯一本地地址（ULA）的组织若要连接互联网，需要少量公有 IPv6 地址并使用 NAT。</p>

<p class="noindent">下列项目总结全球单播地址与唯一本地地址的比较：</p>

<p class="ul-noindent"><strong>全球单播地址（GUA）：</strong> 作用类似于公有 IPv4 地址。需要 IPv6 地址的组织申请注册 IPv6 地址块，以全球路由前缀的形式获得分配。此后，只有该组织使用该地址块内部的地址，也就是以所分配前缀开头的地址。</p>

<p class="ul-noindent"><strong>唯一本地地址（ULA）：</strong> 作用有些类似于私有 IPv4 地址，可能有多个组织使用完全相同的地址，且无须向任何号码管理机构注册。</p>

<p class="noindent"><span id="page_657" data-epub-type="pagebreak"></span>第一大节其余部分将更详细地介绍全球单播地址，第二大节则介绍唯一本地地址。</p>

</section>

<section>

<h4 class="h4" id="ch26lev2sec2">IPv6 全球路由前缀</h4>

<p class="noindent">IPv6 全球单播地址（GUA）让 IPv6 的工作方式更接近 IPv4 互联网的最初设计。每个组织申请一块其他组织不能使用的 IPv6 地址，再将它细分为称为<em>子网</em>的更小地址块。最后，工程师从正确的子网中选择一个地址，分配给主机使用。</p>

<p class="noindent">这块保留给一家企业使用的 IPv6 地址，称为<a id="key_273" href="#ref-gloss_160"><span class="blue">全球路由前缀（global routing prefix）</span></a>。每个希望连接互联网并使用 IPv6 GUA 的组织，都应申请并获得一个全球路由前缀。作为对比，可以将它视为公有 IPv4 地址范围中的 A、B 或 C 类网络号，或将其看作公有 CIDR 地址块。</p>

<p class="noindent"><em>全球路由前缀</em>这一术语，一开始可能不会让你想到一块 IPv6 地址。它表达的含义是：互联网路由器可以用一条路由指向该地址块中的所有地址，而无须为其中更小的部分保留路由。例如，<a href="#ch26fig01">图 26-1</a> 展示三家企业各有不同的 IPv6 全球路由前缀；右侧位于互联网中的 R4，为每个全球路由前缀各保留一条 IPv6 路由。</p>

<figure class="image-c" id="ch26fig01">

<img src="assets/volume1/part7-chapter26/images/vol1_26fig01.jpg" aria-describedby="a26fig01" alt="展示三家企业各有唯一全球路由前缀的网络路由结构的示意图。">

<p class="noindent">图中三个全球路由前缀各定义一个 GUA 范围，分别保留给三家企业。以 2001:DB8:1111::/48 为例，前缀长度 48 恰好等于 12*4。下面第一种说法从更直接的二进制角度解释“2001:DB8:1111::/48”，第二种则给出更容易理解的十六进制角度：</p>

<p class="ul-noindent">前 48 位等于 2001:DB8:1111:: 前 48 位的地址</p>

<p class="ul-noindent">前 12 个十六进制数字等于 2001:DB8:1111:: 前 12 个十六进制数字的地址</p>

<p class="noindent">地址分配过程将这些 IPv6 地址专门留给这一家企业使用，就像 IPv4 中的公有网络或 CIDR 地址块一样。企业内部的所有 IPv6 <span id="page_658" data-epub-type="pagebreak"></span>地址都应以全球路由前缀中的这些起始位开头。其他企业不应使用具有相同前缀的 IPv6 地址。好在 IPv6 空间充足，足以让所有企业都获得拥有大量地址的全球路由前缀。</p>

<p class="noindent">IPv6 和 IPv4 地址分配过程依赖相同的组织：IANA（以及 ICANN）、区域互联网注册机构（RIR）和 ISP。例如，虚构的 Company1 获得了一个全球路由前缀。该前缀表示“前 12 个十六进制数字为 2001:0DB8:1111 的所有地址”，写作 2001:0DB8:1111::/48。获得这一分配需要经过 <a href="#ch26fig02">图 26-2</a> 所示过程。</p>

<figure class="image-c" id="ch26fig02">

<ol class="number">

</ol>

<h4 class="h4" id="ch26lev2sec3"><span id="page_659" data-epub-type="pagebreak"></span>全球单播地址的范围</h4>

<p class="noindent">全球单播地址占 IPv6 地址空间的大部分。不过，与 IPv4 不同，IPv6 地址所属类别的规则被有意设计得更加灵活，不像 IPv4 的 A、B、C、D、E 类规则那样固定。</p>

<p class="noindent">IANA 将所有以十六进制 2 或 3 开头的 IPv6 地址分配为全球单播地址。前缀 2000::/3 正式定义了这一范围，表示前三位（由 /3 前缀长度决定）与 2000:: 前三位匹配的所有地址。进一步解释如下：</p>

<ul class="sq">

<li><p class="bull">第一个十六进制数字 2 对应二进制 0010。</p></li>

<li><p class="bull">/3 表示与所列前缀具有相同前三位的所有地址，本例为二进制 001。</p></li>

<li><p class="bull">前三位为 001 的十六进制值只有 2 和 3，没有其他值。</p></li>

<li><p class="bull">因此，前缀 2000::/3 表示所有以十六进制 2 或 3 开头的地址。</p></li>

</ul>

<p class="noindent">如果需要，IANA 可以逐步将 GUA 范围扩展到 2000::/3 之外。奠定 IPv6 编址基础的 RFC 4291《IPv6 编址体系结构》，将所有没有另行保留的地址都留给 GUA 地址空间。不过，根据当前政策，IANA 仅从 2000::/3 范围分配全球单播地址。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">作为对比，如果将 2000::/3 GUA 地址空间全部按 /48 前缀分配给组织，可提供超过 30 万亿个 /48 全球路由前缀，每个前缀又允许 65,536 个子网。IANA 可能永远不会耗尽 2000::/3 GUA 地址空间。</p>

</div>

<h4 class="h4" id="ch26lev2sec4">使用全球单播地址进行 IPv6 子网划分</h4>

<p class="noindent">企业获得一块保留的 GUA，也就是全球路由前缀后，需要将这个大地址块划分为子网。</p>

<p class="noindent">IPv6 地址的子网划分总体上与 IPv4 类似，但大部分计算更简单（太好了！）。许多 IPv6 RFC 规定，网络中部署的所有子网，也就是在终端和路由器上配置的子网，都使用 /64 前缀长度。所有子网采用 /64，使 IPv6 子网计算像所有 IPv4 子网都使用 /24 掩码一样简单。此外，动态 IPv6 地址分配过程在 /64 前缀长度下也工作得更好。因此，在实践中以及本书中，都应预期 IPv6 设计使用 /64 子网前缀。</p>

<p class="noindent"><span id="page_660" data-epub-type="pagebreak"></span>本节通过 /64 前缀长度的示例，逐步介绍 IPv6 子网划分的不同部分。讨论将定义哪些地址应属于同一子网、哪些需要属于不同子网的规则，还将介绍如何分析全球路由前缀及其长度，求出所有 IPv6 子网前缀及每个子网内的地址。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">如果对 IPv4 子网划分概念有些模糊，可以重读 <a href="v1-11.html#ch11">第 11 章</a>“<a href="v1-11.html#ch11">IPv4 子网划分的不同视角</a>”，其中讨论了 IPv4 子网划分概念。</p>

</div>

<h5 class="h5" id="ch26lev3sec2">IPv6 全球单播地址子网划分的机制</h5>

<p class="noindent">要理解如何划分一大块 IPv6 地址，需要了解 IPv6 使用的一些原理和机制。将 IPv6 与 IPv4 中相似的概念作比较，有助于掌握这些细节。</p>

<p class="noindent">在 IPv4 中，未进行子网划分时，地址有网络部分和主机部分两部分。A、B、C 类规则定义网络部分长度，32 位 IPv4 地址的其余部分构成主机部分，如 <a href="#ch26fig04">图 26-4</a> 所示。</p>

<figure class="image-c" id="ch26fig04">

<img src="assets/volume1/part7-chapter26/images/vol1_26fig04.jpg" aria-describedby="a26fig04" alt="三类 IPv4 网络的对比图。">

<figcaption>

<p class="title-f"><strong>图 26-4</strong> <em>未划分子网的 IPv4 网络的分类视图</em></p>

<aside class="hidden" id="a26fig04">

<p>图中展示 A、B、C 三类 IPv4 网络。每类由横条表示，分为 N（网络）和 H（主机）两部分，注明各自位数。A 类网络部分为 8 位、主机部分为 24 位；B 类两部分各为 16 位；C 类网络部分较长，为 24 位，主机部分仅为 8 位。每类还标有锁图标，表示各自的类别。</p>

</aside>

</figcaption>

</figure>

<p class="noindent"><span id="page_661" data-epub-type="pagebreak"></span>要划分 IPv4 A、B 或 C 类网络，企业网络工程师需要作出一些选择。从概念上看，工程师在中间增加子网字段、缩短主机字段，将地址看作三部分。（许多人将其称为“借用主机位”。）网络部分的大小仍由 A、B、C 类规则固定，而子网与主机部分的边界可根据所选子网掩码灵活变化。<a href="#ch26fig05">图 26-5</a> 展示了一个已划分子网的 B 类网络的字段名称及概念。</p>

<figure class="image-c" id="ch26fig05">

<img src="assets/volume1/part7-chapter26/images/vol1_26fig05.jpg" aria-describedby="a26fig05" alt="展示已划分子网的 B 类 IPv4 网络的结构及各部分决定方式的图。">

<figcaption>

<p class="title-f"><strong>图 26-5</strong> <em>已划分子网的 IPv4 网络的分类视图及字段名称</em></p>

<aside class="hidden" id="a26fig05">

<p>网络分成“网络”“子网”和“主机”三部分。“网络”部分根据 B 类规则设定，“子网”和“主机”部分由本地工程师配置，图中用两个锁图标表示这些设置。</p>

</aside>

</figcaption>

</figure>

<p class="noindent">首先，比较 <a href="#ch26fig06">图 26-6</a> 和 <a href="#ch26fig05">图 26-5</a>，理解 IPv6 的总体思路。IPv6 全球路由前缀（RIR 或 ISP 分配的前缀／长度）对应 IPv4 地址结构中的网络部分。IPv6 子网 ID 对应 IPv4 子网字段。IPv6 地址右侧正式称为<a id="key_275" href="#ref-gloss_194"><span class="blue">接口 ID（interface ID）</span></a>，即接口标识符的缩写，也简称 <em>IID</em>，对应 IPv4 主机字段。</p>

<figure class="image-c" id="ch26fig06">

<img src="assets/volume1/part7-chapter26/images/vol1_26fig06.jpg" aria-describedby="a26fig06" alt="展示已划分子网的 IPv6 全球单播地址的结构及各部分决定方式的图。">

<figcaption>

<p class="title-f"><strong>图 26-6</strong> <em>已划分子网的 IPv6 全球单播地址结构</em></p>

<aside class="hidden" id="a26fig06">

<p>地址分为“全球路由前缀”“子网 ID”和“接口 ID”三部分。全球路由前缀由 IANA、RIR 或 ISP 设定，包含 P 位。子网 ID 由本地工程师决定，包含 S 位。接口 ID 包含 I 位。底部公式“P + S + I = 128”表示三部分位数之和。</p>

</aside>

</figcaption>

</figure>

<p class="noindent">现在关注 IPv6 全球路由前缀及其长度。IPv6 与 IPv4 不同，没有地址类别概念，因此没有预设规则决定全球路由前缀的长度。企业向 ISP、RIR 或其他有权分配全球路由前缀的组织申请时，得到的分配同时包含前缀及其长度。获得全球路由前缀及长度后，长度通常不会随时间改变，而是固定下来。（全球路由前缀长度通常在 /32 到 /48 之间，也可能长达 /56。）</p>

<p class="noindent">接下来，查看 <a href="#ch26fig06">图 26-6</a> 右侧的接口 ID（IID）字段。多篇 RFC（包括 RFC 4291《IPv6 编址体系结构》）规定 IID 应长 64 位。64 位 IID 能与 IPv6 的动态地址分配方法良好配合。</p>

<p class="noindent">最后，查看 <a href="#ch26fig06">图 26-6</a> 的子网 ID 字段。该字段提供了给 IPv6 子网编号的位置。其长度取决于全球路由前缀长度和接口 ID 长度。假设采用典型的 64 位 IID，子网 ID 字段通常为 64–P 位，其中 P 为全球路由前缀长度。</p>

<p class="noindent"><span id="page_662" data-epub-type="pagebreak"></span>例如，考虑具体的全球单播 IPv6 地址 2001:0DB8:1111:0001:0000:0000:0000:0001 的结构，如 <a href="#ch26fig07">图 26-7</a> 所示。本例中：</p>

<ul class="sq">

<li><p class="bull">企业获得分配的全球路由前缀为 2001:0DB8:1111/48。</p>

</li>

<li><p class="bull">企业采用常见的 64 位接口 ID，子网前缀长度为 /64。</p></li>

<li><p class="bull">企业的子网字段为 16 位，允许 2<sup><em>16</em></sup> 个 IPv6 子网。</p></li>

</ul>

<figure class="image-c" id="ch26fig07">

<img src="assets/volume1/part7-chapter26/images/vol1_26fig07.jpg" aria-describedby="a26fig07" alt="展示公司 1 的 IP 地址结构的图。">

<figcaption>

<p class="title-f"><strong>图 26-7</strong> <em>公司 1 示例的地址结构</em></p>

<aside class="hidden" id="a26fig07">

<p>地址分为“全球路由前缀”“子网 ID”和“主机”三部分。全球路由前缀长 48 位，值为“2001:0DB8:1111”；子网 ID 长 16 位，值为“0001”；主机部分长 64 位，值为“0000:0000:0000:0001”。横条下方的标签“子网前缀（子网、子网 ID、前缀、前缀 ID）”表示全球路由前缀与子网 ID 的组合。</p>

</aside>

</figcaption>

</figure>

<p class="noindent"><a href="#ch26fig07">图 26-7</a> 的示例加上一点计算，说明了许多企业接受 64 位 IID 建议的一个原因。采用这种结构，公司 1 可以支持 2<sup><em>16</em></sup> 个子网（65,536 个），很少有企业需要如此多的子网。不过，RIR 和 ISP 在批准更大的公有 IPv6 地址块时可以很慷慨，因此即使 65,536 个子网已足够，企业仍可能申请并获得更短的全球路由前缀，如 /32 或 /40。这会提供更多子网（分别为 2<sup><em>32</em></sup> 和 2<sup><em>24</em></sup> 个），除了满足子网数量需求，还为子网设计和编号规划带来许多可能性。</p>

<p class="noindent">接口 ID 有 64 位时，每个子网可容纳的主机数远远超过所需。采用 64 位 IID 的动机是支持各种 RFC，特别是与动态 IPv6 地址分配有关的 RFC，包括 DHCP 和 SLAAC。</p>

</section>

<h5 class="h5" id="ch26lev3sec3">列出 IPv6 子网前缀（子网 ID）</h5>

<p class="noindent">在 Cisco 路由器上使用 IPv6 时，经常需要处理代表子网的数字。IPv6 中会用到以下术语：</p>

<p class="ul-noindent"><a id="key_277" href="#ref-gloss_391"><span class="blue">子网前缀（subnet prefix）</span></a><strong>：</strong> 表示子网的数字的正式术语，包含 <a href="#ch26fig07">图 26-7</a> 中的全球路由前缀和子网 ID。</p>

<p class="ul-noindent"><a id="key_276" href="#ref-gloss_387"><span class="blue">子网 ID</span> 或<span class="blue">前缀 ID</span></a><strong>：</strong> 作为子网前缀同义词使用的非正式术语。</p>

<p class="noindent">虽然<em>子网前缀</em>一词来自 RFC，但由于<em>子网 ID</em> 在 IPv4 中的历史，人们往往更习惯使用后者。不过，需要注意可能产生的误解：子网 ID 的正式含义是 <a href="#ch26fig07">图 26-7</a> 中地址结构的中间部分，但也可能被当作子网前缀的同义词。</p>

<p class="noindent"><a href="v1-25.html#ch25">第 25 章</a>“<a href="v1-25.html#ch25">IP 版本 6 基础</a>”已经讨论如何根据 IPv6 地址及前缀长度求子网前缀。无论是全球单播地址，还是本章后面讨论的唯一本地地址，计算方法都相同。回顾一个示例，<a href="#ch26fig07">图 26-7</a> 中地址的子网前缀为：</p>

<pre class="pre" tabindex="0"><code class="highlight"><span class="m">2001:DB8:1111:1::/64</span></code></pre>

</section>

<section>

<h5 class="h5" id="ch26lev3sec4"><span id="page_663" data-epub-type="pagebreak"></span>列出所有 IPv6 子网</h5>

<p class="noindent">对于 IPv4，如果所有子网使用同一个掩码，就可据此求出 A、B 或 C 类网络的所有子网。相同思路适用于 IPv6，而 /64 前缀长度意味着无须二进制计算即可找出全部子网。</p>

<p class="noindent">要找出所有子网 ID，只需找出能放入三部分 IPv6 地址的子网 ID 部分的所有唯一值，如 <a href="#ch26fig06">图 26-6</a> 和 <a href="#ch26fig07">图 26-7</a> 所示，基本规则如下：</p>

<ul class="sq">

<li><p class="bull">所有子网 ID 都以全球路由前缀开头。</p></li>

<li><p class="bull">在子网字段中使用不同的值标识各子网。</p></li>

<li><p class="bull">所有子网 ID 的接口 ID 部分均为全 0。</p></li>

</ul>

<p class="noindent">以 <a href="#ch26fig07">图 26-7</a> 的 IPv6 设计为例，考虑全部子网 ID。首先，所有子网使用常见的 /64 前缀长度。企业的全球路由前缀为 2001:0DB8:1111::/48，定义了所有子网 ID 的前 12 个十六进制数字。所有可能的 IPv6 子网前缀列表，涵盖子网 ID 字段内的全部二进制组合，本例中该字段是第四个四位组。同时，用 :: 表示最后四个 0000 四位组。<a href="#ch26fig08">图 26-8</a> 展示了这一列表的开头。</p>

<figure class="image-c" id="ch26fig08">

<img src="assets/volume1/part7-chapter26/images/vol1_26fig08.jpg" aria-describedby="a26fig08" alt="展示采用 16 位子网字段时前 16 个可能子网结构的图。">

<figcaption>

<h3 class="h3" id="ch26lev1sec4">唯一本地单播地址</h3>

<p class="noindent">唯一本地地址（ULA）充当私有 IPv6 单播地址。它们与全球单播地址有许多相似之处，尤其在子网划分方面。最大的<span id="page_665" data-epub-type="pagebreak"></span>差异在于数值本身（ULA 以十六进制 FD 开头）和管理过程：ULA 前缀不向任何号码管理机构注册，并且可由多个组织使用。</p>

<p class="noindent">虽然网络工程师创建唯一本地地址时不经过注册或分配过程，但地址仍需遵循以下规则：</p>

<ul class="sq">

<li><p class="bull">前两个十六进制数字使用 FD。</p>

</li>

<li><p class="bull">选择一个唯一的 40 位全球 ID。</p></li>

<li><p class="bull">将全球 ID 追加到 FD 后，形成 48 位前缀，作为所有地址的前缀。</p></li>

<li><p class="bull">将接下来的 16 位用作子网字段。</p></li>

<li><p class="bull">注意，这种结构留下了便于使用的 64 位接口 ID 字段。</p></li>

</ul>

<p class="noindent"><a href="#ch26fig11">图 26-11</a> 展示了这些唯一本地单播地址的格式。</p>

<h4 class="h4" id="ch26lev2sec6">使用唯一本地 IPv6 地址进行子网划分</h4>

<p class="noindent">假设从 48 位全球路由前缀开始，ULA 的子网划分方式与 GUA 相同。区别在于，GUA 的全球路由前缀及长度必须由外部分配，而 ULA 的前缀由你在本地创建，长度为 /48。</p>

<p class="noindent">要选择 48 位（12 个十六进制数字）的 ULA 前缀，先以 FD 开头，再通过随机数过程选择十个十六进制数字。按照 ULA RFC，应使用规定的伪随机算法确定全球 ID。在实验室练习时，可以直接编造一个数字。例如，假设选取十位十六进制值 00 0001 0001，再在前面加 FD，整个前缀就是 FD00:0001:0001::/48，缩写后为 FD00:1:1::/48。</p>

<p class="noindent">创建子网时，与前面使用 48 位全球路由前缀的示例一样，将整个第四个四位组作为子网 ID 字段，如 <a href="#ch26fig11">图 26-11</a> 所示。</p>

<p class="noindent"><a href="#ch26fig12">图 26-12</a> 展示了使用唯一本地地址的子网规划示例。它重复使用前面 <a href="#ch26fig09">图 26-9</a> 的拓扑，后者展示了全球单播前缀的子网划分。本例为第四个四位组的<span id="page_666" data-epub-type="pagebreak"></span>子网字段采用完全相同的数字，只将 48 位全球单播前缀替换为新的唯一本地前缀 FD00:1:1。</p>

<h4 class="h4" id="ch26lev2sec7">对全球唯一的本地地址的需求</h4>

<p class="noindent"><a href="#ch26fig12">图 26-12</a> 的示例使用易于记忆的前缀 FD00:1:1::/48。作者在此编造了一个容易记忆的全球 ID。你会为自己的企业选择什么全球 ID？会选择无法通过缩写来缩短的数字吗？如果必须从以下列表中为企业的 ULA 选择 IPv6 前缀，你会选哪一个？</p>

<ul class="sq">

<li><p class="bull"><code>FDE9:81BE:A059::/48</code></p></li>

<li><p class="bull"><code>FDF0:E1D2:C3B4::/48</code></p></li>

<li><p class="bull"><code>FD00:1:1::/48</code></p></li>

</ul>

<p class="noindent">如果可以自由选择，多数人会选易于记忆、输入简短的前缀，如 FD00:1:1::/48。在实验室或用于测试的小网络中，编造一个容易使用的数字是合理的。不过，在真实企业网络中，不应随意选择自己喜欢的全球 ID，而应遵守 ULA 规则，使 ULA 在全世界唯一，即使不向 ISP 或 RIR 注册前缀。</p>

<p class="noindent">RFC 4193 强调选择全球 ID 时，应使其在统计上不太可能被其他企业使用。每家企业都具有唯一全球 ID 的结果是什么？这会让所有 <a id="key_279" href="#ref-gloss_419"><span class="blue">ULA 全球 ID（ULA global IDs）</span></a> 在全球范围内唯一。因此，如果计划在真实网络中使用 ULA，应采用 RFC 4193 所列的随机数生成逻辑创建前缀。</p>

<p class="noindent">尽量使用唯一前缀，而不是让大家都用相同的易记前缀，一个主要原因是为企业将来合并或收购其他公司做好准备。如今，在 IPv4 中，很大比例的企业使用私有网络 10.0.0.0。合并网络时，双方都使用 10.0.0.0，会比使用不同私有 IPv4 网络带来更多困难。采用 IPv6 ULA 时，如果两家企业都正确地随机选择前缀，就极有可能使用完全不同的前缀，使合并简单得多。不过，那些看似图省事、选择 FD00:1:1 这类易记前缀的企业，在与同样选择该前缀的另一家公司合并时，需要付出额外工作的风险会大幅增加。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_160"><strong>全球路由前缀（global routing prefix）</strong> 定义由全球单播地址构成的 IPv6 地址块的前缀，分配给一个组织，使该组织获得一块全球唯一的 IPv6 地址用于其网络。</p>

<p class="gloss" id="ref-gloss_161"><strong>全球单播地址（global unicast address）</strong> 一种从公有、全球唯一的 IP 地址范围中分配的单播 IPv6 地址，通过 IANA/ICANN、其成员机构及其他注册机构或 ISP 注册。</p>

<p class="gloss" id="ref-gloss_194"><strong>接口 ID（Interface ID）</strong> IPv6 地址结构最末端（最右侧）的部分，通常长 64 位。</p>

<p class="gloss" id="ref-gloss_387"><strong>子网 ID（前缀 ID）</strong> <em>参见</em><a href="#ref-gloss_389">子网号</a>。</p>

<p class="gloss" id="ref-gloss_389"><strong>子网号</strong> 在 IPv4 中，代表某个子网全部地址的点分十进制数。从数值上说，它是子网数值范围中的最小值，已被保留，不能由主机用作单播 IP 地址。</p>

<p class="gloss" id="ref-gloss_391"><strong>子网前缀（subnet prefix）</strong> 表示 IPv6 子网的数字所用的术语。</p>

<p class="gloss" id="ref-gloss_392"><strong>子网路由器任播地址（subnet router anycast address）</strong> 每个 IPv6 子网中的特殊任播地址，保留给路由器使用，以便将数据包发送给子网上的任意一台路由器。其数值与该子网的子网 ID 相同。</p>

<p class="gloss" id="ref-gloss_419"><strong>ULA 全球 ID（ULA global ID）</strong> 一个组织的唯一本地地址（ULA）采用 /48 前缀，由前 8 位固定的十六进制 FD，以及十位十六进制数字（40 位）的全球 ID 构成；全球 ID 应由伪随机算法生成。</p>

<p class="gloss" id="ref-gloss_423"><strong>唯一本地地址（unique local address）</strong> 一种旨在替代 IPv4 私有地址的 IPv6 单播地址。</p>
