<h2 class="h2a">理解 REST 和 JSON</h2>

<p class="objset">本章涵盖以下考试主题：</p>

<p class="obj">6.0 自动化和可编程性</p>

<p class="obj1">6.5 描述基于 REST 的 API 的特征（CRUD、HTTP 动词和数据编码）</p>

<p class="obj1">6.7 识别 JSON 编码数据的组成部分</p>

<p class="noindent-c">为了实现网络自动化和可编程性，自动化软件会执行多项任务：分析以变量形式表示的数据，根据分析结果作出决策，然后可能采取行动，修改网络设备配置，或报告网络状态信息。</p>

<p class="noindent">不同的自动化功能位于不同设备上，包括网络工程师的设备、服务器、控制器，以及各种网络设备本身。要让这些相关的自动化过程良好协作，所有软件组件都需要实用且定义清晰的约定，使软件组件之间能够轻松通信。</p>

<p class="noindent">本章重点介绍使自动化软件能够通信的两种约定。第一大节讨论应用程序编程接口（API），特别是遵循表述性状态转移（REST）风格的 API。所有类型的 API 都为软件应用之间的通信提供途径，而 RESTful API（采用 REST 约定的 API）遵循一组特定的软件规则。如今，网络自动化中使用的许多 API 都基于 REST。</p>

<p class="noindent">本章后半部分讨论通过 API 交换的数据变量的约定和标准，重点介绍 JavaScript 对象表示法（JSON）。如果说 REST 为两个自动化程序如何通过网络通信提供了一种标准方法，那么 JSON 就定义了如何传递程序使用的变量，包括变量名称、值，以及这些变量的数据结构。</p>

<h3 class="h3" id="ch23lev1sec3">基于 REST 的 API</h3>

<p class="noindent">应用程序的使用<em>应用程序编程接口( API)</em>来交流。 为此,一个程序可以学习另一个程序使用的变量和数据结构,根据这些值进行逻辑选择,改变这些变量的值,创建新的变量,并删除变量. API允许在不同计算机上运行的程序合作工作,交换数据来达到某些目标.</p>

<p class="noindent">在一个API软件世界中,一些应用程序创建了API,其他许多应用程序使用(消耗)API. 软件开发者将API添加到他们的软件中,这样其他应用软件就可以利用第一个应用的功能.</p>

<p class="noindent">编写应用程序时,开发者会写出一些代码,但通常开发者可能会通过寻找能够提供数据和功能的API来做很多工作,减少必须写出的新代码的数量. 因此,许多现代软件开发中心都以了解和学习新的API为中心,还有现有的库(预先建造的软件可以用来完成任务而不是从零写出等同的东西).</p>

<p class="noindent">现有几种类型的API,每一种都有一套不同的公约来满足不同的需要。 CCNA蓝图提到了一种API——<a id="key_344" href="#ref-gloss_289"><span class="blue">国家转让(REST)</span></a>——因其在网络自动化应用中作为API类型而受欢迎. 这一章的第一主要章节更仔细地研究了基于REST的API.</p>

<section>

<h4 class="h4" id="ch23lev2sec1">基于 REST 的（RESTful）API</h4>

<p class="noindent"><a id="key_345" href="#ref-gloss_292"><span class="blue">REST API</span></a>遵循一套关于什么是REST API和什么是非的基础规则. 首先,从字面上看,REST APIs包括了几十年前由它的创造者罗伊·菲尔丁所定义的六个属性. (您可以在下列地点找到一个很好的摘要:<a href="https://restfulapi.net">https://restfulapi.net</a>) 这六个属性是:</p>

<ul class="sq">

<li><p class="bull"><span id="page_529" data-epub-type="pagebreak"></span>客户端/服务器架构</p></li>

<li><p class="bull">无国籍操作</p></li>

<li><p class="bull">可缓存/不可取的清晰语句</p></li>

<li><p class="bull">统一接口</p></li>

<li><p class="bull">已分层</p></li>

<li><p class="bull">随叫随到</p></li>

</ul>

<p class="noindent">这些属性的前三个得到一个REST API如何工作的核心. 您可以比较容易地看到这些前三个功能在与 REST API 网络工作时,所以接下来的几个段落进一步解释了前三个要点.</p>

<h5 class="h5" id="ch23lev3sec2"><span id="page_530" data-epub-type="pagebreak"></span>无状态运行</h5>

<p class="noindent">降温器<a id="key_346" href="#ref-gloss_335"><span class="blue">无国籍人</span></a>操作特性规定,REST服务器不保存任何先前REST请求或REST客户端的数据(状态信息). 使用REST,服务器不会保存一个响应(状态信息)中的信息,用于后期的请求和响应. 相反,REST客户端保留所有来自先前请求的状态数据,以选择未来REST需要做什么才能实现应用的目标.</p>

<p class="noindent">例如,想象一个维护产品数据库的REST服务器. 如果得到API的支持,REST客户端可以使用一个单项请求,列出一份重量低于5磅的产品清单. REST服务器不会记得客户端提出的第一个REST请求,或者在早先的请求中返回的数据. 因此,当客户端随后发出API呼叫时,它不能要求服务器根据先前请求的数据来进行这些未来回复. 相反,客户端必须在以后的每一个请求中提供任何数据,这样每个REST请求都是自成一体的,不需要服务器的状态信息.</p>

</section>

<section>

<h5 class="h5" id="ch23lev3sec3">可缓存（或不可缓存）</h5>

<p class="noindent">欣赏什么<a id="key_335" href="#ref-gloss_057"><span class="blue">可缓存</span></a>意味着,考虑浏览网站时会发生什么. 当您的浏览器加载到一个新的网页时,该页面本身包含各种对象(文本,图像,视频,音频). 有些对象很少改变,因此最好一次下载对象而不再下载;在这种情况下,服务器会标记该对象为可缓存. 例如,一个网站的许多页上显示的标志或其他图像几乎永远不会改变,很可能是可缓存的。 然而,在您最近搜索网站时返回的产品列表将不会被缓存,因为服务器每次请求页面时都会想更新并提供新的列表.</p>

<p class="noindent">REST APIs要求通过API调用请求的任何资源必须有明确的方法标记资源是否可缓存. 目标保持不变:通过减少资源回收次数(可兑现)来提高业绩。 注意可缓存资源被标记为时间段,以便客户端知道何时再次要求获得新的资源副本.</p>

<h4 class="h4" id="ch23lev2sec3"><span id="page_533" data-epub-type="pagebreak"></span>REST API 与 HTTP</h4>

<p class="noindent">API的存在允许两个程序交换数据. 一些API可能被设计为运行在同一台计算机上的程序之间的接口,因此程序之间的通信发生在一个单一的操作系统内. 许多API需要提供给运行在其他计算机上的程序,因此API必须定义由API支持的网络协议类型——许多基于REST的API使用HTTP协议.</p>

<p class="noindent">基于REST的API的创建者经常选择HTTP,因为HTTP的逻辑与一些为REST API更一般地定义的概念相匹配. HTTP使用与REST相同的原理:它使用客户端/服务器模型运行;它使用无国籍的操作模型;它包括了明确将对象标记为可缓存或不可缓存的首部. 它还包括动词——指对一对HTTP请求和响应消息的所期望的行动的用词——它与应用程序喜欢的工作方式相匹配.</p>

<p class="noindent">本节将一些编程术语的基本内容,该词如何与HTTP动词相匹配,以及REST API如何使用统一资源识别符(URIs)来指定从RESTful API调用中想要的数据.</p>

<section>

<h5 class="h5" id="ch23lev3sec6">软件 CRUD 操作与 HTTP 动词</h5>

<p class="noindent">软件行业使用一个令人难忘的缩写——<a id="key_336" href="#ref-gloss_099"><span class="blue">CRUD</span></a>申请的四项主要行动。 这些行动是:</p>

<p class="ul-noindent"><strong>创建 :</strong>允许客户端在服务器上创建一些变量和数据结构的新实例并初始化其保存在服务器上的值</p>

<p class="ul-noindent"><strong>读取:</strong>允许客户端检索(读取)服务器上存在的变量的当前值,在客户端存储变量、结构和值的副本</p>

<p class="ul-noindent"><strong>更新 :</strong>允许客户端更改( 更新) 服务器上存在的变量值</p>

<p class="ul-noindent"><strong>删除:</strong>允许客户端从服务器上删除不同的数据变量实例</p>

<p class="noindent">例如,如果使用思科DNA中心或催化中心控制器的北行REST API,如本文所述。<a href="v2-22.html#ch22">第22章</a>, “<a href="v2-22.html#ch22">Cisco 软件定义接入（Cisco SD-Access）</a>,”你也许想创造一些新的东西,比如新的安全政策。 从编程的角度来看,安全政策作为控制器上相关的一组配置设置存在,内部以变量为代表. 要做到这一点,用户会利用兼容的REST API客户端应用程序,如Postman. 一旦用户建立了客户端应用程序,并采用了与催化中心控制器进行通信所需的适当HTTP方法,便会发出RESTful API呼叫,以便在控制器上"创建"一个代表前述安全政策的新变量. 使用 CRUD 缩略语的 Creat 函数执行控制器上构建的可变或安全政策。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">思科使用思科DNA中心控制器产品名称多年. 2023年,思科将产品重新命名为"思科催化剂中心"控制器. 然而,鉴于大量文件提到旧名并缩写为DNA和DNAC,本章继续将控制器指为DNA中心控制器.</p>

<p class="noindent">为了将一些REST API概念拉到一起,接下来的几页通过几个样本API调用一个名为API开发环境工具的软件应用程序.</p>

<p class="noindent">对于一点开发视角,在努力实现你网络操作任务的某些部分自动化时,你最终会使用一个让API调用的程序. 然而,在开发应用程序的初期,你可能首先关注API提供的数据,并首先忽略所有编程细节. API 开发环境允许您<span id="page_537" data-epub-type="pagebreak"></span>关注API的呼叫。 后来,同一种工具一般可以生成正确的代码,可以复制到您的程序中,让API调用.</p>

<p class="noindent">本节中的例子使用名为Postman的应用程序. Postman可免费下载( Postman) 。<a href="http://www.postman.co">www.postman.co</a>)并按本节所示使用。 注意Cisco DevNet在其众多实验室和实例中广泛使用Postman.</p>

<p class="noindent">在利用API与任何软件平台,应用程序或控制器进行通信时,重要的是要思考你正在试图实现什么——例如,如果你想使用API呼叫Cisco Catalyst Center来拉出控制器内设备的盘点.</p>

<p class="noindent">考虑给目标应用程序或控制器做任何 API 呼叫,就像连接到您网络环境中的任何其他设备一样. 要访问软件应用程序或控制器,必须采取一个重要步骤,即认证。 与这些平台在程序上的互动 与您登录到 CLI 的路由器并在您的证书中输入没有区别 。 这意味着您必须首先通过 API 认证您想要连接的设备 。 但是,这一规则也有例外;如果软件没有担保,在被操纵之前可能不需要认证。 这是非常罕见的,而且通常在任何能够改变你网络环境的东西上都看不到.</p>

<p class="noindent">API有许多不同的认证方法,如API密钥,JSON Web Token(JWT),TLS/SSL客户端证书,基本认证,Java会话ID或cookie等. 以思科催化中心为例, 让我们看看认证文件或标志性API,</p>

<h3 class="h3" id="ch23lev1sec4">数据序列化与 JSON</h3>

<p class="noindent">在你成为拥有网络自动化技能的现代网络工程师的旅程中,你会学会理解几个<a id="key_337" href="#ref-gloss_101"><span class="blue">数据序列化语言</span></a>。每个数据序列化语言都提供了使用文本描述变量的方法,目的是能够发送<span id="page_542" data-epub-type="pagebreak"></span>在网络上保存文本, 或者在文件中保存文本 。 数据序列化语言给了我们一种用文字来表示变量的方法,而不是任何特定编程语言所使用的内部表示.</p>

<p class="noindent">每个数据序列化语言都使API服务器能够返回数据,使API客户端可以复制API服务器上发现的同一种变量名称和数据结构. 为了描述数据结构,数据序列化语言包括特别的字符和常规来交流关于列表变量,字典变量以及其他更复杂的数据结构的想法.</p>

<p class="noindent">本章的第二大节审查了数据序列化语言的概念,重点是目前CCNA蓝图中提到的一种数据建模语言:<a id="key_339" href="#ref-gloss_187"><span class="blue">JavaScript 对象标记( JSON)</span></a>.</p>

<h5 class="h5" id="ch23lev3sec9">XML</h5>

<p class="noindent">早在20世纪90年代,当网页浏览器和万维网(WWW)首次创建时,网页主要使用Hypertext Markup Language(HTML)来定义网页. 作为标记语言,HTML定义了如何在文件中添加文本或网页,然后添加"标记"-附加文本来表示应当显示的文本的格式细节. 例如,标记包括标题、字体类型、大小、颜色、超链接等的代码。</p>

<p class="noindent">密码<a id="key_349" href="#ref-gloss_382"><span class="blue">eXtensible 标记语言( XML)</span></a>后来来为早期的加分语言做一些改进. 特别是随着时间的推移,网页变得越来越有活力,为了让网页充满活力,需要存储其值可以随时间变化并被网络服务器所取代的变量的文件. 为了确定可被替换成网页的变量,世界需要一种可以定义数据变量的标记语言。 XML定义了一种标记语言,它具有许多特性来定义变量,值和数据结构.</p>

<p class="noindent">随着时间的推移,XML已经发展出超越了它作为标记语言的原始使用. XML的特性也使它成为有用的一般数据序列化语言,它今天被这样使用.</p>

<p class="noindent"><span id="page_545" data-epub-type="pagebreak"></span>在牢记人类可读性的同时,XML的创造者选择较少强调人类可读性(与JSON相比),以获得更好的计算机处理功能. 例如,与 HTML 一样, XML 对每个变量使用起始和结尾标记, 如<a href="#exa23_4">示例23-4</a>。在示例中突出显示的行中,"macAddress"和"/macAddress"标记表示一个变量名称,值位于标记之间.</p>

<h5 class="h5" id="ch23lev3sec12">解读 JSON 键值对</h5>

<p class="noindent">首先,考虑JSON中关于键:值对的规则,你可以把它看作是单个变量名称及其值:</p>

<ul class="sq">

<li><p class="bull"><strong>密钥: 值对等 :</strong>每个冒号都识别出一个键:值对,在冒号前有键,在冒口后有值.</p></li>

<li><p class="bull"><strong>键 :</strong>文本 在双引号内,在冒号前,作为引用一个值的名称.</p></li>

<li><p class="bull"><strong>数值 :</strong>代表密钥值的冒号后的项目,可以是</p>

<ul class="sq-i">

<li><p class="bull"><strong>文本 :</strong>以双引出为上.</p></li>

<li><p class="bull"><strong>数字 :</strong>所列而无引相.</p></li>

<li><p class="bull"><strong>矩阵 :</strong>一个特殊值(更多细节稍后).</p></li>

<li><p class="bull"><strong>对象 :</strong>一个特殊值(更多细节稍后).</p></li>

</ul></li>

<li><p class="bull"><strong>多个对等 :</strong>在列出多键:值对时,将每对的末端有逗号的对相分离出(最后一对除外).</p></li>

</ul>

<p class="noindent">为了执行其中一些规则,考虑:<a href="#exa23_7">示例23-7</a>JSON的数据,专注于三把钥匙:值对. 示例后的案文提供了分析.</p>

<p class="ex-caption" id="exa23_7"><strong>示例23-7</strong> <em>1 JSON 对象( 字典) 有 三键: 等价对等</em></p>

<div class="ex-box">

<pre class="pre-ex" tabindex="0"><code>{

    "1stbest": "Messi",

    "2ndbest": "Ronaldo",

    "3rdbest": "Maradona"

}</code></pre>

</div>

<p class="noindent">作为一个方法,只要找到每个冒号, 并寻找引用的字符串 就在每个冒号之前。 这些是“最佳”、“最佳”、“最佳”和“最佳3”键。 )然后看每个分号找到相配值的权利。 您可以知道所有三个值都是文本值,因为 JSON 在双引号中列出了这些值.</p>

<p class="noindent">至于其他特殊字符,请注意逗号和卷括号. 前两个键: 值对以逗号结尾,意思是另一个键:值对应该跟随. 开始和结束JSON数据的花括号表示一个单独的JSON对象(一对花括号,所以一个对象). 通过一个API交换的JSON文件和JSON数据首先作为JSON对象存在,并显示一个开口(左)和收尾(右)曲括号.</p>

<h5 class="h5" id="ch23lev3sec13">解读 JSON 对象与数组</h5>

<p class="noindent">要将数据结构传播到一个键之外: 值对和一个简单的值, JSON 使用<a id="key_341" href="#ref-gloss_189"><span class="blue">JSON 对象</span></a>和<a id="key_340" href="#ref-gloss_188"><span class="blue">JSON 数组</span></a>。对象可以有一定的灵活性,但在大多数用途中,它们表现得像字典. 阵列列出一系列的值.</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para"><span id="page_548" data-epub-type="pagebreak"></span>Python是网络自动化最常用的语言,将JSON对象转换为Python字典,而JSON 数组则转换为Phython列表. 对于一般对话,许多人将JSON结构称为字典和列表,而不是对象和阵列.</p>

</div>

<p class="noindent">首先, 考虑这组规则如何解释 JSON 对象和数组的语法 :</p>

<ul class="sq">

<li><p class="bull"><strong>{ 目标 :</strong>一系列密钥:用相匹配的一对花括号内嵌入相匹配的值对,并有开口的左花括号及其相匹配的右花括号.</p></li>

<li><p class="bull"><strong>[ ]——箭头:</strong>将一系列值(不是按键:值对)放在一对相配的方括号内,并有一个开口的左平方括号及其相配的右平方括号.</p></li>

<li><p class="bull"><strong>密钥: 对象内值对 :</strong>所有键:对象内部的值对都符合之前的键:值对的规则.</p></li>

<li><p class="bull"><strong>数组中的值 :</strong>所有值都符合之前格式化值的规则(例如,双引出围绕文本,不引出围绕数字).</p></li>

</ul>

<h5 class="h5" id="ch23lev3sec14">压缩格式与美化格式的 JSON</h5>

<p class="noindent">到目前为止,所有JSON的例子都显示了大量的空地. JSON根据您的需要允许白空间,或不允许白空间. 对于人类来说,用有空间和对齐的文字来读取JSON可以容易得多. 例如,把相匹配的开口和收尾括号放在同一个左下方就更容易找到哪个括号。</p>

<p class="noindent">当存储在文件中或发送到网络中时,JSON不使用白空间. 例如,本节早些时候,<a href="#exa23_7">示例23-7</a>显示一个 JSON 对象,有三把钥匙:值对,有白空间,取出五行. 然而,存储在一个文件中,或者通过一个网络发送,JSON会看起来像如下:</p>

<p class="codelink"><a href="#code-f0550-01" id="f0550-01a">点击此处查看代码原图</a></p>

<pre class="pre" tabindex="0"><code>{"1stbest": "Messi", "2ndbest": "Ronaldo", "3rdbest": "Maradona"}</code></pre>

<p class="noindent">在与 JSON 合作时, 你可能使用的大多数工具都会让您从一个漂亮的格式( 对人类好) 切换到原始格式( 计算机好) 。 你可能会看到美丽的版本 字面上叫<em>美化</em>或者说<em>美化后的</em>或者说<em>带空白间隔的</em>,而没有额外空白的版本可能会被调用<em>最简化的</em>或者说<em>原始</em>.</p>
