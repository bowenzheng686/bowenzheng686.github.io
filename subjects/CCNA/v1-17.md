<p class="noindent-c">路由器路由 IPv4 数据包。这句简单的话实际上包含许多隐含意义。为了路由数据包，路由器遵循一个路由过程，而该过程依赖于称为 IP 路由的信息。每条 IP 路由都列出一个目的地，即 IP 网络、IP 子网或其他某组 IP 地址。每条路由还列出指示，告诉路由器应将发往该 IP 网络或子网中地址的数据包转发到哪里。为了正确完成数据包路由，路由器需要一份详细且准确的 IP 路由列表。</p>

<p class="noindent">路由器通过三种方法向 IPv4 路由表添加 IPv4 路由。首先学习<a id="key_195" href="#ref-gloss_077"><span class="blue">直连路由</span></a>，即连接在路由器接口上的子网的路由。路由器也可以使用<a id="key_203" href="#ref-gloss_378"><span class="blue">静态路由</span></a>，通过配置命令（<strong>ip route</strong>）创建，告诉路由器应在 IPv4 <a id="key_202" href="#ref-gloss_354"><span class="blue">路由表</span></a>中放入哪条路由。另外，路由器还可以<span id="page_427" data-epub-type="pagebreak"></span>使用路由协议，彼此通告已知的所有路由，让所有路由器都能学习并建立通往各网络和子网的动态路由。</p>

<p class="noindent">本章通过可添加到路由器路由表中的最简单路由，深入研究 IP 路由。首先详细分析 IP 数据包的路由（转发）过程，该过程依赖每台路由器的路由表中都具有可用的 IP 路由。第二节研究直连路由，即通往本地路由器接口所连接子网的路由。第三节研究静态路由，即网络工程师直接配置的路由。</p>

<h3 class="h3" id="ch17lev1sec3">IP 路由</h3>

<p class="noindent">IP 路由，即转发 IP 数据包的过程，将数据包从最初构造它的设备，经由整个 TCP/IP 网络，送达应当接收它的设备。换言之，IP 路由将 IP 数据包从发送主机送达目的主机。</p>

<p class="noindent">完整的端到端路由过程依赖于主机和路由器上的网络层逻辑。发送主机使用第 3 层概念创建 IP 数据包，并将其转发到主机的默认网关（默认路由器）。这个过程也需要路由器上的第 3 层逻辑：路由器将数据包中的目的地址与路由表比较，以决定下一步将 IP 数据包转发到哪里。</p>

<p class="noindent">路由过程还依赖各条链路的数据链路层和物理层细节。IP 路由依赖串行 WAN 链路、以太网 WAN 链路、以太网 LAN、无线 LAN，以及许多实现数据链路层和物理层标准的其他网络。这些低层设备和协议通过将 IP 数据包封装在数据链路层帧中并发送，使其在 TCP/IP 网络中传递。</p>

<p class="noindent">前两段汇总了<a href="v1-03.html#ch03">第 3 章</a>“<a href="v1-03.html#ch03">WAN 与 IP 路由基础</a>”介绍的 IP 路由关键概念。接下来，本节将回顾 IP 路由，并利用此前各章深入介绍的知识，将讨论进一步推进。</p>

<section>

<h4 class="h4" id="ch17lev2sec1"><span id="page_429" data-epub-type="pagebreak"></span>IPv4 路由过程参考</h4>

<p class="noindent">由于你已经在<a href="v1-03.html#ch03">第 3 章</a>学习了基础知识，本节将路由过程整理成步骤供参考。这些步骤使用本书<a href="v1-04.html#part02">第二部分</a>和<a href="v1-08.html#part03">第三部分</a>讨论的许多具体以太网 LAN 术语，以及<a href="v1-11.html#part04">第四部分</a>讨论的一些 IP 编址术语。后续说明和示例会进一步讨论这些路由逻辑概要，确保每个步骤都清楚易懂。</p>

<p class="noindent">路由过程从创建 IP 数据包的主机开始。首先，主机会判断：这个新数据包的目的 IP 地址是否位于我的本地子网？主机使用自己的 IP 地址／掩码，确定本地子网的地址范围。根据主机自身认定的本地子网地址范围，LAN 主机会执行以下操作：</p>

<p class="step"><span class="stepb">步骤 1。</span>如果目的地在本地，直接发送：</p>

<ol class="step-lower-alpha">

<li><p class="alpha">查找目的主机的 MAC 地址。使用已有的地址解析协议（ARP）表项，或者通过 ARP 消息学习该信息。</p></li>

<li><p class="alpha">将 IP 数据包封装在数据链路帧中，目的数据链路地址设为目的主机的地址。</p></li>

</ol>

<p class="step"><span class="stepb">步骤 2。</span>如果目的地不在本地，发送给默认网关：</p>

<ol class="step-lower-alpha">

<li><p class="alpha">查找默认网关的 MAC 地址。使用已有的地址解析协议（ARP）表项，或者通过 ARP 消息学习该信息。</p></li>

<li><p class="alpha">将 IP 数据包封装在数据链路帧中，目的数据链路地址设为默认网关的地址。</p></li>

</ol>

<p class="noindent"><a href="#ch17fig01">图 17-1</a> 汇总了这些概念。图中，主机 A 将本地数据包直接发给主机 D。但对于发往路由器另一侧、因而属于不同子网的主机 B 的数据包，主机 A 会将其发给默认路由器 R1。（提醒一下，<em>默认网关</em>与<em>默认路由器</em>是同义词。）</p>

<figure class="image-c" id="ch17fig01">

<img src="assets/volume1/part5-chapter17/images/vol1_17fig01.jpg" aria-describedby="a17fig01" alt="展示主机路由过程概要的示意图。">

<figcaption>

<p class="title-f"><strong>图 17-1</strong> <em>主机路由逻辑概要</em></p>

<aside class="hidden" id="a17fig01">

<p>示意图中，代表主机 A 的 PC 通过 SW1，将本地数据包发给代表主机 D 的另一台 PC。主机 A 又通过 SW1 将数据包发给远程路由器 R1，R1 再将数据包发给路由器另一侧的主机 B。</p>

</aside>

</figcaption>

</figure>

<p class="noindent">与主机相比，路由器需要完成更多路由工作。主机逻辑从内存中已有的 IP 数据包开始，而路由器在到达这一阶段之前，还要执行一些操作。在下面的路由器路由逻辑五步概要中，前两步只是接收帧并提取 IP 数据包，到步骤 3 才考虑数据包的目的地址。步骤如下：</p>

<span id="page_430" data-epub-type="pagebreak"></span>

<ol class="number">

<li><p class="number">对于每个收到的数据链路帧，决定是否处理它。符合以下条件时进行处理：</p>

<ol class="lower-alpha">

<li><p class="alpha">帧没有错误，以数据链路尾部的帧校验序列（FCS）字段为依据。</p></li>

<li><p class="alpha">帧的目的数据链路地址是路由器的地址，或合适的组播或广播地址。</p></li>

</ol></li>

<li><p class="number">如果步骤 1 决定处理该帧，则从数据链路帧中解封装出数据包。</p></li>

<li><p class="number">做出路由决策。为此，将数据包的目的 IP 地址与路由表比较，找到匹配目的地址的路由。该路由指出路由器的<a id="key_201" href="#ref-gloss_294"><span class="blue">出接口</span></a>，也可能指出<a id="key_200" href="#ref-gloss_282"><span class="blue">下一跳路由器</span></a>。</p></li>

<li><p class="number">将数据包封装成适合出接口的数据链路帧。通过 LAN 接口转发时，根据需要使用 ARP 查找下一个设备的 MAC 地址。</p></li>

<li><p class="number">通过匹配的 IP 路由所列出的出接口发送该帧。</p></li>

</ol>

<p class="noindent">这份路由过程概要列出了许多细节，但有时可以更简单地理解路由过程。例如，省略一些细节后，可用下面这段话表达相同的主要概念：</p>

<p class="ul-noindent">路由器接收帧，从帧中取出数据包，决定将数据包转发到哪里，将数据包放进另一个帧，再发送该帧。</p>

<p class="noindent">为帮助你进一步理解这些步骤，<a href="#ch17fig02">图 17-2</a> 以图示形式拆解了相同的五步路由过程。图中数据包从左侧到达，进入路由器的以太网接口，其 IP 目的地为主机 C。到达的数据包封装在以太网帧内，包含帧头和帧尾。</p>

<figure class="image-c" id="ch17fig02">

<img src="assets/volume1/part5-chapter17/images/vol1_17fig02.jpg" aria-describedby="a17fig02" alt="用五个步骤概述路由器路由过程的示意图。">

<figcaption>

<p class="title-f"><strong>图 17-2</strong> <em>路由器路由逻辑概要</em></p>

<aside class="hidden" id="a17fig02">

<p>步骤 1 显示路由器 R1 确认收到的以太网帧通过 FCS（以太网帧尾）检查，包含数据的 IP 数据包从以太网帧头和帧尾内部通过。步骤 2 解封装 IP 数据包。步骤 3 在路由表中比较 IP 数据包。步骤 4 将 IP 数据包封装在新的数据链路帧头和帧尾内部。步骤 5 向右发送 IP 数据包。</p>

</aside>

</figcaption>

</figure>

<p class="noindent"><span id="page_431" data-epub-type="pagebreak"></span>路由器 R1 按图中编号处理帧和数据包，与图前介绍的五步过程相对应，具体如下：</p>

<ol class="number">

<li><p class="number">路由器 R1 确认收到的以太网帧通过 FCS 检查，且目的以太网 MAC 地址为 R1 的 MAC 地址，因此处理该帧。</p></li>

<li><p class="number">R1 从以太网帧头和帧尾内部解封装出 IP 数据包。</p></li>

<li><p class="number">R1 将 IP 数据包的目的 IP 地址与自己的 IP 路由表比较。</p></li>

<li><p class="number">R1 将 IP 数据包封装进新的数据链路帧；本例中是封装进高级数据链路控制（HDLC）的帧头和帧尾之间。</p></li>

<li><p class="number">R1 将封装在新 HDLC 帧内的 IP 数据包，通过右侧串行链路发送出去。</p></li>

</ol>

<h4 class="h4" id="ch17lev2sec2">IP 路由示例</h4>

<p class="noindent">接下来的几页将通过一个示例，按顺序讨论数据经过多台设备时的每个路由步骤。示例中，主机 A（172.16.1.9）向主机 B（172.16.2.9）发送数据包，并通过主机路由逻辑及五个步骤，展示 R1 如何转发该数据包。</p>

<section>

<h5 class="h5" id="ch17lev3sec2">路由步骤 1：决定是否处理收到的帧</h5>

<p class="noindent">路由器会在接口上接收许多帧，尤其是在 LAN 接口上。不过，路由器可以且应该忽略其中一些帧。因此，路由过程的第一步，是决定应该处理该帧，还是静默丢弃（忽略）它。</p>

<p class="noindent">首先，路由器执行一个简单但重要的检查（过程概要中的步骤 1A），以忽略传输过程中发生比特错误的所有帧。路由器使用数据链路帧尾的 FCS 字段检查帧，如果传输中发生错误，就丢弃该帧。（路由器不会尝试错误恢复，也就是说，不会要求发送方重新传输数据。）</p>

<p class="noindent">路由器还会检查目的数据链路地址（概要中的步骤 1B），以判断该帧是否发给自己。例如，发送到路由器该接口单播 MAC 地址的帧，显然是发给该路由器的。不过，路由器实际上也可能收到发往其他单播 MAC 地址的帧，它应该忽略这些帧。</p>

<p class="noindent">例如，回想 LAN 交换机如何转发未知单播帧，即目的 MAC 地址未列在交换机 MAC 地址表中的帧。LAN 交换机会泛洪这些帧。结果是什么？路由器有时会收到发往<span id="page_433" data-epub-type="pagebreak"></span>其他设备的帧，其中目的 MAC 地址是其他设备的 MAC 地址。路由器应该忽略这些帧。</p>

<p class="noindent"><a href="#ch17fig05">图 17-5</a> 展示了一个正常工作的示例，主机 A 发送目的地址为 R1 的 MAC 地址的帧。收到帧后，R1 通过 FCS 确认没有错误，并确认帧发往自己的 MAC 地址（本例为 0200.0101.0101）。所有检查均通过，因此 R1 将处理该帧。（请注意，图中的大矩形代表路由器 R1 的内部。）</p>

<h5 class="h5" id="ch17lev3sec4">路由步骤 3：选择数据包的转发方向</h5>

<p class="noindent">路由步骤 2 几乎不需要思考，而步骤 3 是所有步骤中需要最多判断的一步。此时，路由器需要选择接下来将数据包转发到哪里。这一过程使用路由器的 IP 路由表，并通过匹配逻辑，将数据包的目的地址与表中内容比较。</p>

<p class="noindent">首先，IP 路由表列出多条路由。每条路由包含若干信息，又可按<a href="#ch17fig07">图 17-7</a> 所示方式分组。每条路由的一部分用于匹配数据包的目的地址，其余部分列出转发指示，即下一步将数据包发到哪里。</p>

<figure class="image-c" id="ch17fig07">

<p class="noindent">接下来，查看这五条路由中 R1 用于匹配数据包的部分。为了完整定义各个子网，每条路由同时列出子网 ID 和子网掩码。将 IP 数据包目的地与路由表匹配时，路由器查看数据包的目的 IP 地址（172.16.2.9），并将它与每个子网定义的地址范围比较。具体而言，路由器查看子网和掩码信息，经过少量计算，就能确定 172.16.2.9 位于哪个子网中，即子网 172.16.2.0/24 对应的路由。</p>

<p class="noindent">最后，查看图右侧这五条路由的转发指示。匹配到具体路由后，路由器使用其中的转发信息，决定下一步将数据包发到哪里。本例中，匹配到子网 172.16.2.0/24 的路由，因此 R1 将从自己的 S0/0/0 接口转发数据包，下一站是路由器 R2，其下一跳路由器 IP 地址列为 172.16.4.2。</p>

<p class="note-para">远程子网的路由通常同时列出出接口和下一跳路由器 IP 地址。直接连接到路由器的子网路由只列出出接口，因为发往这些目的地的数据包无需交给另一台路由器。</p>

<h5 class="h5" id="ch17lev3sec5">路由步骤 4：将数据包封装在新帧中</h5>

<p class="noindent">此时，路由器已经知道如何转发数据包。不过，在转发之前，必须先为数据包加上数据链路帧头和帧尾，即进行封装。</p>

<h3 class="h3" id="ch17lev1sec4">配置 IP 地址和直连路由</h3>

<p class="noindent">Cisco 路由器默认全局启用 IPv4 路由。要使路由器能够在某个特定接口上路由数据包，必须为接口配置 IP 地址，并进行适当配置使接口启动，达到“线路状态 up、线路协议状态 up”。只有达到这一状态，路由器才能通过该接口收发并路由 IP 数据包。</p>

<p class="noindent">当路由器能够通过一个或多个接口路由 IP 数据包后，还需要一些路由。路由器可以通过三种方式向路由表添加路由：</p>

<p class="ul-noindent"><strong>直连路由：</strong>由于在本地路由器上配置 <strong>ip address</strong> 接口子命令而添加。</p>

<p class="ul-noindent"><span id="page_436" data-epub-type="pagebreak"></span><strong>静态路由：</strong>由于在本地路由器上配置 <strong>ip route</strong> 全局命令而添加。</p>

<p class="ul-noindent"><strong>路由协议：</strong>通过在所有路由器上配置来添加这一功能，使路由器动态向彼此通告网络信息，从而让所有路由器学习路由。</p>

<p class="noindent">本章三个主要部分中的第二部分，将讨论配置直连路由的几种方式，下一部分则讨论静态路由。</p>

<section>

<h4 class="h4" id="ch17lev2sec3">直连路由与 ip address 命令</h4>

<p class="noindent">假设以下两个条件成立，Cisco 路由器会自动向路由表添加每个接口所连接子网的路由：</p>

<ul class="sq">

<li><p class="bull">接口处于工作状态。也就是说，<strong>show interfaces</strong> 命令中的接口状态显示线路状态为 up，协议状态也为 up。</p></li>

<li><p class="bull">接口通过 <strong>ip address</strong> 接口子命令分配了 IP 地址。</p></li>

</ul>

<p class="noindent">直连路由的概念相当基础。路由器当然需要知道每个接口所连接的子网号，才能将数据包路由到该子网。路由器会使用接口 IP 地址和掩码进行计算，求出子网 ID。不过，只有接口启动并正常工作时，路由器才需要该路由，因此只有在接口正常工作时，才会在路由表中加入直连路由。</p>

<p class="noindent"><a href="#exa17_1">例 17-1</a> 展示了<a href="#ch17fig10">图 17-10</a> 中路由器 R1 的直连路由。示例第一部分展示 R1 三个接口的 IP 地址配置。示例末尾列出 <strong>show ip route</strong> 命令输出，其中这些路由的代码为 C，表示<em>直连</em>。</p>

<p class="noindent">每次做实验或看到 <strong>show ip route</strong> 命令输出示例时，都要仔细查看各个有类网络的标题行及其后缩进的行。缩进行列出通往具体子网的路由。在<a href="#exa17_1">例 17-1</a> 中，标题行将 B 类网络 172.16.0.0 显示为“172.16.0.0/16”，其中 /16 表示 B 类网络的默认掩码。为什么？因为 IOS 按 A 类、B 类或 C 类网络对输出分组。本例中的标题行告诉我们，后面的缩进行都与网络 172.16.0.0/16 有关。</p>

<p class="noindent">请仔细看 B 类网络 172.16.0.0 标题行下方高亮的三条路由。每条的第一列都是 C，并且都带有“directly connected”文字，两者都表明该路由与路由器直连。每条路由的前半部分列出匹配参数，即子网 ID 和掩码，与前面<a href="#ch17fig07">图 17-7</a> 的示例相同。每条路由的末尾列出出接口。</p>

<p class="noindent"><span id="page_438" data-epub-type="pagebreak"></span>请注意，路由器还会自动生成另一类路由，称为<em>本地路由</em>。本地路由为路由器接口上配置的那个具体 IP 地址定义路由。每条本地路由的前缀长度都是 /32，构成一条<em>主机路由</em>，即只针对单个 IP 地址的路由。例如，最后一条 172.16.5.1/32 的本地路由，只匹配 IP 地址 172.16.5.1。路由器使用这些列出自身本地 IP 地址的路由，更高效地处理发给路由器自己的数据包。</p>

<p class="noindent">示例中的 <strong>show ip route</strong> 命令展示了考试主题 3.1 的几个具体子项（依据 CCNA 200-301 V1.1），本章后续示例会展示更多细节。本节说明了考试主题中的以下术语：</p>

<ul class="sq">

<li><p class="bull"><strong>前缀：</strong><em>前缀</em>（考试主题 3.1.b）只是子网 ID 的另一种名称。</p></li>

<li><p class="bull"><strong>掩码：</strong>每条路由都列出前缀（子网 ID）和网络掩码（考试主题 3.1.c），掩码使用前缀格式，例如 /24。</p></li>

</ul>

<h4 class="h4" id="ch17lev2sec5">Cisco 路由器上的 ARP 表</h4>

<p class="noindent">添加这些直连路由后，路由器就可以在这些子网之间路由 IPv4 数据包。为此，路由器会使用自己的 IP ARP 表。</p>

<p class="noindent"><span id="page_440" data-epub-type="pagebreak"></span>IPv4 <a id="key_194" href="#ref-gloss_026"><span class="blue">ARP 表</span></a>列出与路由器连接到同一子网的主机的 IPv4 地址及对应 MAC 地址。向同一子网中的主机转发数据包时，路由器会使用从 ARP 表中查到的目的 MAC 地址进行封装。如果路由器要将数据包转发到同一子网中的某个 IP 地址，却找不到该地址的 ARP 表项，就会使用 ARP 消息学习该设备的 MAC 地址。</p>

<p class="noindent"><a href="#exa17_4">例 17-4</a> 根据前面的示例展示 R1 的 ARP 表。输出列出 R1 自己的 IP 地址 172.16.1.1，老化时间为 -，表示该表项不会超时。动态学习的 ARP 表项具有向上计数的计时器，例如 IP 地址 172.16.1.9 的表项显示 35 分钟。默认情况下，ARP 表项连续 240 分钟未使用，IOS 就会使其超时并删除。（使用表项时，IOS 会将计时器重置为 0。）请注意，做实验时，你可能希望用 <strong>clear ip arp</strong> [<em>ip-address</em>] EXEC 命令清空所有动态表项，或仅清除某个 IP 地址的表项。</p>

<h3 class="h3" id="ch17lev1sec5">配置静态路由</h3>

<p class="noindent">在真实网络中，每台路由器都有直连路由，由路由器为接口连接的子网创建。你会使用 OSPF 和 EIGRP 等动态路由协议，学习企业中其他子网的路由，即相对于本地路由器而言的远程子网路由。</p>

<p class="noindent">企业使用静态路由，即通过直接配置 <strong>ip route</strong> 命令加入路由表的路由，其频率远低于直连路由和动态路由协议学习的路由。不过，静态路由有时很有用，研究静态路由也是非常好的学习方法。当然，考试主题列出了多种静态路由，因此备考时需要掌握。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">CCNA 200-301 V1.1 考试的主题 3.3，将 IPv4（以及 IPv6）静态路由细分为四个子主题：网络路由、默认路由、主机路由和浮动静态路由。本节将按照后续标题，解释 IPv4 中的这四种类型。</p>

</div>

<h4 class="h4" id="ch17lev2sec6"><span id="page_441" data-epub-type="pagebreak"></span>静态网络路由</h4>

<p class="noindent">虽然路由是静态配置的，IOS 仍会随着出接口工作状态的变化，在路由表中添加或删除静态路由。例如，本例中如果 R1 的 G0/0/0 接口发生故障，R1 会从 IPv4 路由表中删除 172.16.2.0/24 的静态路由。之后接口恢复时，IOS 会将该路由重新加入路由表。</p>

<p class="noindent"><a href="#exa17_3">例 17-3</a> 和<a href="#exa17_4">例 17-4</a> 展示了如何配置静态网络路由，支持<a href="#ch17fig12">图 17-12</a> 中从左向右的数据包流动；但要支持所有方向的数据包流动，路由器需要通往全部子网的路由。即使只是用于 CCNA 学习的小型实验环境，如果仅使用静态路由，也需要为双向数据包流动配置所有子网的静态路由。例如，在<a href="#ch17fig13">图 17-13</a> 中，要支持 PC A 与 PC B 之间的数据包传输，需要：</p>

<p class="ul-noindent">R1 上通往 PC B 所在子网 172.16.2.0/24 的路由</p>

<h5 class="h5" id="ch17lev3sec8"><span id="page_443" data-epub-type="pagebreak"></span>以太网出接口与代理 ARP</h5>

<p class="noindent">虽然<a href="#exa17_5">例 17-5</a> 中两种静态路由形式都能工作，即指定下一跳 IP 地址或指定出接口，但使用下一跳地址更好。两者都可行，不过，当工作人员开始研究静态路由背后的工作机制时，使用下一跳地址造成的困惑要少得多。简单来说，使用下一跳地址不会强制相邻路由器使用代理 ARP，而在以太网链路上指定出接口则需要代理 ARP。</p>

<p class="noindent">本节尝试解释代理 ARP 如何工作，以及静态路由如何使用它。首先，考虑代理 ARP 的一般定义：</p>

<ol class="number">

<li><p class="number">路由器在接口 X 收到 ARP 请求，其目标地址不在接口 X 所连接的子网中。</p></li>

<li><p class="number">路由器具有将数据包转发到该目标地址的路由，而且该路由不应将数据包从同一个接口发回，以免形成环路。换言之，路由器拥有通往目标的有效转发路由。</p></li>

<li><p class="number">因此，路由器愿意且能够有效地充当目标主机的代理。为此，路由器在 ARP 应答中提供自己的 MAC 地址。</p></li>

</ol>

<p class="noindent">这些描述虽然正确，但通过示例更容易理解。再次考虑<a href="#exa17_5">例 17-5</a> 中的 <strong>ip route 172.16.2.0 255.255.255.0 G0/0/0</strong> 命令。假设 PC A 向地址为 172.16.2.9 的 PC B 发送数据包。数据包到达 R1，R1 将它匹配到子网 172.16.2.0/24 的静态路由；现在，R1 必须根据转发指示决定如何转发。R1 使用以下逻辑：</p>

<ol class="number">

<li><p class="number">路由的转发指示表明目的子网连接在接口 G0/0/0 上。这使 R1 发送 ARP 请求，查找目标地址 172.16.2.9。实际上，R1 的路由使其表现得仿佛目的子网 172.16.2.0/24 直接连接到 G0/0/0。当然，PC B 位于另一台路由器的另一侧，所以不会收到该 ARP 请求。</p></li>

<li><p class="number">R2 收到 R1 针对目标 172.16.2.9 的 ARP 请求。该请求符合代理 ARP 的条件：地址不在本地子网，但 R2 有匹配 172.16.2.9 的有效路由。R2 发送 ARP 应答，列出自己 G0/0/1 接口的 MAC 地址，这就是代理 ARP 应答。</p></li>

<li><p class="number">R1 收到 ARP 应答后，就能转发发往 172.16.2.9 的数据包。R1 将这些数据包封装在以太网帧中，以 R2 的 G0/0/1 MAC 地址为目的 MAC 地址，再进行转发。</p></li>

<li><p class="number">R2 收到该帧，按照正常路由过程，将其中封装的数据包路由到 PC B。</p></li>

</ol>

<p class="noindent">从前面大约一页内容可以看出，在路由中使用以太网出接口，其底层逻辑需要相当多的分析。在实际应用中，应改用指定下一跳地址的静态路由。</p>

<h4 class="h4" id="ch17lev2sec7">静态默认路由</h4>

<p class="noindent">路由器尝试路由数据包时，可能找不到任何匹配该数据包目的 IP 地址的路由。发生这种情况时，路由器通常直接丢弃数据包。</p>

<p class="noindent">路由器可以使用<em>默认路由</em>匹配所有数据包。如果数据包没有匹配到路由表中其他更具体的路由，路由器就会根据<span id="page_444" data-epub-type="pagebreak"></span>默认路由转发它。路由器可以通过路由协议学习默认路由，也可以配置静态默认路由。</p>

<h4 class="h4" id="ch17lev2sec8">静态主机路由</h4>

<p class="noindent"><em>网络路由</em>指匹配整个 IP 网络或子网中地址的路由，默认路由则匹配所有目的地。相比之下，<em>主机路由</em>定义通往单个主机地址的路由。配置这类静态路由时，<strong>ip route</strong> 命令使用一个 IP 地址和掩码 255.255.255.255，使匹配逻辑仅匹配该地址。</p>

<p class="noindent">为什么使用静态主机路由？坦率地说，这是最不常用的静态路由形式，因为网络工程师很少遇到需要借助静态主机路由解决的问题。不过，为了大致理解它的作用，可以考虑<a href="#ch17fig15">图 17-15</a> 的拓扑，它对前几幅图中的拓扑进行了扩展。</p>

<h4 class="h4" id="ch17lev2sec9">浮动静态路由</h4>

<p class="noindent"><a id="key_197" href="#ref-gloss_146"><span class="blue">浮动静态路由</span></a>存在于路由器配置中，但路由器会根据特定条件，将它移入或移出路由表。为什么？它是更大配置方案的一部分，使路由器能够在主 WAN 链路发生故障时，建立临时 WAN 链路。</p>

<p class="noindent">要理解其工作方式，可以考虑<a href="#ch17fig16">图 17-16</a> 的示例，其中显示前几幅图中的 R1 和 R2。大多数时候，以太网 WAN 链路是唯一工作的 WAN 链路，但现在两台路由器都具有蜂窝接口。当主链路中断时，它们可以通过 4G/LTE/5G 网络相互连接。</p>

<figure class="image-c" id="ch17fig16">

<img src="assets/volume1/part5-chapter17/images/vol1_17fig16.jpg" aria-describedby="a17fig16" alt="展示在网络中使用浮动静态路由到达关键子网这一概念的示意图。">

<figcaption>

</aside>

</figcaption>

</figure>

<p class="noindent">有意思的是，使用蜂窝网络为以太网 WAN 链路提供备份的配置，关键在于路由。路由器在永久链路上使用 OSPF 等路由协议，因此在本例中，R1 学到一条通往子网 172.16.2.0/24、使用以太网 WAN 链路的 OSPF 路由。R1 还为同一子网定义一条浮动静态路由，将数据包通过蜂窝接口发往路由器 R2。虽然配置了这条路由，但路由器 R1 <em>仅在 OSPF 路由不可用时</em>才选择将该浮动静态路由加入路由表。如果以太网链路正常，R1 就通过该链路路由数据包；否则，就通过蜂窝网络路由数据包。</p>

<p class="noindent">要创建浮动静态路由，需要配置一条路由，并为其指定比竞争的动态学习路由更高（更差）的管理距离。当路由器学到多条通往相同子网／掩码组合的路由时，必须先确定哪个路由来源具有更优的<a id="key_193" href="#ref-gloss_018"><span class="blue">管理距离</span></a>，数值越低越好，然后采用从更优来源学到的路由。默认设置使路由器认为静态路由优于通过任何动态路由协议学到的路由。浮动静态路由则颠倒了这一逻辑。</p>

<p class="noindent">要实现浮动静态路由，需要在 <strong>ip route</strong> 命令中使用一个参数，仅设置该路由的管理距离，使其大于路由协议的<span id="page_448" data-epub-type="pagebreak"></span>默认管理距离。例如，在 R1（见<a href="#ch17fig15">图 17-15</a>）上执行 <strong>ip route 172.16.2.0 255.255.255.0 cell0/1/0 130</strong> 命令，就能将静态路由的管理距离设为 130。只要主链路保持正常，并且 R1 上的 OSPF 学到一条通往 172.16.2.0/24 的路由（OSPF 默认管理距离为 110），R1 就会忽略这条浮动静态路由。当以太网 WAN 链路故障时，R1 会失去该子网的 OSPF 学习路由，于是将浮动静态路由加入路由表。（其余配置未在此处展示，它们告诉路由器如何发起呼叫，以便通过蜂窝网络建立备份链路。）</p>

<p class="noindent">最后请注意，<strong>show ip route</strong> 命令将大多数路由的管理距离列为方括号内两个数字中的第一个，而 <strong>show ip route</strong> <em>subnet</em> 命令则会明确列出管理距离。<a href="#exa17_9">例 17-9</a> 展示了与刚才这个示例相符的输出。</p>

<h4 class="h4" id="ch17lev2sec10">静态路由故障排查</h4>

<p class="noindent">关于 IPv4 静态路由的最后几页探讨静态路由可能出现的一些问题，既回顾前面几页提到的部分原因，也补充更多细节。本主题从三个角度讨论静态路由故障排查：</p>

<ul class="sq">

<li><p class="bull">路由存在于路由表中，但不正确。</p></li>

<li><p class="bull">路由没有出现在路由表中。</p></li>

<li><p class="bull">路由存在于路由表中且正确，但数据包未到达目的主机。</p></li>

</ul>

<section>

<h5 class="h5" id="ch17lev3sec9">出现在 IP 路由表中的错误静态路由</h5>

<p class="noindent">第一个排查要点可能很明显，但值得停下来思考一下。静态路由的正确性取决于输入 <strong>ip route</strong> 命令的内容。IOS 会检查语法，并如前所述执行其他几项检查，下一小节将回顾这些检查。然而，一旦通过检查，即使路由参数选择不当，IOS 也会将该路由加入 IP 路由表。</p>

<p class="noindent">例如，你原本想为子网 172.16.2.0/24 配置静态路由，却配置成了通往子网 172.16.222.0/24 的路由。路由器会接受该命令，但它指向错误的子网。又或者，在选择下一跳路由器地址时，你查看网络图并采用了左侧路由器的下一跳地址，而目的子网<span id="page_449" data-epub-type="pagebreak"></span>却位于图的右侧。还有一种情况是，你参考文档选择命令中的下一跳地址，该地址确实位于正确的目的子网中，却不是下一跳路由器的地址。在这些情况下，路由器都会接受命令，甚至将路由加入路由表，但该路由并无用处。</p>

<p class="noindent">另一个例子是，如果前两个参数表明配置的是子网内的 IP 地址而不是子网 ID，IOS 就会拒绝 <strong>ip route</strong> 命令。例如，前面的<a href="#exa17_5">例 17-5</a> 中，命令使用掩码 255.255.255.0，子网 ID 为 172.16.2.0 和 172.16.3.0。<a href="#exa17_10">例 17-10</a> 再次展示了这些命令，但改为使用子网内的地址 172.16.2.1 和 172.16.3.1。在这两种情况下，IOS 都会显示错误消息，并且不会将命令加入配置。</p>

<p class="ex-caption" id="exa17_10"><strong>例 17-10</strong> <em>IOS 拒绝使用子网内地址的 <span class="font"><strong>ip route</strong></span> 命令</em></p>

<p class="codelink"><a href="#code-f0449-01" id="f0449-01a">点击此处查看代码原图</a></p>

<div class="ex-box">

<pre class="pre-ex" tabindex="0"><code>R1# <strong>configure terminal</strong>

<p class="noindent">当考试题目涉及静态路由，而且你在 <strong>show ip route</strong> 的输出中看到这些路由时，请记得检查以下事项：</p>

<ul class="sq">

<li><p class="bull">子网 ID 和掩码是否正确？</p></li>

<li><p class="bull">下一跳 IP 地址是否正确，且指向相邻路由器上的 IP 地址？</p></li>

<li><p class="bull">下一跳 IP 地址是否标识了正确的路由器？</p></li>

<li><p class="bull">出接口是否正确，且引用的是本地路由器（即配置该静态路由的同一台路由器）上的接口？</p></li>

</ul>

</section>

<section>

<h5 class="h5" id="ch17lev3sec10">静态路由未出现在 IP 路由表中</h5>

<p class="noindent">配置 <strong>ip route</strong> 命令后，IOS 可能将该路由加入 IP 路由表，也可能不加入。在将路由加入路由表之前，IOS 还会考虑以下条件：</p>

<ul class="sq">

<li><p class="bull">对于列出出接口的 <strong>ip route</strong> 命令，该接口必须处于 up/up 状态。</p></li>

<li><p class="bull">对于列出下一跳 IP 地址的 <strong>ip route</strong> 命令，本地路由器必须拥有一条能到达该下一跳地址的路由。</p></li>

</ul>

<p class="noindent">例如，在前面的<a href="#exa17_5">例 17-5</a> 中，R1 的命令 <strong>ip route 172.16.3.0 255.255.255.0 172.16.5.3</strong> 定义了一条静态路由。在将其加入 IP 路由表之前，R1 会查找能到达 172.16.5.3 的现有 IP 路由。在该示例中，只要以太网 WAN 链路正常，R1 就能找到子网 172.16.5.0/24 的直连路由。因此，R1 会加入通往子网 172.16.3.0/24 的静态路由。此后，如果 R1 的 G0/0/1 故障，R1 就会从 IP 路由表中移除通往 172.16.5.0/24 的直连路由，这一操作又会导致 R1 移除通往 172.16.3.0/24 的静态路由。</p>

<p class="noindent"><span id="page_450" data-epub-type="pagebreak"></span>你可以配置静态路由，使 IOS 忽略这些基本检查，始终将该 IP 路由放入路由表。为此，只需在 <strong>ip route</strong> 命令中使用 <strong>permanent</strong> 关键字。例如，像<a href="#exa17_11">例 17-11</a> 那样，在这两条命令末尾加入 <strong>permanent</strong> 关键字后，无论两条 WAN 链路是否正常，R1 都会加入这些路由。</p>

<p class="ex-caption" id="exa17_11"><strong>例 17-11</strong> <em>将静态路由永久加入 IP 路由表（路由器 R1）</em></p>

<p class="codelink"><a href="#code-f0450-01" id="f0450-01a">点击此处查看代码原图</a></p>

<div class="ex-box">

<pre class="pre-ex" tabindex="0"><code>ip route 172.16.2.0 255.255.255.0 G0/0/0 <span class="bg-green">permanent</span>

ip route 172.16.3.0 255.255.255.0 172.16.5.3 <span class="bg-green">permanent</span></code></pre>

</div>

<p class="noindent">请注意，虽然 <strong>permanent</strong> 关键字使路由器无需检查出接口或通往下一跳地址的路由，就能将路由保留在路由表中，但它并不能神奇地修复失效的路由。例如，如果出接口故障，路由仍会保留在路由表中，但由于出接口已关闭，路由器无法转发数据包。</p>

</section>

<section>

<h5 class="h5" id="ch17lev3sec11">正确的静态路由出现在表中，但工作不正常</h5>

<p class="noindent">最后这一节说明两点：一个常见要点，以及一个需要复习的小细节。</p>

<p class="noindent">首先，对于常见要点，静态路由可能完全正确，但数据包仍可能因其他问题而无法到达。当你排查“主机 A 无法连接服务器 B”之类的问题时，错误的静态路由只是众多检查项目之一。根本原因可能是静态路由，也可能是其他因素。<a href="v1-20.html#ch20">第 20 章</a>“<a href="v1-20.html#ch20">IPv4 路由故障排查</a>”将深入讨论此类问题的排查。</p>

<p class="noindent">更具体的一点是，要留意任何带有 <strong>permanent</strong> 关键字的 <strong>ip route</strong> 命令。IOS 会将这些路由加入路由表，而不检查其正确性。你应检查出接口是否关闭，以及路由器是否拥有到达下一跳地址的路由。</p>

<h2 class="h2a">自测题答案</h2>

<section>

<h3 class="h3" id="ref-appclev1sec17">第 17 章</h3>

<p class="quiz"><strong><a id="ref-ques17_1" href="#quess17_1">1</a>．</strong> A 和 C。路由通过子网 ID 和掩码定义其代表的地址组。路由器可以利用这些数值求出应与该路由匹配的地址范围。另外两个答案列出的信息，有助于转发恰好与该路由匹配的数据包。</p>

<p class="quiz"><span id="ref-page_794" data-epub-type="pagebreak"></span><strong><a id="ref-ques17_2" href="#quess17_2">2</a>．</strong> D。路由器每次路由 IP 数据包时，都会从入站数据链路帧中解封装（取出）IP 数据包。在决定下一步将数据包转发到何处之后，它会将数据包重新封装到一个新的数据链路帧中。即使入站和出站数据链路碰巧属于相同类型（本场景正是如此），也会执行这一过程。因此，三台路由器都会对 IP 数据包进行解封装。由于所有链路都是以太网链路，三次解封装都从以太网帧中取出了数据包。</p>

<p class="quiz"><strong><a id="ref-ques17_3" href="#quess17_3">3</a>．</strong> A 和 D。首先，根据子网划分计算，地址 10.1.1.100 配合掩码 /26 得出的子网 ID 是 10.1.1.64。此外，掩码 /26 转换为点分十进制（DDN）掩码后是 255.255.255.192。对于任何正常工作的路由器接口，在加入 <strong>ip address</strong> 命令配置地址和掩码之后，路由器都会为该子网加入一条直连路由。在本例中，路由器加入的是子网 10.1.1.64 255.255.255.192 的直连路由。路由器还会加入一条称为本地路由的路由，它以接口 IP 地址为目的地址，掩码为 255.255.255.255。在本例中，这意味着路由器加入地址为 10.1.1.100、掩码为 255.255.255.255 的本地路由。</p>

<p class="quiz"><strong><a id="ref-ques17_4" href="#quess17_4">4</a>．</strong> B 和 C。<strong>ip route</strong> 命令可以引用两台路由器之间链路上的下一跳路由器 IP 地址，也可以引用本地路由器的出接口 ID。错误答案将这些项目颠倒了，提到的是本地路由器的 IP 地址和下一跳路由器的接口 ID。</p>

<p class="quiz"><strong><a id="ref-ques17_5" href="#quess17_5">5</a>．</strong> A。正确语法先列出子网号，然后是点分十进制形式的子网掩码，最后是出接口或下一跳 IP 地址。错误答案中，一个省略了子网掩码，另外两个使用了前缀式掩码而非 DDN 掩码。</p>

<p class="quiz"><strong><a id="ref-ques17_6" href="#quess17_6">6</a>．</strong> B。网络工程师执行了该命令，但路由器没有加入 IP 路由。因此，要么命令存在语法错误，要么路由器接受了命令，却因某种原因认为不应将路由加入表中。</p>

<p class="quiz-para">两个（错误）答案认为命令存在语法错误：一个笼统地声称有语法错误，另一个明确指出缺少下一跳 IP 地址。然而，<strong>ip route 10.1.1.0 255.255.255.0 s0/0/0</strong> 命令的语法是正确的。请注意，既然列出了出接口 S0/0/0，命令就不需要下一跳 IP 地址。</p>

<p class="quiz-para">至于 IOS 接受命令并将其加入配置后，为什么可能不加入路由，原因是 IOS 在把路由加入路由表之前，会对有效的 <strong>ip route</strong> 命令内容执行若干检查。它会检查出接口是否处于 up/up 状态（如本题正确答案所述），以及是否存在到达下一跳地址的路由。此外，如果路由器已经拥有从其他来源学到的同一子网路由，它还会检查那条路由是否具有更优的管理距离。</p>

</section>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_018"><strong>管理距离（administrative distance）</strong> 在 Cisco 路由器中，当多条通往同一子网的路由由不同路由协议学习而来时，路由器用来在这些路由之间进行选择的方法。管理距离越低，路由信息的来源越优。</p>

<p class="gloss" id="ref-gloss_026"><strong>ARP 表（ARP table）</strong> 主机和路由器保存在内存中的列表，记录同一 VLAN 中邻居的 IP 地址及其 MAC 地址。</p>

<p class="gloss" id="ref-gloss_077"><strong>直连路由（connected route）</strong> 路由器接口既处于启用状态又配置了 IP 地址时，加入路由表的 IP 路由。该路由对应的子网可根据所配置的 IP 地址和掩码计算得出。</p>

<p class="gloss" id="ref-gloss_092"><strong>默认路由（default route）</strong> 路由器上被认为能够匹配所有未被更具体路由匹配的数据包的路由。</p>

<p class="gloss" id="ref-gloss_146"><strong>浮动静态路由（floating static route）</strong> 管理距离高于其他路由（通常是由路由协议学到的路由）的静态 IP 路由。因此，如果已经学到路由协议路由，路由器就不会使用该静态路由；但如果路由协议未能学到路由，路由器就会使用它。</p>

<p class="gloss" id="ref-gloss_174"><strong>主机路由（host route）</strong> 掩码为 /32 的路由。由于该掩码的作用，它代表通往单个主机 IP 地址的路由。</p>

<p class="gloss" id="ref-gloss_280"><strong>网络路由（network route）</strong> 通往某个有类网络的路由。</p>

<p class="gloss" id="ref-gloss_282"><span id="ref-page_828" data-epub-type="pagebreak"></span><strong>下一跳路由器（next-hop router）</strong> 在路由表中的 IP 路由中，路由表项的一部分，用 IP 地址指明应接收与该路由匹配的数据包的下一台 IP 路由器。</p>

<p class="gloss" id="ref-gloss_294"><strong>出接口（outgoing interface）</strong> 在路由表中的 IP 路由中，路由表项的一部分，指明本地路由器应通过哪个本地接口转发与该路由匹配的数据包。</p>

<p class="gloss" id="ref-gloss_354"><span id="ref-page_833" data-epub-type="pagebreak"></span><strong>路由表（routing table）</strong> 路由器中的路由列表；每条路由列出目的子网和掩码、转发去往该子网的分组所使用的路由器出接口，以及在需要时列出的下一跳路由器 IP 地址。</p>

<p class="gloss" id="ref-gloss_378"><strong>静态路由（static route）</strong> 用户通过在本地路由器上配置路由的详细信息而创建的 IP 路由。</p>
