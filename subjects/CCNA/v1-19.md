<p class="noindent-c">在 TCP/IP 的世界中，<em>主机</em>一词指任何具有 IP 地址的设备：手机、平板电脑、PC、服务器、路由器、交换机——任何使用 IP 提供服务，或只需 IP 地址进行管理的设备。<em>主机</em>这一术语还包括一些不那么显而易见的设备：商场里的电子广告视频屏、采用与手机相同技术上传用电信息以供计费的电表，以及你的新汽车。</p>

<p class="noindent">无论属于哪种主机，任何使用 IPv4 的主机都需要四项 IPv4 设置才能正常工作：</p>

<ul class="sq">

<li><p class="bull">IP 地址</p></li>

<li><p class="bull">子网掩码</p></li>

<li><p class="bull">默认路由器</p></li>

<li><p class="bull">DNS 服务器 IP 地址</p></li>

</ul>

<p class="noindent">本章讨论主机上的这些基本 IP 设置。首先介绍主机如何使用动态主机配置协议（DHCP）动态学习这四项设置。本章后半部分展示如何查找主机上的设置，以及显示设置时需要关注的关键信息。</p>

<h3 class="h3" id="ch19lev1sec3">动态主机配置协议</h3>

<p class="noindent">动态主机配置协议（DHCP）提供 TCP/IP 网络中最常用的服务之一。TCP/IP 网络中的绝大多数主机都是用户设备，而绝大多数用户设备通过 DHCP 学习 IPv4 设置。</p>

<p class="noindent">与手动配置 IPv4 设置相比，使用 DHCP 有若干优势。主机 IP 设置的配置保存在 DHCP 服务器中，每个客户端通过 DHCP 消息学习这些设置。因此，主机 IP 配置由 IT 人员集中控制，而不是在每台主机上本地配置，从而减少用户错误。DHCP 允许永久分配主机地址，但更常见的方式是临时租用 IP 地址。通过这些租约，<a id="key_217" href="#ref-gloss_099"><span class="blue">DHCP 服务器</span></a>可以在设备离开网络后回收 IP 地址，更充分地利用可用地址。</p>

<p class="noindent">DHCP 还支持移动性。例如，用户每次带着平板电脑移动到新位置——咖啡店、客户现场或返回办公室——设备都可以连接另一个无线 LAN，使用 DHCP 租用该 LAN 中的新 IP 地址，然后开始在新网络中工作。如果没有 DHCP，用户就必须询问本地网络的信息，并手动配置设置，而且会有不少用户出错。</p>

<p class="noindent">虽然 DHCP 对用户主机自动工作，但它需要网络事先做些准备，并在路由器上配置一些内容。在某些企业网络中，这种路由器配置可能是在许多 LAN 接口上各配置一条命令（<strong>ip helper-address</strong> <em>server-ip</em>），通过 IP 地址标识 DHCP 服务器。在其他情况下，路由器自身充当 DHCP 服务器。无论如何，路由器都要发挥某种作用。</p>

<p class="noindent">本章第一个主要部分概览 DHCP，包括相关概念，以及使路由器能够与独立 DHCP 服务器协同工作的路由器配置。</p>

<section>

<h4 class="h4" id="ch19lev2sec1">DHCP 概念</h4>

<p class="noindent">请停下来想一想 DHCP 对主机计算机的作用。主机充当 <a id="key_215" href="#ref-gloss_097"><span class="blue">DHCP 客户端</span></a>。作为 DHCP 客户端，主机最初没有任何 IPv4 设置：没有 IPv4 地址、掩码、默认路由器，也没有 <a id="key_218" href="#ref-gloss_111"><span class="blue">DNS 服务器</span></a> IP 地址。但 DHCP 客户端确实<span id="page_489" data-epub-type="pagebreak"></span>了解 DHCP 协议，因此可以使用该协议来（a）发现 DHCP 服务器，以及（b）请求租用 IPv4 地址。</p>

<p class="noindent">DHCP 在客户端与服务器之间使用以下四种消息。（为便于记忆，请注意它们的首字母组成 DORA。）</p>

<p class="ul-noindent"><strong>Discover（发现）：</strong>由 DHCP 客户端发送，以寻找愿意提供服务的 DHCP 服务器</p>

<p class="ul-noindent"><strong>Offer（提供）：</strong>由 DHCP 服务器发送，提议向该客户端出租特定 IP 地址，并告知其他参数</p>

<p class="ul-noindent"><strong>Request（请求）：</strong>由 DHCP 客户端发送，请求服务器出租 Offer 消息中列出的 IPv4 地址</p>

<p class="ul-noindent"><strong>Acknowledgment（确认）：</strong>由 DHCP 服务器发送，用于分配地址，并列出掩码、默认路由器和 DNS 服务器 IP 地址</p>

<p class="noindent">然而，DHCP 客户端面临一个比较特殊的问题：尚未拥有 IP 地址，却需要在 IP 数据包内发送这些 DHCP 消息。为实现这一点，DHCP 消息使用两个特殊的 IPv4 地址，使没有 IP 地址的主机仍能在本地子网上收发消息：</p>

<p class="ul-noindent"><strong>0.0.0.0：</strong>保留给尚未拥有 IP 地址的主机用作源 IPv4 地址的地址。</p>

<p class="ul-noindent"><strong>255.255.255.255：</strong>本地广播 IP 地址。发往该目的地址的数据包会在本地数据链路上广播，但路由器不会转发它们。</p>

<p class="noindent">为展示这些地址的工作方式，<a href="#ch19fig01">图 19-1</a> 举例说明同一 LAN 上主机 A 与 DHCP 服务器之间使用的 IP 地址。主机 A 作为客户端发送 Discover 消息，源 IP 地址为 0.0.0.0，因为它还没有可用的 IP 地址。主机 A 将数据包发往目的地址 255.255.255.255，并放在 LAN 广播帧中发送，到达子网内所有主机。客户端希望本地子网上有 DHCP 服务器。为什么？因为发往 255.255.255.255 的数据包只会到达本地子网的主机，路由器 R1 不会转发该数据包。</p>

<p class="noindent"><span id="page_490" data-epub-type="pagebreak"></span>现在看 DHCP 服务器返回的 Offer 消息。服务器再次将目的 IP 地址设为 255.255.255.255。为什么？主机 A 仍没有 IP 地址，所以服务器无法直接向它发送数据包。因此，服务器将数据包发往代表“子网中所有本地主机”的地址 255.255.255.255。（数据包也封装在以太网广播帧中。）</p>

<p class="noindent">请注意，子网中的所有主机都会收到 Offer 消息。不过，最初的 Discover 消息列出一个名为客户端 ID 的编号，其中包含主机的 MAC 地址，用来标识最初的主机（本例为主机 A）。因此，主机 A 知道 Offer 消息是发给自己的。其他主机也会收到 Offer 消息，但注意到其中列出的是另一台设备的 DHCP 客户端 ID，因此忽略该消息。</p>

<section>

<h5 class="h5" id="ch19lev3sec1">APIPA IP 地址（169.254.x.x）</h5>

<p class="noindent">如果 DHCP 客户端的 DHCP 过程失败，主机有一种默认方式自行分配 IP 地址，使用的功能称为自动私有 IP 编址（<a id="key_213" href="#ref-gloss_023"><span class="blue">APIPA</span></a>）。当 DHCP 过程失败时，DHCP 客户端从 169.254.0.0 B 类网络的一个子集中自行分配 APIPA IP 地址，并使用默认掩码 255.255.0.0。</p>

<p class="noindent">使用 APIPA 地址并不能让设备像普通主机一样工作。例如，主机不知道默认路由器，也不会学到 DNS 服务器列表。它只能向同一 LAN 上的其他 APIPA 主机发送数据包。</p>

<p class="noindent">APIPA 过程如下：</p>

<ol class="number">

<li><p class="number">客户端从网络 169.254.0.0 中选择任意 IP 地址（实际地址范围：169.54.1.0–169.254.254.255）。</p></li>

<li><p class="number">DHCP 客户端通过 ARP 执行重复地址检测（DAD），发现同一链路上是否已有其他主机使用所选的 APIPA 地址。如果已有主机使用相同地址，客户端就停止使用该地址，并选择另一个。</p></li>

<li><p class="number">客户端只能在本地网络上收发数据包。</p></li>

</ol>

</section>

<section>

<h5 class="h5" id="ch19lev3sec2">通过 DHCP 中继支持远程子网的 DHCP</h5>

<p class="noindent">网络工程师在 DHCP 方面有一个重要设计选择：在每个 LAN 子网中放置 DHCP 服务器，还是将 DHCP 服务器集中在中心站点？这是一个合理的问题。Cisco 路由器可以充当 DHCP 服务器，因此分布式设计可以使用每个站点的路由器作为 DHCP 服务器。如果像<a href="#ch19fig01">图 19-1</a> 那样，每个子网中都有 DHCP 服务器，协议消息流就保持在各自 LAN 内。</p>

<p class="noindent">不过，集中式 DHCP 服务器方案也有优势。实际上，一些 Cisco 设计文档将集中式设计建议为最佳实践，部分原因是它允许集中控制和配置整个企业中分配的所有 IPv4 地址。</p>

<p class="noindent"><span id="page_491" data-epub-type="pagebreak"></span>使用集中式 DHCP 服务器时，<a href="#ch19fig01">图 19-1</a> 中原本只在本地子网内流动的 DHCP 消息，需要以某种方式通过 IP 网络到达集中式 DHCP 服务器并返回。为实现这一点，连接远程 LAN 子网的路由器需要配置接口子命令 <strong>ip helper-address</strong> <em>server-ip</em>。</p>

<p class="noindent"><strong>ip helper-address</strong> <em>server-ip</em> 子命令指示路由器，对从接口进入的 DHCP 客户端消息执行以下操作：</p>

<ol class="number">

<li><p class="number">留意目的 IP 地址为 255.255.255.255 的入站 DHCP 消息。</p></li>

<li><p class="number">将该数据包的源 IP 地址更改为路由器入接口的 IP 地址。</p></li>

<li><p class="number">将该数据包的目的 IP 地址更改为 DHCP 服务器地址（即 <strong>ip helper-address</strong> 命令中配置的地址）。</p></li>

<li><p class="number">将数据包路由到 DHCP 服务器。</p></li>

</ol>

<p class="noindent">该命令通过更改目的 IP 地址，绕过“不路由发往 255.255.255.255 的本地子网广播数据包”这一规则。一旦目的地址设为 DHCP 服务器的 IP 地址，网络就能将数据包路由到服务器。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">路由器通过更改数据包首部中的 IP 地址来中继 DHCP 消息的功能，称为 <em>DHCP 中继</em>。</p>

</div>

<p class="noindent"><a href="#ch19fig02">图 19-2</a> 展示该过程的示例。主机 A 位于左侧，作为 DHCP 客户端；DHCP 服务器（172.16.2.11）位于右侧。R1 在 G0/0 接口下配置了 <strong>ip helper-address 172.16.2.11</strong> 命令。在步骤 1，路由器 R1 发现目的地址为 255.255.255.255 的入站 DHCP 数据包。步骤 2 展示更改源和目的 IP 地址后的结果，并由 R1 路由该数据包。</p>

<figure class="image-c" id="ch19fig02">

<p class="noindent">对于服务器返回的 DHCP 消息，路由器使用类似过程。首先，DHCP 服务器返回数据包时，只需对调从路由器（中继代理）收到的数据包的源和目的 IP 地址。例如，在<a href="#ch19fig02">图 19-2</a> 中，Discover 消息列出的源 IP 地址为 172.16.1.1，因此服务器将 Offer 消息发回目的 IP 地址 172.16.1.1。</p>

<p class="noindent">当路由器收到目的地址为自身某个 IP 地址的 DHCP 消息时，它会意识到该数据包可能属于 DHCP 中继功能的一部分。此时，<a id="key_216" href="#ref-gloss_098"><span class="blue">DHCP 中继代理</span></a>（路由器 R1）需要更改目的 IP 地址，让尚未拥有 IP 地址的<span id="page_492" data-epub-type="pagebreak"></span>真正 DHCP 客户端（主机 A）能够接收并处理该数据包。</p>

<p class="noindent"><a href="#ch19fig03">图 19-3</a> 展示 R1 收到发往自身地址 172.16.1.1 的 DHCP Offer 消息时，这些地址如何工作。R1 将数据包目的地址改为 255.255.255.255，并从 G0/0 转发出去，因为该数据包原本发往 G0/0 的 IP 地址 172.16.1.1。因此，该 LAN 中的所有主机（包括 DHCP 客户端 A）都会收到消息。</p>

<h5 class="h5" id="ch19lev3sec3">DHCP 服务器存储的信息</h5>

<p class="noindent">DHCP 服务器听起来可能像是一台放在上锁大房间里的大型硬件，周围有大量空调为其散热。然而，与大多数服务器一样，这里的服务器实际上是运行在某种服务器操作系统上的软件。DHCP 服务器可以是免费下载并安装在旧 PC 上的软件。不过，为支持新的 DHCP 客户端，服务器需要始终可用，因此大多数公司将软件安装在非常稳定、具备高可用性功能的数据中心中。但 DHCP 服务仍由软件提供。</p>

<p class="noindent">为了能够响应 DHCP 客户端，为其提供 IPv4 地址和其他信息，DHCP 服务器（软件）需要进行配置。DHCP 服务器按子网组织这些 IPv4 设置，列出地址池和默认路由器设置，这些设置因子网而异。以下列表展示 DHCP 服务器为支持客户端需要了解的设置类型：</p>

<p class="ul-noindent"><strong>子网 ID 和掩码：</strong>DHCP 服务器可利用这些信息确定子网中的所有地址。（DHCP 服务器知道不能出租子网 ID 或子网广播地址。）</p>

<p class="ul-noindent"><strong>保留（排除）地址：</strong>服务器需要知道子网中哪些地址<em>不能</em>出租。该列表允许工程师保留用作静态 IP 地址的地址。例如，大多数路由器和交换机 IP 地址、服务器地址，以及用户设备以外的大多数设备地址，都使用静态分配的 IP 地址。多数情况下，工程师对所有子网采用相同惯例，要么保留各子网中最低的 IP 地址，要么保留最高的 IP 地址。</p>

<p class="ul-noindent"><span id="page_493" data-epub-type="pagebreak"></span><strong>默认路由器：</strong>该子网上路由器的 IP 地址。</p>

<p class="ul-noindent"><strong>DNS IP 地址：</strong>DNS 服务器 IP 地址的列表。</p>

<p class="noindent"><a href="#ch19fig04">图 19-4</a> 展示 DHCP 服务器为两个 LAN 子网 172.16.1.0/24 和 172.16.2.0/24 预先配置的概念。DHCP 服务器位于右侧，为每个子网定义上述所有项目。在本例中，配置保留了子网中最低的 IP 地址，供静态地址使用。</p>

<figure class="image-c" id="ch19fig04">

<p class="noindent">配置还可以列出其他参数。例如，可以设置租用 IP 地址的时间限制。服务器将地址出租一段时间（通常若干天），随后客户端可以请求续租。如果客户端不续租，服务器就可以回收 IP 地址，将其放回可用 IP 地址池。服务器配置规定租约的最长时间。</p>

<p class="noindent">根据 DHCP 服务器配置上的细微差别，DHCP 使用三种分配模式。<em>动态分配</em>指本章通篇描述的 DHCP 机制和配置。另一种方法是<em>自动分配</em>，它将 DHCP 租期设为无限。因此，一旦服务器从地址池选择并向客户端分配 IP 地址，该地址就无限期地归该客户端使用。第三种模式是<em>静态分配</em>，根据客户端 MAC 地址预先为其配置特定 IP 地址，此后只有该特定客户端使用这个地址。（请注意，本章仅展示动态分配的示例和配置。）</p>

<p class="noindent">此外，还可以配置 DHCP 服务器提供其他有用的设置。例如，服务器可以提供简单文件传输协议（TFTP）服务器的 IP 地址。TFTP 服务器提供一种基本的文件存储方式，可将文件传输到客户端主机。例如，Cisco IP 电话在初始化时依赖 TFTP 获取若干配置文件。DHCP 通过提供电话应使用的 TFTP 服务器 IP 地址，发挥关键作用。</p>

<h5 class="h5" id="ch19lev3sec4">配置 DHCP 中继</h5>

<p class="noindent">配置 DHCP 中继只需要一个简单决策和一条直接的配置命令。首先，必须确定哪些接口需要该功能。对于连接到满足以下条件的子网的任何路由器接口，都必须配置 DHCP 中继功能：</p>

<ul class="sq">

<li><p class="bull">子网中有 DHCP 客户端</p></li>

<li><p class="bull">子网中没有 DHCP 服务器</p></li>

</ul>

<p class="noindent">确定这些接口之后，就需要在每个接口上配置 <strong>ip helper-address</strong> 接口子命令。例如，在前面三幅图的拓扑中，R1 的 G0/0 接口需要配置 <strong>ip helper-address 172.16.2.11</strong> 接口子命令。在接口上启用后，IOS DHCP 中继代理就会按本章前面所述，更改入站 DHCP 消息中的地址。如果没有 DHCP 中继代理，DHCP 请求就永远无法到达服务器。</p>

<h5 class="h5" id="ch19lev3sec6">将路由器配置为 DHCP 客户端</h5>

<p class="noindent">与交换机一样，可以将路由器接口配置为通过 DHCP 租用 IP 地址，而不是使用静态 IP 地址，尽管这种情况很少见。几乎所有情况下，通过 <strong>ip address</strong> <em>address mask</em> 接口子命令静态配置路由器接口 IP 地址更合理。不过，在某些路由器连接互联网的场景中，将路由器配置为使用 DHCP 租用地址很合理；实际上，几乎所有家用路由器都这样做。</p>

<p class="noindent">具有互联网链路的路由器可以通过 DHCP 学习自身 IP 地址和掩码，也可以将相邻 ISP 路由器的地址学为<a id="key_214" href="#ref-gloss_090"><span class="blue">默认网关</span></a>。<a href="#ch19fig05">图 19-5</a> 展示一个示例，左侧是企业某站点的三台路由器。路由器 R1 通过互联网连接，使用 DHCP 从 ISP 路由器学习自身 IP 地址 192.0.2.2。</p>

<p class="noindent">无论是否通过 DHCP 学习，每台使用 IP 第 4 版的主机都需要一些设置才能正常工作。本章第二个主要部分研究这些设置，并展示 Windows、Linux 和 macOS 上的示例。</p>

<h4 class="h4" id="ch19lev2sec3">主机的 IPv4 设置</h4>

<p class="noindent">要正常工作，IPv4 主机需要知道以下值：</p>

<ul class="sq">

<li><p class="bull">DNS 服务器 IP 地址</p></li>

<li><p class="bull">默认网关（路由器）IP 地址</p></li>

<li><p class="bull">设备自身的子网掩码</p></li>

<p class="noindent">重点看 <strong>ifconfig</strong> 命令，它以十六进制列出子网掩码，本例为 0xffffff00。要将掩码转换为点分十进制，先将每对十六进制数字转换为二进制，再将二进制转换为对应十进制，得到点分十进制掩码的四个八位组。本例中，0xffffff00 的前三对是 ff，转换为二进制 11111111，再转换为十进制 255；最后一对 00 转换为二进制 00000000，再转换为十进制 0。最终得到熟悉的十进制掩码 255.255.255.0。</p>

<p class="noindent"><a href="#exa19_9">例 19-9</a> 中的 <strong>networksetup</strong> 命令比旧的 <strong>ifconfig</strong> 列出更多细节，包含除 DNS 服务器列表之外的常见 IP 设置。请注意，macOS 的 <strong>networksetup</strong> 命令具有多种选项。</p>

<h2 class="h2" id="ref-appc"><span id="ref-page_779" data-epub-type="pagebreak"></span>附录 C</h2>

<h2 class="h2a">“这些知识我已经掌握了吗？”自测题答案</h2>

<section>

<h3 class="h3" id="ref-appclev1sec19">第 19 章</h3>

<p class="quiz"><strong><a id="ref-ques19_1" href="#quess19_1">1</a>．</strong> B 和 D。客户端发送 Discover 消息，服务器返回 Offer 消息。随后客户端发送 Request，服务器通过 Acknowledgment 消息返回 IP 地址。</p>

<p class="quiz"><strong><a id="ref-ques19_2" href="#quess19_2">2</a>．</strong> A 和 B。两个正确答案列出决定服务器向客户端出租哪些 IP 地址的两项主要信息。对于涉及 DNS 服务器的错误答案，DHCP 服务器确实提供 DNS 服务器的 IP 地址，但不提供其主机名。此外，DHCP 服务器提供每个子网默认网关的 IP 地址，但不提供 MAC 地址。</p>

<p class="quiz"><strong><a id="ref-ques19_3" href="#quess19_3">3</a>．</strong> A 和 C。如果直连子网中有 DHCP 客户端，却没有 DHCP 服务器，路由器就需要充当 DHCP 中继代理。如果子网中存在 DHCP 服务器，路由器就不需要向远程 DHCP 服务器转发 DHCP 消息（这正是 DHCP 中继代理的功能）。提到 <strong>ip address dhcp</strong> 命令的答案，会使路由器接口充当 DHCP 客户端，与 DHCP 中继代理无关。</p>

<p class="quiz"><strong><a id="ref-ques19_4" href="#quess19_4">4</a>．</strong> D。<strong>ip address dhcp</strong> 命令指示路由器通过 DHCP 获取地址。路由器学到的信息与普通 DHCP 客户端完全相同。它使用列为默认网关的地址构建默认路由，将默认网关 IP 地址用作下一跳地址。路由器继续按通常方式工作，根据 IP 路由表转发数据包。</p>

<p class="quiz"><strong><a id="ref-ques19_5" href="#quess19_5">5</a>．</strong> B 和 C。输出显示 MAC 地址、IP 地址、子网掩码（十六进制）和子网广播地址。其中，DHCP 服务器提供两个正确答案中的信息。两个错误答案分别提到 MAC 地址（不是由 DHCP 提供，而是设备 NIC 已知）和子网广播地址（由主机计算）。</p>

<p class="quiz"><strong><a id="ref-ques19_6" href="#quess19_6">6</a>．</strong> D。Windows 同时支持 <strong>ipconfig</strong> 和 <strong>ipconfig /all</strong> 命令，但 <strong>ipconfig</strong> 不会提及 DNS 服务器。请注意，<strong>ifconfig</strong> 可用于 Linux 和 macOS，但不能用于 Windows，而 <strong>ifconfig /all</strong> 在这三种系统上都是无效命令。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_023"><strong>APIPA</strong> 自动私有 IP 编址。RFC 3927 规定的一种惯例，包含一个过程和一组保留 IPv4 地址（169.254.0.0/16），供需要使用 IPv4 地址、却未能通过 DHCP 等动态过程租到 IPv4 地址的主机使用。</p>

<p class="gloss" id="ref-gloss_090"><span id="ref-page_815" data-epub-type="pagebreak"></span><strong>默认网关／默认路由器（default gateway/default router）</strong> 在 IP 主机上，指某台路由器的 IP 地址；当分组的目的地址位于本地子网之外的子网时，主机会将分组发送给该路由器。</p>

<p class="gloss" id="ref-gloss_097"><strong>DHCP 客户端（DHCP client）</strong> 任何使用 DHCP 协议请求从 DHCP 服务器租用 IP 地址，或从该服务器学习 IP 设置的设备。</p>

<p class="gloss" id="ref-gloss_098"><strong>DHCP 中继代理（DHCP relay agent）</strong> 路由器 IOS 功能的名称，通过将目的 IP 地址从 255.255.255.255 更改为 DHCP 服务器的 IP 地址，将 DHCP 消息从客户端转发给服务器。</p>

<p class="gloss" id="ref-gloss_099"><strong>DHCP 服务器（DHCP server）</strong> 等待 DHCP 客户端请求租用 IP 地址的软件。服务器为客户端分配 IP 地址租约，并列出其他重要 IP 设置。</p>

<p class="gloss" id="ref-gloss_111"><strong>DNS 服务器（DNS server）</strong> 依据域名系统（DNS）协议和全球系统提供名称解析服务的服务器应用程序。</p>

<p class="gloss" id="ref-gloss_112"><strong>DNS 服务器列表（DNS server list）</strong> IP 主机已知的 DNS 服务器 IP 地址列表，供主机发送 DNS 名称解析请求时使用。</p>
