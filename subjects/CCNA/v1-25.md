<p class="objset">本章涵盖以下考试主题：</p>

<p class="obj">1.0 网络基础</p>

<p class="obj1">1.8 配置并验证 IPv6 编址和前缀</p>

<p class="obj1">1.9 描述 IPv6 地址类型</p>

<p class="noindent-c">IPv4 一直是 TCP/IP 和互联网发展过程中稳定且非常有用的组成部分。在互联网漫长历史的大部分时间里，以及大多数使用 TCP/IP 的企业网络中，IPv4 都是定义编址和路由的核心协议。不过，虽然 IPv4 有许多优点，它也存在一些不足，因此需要一种替代协议：IP 版本 6（IPv6）。</p>

<p class="noindent">IPv6 定义的总体功能与 IPv4 相同，但实现方法不同。例如，IPv4 和 IPv6 都定义了编址、将较大地址组划分为较小地址组的子网划分概念、用于构成 IPv4 或 IPv6 数据包的首部，以及路由这些数据包的规则。同时，IPv6 对细节的处理有所不同，例如使用 128 位 IPv6 地址，而不是 32 位 IPv4 地址。</p>

<p class="noindent">本章重点介绍网络层的核心功能：编址和路由。第一节讨论整体概念，第二节介绍如何书写和输入 IPv6 地址的具体细节。</p>

<h3 class="h3" id="ch25lev1sec3">IPv6 简介</h3>

<p class="noindent"><a id="key_267" href="#ref-gloss_211"><span class="blue">IP 版本 6（IPv6）</span></a> 是 IP 版本 4（IPv4）的替代协议。为此，网络可以逐步迁移，同时使用两种协议，由 IPv6 克服那些促使人们寻求 IPv4 替代协议的部分问题。</p>

<p class="noindent">遗憾的是，这段介绍提出的问题比解答的更多。为什么需要替换 IPv4？如果需要替换，什么时候会发生，进展会很快吗？当企业或互联网用 IPv6 替换 IPv4 时，究竟会发生什么？类似问题还有很多。</p>

<p class="noindent">虽然本章作为入门章节，无法详述 IPv4 最终需要被 IPv6 替换的所有原因，但将 TCP/IP 网络迁移到 IPv6 最清楚、最明显的原因是增长。IPv4 使用 32 位地址，总计有几十亿个地址。有趣的是，看起来如此庞大的地址数量仍然太少。IPv6 将地址长度增加到 128 位。作为对比，IPv6 提供的地址数量是 IPv4 的 10,000,000,000,000,000,000,000,000,000 倍以上。IPv4 提供略少于 10<sup><em>10</em></sup> 个地址，而 IPv6 提供略少于 10<sup><em>38</em></sup> 个地址。</p>

<p class="noindent">IPv6 使用不同大小的地址字段以及一些不同的编址规则，这意味着许多其他协议和功能也必须改变。例如，IPv4 路由，也就是数据包转发过程，依赖对 IPv4 地址的理解。为支持 IPv6 路由，路由器必须理解 IPv6 地址和路由。要动态学习 IPv6 子网的路由，路由协议必须支持这些不同的 IPv6 编址规则，包括 IPv6 如何创建子网的规则。因此，从 IPv4 迁移到 IPv6 远不止更改一个协议（IP），而是会影响许多协议。</p>

<p class="noindent">本章第一节讨论从 IPv4 转向 IPv6 的一些原因，以及因此必须改变的协议。</p>

<h4 class="h4" id="ch25lev2sec1">IPv6 出现的历史原因</h4>

<p class="noindent">在过去 50 多年里，互联网从萌芽阶段发展成为对世界影响巨大的事物。它最初通过大学研究发展，从 20 世纪 60 年代末互联网的 ARPANET 起点，延续到 70 年代。80 年代，互联网继续快速增长，推动力仍主要来自研究以及参与研究的大学。</p>

<p class="noindent">到 20 世纪 90 年代初，互联网允许商业用途，进一步加快了增长。后来，家庭固定互联网接入变得普遍，接着智能手机等移动设备广泛使用互联网。如今，物联网（IoT）推动互联网增长，为各行业增加各种能够通过 IP 网络通信的设备。<a href="#ch25fig01">图 25-1</a> 展示了其中一些主要里程碑及大致时间。</p>

<p class="noindent">互联网在相当长时期内的惊人增长，为公有 IPv4 地址带来了一个大问题：全球地址即将用尽。以一个里程碑为例，2011 年，互联网号码分配机构（IANA）将最后五个 /8 地址块（大小与 A 类网络相同）分别分配给五个区域互联网注册机构（RIR）。此时，IANA 已没有更多公有 IPv4 地址可分配给 RIR。RIR 无法再从 IANA 获得新的公有地址分配，但仍可从剩余的公有地址空间中继续分配地址块。</p>

<p class="noindent">在 2010 年代，五个 RIR 最终都分配完了各自的公有地址空间。例如，2015 年末，ARIN（北美）宣布其地址储备已经耗尽。所有 RIR 都制定了应对 IPv4 地址耗尽的计划，它们要么已经没有 IPv4 地址空间，要么采用维护计划回收未使用的 IPv4 地址并重新分配。</p>

<p class="noindent">这些事件意义重大，因为这一天终于到来：新公司尝试连接互联网时，已不能再仅使用 IPv4 而忽略 IPv6。它们唯一的选择将是 IPv6，因为 IPv4 已没有剩余的公有地址。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">你可以在 ARIN 的 IPv4 地址耗尽网站上跟踪它在互联网历史上这场有趣转变中的进展：<a href="https://www.arin.net/resources/guide/ipv4/">https://www.arin.net/resources/guide/ipv4/</a>。也可以在 <a href="http://ipv4.potaroo.net">http://ipv4.potaroo.net</a> 查看汇总报告。</p>

</div>

<p class="noindent">虽然媒体理所当然地高度关注 IPv4 地址耗尽，但关心互联网的人从 20 世纪 80 年代末就知道这一潜在问题。这个通常称为 <a id="key_268" href="#ref-gloss_213"><span class="blue">IPv4 地址耗尽（IPv4 address exhaustion）</span></a>的问题，甚至可能让互联网在 90 年代的高速增长戛然而止！必须采取措施。</p>

<p class="noindent">IETF 提出了几种延长 IPv4 地址使用寿命的短期解决方案，以及一个长期解决方案：IPv6。不过，网络地址转换（NAT）和无类别域间路由（CIDR）等其他工具，帮助 IPv4 又延续了几十年。IPv6 提供了更持久的解决方案：用新的 IPv6 首部和 IPv6 地址替代 IPv4。其地址大小支持极其庞大的地址数量，有望为未来几代人解决地址短缺问题。<a href="#ch25fig02">图 25-2</a> 展示了 IPv4 地址耗尽过程中的一些主要时间节点。</p>

<p class="noindent">第一节的其余部分将比较 IPv6 与 IPv4，重点关注两种协议的共同功能。具体而言，将比较协议本身（包括地址）、路由、路由协议以及其他相关主题。</p>

<h4 class="h4" id="ch25lev2sec2">IPv6 协议</h4>

<p class="noindent">核心 IPv6 协议的主要目的与 IPv4 协议相同。RFC 8200 定义的核心 IPv6 协议规定了数据包概念、数据包地址，以及主机和路由器的角色。这些规则让设备能够转发源自主机、途经多台路由器的数据包，使其到达正确的目的主机。（IPv4 早在 RFC 791 中就为 IPv4 定义了相同概念。）</p>

<p class="noindent">不过，由于 IPv6 影响 TCP/IP 网络中许多其他功能，需要更多 RFC 来定义 IPv6 的细节。一些 RFC 定义如何从 IPv4 迁移到 IPv6，另一些则定义熟悉协议的新版本，或用新协议替代旧协议。例如：</p>

<p class="ul-noindent"><strong>旧版 OSPF 版本 2 升级为 OSPF 版本 3：</strong> 较早的开放最短路径优先（OSPF）版本 2 适用于 IPv4，但不适用于 IPv6，因此创建了新版 <a id="key_269" href="#ref-gloss_293"><span class="blue">OSPF 版本 3（OSPFv3）</span></a> 来支持 IPv6。（注：OSPFv3 后来又升级为可同时通告 IPv4 和 IPv6 路由。）</p>

<p class="ul-noindent"><strong>ICMP 升级为 ICMP 版本 6：</strong> 互联网控制消息协议（ICMP）与 IPv4 配合良好，但需要修改才能支持 IPv6。新名称为 ICMPv6。</p>

<p class="ul-noindent"><strong>ARP 被邻居发现协议取代：</strong> 对于 IPv4，地址解析协议（ARP）发现邻居使用的 MAC 地址。IPv6 用功能更广泛的邻居发现协议（NDP）替代 ARP。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para">大量互联网 RFC 定义了 IPv6。最近在 <a href="https://www.rfc-editor.org">https://www.rfc-editor.org</a> 搜索“IPv6”，得到超过 550 篇这样的 RFC。</p>

</div>

<p class="noindent">虽然广义的 <em>IPv6</em> 一词包含许多协议，但名为 IPv6 的这一具体协议定义了新的 128 位 IPv6 地址。当然，以二进制书写这些地址会很麻烦，它们甚至可能超出一张<span id="page_643" data-epub-type="pagebreak"></span>纸的宽度！IPv6 定义了更短的十六进制格式，最多需要 32 个十六进制数字（每个十六进制数字表示 4 位），并提供了缩写十六进制地址的方法。</p>

<p class="noindent">例如，以下都是 IPv6 地址，每个地址的十六进制数字不超过 32 个。</p>

<p class="codelink"><a href="#code-f0643-01" id="f0643-01a">点击此处查看代码原图</a></p>



<pre class="pre" tabindex="0"><code>2345:1111:2222:3333:4444:5555:6666:AAAA

2000:1:2:3:4:5:6:A

<p class="noindent">与 IPv4 一样，IPv6 定义了首部，其中有存放源地址和目的地址的字段。与 IPv4 相比，IPv6 首部除了扩大地址字段，还作了一些其他改动。不过，虽然 IPv6 首部比 IPv4 首部更大，它实际上却更简单，这是有意的设计。<a href="#ch25fig03">图 25-3</a> 展示了 IPv6 首部中必需的 40 字节部分。</p>

<h4 class="h4" id="ch25lev2sec3">IPv6 路由</h4>

<p class="noindent">与 IPv6 的许多功能一样，从总体上看，IPv6 路由与 IPv4 路由相同，只有考察具体细节才能看清差异。暂时保持概括性讨论，IPv6 与 IPv4 以相同方式使用以下概念：</p>

<ul class="sq">

<li><p class="bull">终端用户设备要能够构造 IPv6 数据包并通过接口发送，就需要在该接口上具有 IPv6 地址。</p>

</li>

<li><p class="bull">终端用户主机需要知道默认路由器的 IPv6 地址；如果目的主机位于不同子网，主机就将 IPv6 数据包发送给该默认路由器。</p></li>

<li><p class="bull">IPv6 路由器在路由每个 IPv6 数据包时，对其解封装并重新封装。</p></li>

<li><p class="bull">IPv6 路由器将数据包的目的 IPv6 地址与自身的 IPv6 路由表比较，作出路由决策；匹配路由列出下一步向何处发送 IPv6 数据包的指引。</p></li>

</ul>

<div class="note">

<p class="note-title"><span id="page_644" data-epub-type="pagebreak"></span>注意</p>

<p class="note-para">将上述列表中每一处 IPv6 替换为 IPv4，所有说法对 IPv4 也同样成立。</p>

</div>

<p class="noindent">接下来的几幅图通过示例展示这些概念。首先，<a href="#ch25fig04">图 25-4</a> 展示了主机上的几个设置。主机 PC1 的地址为 2345::1，也知道其默认网关为 2345::2。（这两个值都是真实 IPv6 地址的有效缩写。）要将 IPv6 数据包发送给另一个 IPv6 子网中的主机 PC2，PC1 会创建 IPv6 数据包，并将其发送给自己的默认网关 R1。</p>

<p class="noindent">最后，在大多数企业网络中，路由器会同时路由 IPv4 和 IPv6 数据包。也就是说，公司不会决定采用 IPv6 后，就在某个周末深夜关闭所有 IPv4，并在每台设备上启用 IPv6。IPv6 允许逐步迁移，在此期间，部分或全部路由器同时转发 IPv4 和 IPv6 数据包。（同时运行 IPv4 与 IPv6 的迁移策略称为<em>双栈（dual stack）</em>。）你只需在现有 IPv4 路由配置的基础上，额外配置路由器以路由 IPv6 数据包。</p>

<h3 class="h3" id="ch25lev1sec4">IPv6 地址格式与约定</h3>

<p class="noindent">CCNA 考试要求具备处理 IPv4 地址的一些基本技能。例如，你需要能够解读 172.21.73.14 这样的 IPv4 地址，使用 /25 这样的前缀式掩码，并理解它与某个具体 IPv4 地址配合时的含义。你还需要能够根据地址和掩码（如 172.21.73.14/25）求出子网 ID。</p>

<p class="noindent">本章第二大节讨论 IPv6 地址中的相同概念，具体包括：</p>

<h4 class="h4" id="ch25lev2sec6">缩写和展开 IPv6 地址</h4>

<p class="noindent">IPv6 还定义了缩短书写或输入地址的方法。为什么？虽然使用 32 位十六进制数比使用 128 位二进制数方便得多，但 32 个十六进制数字对于记忆、在命令输出中识别和在命令行输入而言，仍然很多。IPv6 地址缩写规则可缩短这些数字。</p>

<p class="noindent">即使你输入地址的全部 32 个十六进制数字，计算机和路由器也会使用最短缩写。因此，即便你更愿意使用较长的完整 IPv6 地址，也需要能够解读路由器或主机列出的缩写地址。本节先介绍地址缩写，再介绍地址展开。</p>

<section>

<h5 class="h5" id="ch25lev3sec1">缩写 IPv6 地址</h5>

<p class="noindent">两条基本规则允许你或计算机缩短 IPv6 地址：</p>

<ol class="number">

<li><p class="number">在每个由四个十六进制数字组成的四位组内，删除左侧三个位置中最多三个前导 0。（注意：这一步中，0000 四位组会留下一个 0。）</p>

</li>

<li><p class="number">将最长的一段连续两个或更多 0000 四位组替换为双冒号。缩写 :: 表示“两个或更多全 0 四位组”。不过，一个地址中只能使用一次这种替换，用于最长的连续 0000 四位组序列；若并列最长，则替换第一段。</p></li>

</ol>

<p class="noindent">例如，考虑以下 IPv6 地址。粗体数字表示可以缩写的数字。</p>

<p class="codelink"><a href="#code-f0647-01" id="f0647-01a">点击此处查看代码原图</a></p>



<pre class="pre" tabindex="0"><code>2100:<strong>0000</strong>:<strong>0000</strong>:<strong>000</strong>1:<strong>0000</strong>:<strong>0000</strong>:<strong>0000</strong>:<strong>00</strong>56</code></pre>

<p class="noindent"><span id="page_648" data-epub-type="pagebreak"></span>应用第一条规则时，独立查看全部八个四位组，分别删除所有前导 0。注意，其中五个四位组有四个 0，因此只删除三个前导二进制 0，留下以下值：</p>

<pre class="pre" tabindex="0"><code>2100:0:0:1:0:0:0:56</code></pre>

<p class="noindent">虽然这种缩写有效，但仍可使用第二条规则进一步缩写。本例中，有两处包含连续多个仅有一个 0 的四位组。选择最长的一段，用 :: 替换，得到最短的合法缩写：</p>

<pre class="pre" tabindex="0"><code>2100:0:0:1::56</code></pre>

<p class="noindent">虽然 2100:0:0:1::56 确实是最短缩写，但本例也便于看清缩写 IPv6 地址时最常见的两个错误。首先，绝不能删除四位组中的尾随 0（位于右侧的 0）。本例中，第一个四位组 2100 完全不能缩短，因为两个 0 位于末尾。因此，下面这个第一个四位组仅以 FE 开头的地址，不是原 IPv6 地址的正确缩写：</p>

<pre class="pre" tabindex="0"><code>21:0:0:1::56</code></pre>

<p class="noindent">第二个常见错误是将两段 0000 四位组都替换为双冒号。例如，以下缩写对于本主题给出的原始 IPv6 地址是不正确的：</p>

<pre class="pre" tabindex="0"><code>2100::1::56</code></pre>

<p class="noindent">这种缩写不正确的原因是，要还原完整地址时，无法确定应在每个 :: 处代入多少个全 0 四位组。</p>

</section>

<section>

<h5 class="h5" id="ch25lev3sec2">展开缩写后的 IPv6 地址</h5>

<p class="noindent">要将 IPv6 地址展开为完整的 32 位十六进制数，可使用两条类似规则，它们基本上逆转了前两条规则的逻辑：</p>

<ol class="number">

<li><p class="number">根据需要，在每个四位组前补 0，直到该组有四个十六进制数字。</p>

</li>

<li><p class="number">如果存在双冒号（::），先统计当前显示的四位组数量，总数应小于 8。用多个 0000 四位组替换 ::，使总数达到八个。</p></li>

</ol>

<h4 class="h4" id="ch25lev2sec7">表示地址的前缀长度</h4>

<p class="noindent">IPv6 使用与 IPv4 子网掩码类似的掩码概念，称为<a id="key_270" href="#ref-gloss_313"><span class="blue">前缀长度（prefix length）</span></a>。类似于 IPv4 前缀式掩码，IPv6 前缀长度写成 / 后接一个十进制数（IPv6 没有对应的点分十进制掩码）。前缀长度规定，某个子网前缀内的所有地址，其左侧多少位具有相同的值。如果概括为“前缀／长度”，那么子网前缀中的所有地址，在长度所指定的起始位数内，都以相同的值开头。</p>

<p class="noindent">在文档中书写 IPv6 地址和前缀长度时，为便于阅读，可以在 / 前留一个空格，也可以不留。不过，Cisco 设备上的命令通常不允许在 / 前后加空格。</p>

<p class="codelink"><a href="#code-f0649-01" id="f0649-01a">点击此处查看代码原图</a></p>



<pre class="pre" tabindex="0"><code>2222:1111:0:1:A:B:C:D/64

2222:1111:0:1:A:B:C:D /64</code></pre>

<p class="noindent">最后，前缀长度表示位数，因此 IPv6 的合法取值范围为 0 到 128，含两端。</p>

</section>

<section>

<h4 class="h4" id="ch25lev2sec8">计算 IPv6 子网前缀（子网 ID）</h4>

<p class="noindent">对于 IPv4，可以根据 IP 地址及其子网掩码计算子网 ID。对于 IPv6 子网划分，也可以根据 IPv6 地址及其前缀长度，计算与子网 ID 对应的 <em>IPv6</em> <a id="key_272" href="#ref-gloss_391"><span class="blue">子网前缀（subnet prefix）</span></a>。</p>

<p class="noindent">与不同的 IPv4 子网掩码类似，一些 IPv6 前缀长度使求子网前缀的计算很容易，另一些则更难。本节介绍较简单的情况，主要是因为 IPv6 地址空间足够大，让大家都能选择使计算更容易的前缀长度。</p>

</section>

<section>

<h4 class="h4" id="ch25lev2sec9">求 IPv6 子网前缀</h4>

<p class="noindent">在 IPv6 中，子网前缀表示一组 IPv6 地址。目前，本节只关注如何计算代表该子网前缀的数值。<a href="v1-26.html#ch26">第 26 章</a>“<a href="v1-26.html#ch26">IPv6 编址与子网划分</a>”将进一步解释这些数字的实际含义。</p>

<p class="noindent">每个 IPv6 子网前缀，或者简称子网，都有一个表示该地址组的数字。许多人沿用 IPv4 的术语，将其称为子网号或子网 ID。与 IPv4 一样，可以根据 IPv6 地址及前缀长度，使用相同的总体规则求子网前缀。如果前缀长度为 /P，规则如下：</p>

<ol class="number">

<li><p class="number">复制前 P 位。</p>

</li>

<li><p class="number">将其余位改为 0。</p></li>

</ol>

<p class="noindent">如果前缀长度恰好是 4 的倍数，就不必按二进制位思考，而可以按十六进制数字思考。前缀长度是 4 的倍数，意味着<span id="page_650" data-epub-type="pagebreak"></span>每个十六进制数字要么被复制，要么被改为十六进制 0。例如，/44 前缀长度对应 11 个十六进制数字，/48 对应 12 个，依此类推。为说明完整，如果前缀长度确实是 4 的倍数，过程就变为：</p>

<ol class="number">

<li><p class="number">将前缀长度（以位为单位）除以 4，确定子网前缀包含的十六进制数字数量。</p></li>

<li><p class="number">复制第一步确定的属于子网前缀的十六进制数字。</p></li>

<li><p class="number">将其余十六进制数字改为 0。</p></li>

</ol>

<p class="noindent"><a href="#ch25fig07">图 25-7</a> 展示了前缀长度为 64 的示例。步骤 1 根据 /64 计算得出子网前缀含 16 个十六进制数字。步骤 2 复制 IPv6 地址的前 16 个数字，步骤 3 将其余数字记为十六进制 0。</p>

<h4 class="h4" id="ch25lev2sec10">处理更难的 IPv6 前缀长度</h4>

<p class="noindent"><a href="v1-26.html#ch26">第 26 章</a> 将进一步介绍 IPv6 子网划分，它比 IPv4 子网划分容易学习得多。IPv6 子网划分较简单的原因之一，是包括 RFC 4291《IPv6 编址体系结构》在内的多篇 RFC 建议，所有已部署子网都使用 /64 前缀长度。</p>

<p class="noindent">在制定企业子网划分计划时，有时也需要处理短于 /64 的前缀长度。为此，本章最后一个主题提供其他较短前缀长度的练习，采用较简单的、前缀长度为 4 的倍数的情况。</p>

<p class="noindent">例如，考虑以下 IPv6 地址和前缀长度：</p>

<p class="codelink"><a href="#code-f0651-01" id="f0651-01a">点击此处查看代码原图</a></p>



<pre class="pre" tabindex="0"><code>2000:1234:5678:9ABC:1234:5678:9ABC:1111/56</code></pre>

<p class="noindent">由于本例使用 /56 前缀长度，子网前缀包括地址的前 56 位，也就是前 14 个完整十六进制数字。其余十六进制数字置零，得到以下子网前缀：</p>

<p class="codelink"><a href="#code-f0651-02" id="f0651-02a">点击此处查看代码原图</a></p>



<pre class="pre" tabindex="0"><code>2000:1234:5678:9A<strong>00</strong>:<strong>0000:0000:0000:0000</strong>/56</code></pre>

<p class="noindent">此值末尾有四个全 0 四位组，可以缩写如下：</p>

<pre class="pre" tabindex="0"><code>2000:1234:5678:9A<strong>00</strong>::/56</code></pre>

<p class="noindent">本例展示了一个容易出错的地方。有时，人们看到 /56，认为它表示前 14 个十六进制数字，这是正确的。但随后他们复制前 14 个数字，再添加双冒号，写成如下形式：</p>

<pre class="pre" tabindex="0"><code>2000:1234:5678:<strong>9A</strong>::/56</code></pre>

<h3 class="h3" id="ref-appclev1sec25">第 25 章</h3>

<p class="quiz"><strong><a id="ref-ques25_1" href="#quess25_1">1</a>．</strong> C。NAT，具体而言是允许多台主机使用私有 IPv4 地址、同时由单个公有 IPv4 地址支持的 PAT 功能，是 IPv4 地址耗尽问题的一种短期解决方案。IP 版本 5 曾作为实验性协议短暂存在，与 IPv4 地址耗尽无关。IPv6 直接解决 IPv4 地址耗尽问题，但它是长期解决方案。ARP 不影响所使用的 IPv4 地址数量。</p>

<p class="quiz"><strong><a id="ref-ques25_2" href="#quess25_2">2</a>．</strong> A。路由器路由 IPv6 数据包时使用与 IPv4 数据包相同的步骤。它根据 IPv6 首部中的地址，将目的 IPv6 地址与自身 IPv6 路由表比较，完成路由。因此，路由器丢弃传入帧的数据链路层首部和尾部，留下 IPv6 数据包。它将首部中的目的地址（而不是源地址）与 IPv6 路由表（而不是 IPv4 路由表）比较，再根据匹配路由转发数据包。</p>

<p class="quiz"><strong><a id="ref-ques25_3" href="#quess25_3">3</a>．</strong> D。按本书步骤，第一步删除每个四位组中最多三个前导 0，留下 FE80:0:0:0:100:0:0:123。此值有两段连续的全 0 四位组；将最长的一段替换为 ::，得到 FE80::100:0:0:123。</p>

<p class="quiz"><strong><a id="ref-ques25_4" href="#quess25_4">4</a>．</strong> B。本题有多个容易引发常见错误的四位组，即错误删除十六进制四位组中的尾随 0。只能删除前导 0，不能删除尾随 0。许多四位组都有位于右侧的尾随 0，务必不要删除。</p>

<p class="quiz"><strong><a id="ref-ques25_5" href="#quess25_5">5</a>．</strong> A。IPv6 地址的完整展开形式必须有 32 个数字，而只有一个答案具有 32 个十六进制数字。本例原值显示了四个四位组和一个 ::，因此用四个 0000 四位组替换 ::，使总数达到八组。随后，对不足四个数字的每个四位组补充前导 0，使每组都具有四个十六进制数字。</p>

<p class="quiz"><strong><a id="ref-ques25_6" href="#quess25_6">6</a>．</strong> C。/64 前缀长度意味着地址最后 64 位，也就是最后 16 个数字，应全部置零。这样得到完整子网前缀 2000:0000:0000:0005:0000:0000:0000:0000。最后四个四位组全为 0，是最长且最适合用 :: 替换的一段。再删除其他四位组的前导 0，答案为 2000:0:0:5::/64。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_118"><strong>EIGRP 版本 6（EIGRP version 6）</strong> 支持 IPv6 而不支持 IPv4 的 EIGRP 路由协议版本。</p>

<p class="gloss" id="ref-gloss_211"><span id="ref-page_823" data-epub-type="pagebreak"></span><strong>IP 版本 6（IP version 6）</strong> RFC 2460 及许多其他 RFC 定义的较新版互联网协议，其创建动机是避免 IPv4 地址耗尽问题。</p>

<p class="gloss" id="ref-gloss_213"><strong>IPv4 地址耗尽（IPv4 address exhaustion）</strong> 从 20 世纪 80 年代至今，可用于构建互联网的公有 IPv4 地址不断被消耗的过程，人们预期全球可用的 IPv4 地址最终会用尽。</p>

<p class="gloss" id="ref-gloss_293"><strong>OSPF 版本 3（OSPF version 3）</strong> 最初仅支持 IPv6、不支持 IPv4 的 OSPF 路由协议版本，现在通过地址族配置也支持 IPv4。</p>

<p class="gloss" id="ref-gloss_313"><strong>前缀长度（prefix length）</strong> 在 IPv6 中，IPv6 前缀包含的位数。</p>

<p class="gloss" id="ref-gloss_323"><strong>四位组（quartet）</strong> 本书使用、而其他参考资料不使用的术语，指 IPv6 地址中的一组四个十六进制数字。</p>

<p class="gloss" id="ref-gloss_391"><strong>子网前缀（subnet prefix）</strong> 表示 IPv6 子网的数字所用的术语。</p>

</section>
