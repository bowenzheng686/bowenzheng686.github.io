<p class="noindent-c">如果依赖默认设置，OSPFv2 只需要少量配置命令。要使用 OSPF，只需在网络中计划使用的每个接口上启用它，OSPF 就会通过消息发现邻居，并经由这些邻居学习路由。OSPF 在后台执行许多任务，可以通过大量 OSPF <strong>show</strong> 命令了解细节。不过，对所有可选功能主要使用默认设置时，配置 OSPF 只需几条命令。本章将帮助你学习这些最低限度的设置。</p>

<p class="noindent">本章第一个主要部分介绍使用 <strong>network</strong> 命令的传统 OSPFv2 配置，以及多种相关 <strong>show</strong> 命令。它教你让 OSPFv2 使用默认设置运行，并通过这些 <strong>show</strong> 命令确认协议确实正常工作。</p>

<p class="noindent">第二个主要部分介绍另一种配置选项，称为 OSPF 接口模式，与第一部分展示的传统配置相对。它使用 <strong>ip ospf</strong> <em>process-id</em> <strong>area</strong> <em>area-number</em> 配置命令代替 <strong>network</strong>。</p>

<p class="noindent">此外，第一个主要部分还详细介绍如何设置 OSPF 路由器 ID（RID）。虽然这是可选项，但配置可预测且稳定的 OSPF RID 能简化运维和故障排查，可能是最重要的可选 OSPF 设置。</p>

<h3 class="h3" id="ch22lev1sec3">使用 network 命令实现 OSPFv2</h3>

<p class="noindent">选定 OSPF 设计后（在大型 IP 互联网络中可能很复杂），配置可以简单到只需在各路由器接口上启用 OSPF，并将接口放入正确区域。本章第一个主要部分关注使用传统 OSPFv2 <strong>network</strong> 命令的必需配置，以及一个可选设置：如何设置 <a id="key_253" href="#ref-gloss_291"><span class="blue">OSPF router-id</span></a>。此外，还介绍如何显示各种列表和表格，确认 OSPF 的工作情况。</p>

<p class="noindent">为便于参考和学习，以下概述第一个主要部分介绍的配置步骤：</p>

<p class="step"><span class="stepb">步骤 1。</span>使用全局命令 <strong>router ospf</strong> <em>process-id</em>，进入特定 OSPF 进程的配置模式。</p>

<figure class="figure1">

<img src="assets/volume1/part6-chapter22/images/vol1_config_checklist.jpg" alt="配置检查表按钮图标。">

</figure>

<p class="step"><span class="stepb">步骤 2。</span>（可选）通过以下方式配置 OSPF 路由器 ID：</p>

<ol class="step-lower-alpha">

<li><p class="alpha">使用 <strong>router-id</strong> <em>id-value</em> 路由器子命令定义路由器 ID，或者</p></li>

<li><p class="alpha">使用全局命令 <strong>interface loopback</strong> <em>number</em> 配合 <strong>ip address</strong> <em>address mask</em>，为环回接口配置 IP 地址（从所有正常工作的环回接口中选择最高 IP 地址），或者</p></li>

<li><p class="alpha">依赖接口 IP 地址（从所有正常工作的非环回接口中选择最高 IP 地址）。</p></li>

</ol>

<p class="step"><span class="stepb">步骤 3。</span>使用一条或多条 <strong>network</strong> <em>ip-address wildcard-mask</em> <strong>area</strong> <em>area-id</em> 路由器子命令，在匹配所配地址及掩码的接口上启用 OSPFv2，并将接口上的 OSPF 归入指定区域。</p>

<h4 class="h4" id="ch22lev2sec2">network 命令的通配符匹配</h4>

<p class="noindent">理解第一个示例中的传统 OSPFv2 配置，关键是理解 OSPF <strong>network</strong> 命令。它将命令中的<span id="page_567" data-epub-type="pagebreak"></span>第一个参数与本地路由器每个接口 IP 地址比较，尝试找出匹配。但 <strong>network</strong> 并非一定将整个参数值与接口完整 IPv4 地址比较；路由器可以根据通配符掩码，仅比较 <strong>network</strong> 中地址的部分八位组，具体如下：</p>

<p class="ul-noindent"><strong>通配符 0.0.0.0：</strong>比较全部四个八位组，也就是说，地址必须完全匹配。</p>

<p class="ul-noindent"><strong>通配符 0.0.0.255：</strong>只比较前三个八位组，比较时忽略最后一个。</p>

<p class="ul-noindent"><strong>通配符 0.0.255.255：</strong>只比较前两个八位组，比较时忽略最后两个。</p>

<p class="ul-noindent"><strong>通配符 0.255.255.255：</strong>只比较第一个八位组，比较时忽略最后三个。</p>

<p class="ul-noindent"><strong>通配符 255.255.255.255：</strong>不比较任何部分，表示所有地址都匹配该 <strong>network</strong> 命令。</p>

<p class="noindent">基本上，通配符掩码某个八位组的十进制值为 0，指示 IOS 比较该处数值是否匹配；值为 255，则指示 IOS 在比较时忽略该八位组。</p>

<p class="noindent">由于采用通配符掩码，<strong>network</strong> 命令提供许多灵活选项。例如，在 R1 上可以使用多种 <strong>network</strong> 命令，有的匹配全部接口，有的只匹配部分接口。<a href="#ch22tab02">表 22-2</a> 展示若干选项及说明。</p>

<h4 class="h4" id="ch22lev2sec3"><span id="page_569" data-epub-type="pagebreak"></span>验证 OSPF 运行</h4>

<p class="noindent">如<a href="v1-21.html#ch21">第 21 章</a>“<a href="v1-21.html#ch21">理解 OSPF 概念</a>”所述，OSPF 路由器通过三步，最终将 OSPF 学到的路由加入 IP 路由表。首先创建邻居关系，然后在邻居之间构建并泛洪 LSA，使同一区域每台路由器都拥有相同 LSDB 副本。最后，各路由器独立使用 SPF 算法计算自身 IP 路由，并加入路由表。接下来介绍如何显示各步骤的结果，从而确认 OSPF 是否正确工作。</p>

<p class="noindent"><span id="page_570" data-epub-type="pagebreak"></span>输出细节包含若干重要信息，对多数人来说，这里从右往左看最合适。例如，查看各列标题：</p>

<p class="ul-noindent"><strong>Interface：</strong>本地路由器连接邻居的接口。例如，列表中第一个邻居可通过 R1 的 G0/0/1 到达。</p>

<p class="ul-noindent"><strong>Address：</strong>邻居在该链路上的 IP 地址。第一个邻居是 R2，使用地址 10.1.12.2。</p>

<p class="ul-noindent"><strong>State：</strong>虽然存在许多可能状态，但就本章讨论的细节而言，此例中 FULL 是正确且完全正常工作的状态。</p>

<p class="ul-noindent"><strong>Neighbor ID：</strong>邻居的路由器 ID。</p>

<div class="note">

<p class="note-title">注意</p>

<p class="note-para"><a href="#exa22_4">例 22-4</a> 至<a href="#exa22_8">例 22-8</a> 使用了此处未展示的配置，将 RID 设置为易于识别路由器的值，例如 R2 使用 2.2.2.2，R3 使用 3.3.3.3，依此类推。后面的“<a href="#ch22lev2sec5">配置 OSPF 路由器 ID</a>”一节将介绍设置方法。</p>

</div>

<p class="noindent">OSPF 收敛完成后，路由器应列出每个邻居。在使用指定路由器（DR）的链路上，状态还会在斜杠 / 后列出邻居角色（DR、BDR 或 DROther）。因此，正常工作状态包括：</p>

<p class="ul-noindent"><strong>FULL/ -：</strong>邻居状态为 full，使用“-”而非字母表示该链路不使用 DR／BDR。</p>

<p class="ul-noindent"><strong>FULL/DR：</strong>邻居状态为 full，且邻居是 DR。</p>

<p class="ul-noindent"><strong>FULL/BDR：</strong>邻居状态为 full，且邻居是备用 DR（BDR）。</p>

<p class="ul-noindent"><strong>FULL/DROTHER：</strong>邻居状态为 full，且邻居既不是 DR 也不是 BDR。（这也意味着本地路由器是 DR 或 BDR，因为状态为 FULL。）</p>

<p class="ul-noindent"><strong>2WAY/DROTHER：</strong>邻居状态为 2-way，且邻居既不是 DR 也不是 BDR，即 DROther。（这也意味着本地路由器同样是 DROther，否则状态会达到 full。）</p>

<p class="noindent">路由器的 OSPF 进程建立正常的邻居关系后，路由器直接或通过子网上的 DR 交换 LSDB 内容。<a href="#exa22_5">例 22-5</a> 展示 R1 的 LSDB。有意思的是，在单区域设计中，一旦所有邻居正常且全部 LSA 交换完毕，所有路由器的 LSDB 内容都相同。因此，无论在四台路由器中的哪台执行<a href="#exa22_5">例 22-5</a> 中的 <strong>show ip ospf database</strong>，都应列出完全相同的信息。</p>

<h4 class="h4" id="ch22lev2sec5">配置 OSPF 路由器 ID</h4>

<p class="noindent">虽然 OSPF 有许多其他可选功能，但大多数使用 OSPF 的企业网络都会选择配置每台路由器的 OSPF 路由器 ID。运行 OSPF 的路由器必须有 RID 才能正常工作。默认情况下，会选择一个接口 IP 地址作为 RID。不过，许多工程师倾向于指定各路由器 RID，使 <strong>show ip ospf neighbor</strong> 等命令显示更容易辨认的路由器 ID。</p>

<p class="noindent">Cisco 路由器在重新加载并启动 OSPF 进程时，按以下过程选择 RID。请注意，一旦某一步找到可用值，就停止继续查找。</p>

<ol class="number">

<li><p class="number">如果配置了 OSPF 子命令 <strong>router-id</strong> <em>rid</em>，就使用该值作为 RID。</p>

</li>

<li><p class="number">如果环回接口配置了 IP 地址，且接口状态为 up，路由器就从这些环回接口中选择数值最高的 IP 地址。</p></li>

<li><p class="number">路由器从接口状态码（第一个状态码）为 up 的所有其他接口中，选择数值最高的 IP 地址。（换句话说，up/down 接口也会被 OSPF 纳入 RID 选择范围。）</p></li>

</ol>

<p class="noindent">第一和第三个条件应该容易理解：RID 要么显式配置，要么取自正常工作接口的 IP 地址。但本书尚未解释步骤 2 提到的<em>环回接口</em>概念。</p>

<p class="noindent">环回接口是虚拟接口，可通过 <strong>interface loopback</strong> <em>interface-number</em> 配置，其中 <em>interface-number</em> 为整数。除非被管理性关闭，环回接口始终处于 up/up。例如，简单配置 <strong>interface loopback 0</strong>，再配置 <strong>ip address 2.2.2.2 255.255.255.0</strong>，就会创建环回接口并分配 IP 地址。因为不依赖任何硬件，只要 IOS 运行，它就可以保持 up/up，因此很适合作为 OSPF RID 的依据。</p>

<h3 class="h3" id="ch22lev1sec4">使用接口子命令实现 OSPFv2</h3>

<p class="noindent">从 Cisco 路由器最早支持 OSPFv2 开始，配置就采用本章讨论的 OSPF <strong>network</strong> 命令。然而，这种风格可能令人困惑，而且确实需要一定解释。因此，Cisco 增加另一种 OSPFv2 配置选项，称为 OSPF 接口配置。</p>

<p class="noindent">较新的接口式 OSPF 配置仍在接口上启用 OSPF，但直接通过 <strong>ip ospf</strong> 接口子命令完成。它不使用 <strong>network</strong> 的间接逻辑匹配接口，而是在各接口配置子命令，直接启用 OSPFv2。</p>

<h3 class="h3" id="ref-appclev1sec22">第 22 章</h3>

<p class="quiz"><strong><a id="ref-ques22_1" href="#quess22_1">1</a>．</strong> B。<strong>network 10.0.0.0 0.255.255.255 area 0</strong> 匹配三个接口 IP 地址，因为它只比较第一个八位组 10，三者都匹配。</p>

<p class="quiz-para">三个错误答案都无法匹配全部三个接口 IP 地址，因为每个都会比较至少一个与 <strong>network</strong> 中地址不匹配的八位组：</p>

<p class="ul-noindent2"><strong>network 10.0.0.0 0.0.0.0</strong> 要求四个八位组完全匹配 10.0.0.0，因此不匹配任何接口。</p>

<p class="ul-noindent2"><strong>network 10.0.0.0 0.0.0.255</strong> 要求前三个八位组（10.0.0）完全匹配，因此不匹配任何接口 IP 地址。</p>

<p class="ul-noindent2"><strong>network 10.0.0.0 0.0.255.255</strong> 要求前两个八位组（10.0）完全匹配，因此不匹配任何接口 IP 地址。</p>

<p class="quiz"><strong><a id="ref-ques22_2" href="#quess22_2">2</a>．</strong> A。<strong>network 10.1.0.0 0.0.255.255 area 0</strong> 命令匹配所有以 10.1 开头的 IP 地址，在所有接口上为区域 0 启用 OSPF。三个错误答案都无法匹配全部三个接口 IP 地址，因为它们各自至少比较一个与 <strong>network</strong> 命令中的地址不匹配的八位组：</p>

<p class="ul-noindent2"><strong>network 10.0.0.0 0.255.255.0</strong> 忽略中间两个八位组，但会将第一个（10）和最后一个（0）八位组与接口地址比较。第一个八位组匹配，但第四个八位组不匹配任何地址。</p>

<p class="ul-noindent2"><span id="ref-page_798" data-epub-type="pagebreak"></span><strong>networ</strong>k <strong>10.1.1.0 0.x.1x.0</strong> 不符合语法要求，因为通配符掩码中包含字母（x）。如果在配置模式下尝试输入，会被拒绝。</p>

<p class="ul-noindent2"><strong>network 10.1.1.0 255.0.0.0</strong> 忽略第一个八位组，但将后三个八位组（1.1.0）与地址比较。没有任何地址以 1.1.0 结尾，因此没有地址匹配此命令。</p>

<p class="quiz"><strong><a id="ref-ques22_3" href="#quess22_3">3</a>．</strong> A 和 E。三个错误答案中，有两个是真实的命令，只是不会列出 OSPF 邻居。<strong>show ip ospf interface brief</strong> 列出启用了 OSPF 的接口，但不列出邻居。<strong>show ip interface</strong> 列出接口的 IPv4 详细信息，但没有 OSPF 相关信息。另一个错误答案 <strong>show ip neighbor</strong> 不是有效的 IOS 命令。</p>

<p class="quiz"><strong><a id="ref-ques22_4" href="#quess22_4">4</a>．</strong> B。选择 OSPF RID 时，首先检查 OSPF 进程配置中的 <strong>router-id</strong> 命令，但该路由器没有此命令。下一条规则考虑所有正常工作（up/up）的环回接口，OSPF 从中选择数值最大的 IP 地址。本例有两个这样的环回接口，其中环回接口 1 的地址为 10.8.8.8，数值最大。</p>

<p class="quiz"><strong><a id="ref-ques22_5" href="#quess22_5">5</a>．</strong> B。使用 OSPFv2 接口配置模式时，配置与传统方式基本相同，只有少数例外。不再需要 <strong>network</strong> 路由器子命令，而是在每个需要启用 OSPF 的接口上配置 <strong>ip ospf</strong> <em>process-id</em> <strong>area</strong> <em>area-id</em> 接口子命令。此命令指定应在接口上启用的 OSPF 路由进程，以及 OSPFv2 区域。</p>

<p class="quiz"><strong><a id="ref-ques22_6" href="#quess22_6">6</a>．</strong> A 和 D。许多 OSPF <strong>show</strong> 命令并不说明 OSPF 是通过接口子命令（<strong>ip ospf</strong> 接口子命令）还是路由器子命令（<strong>network</strong> 命令）启用的。<strong>show ip protocols</strong> 命令在“Routing on Interfaces Configured Explicitly”（在显式配置的接口上进行路由）标题下列出所有通过 <strong>ip ospf interface</strong> 子命令启用了 OSPF 的接口。此外，<strong>show ip ospf interface</strong> 命令会为每个接口列出多行输出，其中包含“Attached via Interface Enable”（通过接口启用方式关联）这一短语。虽然不在答案中，你也可以使用 <strong>show running-config</strong> 或 <strong>show startup-config</strong> 命令查看配置。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_289"><strong>OSPF 邻居（OSPF neighbor）</strong> 当本地路由器与同一子网上的另一台路由器都使用 OSPF，且采用适当的 OSPF 设置，从而选择相互交换路由信息时，本地路由器对该另一台路由器所持的关系状态。</p>

<p class="gloss" id="ref-gloss_291"><strong>OSPF 路由器 ID（OSPF router-id）</strong> OSPF 中用于唯一标识 OSPF 域内每台 OSPF 路由器的 32 位数字，通常采用点分十进制表示，也允许列为整数。</p>
