<h2 class="h2a">广域网与 IP 路由基础</h2>
<p class="objset">本章涵盖以下考试主题：</p>
<p class="obj">1.0 网络基础</p>
<p class="obj1">1.1 解释网络组件的角色和功能</p>
<p class="obj2">1.1.a 路由器</p>
<p class="obj1">1.2 描述网络拓扑架构的特征</p>
<p class="obj2">1.2.d 广域网（WAN）</p>
<p class="noindent-c">本章介绍广域网以及 TCP/IP 网络层的各项功能。</p>
<p class="noindent">首先谈到广域网时，需要注意，当前 CCNA 考试大纲并不将广域网本身作为详细考查的目标。但是，要理解 IP 路由，就需要掌握本章第一个主要部分介绍的两类广域网链路的基础知识：串行链路和以太网广域网链路。这些链路最基本的形式，是连接位于相距几英里到数百英里的不同站点中的路由器，从而实现远程站点之间的通信。</p>
<p class="noindent">本章其余内容转向 TCP/IP 网络层，并以 IP 为讨论中心。第二部分介绍 IP 的主要功能：路由、编址和路由协议。最后一部分介绍 IP 之外的几个协议，它们同样帮助 TCP/IP 网络层构建网络，实现端点之间的端到端通信。</p>

<section>
<h3 class="h3" id="ch03lev1sec3">广域网</h3>
<p class="noindent">想象一家企业分支机构中平常的一天。用户坐在某台终端设备前，例如 PC、平板电脑或手机。设备通过以太网电缆或无线局域网连接到局域网。但是，用户此时正在查看某个网站上的信息，而 Web 服务器位于公司总部。为了完成访问，数据需要经过一条或多条<a id="key_056" href="#ref-gloss_442"><span class="blue">广域网（WAN）</span></a>链路。</p>
<p class="noindent">广域网技术定义了用于远距离通信的物理层（第 1 层）标准和数据链路层（第 2 层）协议。第一节介绍两种广域网技术：租用线路广域网和以太网广域网。自 20 世纪 60 年代起，租用线路广域网就已成为一种选择，但如今很少使用。不过，由于租用线路广域网存在多年，而且从 CCNA 诞生以来就一直是考试内容的一部分，因此备考当前 CCNA 仍需要了解其基础知识。</p>
<p class="noindent">相较于租用线路，如今企业更常使用<em>以太网广域网</em>链路。这些链路使用与上一章讨论的相同的以太网数据链路层协议，但采用能够覆盖广域网所需更长距离的以太网物理层标准。接下来的内容先介绍租用线路广域网，再介绍以太网广域网。</p>
<section>
<h4 class="h4" id="ch03lev2sec1">租用线路广域网</h4>
<p class="noindent">为了通过广域网连接多个局域网，互联网络在各个局域网上连接路由器，并在路由器之间使用广域网链路。对于广域网链路，企业的网络工程师必须先进行规划，再向广域网服务提供商订购某种链路。提供商会在两台路由器之间安装广域网链路，如<a href="#ch03fig01">图 3-1</a> 所示。请注意，租用线路广域网链路通常以曲折的闪电形线条表示，暗示这条广域网链路是一条租用线路。</p>

<h5 class="h5" id="ch03lev3sec1">租用线路的物理细节</h5>
<p class="noindent"><a id="key_049" href="#ref-gloss_230"><span class="blue">租用线路</span></a>是一种物理层服务，使用全双工逻辑，以预先确定的速率在两个方向上传送比特。实际上，从概念上看，它就像在两台路由器之间连接了一条全双工以太网交叉链路，如<a href="#ch03fig02">图 3-2</a> 所示。租用线路使用两对导线，每个发送方向各一对，因此能够实现全双工工作。</p>
<figure class="image-c" id="ch03fig02">
<img src="assets/volume1/part1-chapter3/images/vol1_03fig02.jpg" aria-describedby="a03fig02" alt="示意图展示阻止中央局域网上建立 OSPF 邻居关系的问题。译注：原书替代文本与图像不符；实际图像用两个方向的双绞线电路，示意相距 1000 英里的两栋建筑中 R1 与 R2 之间的租用线路。">
<figcaption>
<p class="title-f"><strong>图 3-2</strong> <em>租用线路服务的概念图</em></p>
<aside class="hidden" id="a03fig02">
<p>网络设计包含四台路由器 R1、R2、R3 和 R4。R1 和 R3 具有唯一的路由器 ID（RID）：R1 的 RID 为 1.1.1.1，R3 的 RID 为 1.1.1.1（应为 3.3.3.3）。路由器通过接口互连。R1 的 G0/1 接口连接子网 10.1.11.1/24，G0/0 接口连接子网 10.1.1.1/24。R2 的 G0/1 接口连接子网 10.1.22.2/24，G0/0 接口连接子网 10.1.1.2/24，标注为“错误配置：区域 1；预期设计：仅区域 0”。R3 的 G0/0 接口连接子网 10.1.1.3/24，G0/1 接口连接子网 10.1.33.3/24。R4 的 G0/0 接口连接子网 10.1.1.4/24，并标有 Hello／Dead 为 5／20，G0/1 接口连接子网 10.1.44.4/24。 译注：原书这段隐藏说明与实际图 3-2 不符。图中是两栋建筑内的 R1、R2 及各自的局域网，以两个方向的双绞线电路示意跨越 1000 英里的租用线路，没有 OSPF 邻居配置。</p>

<p class="noindent">要建立租用线路，链路两端的路由器之间必须存在某条物理路径。物理布线必须从各路由器所在的客户建筑物延伸出去；但是，<a id="key_055" href="#ref-gloss_404"><span class="blue">电信公司（telco）</span></a>并不是简单地在两栋建筑物之间安装一根电缆，而是利用通常规模庞大且复杂的网络，营造出两台路由器之间仿佛存在一根电缆的效果。</p>
<p class="noindent"><a href="#ch03fig03">图 3-3</a> 展示了电信公司网络中一小部分的概念图。电信公司将设备放置在称为中心局（CO）的建筑物中，并从中心局向城市中的几乎所有其他建筑物铺设电缆，期望将来向这些建筑物中的用户出售服务。随后，电信公司配置其交换设备，利用各条电缆的一部分容量双向发送数据，从而在两台路由器之间形成等效于交叉电缆的连接。</p>

<h5 class="h5" id="ch03lev3sec2">租用线路的数据链路层细节</h5>
<p class="noindent">租用线路提供第 1 层服务。换句话说，它承诺在连接到租用线路的设备之间传送比特，但租用线路本身并不定义在线路上使用哪种数据链路层协议。因此，为了使用租用线路，线路两端的路由器会采用以下两种数据链路层协议之一：高级数据链路控制（<a id="key_043" href="#ref-gloss_163"><span class="blue">HDLC</span></a>）或点对点协议（PPP）。</p>
<p class="noindent">所有数据链路层协议都承担类似职责：控制数据通过某种特定类型的物理链路被正确交付。例如，以太网数据链路层协议使用目的地址字段标识应接收数据的正确设备，并通过 FCS 字段让接收设备判断数据是否正确到达。广域网数据链路层协议 HDLC 和 PPP 提供类似功能。</p>
<p class="noindent"><span id="page_67" data-epub-type="pagebreak"></span>由于租用线路采用简单的点对点拓扑，HDLC 和 PPP 需要完成的工作甚至比以太网更少。以 HDLC 为例，当一台路由器通过租用线路发送 HDLC 帧时，帧只能到达一个目的设备，也就是链路另一端的路由器。因此，虽然 HDLC 有地址字段，但目的设备已经隐含确定，实际地址值并不重要。这有点像我和朋友 Gary 两个人一起吃午饭：我不必每句话都以“嘿，Gary”开头，他知道我是在对他说话。</p>

<h5 class="h5" id="ch03lev3sec3">路由器如何使用广域网数据链路</h5>
<p class="noindent">租用线路连接路由器，而路由器专注于将分组送达目的主机。但是，路由器在物理上同时连接局域网和广域网，这些网络都要求将数据放在数据链路层帧中发送。因此，了解 HDLC 和 PPP 的一些知识之后，再思考路由器发送数据时如何使用这些数据链路层协议，会很有帮助。</p>
<p class="noindent">首先，TCP/IP 网络层关注的是将 <a id="key_047" href="#ref-gloss_207"><span class="blue">IP 分组</span></a>从发送主机转发到目的主机。底层的局域网和广域网只是把分组传送到下一台路由器或终端用户设备的手段。<a href="#ch03fig05">图 3-5</a> 展示了这种网络层视角。</p>
<span id="page_68" data-epub-type="pagebreak"></span>
<figure class="image-c" id="ch03fig05">
<img src="assets/volume1/part1-chapter3/images/vol1_03fig05.jpg" aria-describedby="a03fig05" alt="示意图展示从 PC1 发往 PC2 的 IP 地址的分组，依据 IP 路由逻辑经过局域网和广域网的过程。">
<figcaption>
<p class="title-f"><strong>图 3-5</strong> <em>跨越局域网和广域网的 IP 路由逻辑</em></p>
<aside class="hidden" id="a03fig05">
<p>PC1 的网络层逻辑引导它将分组发送给最近的路由器 R1。R1 利用网络层逻辑确定最佳路径，通过租用线路将分组转发给 R2。接着，R2 的网络层逻辑判断局域网链路是到达 PC2 的合适路径。这一过程的每一步都体现了 IP 路由的基本原理。</p>
</aside>
</figcaption>
</figure>
<p class="noindent">按照图中的步骤，对于 PC1 发往 PC2 的 IP 地址的分组：</p>
<ol class="number">
<li><p class="number">PC1 的网络层（IP）逻辑要求它将分组发送给附近的路由器 R1。</p></li>
<li><p class="number">路由器 R1 的网络层逻辑要求它下一步通过租用线路，将分组转发（路由）给路由器 R2。</p></li>
<li><p class="number">路由器 R2 的网络层逻辑要求它下一步通过局域网链路，将分组转发（路由）给 PC2。</p></li>
</ol>
<p class="noindent">虽然<a href="#ch03fig05">图 3-5</a> 展示了网络层逻辑，但 PC 和路由器必须依赖图中的局域网和广域网，才能实际传送分组中的比特。<a href="#ch03fig06">图 3-6</a> 使用相同的网络和分组，但这次展示了主机与路由器使用的部分数据链路层逻辑。基本上，分组在互联网络中经过三跳时，分别经历三个独立的数据链路层封装步骤：从 PC1 到 R1、从 R1 到 R2，以及从 R2 到 PC2；每一步都将分组封装在数据链路层帧中。</p>
<figure class="image-c" id="ch03fig06">
<img src="assets/volume1/part1-chapter3/images/vol1_03fig06.jpg" aria-describedby="a03fig06" alt="示意图展示 IP 分组从 PC1 传送到 PC2 的 IP 地址时，路由器进行解封装和重新封装的过程。">
<figcaption>
<p class="title-f"><strong>图 3-6</strong> <em>路由器对 IP 分组解封装和重新封装的基本概念</em></p>
<aside class="hidden" id="a03fig06">
<p>PC1 将 IP 分组封装到发往路由器 R1 的以太网帧中。R1 收到后，从以太网帧中解封装出 IP 分组，再将其重新封装到 HDLC 帧中，转发给路由器 R2。随后，R2 从 HDLC 帧中解封装出分组，并重新封装到以 PC2 为目的地的以太网帧中。</p>
</aside>
</figcaption>
</figure>
<p class="noindent">仍以 PC1 发往 PC2 的 IP 地址的分组为例，按照图中的步骤：</p>
<ol class="number">
<li><p class="number">为了将 IP 分组下一步发送给路由器 R1，PC1 把该分组封装到一个目的 MAC 地址为 R1 的以太网帧中。</p></li>
<li><p class="number">路由器 R1 从以太网帧中解封装（取出）IP 分组，再使用 HDLC 首部和尾部，将分组封装（放入）HDLC 帧中，并将 HDLC 帧转发给下一台路由器 R2。</p></li>
<li><p class="number">路由器 R2 从 HDLC 帧中解封装（取出）IP 分组，再将分组封装（放入）目的 MAC 地址为 PC2 的以太网帧中，最后将以太网帧转发给 PC2。</p></li>
</ol>
<p class="noindent">总的来说，使用 HDLC 的租用线路在两台路由器之间构成广域网链路，使路由器能够为所连接局域网中的设备转发分组。租用线路本身提供在两个方向上传送比特的<span id="page_69" data-epub-type="pagebreak"></span>物理手段；HDLC 帧则提供正确封装网络层分组的方式，使其能够穿过路由器之间的链路。同样，如果路由器使用 PPP 而非 HDLC，就会将分组封装在 PPP 帧而非 HDLC 帧中。</p>
<p class="noindent">租用线路具有多项优点，因此在广域网市场中长期存在。对客户来说，这些线路使用简单、可获得性高、质量好，而且是私有的。但与较新的广域网技术相比，它们也有一些不足，例如成本较高，服务安装通常需要更长的交付周期。此外，以今天的标准来看，租用线路广域网链路速度较慢，最快的租用线路速率也只有每秒数十兆比特。更新、更快的广域网技术已推动市场逐渐离开租用线路；在 21 世纪 20 年代，以太网广域网已经十分常见。</p>
</section>

<section>
<h4 class="h4" id="ch03lev2sec2">以太网作为广域网技术</h4>
<p class="noindent">在以太网问世后的最初几十年里，它只适用于局域网。受电缆长度和设备的限制，局域网或许能够延伸一两千米，用于园区局域网，但这已是其极限。</p>
<p class="noindent">随着时间推移，IEEE 改进了以太网标准，使以太网逐渐成为一种适用的广域网技术。例如，1000BASE-LX 标准使用单模光纤布线，支持 5 km 的电缆长度；1000BASE-ZX 标准则支持更长的 70 km 电缆长度。随着 IEEE 不断提高光纤以太网链路的布线距离，以太网成为了广域网技术的一种可行选择。</p>
<p class="noindent">如今，许多广域网服务提供商（SP）都提供基于以太网的广域网服务。这些服务种类繁多，名称各异，但都采用相似的模式：在客户站点与 SP 的网络之间使用以太网，如<a href="#ch03fig07">图 3-7</a> 所示。</p>
<figure class="image-c" id="ch03fig07">

<section>
<h5 class="h5" id="ch03lev3sec4"><span id="page_70" data-epub-type="pagebreak"></span>提供第 2 层服务的以太网广域网</h5>
<p class="noindent">以太网广域网服务包含多种具体服务，它们之间的差异会影响路由器使用服务的方式。不过，就 CCNA 而言，你只需理解最基本的以太网广域网服务。这种服务的工作方式很像一根以太网交叉线，只是跨越了广域网。换言之：</p>
<ul class="sq">
<li><p class="bull">从逻辑上看，其行为类似于两台路由器之间的点到点连接。</p></li>
<li><p class="bull">从物理上看，其行为就像两台路由器之间存在一条实际的光纤以太网链路。</p></li>
</ul>
<p class="noindent">本书使用以下几个常见名称来称呼这种以太网广域网服务：</p>
<p class="ul-noindent"><a id="key_042" href="#ref-gloss_440"><span class="blue">以太网广域网</span></a><strong>：</strong>一个通用名称，用于将其与以太网局域网区分开来。</p>
<p class="ul-noindent"><strong>以太网点到点链路：</strong>这个术语强调典型以太网广域网链路的拓扑结构：它恰好有两个端点，即链路两端的路由器。</p>
<p class="ul-noindent"><a id="key_041" href="#ref-gloss_134"><span class="blue">以太网线路服务（E-Line）</span></a><strong>：</strong>城域以太网论坛（MEF）使用的术语，表示本书中所展示的这种点到点以太网广域网服务。</p>
<p class="ul-noindent"><strong>基于 MPLS 的以太网（EoMPLS）：</strong>这个术语涉及多协议标签交换（MPLS），这种技术可用于为客户提供以太网服务。</p>
<p class="noindent">因此，只要你能想象两台路由器之间存在一条以太网链路，就能理解这种以太网广域网服务的作用，如<a href="#ch03fig08">图 3-8</a> 所示。在这个例子中，两台路由器 R1 和 R2 通过以太网广域网服务连接，而不是通过串行链路连接。路由器使用以太网接口，可以同时在两个方向上发送数据。从物理上看，每台路由器实际上都连接到某个 SP 接入点，如前面的<a href="#ch03fig07">图 3-7</a> 所示；但从逻辑上看，两台路由器可以通过该链路互相发送以太网帧。</p>

<h5 class="h5" id="ch03lev3sec5">路由器如何使用以太网广域网链路路由 IP 分组</h5>
<p class="noindent">广域网的本质作用，是让 IP 路由器能够将 IP 分组从一个站点的局域网，经广域网转发到另一个站点的局域网。无论广域网链路是串行链路还是以太网广域网链路，路由逻辑都相同，只是封装细节略有区别。以太网广域网链路使用以太网实现第 1 层和第 2 层功能，因此路由器使用熟悉的以太网首部和尾部进行封装，如<a href="#ch03fig09">图 3-9</a> 中部所示。另请注意，图中在以太网链路上画了一朵小云，用来表示这是一条以太网广域网链路，而非以太网局域网链路。</p>
<span id="page_71" data-epub-type="pagebreak"></span>
<figure class="image-c" id="ch03fig09">
<img src="assets/volume1/part1-chapter3/images/vol1_03fig09.jpg" aria-describedby="a03fig09" alt="模型展示 PC1 经路由器 R1 和 R2，通过以太网广域网连接到达 PC2 的路由路径。">
<figcaption>
<p class="title-f"><strong>图 3-9</strong> <em>通过以太网广域网链路进行路由</em></p>
<aside class="hidden" id="a03fig09">

</aside>
</figcaption>
</figure>
<div class="note">
<p class="note-title">注意</p>
<p class="note-para">图中每个阶段的 802.3 首部和尾部都不相同！请务必注意接下来逐步说明中给出的原因。</p>
</div>
<p class="noindent">图中展示的三个路由步骤，与前面<a href="#ch03fig06">图 3-6</a> 中使用串行链路时的三个步骤相同。在本例中，三个路由步骤都使用相同的以太网（802.3）协议。不过请注意，每个帧的数据链路首部和尾部都不同。每台路由器都会丢弃旧的数据链路首部和尾部，并添加一组新的首部和尾部，具体过程如下。请主要关注第 2 步，因为与<a href="#ch03fig06">图 3-6</a> 中的类似示例相比，第 1 步和第 3 步没有变化：</p>
<ol class="number">
<li><p class="number">为了将 IP 分组发送给下一站路由器 R1，PC1 将 IP 分组封装（插入）到一个以 R1 的 MAC 地址为目的地址的以太网帧中。</p></li>
<li><p class="number">路由器 R1 从以太网帧中解封装（取出）IP 分组，再将分组封装（插入）到一个新的以太网帧中，添加新的以太网首部和尾部。目的 MAC 地址是 R2 的 G0/0 MAC 地址，源 MAC 地址是 R1 的 G0/1 MAC 地址。随后，R1 通过以太网广域网服务将此帧转发给 R2。</p></li>
<li><p class="number">路由器 R2 从以太网帧中解封装（取出）IP 分组，将分组封装（插入）到以 PC2 的 MAC 地址为目的地址的以太网帧中，并将该以太网帧转发给 PC2。</p></li>
</ol>
<p class="noindent">在本书中，广域网链路（串行链路和以太网链路）都将像这里所示那样连接路由器，而重点放在局域网和 IP 路由上。本章余下内容将更深入地介绍 IP 路由。</p>
</section>

<section>
<h3 class="h3" id="ch03lev1sec4">IP 路由</h3>
<p class="noindent">多年来出现过许多协议模型，但如今占主导地位的是 TCP/IP 模型。在 TCP/IP 的网络层，作为其他所有网络层功能核心的主要协议有两个选择：IP 版本 4（IPv4）和 IP 版本 6（IPv6）。IPv4 和 IPv6 定义的网络层功能类型相同，但具体细节不同。本章介绍 IPv4 的这些网络层功能，IPv6 的细节则留到本书<a data-original-href="vol1_part07.xhtml#part07" data-unavailable="true" title="未提取此章节；请参阅原始 EPUB：vol1_part07.xhtml#part07">第 VII 部分</a>再介绍。</p>
<span id="page_72" data-epub-type="pagebreak"></span>
<div class="note">
<p class="note-title">注意</p>
<p class="note-para">本章所有提到 IP 的地方，均指历史更久、应用更成熟的 IPv4；所有<a id="key_045" href="#ref-gloss_203"><span class="blue">IP 地址</span></a>一词，均指 IPv4 地址。</p>
</div>
<p class="noindent">网际协议（IP）专注于将数据以 IP 分组的形式，从源主机路由到目的主机。IP 不关注数据的物理传输，而是依赖较低的 TCP/IP 层来完成这些功能。IP 关注的是交付数据时的逻辑细节，而非物理细节。具体来说，网络层规定了分组如何在 TCP/IP 网络中从一端传送到另一端，即使分组会跨越多种不同类型的局域网和广域网链路。</p>
<p class="noindent">本章接下来的主要部分将更深入地探讨 IP 路由。首先，IP 定义了如何利用沿途连续使用的数据链路协议，将一个 IP 分组从发送主机路由到目的主机。随后，本节讨论 IP 编址规则如何通过把地址划分为子网，使 IP 路由更加高效。最后，本节介绍 IP <a id="key_051" href="#ref-gloss_197"><span class="blue">路由协议</span></a>的作用：它们让路由器能够学习互联网络中所有 IP 子网的路由。</p>
<section>
<h4 class="h4" id="ch03lev2sec3">网络层路由（转发）逻辑</h4>
<p class="noindent">路由器与终端用户计算机（在 TCP/IP 网络中称为<em>主机</em>）协同完成 IP 路由。主机操作系统（OS）包含 TCP/IP 软件，其中也包括实现网络层的软件。主机使用这些软件来选择 IP 分组的发送目标，通常是附近的一台路由器。这些路由器再决定接下来把 IP 分组发送到哪里。主机和路由器共同将 IP 分组交付到正确的目的地，如<a href="#ch03fig10">图 3-10</a> 中的示例所示。</p>

<section>
<h5 class="h5" id="ch03lev3sec6">主机的转发逻辑：将分组发送给默认路由器</h5>
<p class="noindent">在这个例子中，PC1 进行一些基本分析，然后选择将 IP 分组发送给路由器，以便由路由器转发。PC1 分析目的地址，发现 PC2 的地址（150.150.4.10）与 PC1 不在同一个局域网。因此，PC1 的逻辑会让它将分组发送给一个负责知道如何路由数据的设备：同一局域网上附近的一台路由器，称为 PC1 的<a id="key_039" href="#ref-gloss_090"><span class="blue">默认路由器</span></a>。</p>
<p class="noindent">为了将 IP 分组发送给默认路由器，发送方通过介质向附近的路由器发送一个数据链路帧；分组位于该帧的数据部分。此帧在数据链路首部中使用数据链路层（第 2 层）地址，以确保附近的路由器收到该帧。</p>
<div class="note">
<p class="note-title">注意</p>
<p class="note-para"><em>默认路由器</em>也称为<em>默认网关</em>。</p>
</div>
</section>
<section>
<h5 class="h5" id="ch03lev3sec7">R1 和 R2 的逻辑：在网络中路由数据</h5>
<p class="noindent">所有路由器都使用相同的一般过程来路由分组。每台路由器都维护一张 <em>IP</em> <a id="key_052" href="#ref-gloss_208"><span class="blue">路由表</span></a>。该表列出 IP 地址的<em>分组</em>，称为 <a id="key_046" href="#ref-gloss_206"><span class="blue">IP 网络</span></a>和 <a id="key_048" href="#ref-gloss_209"><span class="blue">IP 子网</span></a>。路由器收到分组时，会将分组的目的 IP 地址与路由表中的条目进行比较并找到匹配项。匹配的条目还包含转发指示，告诉路由器接下来应将分组转发到哪里。</p>
<p class="noindent">在<a href="#ch03fig10">图 3-10</a> 中，R1 会将目的地址（150.150.4.10）与某个路由表条目匹配，而该条目告诉 R1，接下来将分组发送给 R2。同样，R2 会匹配到一个路由表条目，告诉它接下来通过以太网广域网链路将分组发送给 R3。</p>
<p class="noindent">路由的概念有点像在高速公路上行驶，即将到达一处大型互通立交。你抬头看到附近城镇的指示牌，上面告诉你前往各个城镇应从哪个出口驶出。类似地，路由器查看 IP 路由表（相当于路标），引导每个分组经过正确的下一条局域网或广域网链路（相当于道路）。</p>
</section>
<section>
<h5 class="h5" id="ch03lev3sec8">R3 的逻辑：将数据交付到最终目的地</h5>
<p class="noindent">路径中的最后一台路由器 R3，使用的逻辑与 R1 和 R2 几乎相同，但有一个小区别：R3 需要将分组直接转发给 PC2，而不是其他路由器。表面看来，这个区别似乎无关紧要。在下一节介绍网络层如何使用局域网和广域网时，这一区别的重要性就会变得清楚。</p>
</section>
</section>
<section>
<h4 class="h4" id="ch03lev2sec4">网络层路由如何使用局域网和广域网</h4>
<p class="noindent">虽然网络层路由逻辑不考虑物理传输细节，但比特仍然必须被传输。为完成这项工作，主机或路由器中的网络层逻辑必须<span id="page_74" data-epub-type="pagebreak"></span>将分组交给数据链路层协议，后者再请求物理层实际发送数据。数据链路层在分组上添加适当的首部和尾部，形成帧，然后通过各个物理网络发送这些帧。</p>
<p class="noindent">路由过程将网络层分组从网络的一端转发到另一端，而每个数据链路帧只完成整个行程中的一小段。沿途的每个数据链路层帧，都把分组送到下一个需要执行网络层逻辑的设备。简而言之，网络层从整体上考虑目标，例如“将此分组发送给指定的下一台路由器或主机……”，而数据链路层关注具体细节，例如“将分组封装到数据链路帧中并发送”。以下列表概述了路由器内部针对每个分组执行网络层路由的主要步骤，从帧到达路由器接口开始：</p>
<p class="step"><span class="stepb">第 1 步。</span>使用数据链路的帧校验序列（FCS）字段，确认帧中没有错误；如果发生错误，则丢弃该帧。</p>
<p class="step"><span class="stepb">第 2 步。</span>假设第 1 步没有丢弃该帧，则丢弃旧的数据链路首部和尾部，留下 IP 分组。</p>
<p class="step"><span class="stepb">第 3 步。</span>将 IP 分组的目的 IP 地址与路由表进行比较，找到与目的地址最匹配的路由。该路由指出路由器的出接口，还可能指出下一跳路由器的 IP 地址。</p>
<p class="step"><span class="stepb">第 4 步。</span>将 IP 分组封装在适合出接口的、新的数据链路首部和尾部之内，然后转发该帧。</p>
<p class="noindent"><a href="#ch03fig11">图 3-11</a> 再次展示 PC1 向 PC2 发送分组的示例，随后详细分析各设备的路由逻辑。每段说明都包含 PC1 和三台路由器如何构建适当的新数据链路首部的细节。</p>
<figure class="image-c" id="ch03fig11">

<p class="step"><span class="stepb">步骤 A。</span><strong>PC1 将分组发送给默认路由器。</strong>PC1 的网络层逻辑构建 IP 分组，将目的地址设为 PC2 的 IP 地址（150.150.4.10）。网络层还进行分析，确定 150.150.4.10 不在本地 IP 子网内，因此 PC1 需要将分组发送给 R1（PC1 的默认路由器）。PC1 将 IP 分组放入以太网数据链路帧中，以 R1 的以太网地址作为目的以太网地址。PC1 将帧发送到以太网上。</p>
<p class="step"><span class="stepb">步骤 B。</span><strong>R1 处理收到的帧，并将分组转发给 R2。</strong>由于收到的以太网帧以 R1 的以太网 MAC 地址为目的 MAC 地址，R1 决定处理该帧。R1 检查帧的 FCS，判断是否有错误；如果没有错误，R1 就丢弃以太网首部和尾部。接下来，R1 将分组的目的地址（150.150.4.10）与路由表比较，找到子网 150.150.4.0 的条目。由于目的地址 150.150.4.10 属于该子网，R1 便通过匹配路由中列出的接口（Serial0），将分组转发给下一跳路由器 R2（150.150.2.7）。R1 必须先将 IP 分组封装到 HDLC 帧中。</p>
<p class="step"><span class="stepb">步骤 C。</span><strong>R2 处理收到的帧，并将分组转发给 R3。</strong>R2 收到 HDLC 帧后，重复与 R1 相同的一般过程。R2 检查 FCS 字段，确定没有发生错误，然后丢弃 HDLC 首部和尾部。接下来，R2 将分组的目的地址（150.150.4.10）与路由表比较，找到子网 150.150.4.0 的条目；该路由指示 R2 经 Fast Ethernet 0/0 接口，将分组发送给下一跳路由器 150.150.3.1（R3）。但在此之前，R2 必须为分组封装以太网首部。该首部使用以太网广域网链路上 R2 和 R3 的 MAC 地址，分别作为源 MAC 地址和目的 MAC 地址。</p>
<p class="step"><span class="stepb">步骤 D。</span><strong>R3 处理收到的帧，并将分组转发给 PC2。</strong>与 R1 和 R2 一样，R3 检查 FCS，丢弃旧的数据链路首部和尾部，并匹配自己的子网 150.150.4.0 路由。R3 路由表中 150.150.4.0 的条目表明，出接口为 R3 的以太网接口，但没有下一跳路由器，因为 R3 直接连接子网 150.150.4.0。R3 只需将分组封装在新的以太网首部和尾部之内，并以 PC2 的 MAC 地址作为目的以太网地址。</p>
<p class="noindent">由于路由器会构建新的数据链路首部和尾部，而新首部中包含数据链路地址，因此 PC 和路由器必须能够确定应使用哪些数据链路地址。IP 地址解析协议（ARP）就是路由器确定应使用哪个数据链路地址的一种机制。<em>ARP 动态学习连接到局域网的 IP 主机的数据链路地址</em>。例如，在<a href="#ch03fig11">图 3-11</a> 底部的最后一步，路由器 R3 在向 PC2 发送任何分组之前，会使用一次 ARP 来学习 PC2 的 MAC 地址。</p>
</section>
<section>
<h4 class="h4" id="ch03lev2sec5"><span id="page_76" data-epub-type="pagebreak"></span>IP 编址如何帮助 IP 路由</h4>
<p class="noindent">IP 定义了网络层地址，用于标识连接到 TCP/IP 网络的任何主机或路由器接口。这个概念基本上类似于邮政地址：任何希望接收 IP 分组的接口都需要一个 IP 地址，就像你必须有邮政地址，才能接收邮政部门投递的邮件一样。接下来这个简短主题将介绍 IP 网络和子网的概念，它们是 IP 定义的地址组。</p>
<div class="note">
<p class="note-title">注意</p>
<p class="note-para">IP 将<em>网络</em>一词定义为一个非常具体的概念。为避免在介绍 IP 编址时产生混淆，本书（以及其他书籍）通常避免在其他含义上使用<em>网络</em>这个术语。具体来说，本书使用<em>互联网络</em>一词，泛指由路由器、交换机、电缆和其他设备组成的网络。</p>
</div>
<section>
<h5 class="h5" id="ch03lev3sec9">IP 地址分组（网络和子网）的规则</h5>
<p class="noindent">TCP/IP 对 IP 地址进行分组，使同一物理网络上使用的 IP 地址属于同一个组。IP 将这些地址组称为 <em>IP 网络</em>或 <em>IP 子网</em>。继续使用邮政服务的类比，每个 IP 网络和 IP 子网都类似于一个邮政编码（在美国称为 ZIP code）。所有邻近的邮政地址都属于同一个邮政编码区域，而所有邻近的 IP 地址都必须属于同一个 IP 网络或 IP 子网。</p>
<p class="noindent">IP 定义了具体规则，规定哪些 IP 地址应属于同一个 IP 网络或 IP 子网。从数值上看，同组地址的前一部分具有相同的值。例如，<a href="#ch03fig10">图 3-10</a> 和<a href="#ch03fig11">图 3-11</a> 可以采用以下约定：</p>
<ul class="sq">
<li><p class="bull">顶部以太网上的主机：地址以 150.150.1 开头。</p></li>
<li><p class="bull">R1–R2 串行链路上的主机：地址以 150.150.2 开头。</p></li>
<li><p class="bull">R2–R3 以太网广域网链路上的主机：地址以 150.150.3 开头。</p></li>
<li><p class="bull">底部以太网上的主机：地址以 150.150.4 开头。</p></li>
</ul>
<p class="noindent">从 IP 路由的角度看，对 IP 地址分组意味着路由表可以小得多。路由器可以为每个 IP 网络或子网列出一个路由表条目，用来代表一组地址，而不必为每个单独的 IP 地址列出一个条目。</p>
<p class="noindent">上述列表只展示了 IP 地址分组的一种示例；要掌握使用子网进行地址分组的规则，还需要花些功夫理解相关概念和数学计算。本书<a data-original-href="vol1_part04.xhtml#part04" data-unavailable="true" title="未提取此章节；请参阅原始 EPUB：vol1_part04.xhtml#part04">第 IV 部分</a>详细介绍 IP 编址和子网划分，并配有其他子网划分视频和练习题。不过，<a id="key_054" href="#ref-gloss_394"><span class="blue">子网划分</span></a>的两条基本规则可以简要概括如下：</p>
<ul class="sq">
<li><p class="bull">两个彼此之间没有路由器隔开的 IP 地址，必须位于同一组（子网）。</p></li>
<li><p class="bull">两个彼此之间至少隔着一台路由器的 IP 地址，必须位于不同的组（子网）。</p></li>
</ul>
<p class="noindent">这类似于美国邮政署（USPS）的 ZIP 邮编系统，以及它要求地方政府为新建建筑分配地址的方式。让两栋紧挨着的<span id="page_77" data-epub-type="pagebreak"></span>房屋具有不同的邮政编码，显然不合理。同样，让居住在国家两端的人使用相同邮政编码的地址，也是不合理的。</p>
</section>

<h4 class="h4" id="ch03lev2sec6">IP 路由协议如何帮助 IP 路由</h4>
<p class="noindent">为了让主机和路由器上的路由逻辑正常工作，每台主机和路由器都需要了解 TCP/IP 互联网络的某些信息。主机需要知道默认路由器的 IP 地址，以便向远程目的地发送分组。路由器则需要知道路由，才能将分组转发到每个可达的 IP 网络和 IP 子网。</p>
<p class="noindent">让路由器获知所有有用路由的最佳方法，是配置它们使用相同的 IP 路由协议。如果在 TCP/IP 互联网络中的所有路由器上启用相同的路由协议，并正确配置相关设置，路由器就会互相发送路由协议消息。这样，所有路由器都会学习到该 TCP/IP 互联网络中所有 IP 网络和子网的路由。</p>
<p class="noindent">IP 支持少数几种不同的 IP 路由协议。它们都使用一些相似的思想和过程来学习 IP 路由，但不同路由协议的内部实现确实有所区别。所有路由协议都使用以下一般步骤来学习路由：</p>
<p class="step"><span class="stepb">第 1 步。</span>每台路由器都会为每个直接连接到该路由器的子网，在路由表中添加一条路由；这一过程与路由协议无关。</p>
<p class="step"><span class="stepb">第 2 步。</span>每台路由器的路由协议会将路由表中的路由告知邻居，包括直连路由和从其他路由器学习到的路由。</p>
<p class="step"><span class="stepb">第 3 步。</span>每台路由器的路由协议会侦听邻居路由器发送的消息并学习路由；该路由的下一跳路由器，通常就是向本机提供这条路由的邻居。</p>
<p class="noindent"><span id="page_78" data-epub-type="pagebreak"></span>还要注意，在最后一步中，路由器可能需要从通往同一个子网的多条路由中进行选择。此时，路由器会把当前到达该子网的最佳可用路由放入路由表，选择依据是一种称为度量值的衡量指标。</p>

<h3 class="h3" id="ch03lev1sec5"><span id="page_79" data-epub-type="pagebreak"></span>其他网络层功能</h3>
<p class="noindent">TCP/IP 网络层定义了许多 IP 之外的功能。IP 当然在当今网络中发挥着巨大作用，定义了 IP 编址和 IP 路由。不过，其他请求评论文档（RFC）中定义的协议和标准，也对网络层功能起着重要作用。例如，开放最短路径优先（OSPF）等路由协议是独立的协议，定义在独立的 RFC 中。</p>

<ul class="sq">
<li><p class="bull">域名系统（DNS）</p></li>
<li><p class="bull">地址解析协议（ARP）</p></li>

<h4 class="h4" id="ch03lev2sec7">使用名称与域名系统</h4>
<p class="noindent">你能想象这样一个世界吗：每次使用应用程序时，都必须通过 IP 地址来指代它？你无法使用 <a href="http://google.com">google.com</a> 或 <a href="http://cisco.com">cisco.com</a> 这样的易记名称，而必须记住并输入 64.233.177.100 这样的 IP 地址。（本书付印时，64.233.177.100 是 Google 使用的一个地址，你可以在浏览器中输入这个地址来访问 Google 网站。）显然，要求用户记忆 IP 地址很不友好，甚至可能让一些人完全放弃使用计算机。</p>
<p class="noindent">幸运的是，TCP/IP 定义了一种通过<a id="key_044" href="#ref-gloss_175"><span class="blue">主机名</span></a>来标识其他计算机的方法。用户要么根本不需要考虑对方计算机，要么通过名称来指代它。随后，协议会动态发现基于该名称进行通信所需的全部信息。</p>
<p class="noindent">例如，当你打开 Web 浏览器并输入主机名 <strong><a href="http://www.google.com">www.google.com</a></strong> 时，计算机并不会发送一个以 <a href="http://www.google.com">www.google.com</a> 为目的 IP 地址的 IP 分组；它发送的 IP 分组以 Google Web 服务器使用的某个 IP 地址为目的地址。TCP/IP 需要一种方法，让计算机能够查出给定主机名所使用的 IP 地址，这种方法使用域名系统（<a id="key_040" href="#ref-gloss_108"><span class="blue">DNS</span></a>）。</p>
<p class="noindent">企业使用 DNS 过程，将名称解析为匹配的 IP 地址，如<a href="#ch03fig14">图 3-14</a> 的示例所示。在本例中，左侧的 PC11 需要连接一台名为 Server1 的服务器。在某个时刻，用户输入了名称 Server1，或者 PC11 上的某个应用程序通过名称引用该服务器。在第 1 步，PC11 向 DNS 服务器发送一条 DNS 消息，即 DNS 查询。在第 2 步，DNS 服务器返回 DNS 应答，其中列出 Server1 的 IP 地址。在第 3 步，PC11 便可以向目的地址 10.1.2.3 发送 IP 分组，该地址正是 Server1 使用的地址。</p>
<p class="noindent">请注意，<a href="#ch03fig14">图 3-14</a> 使用一朵云表示 TCP/IP 网络，因为包括路由器在内的网络细节与名称解析过程无关。路由器对待 DNS 消息的方式与其他任何 IP 分组相同，都是根据目的 IP 地址进行路由。例如，在图中的第 1 步，DNS 查询以 DNS 服务器的 IP 地址作为目的地址，沿途路由器将使用该地址转发分组。</p>
<span id="page_80" data-epub-type="pagebreak"></span>
<figure class="image-c" id="ch03fig14">
<img src="assets/volume1/part1-chapter3/images/vol1_03fig14.jpg" aria-describedby="a03fig14" alt="示意图展示 DNS 名称解析的基本机制，即将域名转换为相应的 IP 地址。">

<p class="noindent">最后，DNS 定义的内容远不止几种消息。DNS 定义了协议、全世界使用的文本名称的标准，以及由分布式 DNS 服务器组成的全球体系。人们每天浏览网页时使用的域名，例如 <a href="http://www.example.com">www.example.com</a>，都遵循 DNS 命名标准。此外，没有任何一台 DNS 服务器知道所有名称及其匹配的 IP 地址，这些信息分散存储在许多 DNS 服务器中。因此，世界各地的 DNS 服务器协同工作，彼此转发查询，直到知道答案的服务器提供所需的 IP 地址信息。</p>

<h4 class="h4" id="ch03lev2sec8">地址解析协议</h4>
<p class="noindent">正如本章多处深入讨论的那样，IP 路由逻辑要求主机和路由器将 IP 分组封装在数据链路层帧中。对于以太网接口，路由器如何知道应使用哪个 MAC 地址作为目的地址？它使用 <a id="key_038" href="#ref-gloss_025"><span class="blue">ARP</span></a>。</p>
<p class="noindent">在以太网局域网上，每当主机或路由器需要将 IP 分组封装在新的以太网帧中时，除了目的 MAC 地址，它都已知道构建该首部所需的所有重要信息。主机知道下一台设备的 IP 地址，它可能是另一台主机的 IP 地址，也可能是默认路由器的 IP 地址。路由器知道用于转发 IP 分组的 IP 路由，其中列出下一台路由器的 IP 地址。不过，主机和路由器事先并不知道这些邻近设备的 MAC 地址。</p>
<p class="noindent">TCP/IP 定义地址解析协议（ARP），使局域网中的任何主机或路由器，都能够动态学习同一局域网中另一台 IP 主机或路由器的 MAC 地址。ARP 定义的协议包含 <em>ARP 请求</em>，这条消息提出一个简单请求：“如果这是你的 IP 地址，请用你的 MAC 地址回复。”ARP 还定义了 <em>ARP 应答</em>消息，其中确实同时列出原来的 IP 地址和匹配的 MAC 地址。</p>
<p class="noindent"><a href="#ch03fig15">图 3-15</a> 使用前面<a href="#ch03fig13">图 3-13</a> 底部相同的路由器和主机，展示了一个示例。图的左侧显示路由器 R3 以局域网广播方式发送 ARP 请求。局域网中的所有设备随后都会处理收到的帧。在右侧的第 2 步，主机 PC2 发回 ARP 应答，告知 PC2 的 MAC 地址。每条消息旁边的文字展示了 ARP 消息本身的内容，这些内容使 PC2 能够学习 R3 的 IP 地址及其匹配的 MAC 地址，也使 R3 能够学习 PC2 的 IP 地址及其匹配的 MAC 地址。</p>
<span id="page_81" data-epub-type="pagebreak"></span>
<figure class="image-c" id="ch03fig15">
<img src="assets/volume1/part1-chapter3/images/vol1_03fig15.jpg" aria-describedby="a03fig15" alt="示意图展示地址解析协议（ARP）过程的一个示例。">

<p class="noindent">请注意，主机和路由器会记住 ARP 的结果，将这些信息保存在 <em>ARP 缓存</em>或 <em>ARP 表</em>中。主机或路由器只需偶尔使用 ARP，以便首次建立 ARP 缓存。每次主机或路由器需要发送封装在以太网帧中的分组时，它都会先检查 ARP 缓存，查找正确的 IP 地址及其匹配的 MAC 地址。主机和路由器会让 ARP 缓存条目超时失效，以清理表项，因此仍会偶尔看到 ARP 请求。</p>

<h4 class="h4" id="ch03lev2sec9">ICMP 回显与 ping 命令</h4>
<p class="noindent">实现 TCP/IP 互联网络之后，你需要一种方法来测试基本的 IP 连通性，而且不依赖任何应用程序正常工作。用于测试基本网络连通性的主要工具是 <strong>ping</strong> 命令。</p>
<p class="noindent"><a id="key_050" href="#ref-gloss_304"><span class="blue">Ping</span></a> 使用网际控制报文协议（ICMP），向另一个 IP 地址发送一条称为 <em>ICMP 回显请求</em>的消息。使用该 IP 地址的计算机应以 <em>ICMP 回显应答</em>进行回复。如果这一过程成功，你就成功测试了 IP 网络。换言之，你知道网络能够将分组从一台主机交付给另一台主机，并将分组送回。ICMP 不依赖任何应用程序，因此它实际上只测试基本的 IP 连通性，也就是 OSI 模型的第 1、2、3 层。<a href="#ch03fig16">图 3-16</a> 概述了基本过程。</p>
<figure class="image-c" id="ch03fig16">

<p class="title-f"><strong>图 3-16</strong> <em>网络示例，<span class="font"><strong>ping</strong></span> 命令</em></p>

<h3 class="h3" id="ref-appclev1sec3">第 3 章</h3>
<p class="quiz"><strong><a id="ref-ques3_1" href="#quess3_1">1</a>。</strong>D。正确答案列出了两个站点之间以太网广域网链路的一种称呼：E-line，即 Ethernet line（以太网线路）的简称。其他答案列出的都是串行链路的常见同义词。</p>
<p class="quiz"><strong><a id="ref-ques3_2" href="#quess3_2">2</a>。</strong>B 和 D。物理安装采用这样一种模式：每台路由器都通过一条物理以太网链路，连接到 SP 设施中的某台 SP 设备，该设施称为接入点（PoP）。以太网链路并不直接从一台客户设备延伸到另一台客户设备。从数据链路角度看，两台路由器使用的都是与局域网相同的标准以太网首部和尾部；HDLC 与这些以太网广域网链路无关。</p>
<p class="quiz"><strong><a id="ref-ques3_3" href="#quess3_3">3</a>。</strong>A。PC1 会向 Router1 发送一个以太网帧，以 PC1 的 MAC 地址为源地址，以 Router1 的 MAC 地址为目的地址。Router1 将从该以太网帧中取出封装的 IP 分组，丢弃帧首部和尾部，并且不再使用它们。Router1 会先将 IP 分组封装到 PPP 帧内，再转发该分组。Router1 不会把原来的<span id="ref-page_781" data-epub-type="pagebreak"></span>以太网帧封装到 PPP 帧中，而是封装 IP 分组。PPP 首部使用的地址与以太网不同，因此不会使用原始帧中的以太网地址。</p>
<p class="quiz"><strong><a id="ref-ques3_4" href="#quess3_4">4</a>。</strong>C。路由器将分组的目的 IP 地址与自己的 IP 路由表进行比较，找到匹配项，并使用匹配路由中的转发指示来转发 IP 分组。</p>
<p class="quiz"><strong><a id="ref-ques3_5" href="#quess3_5">5</a>。</strong>C。IPv4 主机通常使用基本的双分支逻辑。要将 IP 分组发送给同一局域网内、同一 IP 网络或子网上的另一台主机时，发送方会将 IP 分组直接发送给该主机。否则，发送方会将分组发送给自己的默认路由器（也称为默认网关）。</p>
<p class="quiz"><strong><a id="ref-ques3_6" href="#quess3_6">6</a>。</strong>A 和 C。路由器会执行答案中列出的所有操作。不过，路由协议负责的是两个正确答案所列的功能。路由器学习直接连接到其接口的 IP 子网和 IP 网络的路由，这一过程与路由协议无关。路由器还会转发（路由）IP 分组，但这一过程称为 IP 路由或 IP 转发，相对于路由协议的工作而言，它是一个独立过程。</p>
<p class="quiz"><strong><a id="ref-ques3_7" href="#quess3_7">7</a>。</strong>C。地址解析协议（ARP）确实能够让 PC1 学习信息，但这些信息并非存储在服务器上。<strong>ping</strong> 命令确实能够让 PC1 的用户知道分组能否在网络中传送，但它同样不使用服务器。在域名系统（DNS）中，PC1 充当 DNS 客户端，依赖 DNS 服务器应答，提供与给定主机名匹配的 IP 地址信息。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_025"><strong>ARP</strong> 地址解析协议。用于将 IP 地址映射为 MAC 地址的互联网协议，定义于 RFC 826。</p>
<p class="gloss" id="ref-gloss_065"><strong>分类 IP 网络（classful IP network）</strong> IPv4 的 A 类、B 类或 C 类网络；之所以称为分类网络，是因为这些网络按照 IPv4 编址的类别规则定义。</p>
<p class="gloss" id="ref-gloss_090"><span id="ref-page_815" data-epub-type="pagebreak"></span><strong>默认网关／默认路由器（default gateway/default router）</strong> 在 IP 主机上，指某台路由器的 IP 地址；当分组的目的地址位于本地子网之外的子网时，主机会将分组发送给该路由器。</p>
<p class="gloss" id="ref-gloss_108"><strong>DNS</strong> 域名系统。广泛用于互联网的应用层协议，用于将主机名转换为相应的 IP 地址。</p>
<p class="gloss" id="ref-gloss_134"><strong>以太网线路服务（Ethernet Line Service，E-Line）</strong> MEF（MEF.net）定义的一种特定的运营商／城域以太网服务，在两台客户设备之间提供点到点拓扑，其效果非常类似于使用以太网交叉线连接这两台设备。</p>
<p class="gloss" id="ref-gloss_163"><strong>HDLC</strong> 高级数据链路控制。由国际标准化组织（ISO）开发的一种面向比特的同步数据链路层协议。</p>
<p class="gloss" id="ref-gloss_175"><strong>主机名（hostname）</strong> IP 主机的字母数字名称。</p>
<p class="gloss" id="ref-gloss_196"><strong>内部网关协议（interior gateway protocol，IGP）</strong> 设计用于在单个自治系统内部交换路由信息的路由协议。</p>
<p class="gloss" id="ref-gloss_197"><strong>内部路由协议（interior routing protocol）</strong> 内部网关协议的同义词。<em>参见</em><a href="#ref-gloss_196">内部网关协议</a>。</p>
<p class="gloss" id="ref-gloss_203"><strong>IP</strong> 网际协议。TCP/IP 协议栈中的网络层协议，提供路由和逻辑编址的标准与服务。</p>
<p class="gloss" id="ref-gloss_206"><strong>IP 网络（IP network）</strong> <em>参见</em><a href="#ref-gloss_065">分类 IP 网络</a>。</p>
<p class="gloss" id="ref-gloss_207"><strong>IP 分组（IP packet）</strong> 由 IP 首部以及封装在 IP 首部之后的数据组成，明确不包含网络层以下各层的任何首部和尾部。</p>
<p class="gloss" id="ref-gloss_208"><strong>IP 路由表（IP routing table）</strong> <em>参见</em><a href="#ref-gloss_354">路由表</a>。</p>
<p class="gloss" id="ref-gloss_209"><strong>IP 子网（IP subnet）</strong> 由网络管理员配置，对 A 类、B 类或 C 类网络进行细分后得到的部分。子网使一个 A 类、B 类或 C 类网络能够代替多个网络使用，同时仍能提供高效 IP 路由所需的大量 IP 地址组。</p>
<p class="gloss" id="ref-gloss_230"><strong>租用线路（leased line）</strong> 由某个服务提供商（通常是电话公司，即 telco）提供的两点之间的串行通信电路。由于电话公司并不出售两个端点之间的物理电缆，而是按月收取费用，让客户能够在两个站点之间发送比特，因此这种服务被视为租用服务。</p>
<p class="gloss" id="ref-gloss_304"><strong>ping</strong> 网际控制报文协议（ICMP）的回显消息及其应答；ping 常用于 IP 网络，以测试网络设备的可达性。</p>
<p class="gloss" id="ref-gloss_354"><span id="ref-page_833" data-epub-type="pagebreak"></span><strong>路由表（routing table）</strong> 路由器中的路由列表；每条路由列出目的子网和掩码、转发去往该子网的分组所使用的路由器出接口，以及在需要时列出的下一跳路由器 IP 地址。</p>
<p class="gloss" id="ref-gloss_394"><strong>子网划分（subnetting）</strong> 将 A 类、B 类或 C 类网络划分为更小的组（称为子网）的过程。</p>
<p class="gloss" id="ref-gloss_404"><strong>telco</strong> <em>电话公司（telephone company）</em>的常见缩写。</p>
<p class="gloss" id="ref-gloss_440"><strong>WAN</strong> <em>参见</em><a href="#ref-gloss_442">广域网</a>。</p>
<p class="gloss" id="ref-gloss_442"><strong>广域网（wide-area network，WAN）</strong> 较大网络中的一部分，主要实现 OSI 第 1 层和第 2 层技术，连接通常相距较远的站点，并采用这样一种商业模式：使用者（个人或企业）必须向服务提供商（通常是电话公司）租用广域网。</p>
