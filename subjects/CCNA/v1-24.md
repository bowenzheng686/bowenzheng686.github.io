<h3 class="h3" id="ch24lev1sec3">OSPF 邻居关系</h3>



<p class="noindent">路由器的 OSPF 配置会在一组接口上启用 OSPF。随后，IOS 通过发送和侦听 OSPF Hello 消息，尝试发现这些接口上的其他邻居。不过，即使相互发现，两台路由器也未必能成为邻居。它们交换的 Hello 中列出了若干设置，这些设置的值必须兼容。本章第二大节将探讨这些原因。</p>



<section>



<h4 class="h4" id="ch24lev2sec1">OSPF 邻居要求</h4>

<h4 class="h4" id="ch24lev2sec2">阻止建立邻接关系的问题</h4>



<p class="noindent">接下来的几页使用 <a href="#ch24fig01">图 24-1</a> 的拓扑作为示例，讨论 <a href="#ch24tab02">表 24-2</a> 中的三个邻居问题。R1 最初具有全部正确配置，如 <a href="#exa24_1">例 24-1</a> 所列。不过，后续示例会在 R2、R3 和 R4 上引入以下配置错误：</p>

<h5 class="h5" id="ch24lev3sec4">关闭 OSPF 进程</h5>



<p class="noindent">类似于通过管理操作禁用和启用接口，IOS 也允许分别通过路由器模式子命令 <strong>shutdown</strong> 和 <strong>no shutdown</strong> 禁用和启用 OSPFv2 路由协议进程。关闭路由协议进程时，IOS 会执行以下操作：</p>



<ul class="sq">



<li><p class="bull">关闭所有邻居关系，并清空 OSPF 邻居表。</p></li>



<li><p class="bull">清空 LSDB。</p></li>



<li><p class="bull">从 IP 路由表中清除所有通过 OSPF 学到的路由。</p></li>



</ul>



<p class="noindent"><span id="page_616" data-epub-type="pagebreak"></span>与此同时，关闭 OSPF 仍会保留一些重要的 OSPF 信息，具体包括：</p>



<ul class="sq">



<li><p class="bull">IOS 保留所有 OSPF 配置。</p></li>



<li><p class="bull">IOS 仍在 OSPF 接口列表（<strong>show ip ospf interface</strong>）中列出所有启用了 OSPF 的接口，但状态为 DOWN。</p></li>



</ul>



<p class="noindent">关闭 OSPF 路由协议进程，可让网络工程师停止在该路由器上使用这一协议，而无须删除所有配置。进程关闭后，<strong>show ip ospf interface</strong> [<strong>brief</strong>] 命令和 <strong>show ip ospf</strong> 命令仍应列出一些输出，而其他命令则不列出任何内容。</p>

<section>



<h5 class="h5" id="ch24lev3sec5">在接口上关闭 OSPF</h5>



<p class="noindent">IOS 还支持在接口上禁用 OSPF，而无须删除任何 OSPF 配置。该功能的目的与路由器配置模式下的 <strong>shutdown</strong> 命令相同：停止 OSPF，同时保留其配置。不过，在接口上关闭 OSPF，只会停止该接口上的所有 OSPF 操作，而不会停止整台路由器上的所有 OSPF 操作。</p>



<p class="noindent">要在接口上关闭 OSPF，使用 <strong>ip ospf shutdown</strong> 接口子命令；要重新启用，使用 <strong>no ip ospf shutdown</strong> 命令。使用 <strong>ip ospf shutdown</strong> 后，路由器会发生以下变化：</p>



<ul class="sq">



<li><p class="bull">路由器停止在该接口上发送 Hello，使现有 OSPF 邻居关系超时。</p></li>



<li><p class="bull">邻居关系失效会触发 OSPF 重新收敛，从而删除所有将该接口用作出接口的路由。</p></li>



<li><p class="bull">路由器也停止通告被关闭链路上的子网。</p></li>



</ul>



<p class="noindent">如果这些行为听起来很熟悉，那是因为该功能与 OSPF 被动接口非常相似，只是在关闭状态下，OSPF 还会停止通告直连子网。</p>



<p class="noindent">有趣的是，使用 <strong>ip ospf shutdown</strong> 接口子命令，也不会改变某些接口相关命令的显示。例如，在 G0/0/0 接口配置 <strong>ip ospf shutdown</strong> 后，<strong>show ip ospf interface</strong> 和 <strong>show ip ospf interface brief</strong> 命令仍会在接口列表中显示 G0/0/0。</p>

<p class="noindent">一些配置不匹配会阻止学习 OSPF 路由，但仍允许路由器成为邻居，如 <a href="#ch24tab02">表 24-2</a> 的最后一部分所述。这些问题是：</p>



<ul class="sq">



<li><p class="bull">MTU 设置不匹配</p>



</li>



<li><p class="bull">OSPF 网络类型不匹配</p></li>



<li><p class="bull">两个邻居均使用 OSPF 优先级 0</p></li>



</ul>



<p class="noindent">接下来的几页将解释这些问题，并通过示例展示这三种错误配置及其对应的 <strong>show</strong> 命令输出。</p>



<section>



<h5 class="h5" id="ch24lev3sec6">MTU 设置不匹配</h5>



<p class="noindent">最大传输单元（MTU）大小是一项逐接口设置，供路由器的第 3 层转发逻辑使用，用于定义路由器可通过各接口转发的最大网络层数据包。接口的 IPv4 MTU 大小规定路由器可通过该接口转发的最大 IPv4 数据包；类似地，IPv6 MTU 大小规定最大的 IPv6 数据包。</p>



<p class="noindent">路由器通常使用默认的 1500 字节 IP MTU，也允许设置该值。<strong>ip mtu</strong> <em>size</em> 接口子命令定义 IPv4 MTU，<strong>ipv6 mtu</strong> <em>size</em> 命令为 IPv6 数据包设置对应值。</p>



<p class="noindent">也可以使用 <strong>mtu</strong> <em>size</em> 接口子命令同时设置 IPv4 和 IPv6 的 MTU 大小。如果接口上没有 <strong>ip mtu</strong> <em>size</em> 命令，它就设置 IPv4 的 MTU；如果没有 <strong>ipv6 mtu</strong> <em>size</em> 命令，它就设置 IPv6 的 MTU。</p>



<p class="noindent">IPv4 MTU 设置不同时，两台 OSPFv2 路由器可以成为 OSPF 邻居，但无法完成正常的 OSPF 数据库交换；它们会到达其他中间邻居状态，随后失效并变为 down。随着时间推移，两者会反复成为邻居、尝试交换 LSDB、失败，再退回 down 状态。</p>



</section>



<section>



<h5 class="h5" id="ch24lev3sec7">OSPF 网络类型不匹配</h5>



<p class="noindent">在 <a href="v1-23.html#ch23">第 23 章</a>“<a href="v1-23.html#ch23">实现可选的 OSPF 功能</a>”的“<a href="v1-23.html#ch23lev1sec3">OSPF 网络类型</a>”一节中，你了解了使用 DR/BDR 的 OSPF 广播网络类型，以及不使用 DR/BDR 的 OSPF 点到点网络类型。有趣的是，如果错误配置网络类型，使一台路由器使用 broadcast，另一台使用 point-to-point，两者仍会成为邻居并达到 full 状态。它们会稳定地保持 full 状态，说明已交换 LSDB；不过，两台路由器都无法使用基于从对方学到的 LSA 所形成的路由。</p>



<p class="noindent">不添加这些路由的原因，与 LSA 的细节以及使用或不使用 DR 如何改变 LSA 有关。基本上，两台路由器期望 LSA 中具有不同的细节，SPF 算法在计算路由时发现这些差异，却无法消解它们。</p>



</section>



<section>



<h5 class="h5" id="ch24lev3sec8">两个邻居均使用 OSPF 优先级 0</h5>



<p class="noindent">使用广播网络类型时，OSPF 接口优先级可用来影响哪台路由器赢得 DR 或 BDR 选举。优先级最高的路由器胜出，默认值为 1，允许的十进制取值范围为 0 到 255。</p>



<p class="noindent"><span id="page_619" data-epub-type="pagebreak"></span>优先级 0 是一种特殊情况，表示路由器不会充当 DR 或 BDR。例如，在多台路由器共享同一子网的拓扑中，可以让某些路由器使用优先级 0，实际效果是拒绝成为 DR 或 BDR，从而使网络运行更可预测。</p>



<p class="noindent">如果作出不合理的配置选择，让子网上的所有路由器都使用优先级 0，就会产生问题。此时，子网必须有一台 DR，却没有任何路由器愿意承担该角色。路由器照常使用 Hello 相互发现，彼此列为邻居，并达到 2WAY 状态。但是，由于没有路由器充当 DR，数据库交换过程就在此停止。典型症状是邻居稳定地处于 2WAY/DROTHER 状态。</p>



</section>

<section>



<h3 class="h3" id="ch24lev1sec4">路由选择</h3>



<p class="noindent">OSPF 计算到某个子网的路由时，路由之间的竞争可能简单明了。路由器可能只为子网计算出一条路由，随后使用它；也可能计算出多条到达该子网的路由，于是找出度量值（开销）最低的路由，将其放入 IP 路由表。</p>



<p class="noindent">不过，在 OSPF 内部和外部还会出现其他情况，需要更深入理解路由器所用的逻辑。本章最后一大节讨论三个主题，引导我们思考：</p>



<ol class="number">



<li><p class="number">一台路由器如何在到同一子网的多条等价 OSPF 路由之间作出选择。</p></li>



<li><p class="number">一台路由器如何在由不同路由协议学到的、到同一子网的多条路由之间作出选择。</p></li>



<li><p class="number">转发数据包时，路由器如何匹配路由表中的路由，尤其是数据包的目的地址匹配多条路由时。</p></li>



</ol>



<section>



<h4 class="h4" id="ch24lev2sec4">OSPF 等价多路径路由</h4>



<p class="noindent">考虑一台 OSPF 路由器为某个目的子网计算的路由。如果到该子网有多条路由，而其中一条的度量值最低，那么 OSPF 的逻辑很简单：将该路由加入 IP 路由表。但是，如果到同一子网的多条路由具有相同的度量值，路由器就采用不同的逻辑：将多条<a id="key_264" href="#ref-gloss_125"><span class="blue">等价路由（equal-cost routes）</span></a>放入路由表。</p>



<p class="noindent">IOS 根据 <strong>router ospf</strong> 下的 <strong>maximum-paths</strong> <em>number</em> 子命令，限制每个目的子网同时存在的等价 OSPF 路由数量。默认值随路由器平台而异，常见的默认设置是同时保留四条路由。</p>



<p class="noindent">例如，考虑最近的 <a href="#ch24fig03">图 24-3</a>，但修复所有配置错误，使所有路由器都学到所有子网的路由。R1 到 R4 所连接的子网 10.1.4.0/24 只有一条可能路由。不过，R1 到子网 10.1.23.0/24 有两条可能路由：一条经过邻居 R2，另一条经过邻居 R3。如果所有 GigabitEthernet 接口的 OSPF 开销都为 10，那么 R1 到子网 10.1.23.0/24 的两条路由开销都为 20。<a href="#exa24_8">例 24-8</a> 通过列出 R1 上通过 OSPF 学到的路由，展示了这一结果。</p>

<section>



<h4 class="h4" id="ch24lev2sec5">从相互竞争的来源学到多条路由</h4>



<p class="noindent">典型的企业路由器首先根据接口 IP 地址学习直连路由。这些路由恰好是到达相应子网的最佳路由，因为子网直接连接到路由器。此外，每台企业路由器使用一种路由协议（例如 OSPF）动态学习其他所有路由。</p>



<p class="noindent">不过，在一些合理场景中，路由器学习路由的来源不止直连路由和一种路由协议。例如，某些路由器还具有静态路由，如 <a href="v1-17.html#ch17">第 17 章</a>“<a href="v1-17.html#ch17">配置 IPv4 地址和静态路由</a>”所述。路由器配置可能定义一条到某个子网的静态路由，同时 IGP 也学到一条到同一子网的路由。哪条更好？在其他情况下，一台路由器可能同时运行 OSPF 和 BGP。如果两者都学到同一子网的路由，哪条更好？或者路由器可能使用多个 IGP，例如同时使用 OSPF 和 EIGRP。两者同样可能学到同一子网的路由，从而引出相同的问题。</p>



<div class="note">



<p class="note-title">注意</p>



<p class="note-para">要认为两条路由通向同一子网，它们必须具有相同的子网 ID 和子网掩码。</p>



</div>



<p class="noindent">在这些情况下，路由协议度量值无法帮助路由器在相互竞争的路由之间作出选择。例如，EIGRP 通常采用数百万或数十亿的度量值，而 OSPF 则使用数百或数千。此外，直连路由和静态路由没有<span id="page_623" data-epub-type="pagebreak"></span>度量值。因此，此时度量值无法帮助路由器选择最佳路由，IOS 需要另一种方法在不同来源的路由之间作出选择。</p>



<p class="noindent">当 IOS 必须在使用不同路由协议学到的路由之间选择时，会使用称为<a id="key_262" href="#ref-gloss_216"><span class="blue">管理距离（administrative distance）</span></a>的概念。管理距离（AD）是一个数字，表示在单台路由器上整个路由协议的可信程度。数值越小，路由协议越优或越可信。例如，RIP 的默认管理距离为 120，OSPF 为 110，EIGRP 为 90。同时使用 OSPF 和 EIGRP 时，路由器会相信 EIGRP 路由而不是 OSPF 路由（至少默认如此）。管理距离值在单台路由器上配置，不与其他路由器交换。<a href="#ch24tab04">表 24-4</a> 列出了各种路由信息来源及其默认管理距离。</p>

<section>



<h4 class="h4" id="ch24lev2sec6">使用最长前缀匹配进行 IP 转发</h4>



<p class="noindent">本章最后几页关注路由器如何将数据包的目的 IP 地址与路由表中已有的某条路由匹配。这一过程有几个名称，如 <em>IP 路由</em>、<em>转发</em>或<em>数据平面</em>。无论叫什么，都应关注其逻辑。</p>



<p class="noindent">路由器的 IP 路由过程要求它将每个数据包的目的 IP 地址与自身 IP 路由表中的现有内容比较。很多时候，只有一条路由匹配某个目的地址。当只有一条路由匹配数据包目的地时，操作很明确：根据该路由列出的详细信息转发数据包。</p>



<p class="noindent"><span id="page_626" data-epub-type="pagebreak"></span>某些情况下，到完全相同的子网存在多条路由，也就是子网和掩码完全相同。前面的“<a href="#ch24lev2sec4">OSPF 等价多路径路由</a>”一节讨论了 OSPF 如何选择将这些多条路由加入路由表，以及路由器如何对匹配这些路由的数据包进行负载均衡。</p>



<p class="noindent">本节讨论另一种情况：一组路由列出不同子网，而这些子网的地址范围重叠。此时，某些数据包的目的地址会匹配 IP 路由表中的多条路由。例如，一条路由可能列出子网 10.1.0.0/16，另一条列出 10.1.1.0/25，还有一条列出 10.1.1.1/32。每个子网的地址范围都包含 10.1.1.1，因此，发往 IP 地址 10.1.1.1 的数据包会匹配这些全部路由。</p>



<p class="noindent">许多正常的路由器功能都可能让路由表中出现这些重叠的路由，包括：</p>



<ul class="sq">



<li><p class="bull">静态路由（包括主机路由）</p></li>



<li><p class="bull">路由自动汇总</p></li>



<li><p class="bull">手动路由汇总</p></li>



<li><p class="bull">默认路由</p></li>



</ul>



<p class="noindent">在这种情况下，路由器按以下方式选择最佳路由：</p>



<p class="ul-noindent">当某个目的 IP 地址匹配路由器 IPv4 路由表中的多条路由，且这些路由列出的是不同子网而不是相同子网（子网 ID 和掩码不同）时，路由器使用<a id="key_265" href="#ref-gloss_246"><span class="blue">最长前缀匹配（longest prefix match）</span></a>逻辑，匹配最具体的路由，也就是掩码前缀长度最长的路由。</p>

<h2 class="h2a">“这些知识我已经掌握了吗？”自测题答案</h2>

<section>

<h3 class="h3" id="ref-appclev1sec24">第 24 章</h3>

<p class="quiz"><strong><a id="ref-ques24_1" href="#quess24_1">1</a>．</strong> A 和 D。根据题意，正确答案应描述会阻止建立邻居关系的场景。一个正确答案提到潜在 OSPF 邻居使用两个不同的 OSPF 区域；要成为邻居，两台路由器必须使用相同的区域号。另一个正确答案提到使用两个不同的 Hello 定时器，这种不匹配会使两台路由器相互拒绝，无法成为邻居。</p>

<p class="quiz-para">两个错误答案列出的场景不会导致问题，因此不符合题意。一个提到 OSPF 进程 ID 不匹配；两台路由器要成为邻居，并不要求 OSPF 进程 ID 相同。另一个错误答案（也就是不会造成问题的场景）提到使用两个不同的优先级值。优先级值让 OSPF 在选举 DR/BDR 时能够优先选择某台路由器，因此该设置本来就允许在不同路由器上采用不同的值，不会造成问题。</p>

<p class="quiz"><span id="ref-page_800" data-epub-type="pagebreak"></span><strong><a id="ref-ques24_2" href="#quess24_2">2</a>．</strong> C。根据题意，正确答案应描述会阻止建立邻居关系的场景。所有答案列出的都是两台路由器上相同或相近的设置值。其中，两台路由器使用完全相同的 OSPF 路由器 ID（RID）会阻止它们成为邻居，因此这一答案正确。</p>

<p class="quiz-para">对于错误答案，两台路由器必须具有相同的 Dead 间隔，所以都使用 40 不会导致问题。两台路由器可以使用任意 OSPF 进程 ID（相同或不同都无关紧要），因此对应答案错误。最后，两台路由器的 IP 地址必须位于同一子网，所以这一场景同样不会阻止 R13 和 R14 成为邻居。</p>

<p class="quiz"><strong><a id="ref-ques24_3" href="#quess24_3">3</a>．</strong> D。OSPF <strong>shutdown</strong> 命令告诉 OSPF 进程停止运行，包括从 IP 路由表中删除所有通过 OSPF 学到的路由、清空路由器的 LSDB，以及关闭现有 OSPF 邻居关系。实际上，它使 OSPF 在路由器上停止工作，但保留配置，因此在 OSPF 配置模式下执行 <strong>no shutdown</strong>，即可让路由器重新开始使用 OSPF，无须更改配置。</p>

<p class="quiz"><strong><a id="ref-ques24_4" href="#quess24_4">4</a>．</strong> B。OSPF 使用等价多路径功能：当它计算出到同一子网的多条路由，且这些路由并列具有最低度量值时，就将多条路由放入路由表。IOS 根据路由器上的 <strong>maximum-paths</strong> 设置限制每个目的子网的此类路由数量，该值通常默认为 6。路由器不会使用度量值为 15001 的路由，因为它比另外两条度量值为 15000 的路由更差。</p>

<p class="quiz"><strong><a id="ref-ques24_5" href="#quess24_5">5</a>．</strong> D。在一种路由协议内部，协议根据度量值选择最佳路由。因此，OSPF 选择度量值为 1000 的路由，EIGRP 选择度量值为 1,000,000 的路由。随后，路由器必须根据管理距离在这两个路由协议来源之间选择。使用默认设置时，EIGRP 的管理距离为 90，优于 OSPF 的 110。因此，路由器将最佳 EIGRP 路由放入路由表，也就是通过 EIGRP 学到的、度量值为 1,000,000 的路由。</p>

<p class="quiz"><strong><a id="ref-ques24_6" href="#quess24_6">6</a>．</strong> D。各路由定义的 IP 地址范围如下：</p>

<ul class="sq1">

<li><p class="bull">172.20.90.9/32：仅 172.20.90.9</p></li>

<li><p class="bull">172.20.88.0/23: 172.20.88.0–172.20.89.255</p></li>

<li><p class="bull">172.20.80.0/20: 172.20.80.0–172.20.95.255</p></li>

<li><p class="bull">172.20.0.0/16: 172.20.0.0–172.20.255.255</p></li>

<li><p class="bull">0.0.0.0/0: 0.0.0.0–255.255.255.255</p></li>

</ul>

<p class="quiz-para">根据这些范围，发往地址 172.20.89.100 的数据包匹配列表中除第一条外的所有路由。</p>

<p class="quiz"><strong><a id="ref-ques24_7" href="#quess24_7">7</a>．</strong> C。各路由定义的 IP 地址范围如下：</p>

<ul class="sq1">

<li><p class="bull">172.20.90.9/32：仅 172.20.90.9</p></li>

<li><p class="bull">172.20.88.0/23: 172.20.88.0–172.20.89.255</p></li>

<li><p class="bull">172.20.80.0/20: 172.20.80.0–172.20.95.255</p></li>

<li><p class="bull"><span id="ref-page_801" data-epub-type="pagebreak"></span>172.20.0.0/16: 172.20.0.0–172.20.255.255</p></li>

<li><p class="bull">0.0.0.0/0: 0.0.0.0–255.255.255.255</p></li>

</ul>

<p class="quiz-para">根据这些范围，发往地址 172.20.90.1 的数据包匹配列表中最后三条路由。其中，路由器会使用最具体的路由，也就是前缀位数最多的路由。因此，路由器使用前缀长度为 /20 的路由，其下一跳地址为 172.20.13.3。</p>

<section id="ref-glossary"><h2 class="h2a">术语表</h2><p class="gloss" id="ref-gloss_124"><strong>等价多路径（equal-cost multipath，ECMP）</strong> 一个术语，描述路由器到同一子网拥有多条度量值（开销）相同的路由时所采用的转发逻辑。</p>

<p class="gloss" id="ref-gloss_125"><strong>等价路由（equal-cost route）</strong> 路由协议计算到某个子网的所有可能路由时，其中多条路由具有相同度量值（开销）的情况。</p>

<p class="gloss" id="ref-gloss_216"><strong>IPv6 管理距离（IPv6 administrative distance）</strong> 在 Cisco 路由器中，当到同一子网的多条 IPv6 路由由不同路由协议学到时，供路由器在这些路由之间作出选择的一种机制。管理距离越小，路由信息来源越优。</p>

<p class="gloss" id="ref-gloss_246"><strong>最长前缀匹配（longest prefix match）</strong> 当路由器的 IP 路由表中有多条路由匹配数据包的目的地址时，选择其中掩码最长（掩码中二进制 1 的数量最多）的匹配路由。</p>
